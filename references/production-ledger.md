# 生产台账与放行门（生成过程的质量控制）

> **何时读**：进第三步、开始逐镜生成之前读一遍；每镜生成完记一行台账。
> **读完回哪**：回到 `studio-workflow.md` 第三步，或 `asset-consistency-part2.md` §八 工作流。
>
> 一句话：**这个库强在"怎么写"，弱在"怎么管"**——本文件补的是**生产过程**那一层：
> 资产什么时候算锁定、生成到第几次该换方案、每一笔生成花在哪。

---

## 一、为什么需要这一层

前面所有文件解决的是**单条提示词写得好不好**。但一条片子的成败还取决于两件事，它们**不在任何一条提示词里**：

1. **资产是否真的锁定了**——"看着像"和"能复用"是两回事。用一张偶然拍好的图当锚，后面每一镜都在赌。
2. **钱和时间花在哪了**——不记账的人**永远学不到自己的真实命中率**，于是每次都按最乐观的预算排片，超支发生时已无法回头。

两条纪律贯穿全篇：

> **① 门禁在生成之前**，不在生成之后。资产没锁定，不许开这一场的生成。
> **② 每次生成都留一行**。不记的就等于没发生。

## 二、资产状态机（draft → locked）

**状态只有两个，不设中间态。** 中间态会被当成"差不多可以了"，那正是漂移的来源。

```
draft（草稿）── 通过战斗矩阵 ──→ locked（锁定）
   ↑                                  │
   └──── 任何一处不达标 ───────────────┘（回退，不是"再抽几次"）
```

| 状态 | 含义 | 允许做什么 | 不允许做什么 |
|---|---|---|---|
| **draft** | 资产图已出，但**没有跑过战斗矩阵** | 继续出候选、继续调 | **不许**写进任何最终镜头的提示词；**不许**开该场景的生成 |
| **locked** | 战斗矩阵**全项通过** | 逐字复制进提示词 | **不许再改措辞**（改词即漂移，见 `character-continuity.md`）；要改就回 draft 重走 |

**★ 放行条件（硬门）**：**一场戏开生成之前，这一场涉及的每一个资产都必须读到 `locked`。** 只要有一个还是 draft，**这一场整体不开工**——不是"先跑着看"，因为一个漂移的资产会污染它出现的每一条生成（`asset-consistency.md` §一·补：设定图的光与形象会被继承进下游每一条）。

**★ 与 `asset-standard.md` §9 的映射（2026-10-31）**：完整生命周期是 `draft → review → approved → deprecated / stale`；**`locked` 不是第六个状态**，而是 `approved ∧ artifact_ready`（已批且产物已生效）。即 `draft→draft`、`locked→approved+artifact_ready`；`review / deprecated / stale` 本册未覆盖，按标准册执行。

## 三、战斗矩阵（draft → locked 的判据）

`asset-consistency-part2.md` §八 第 5 步给了"动测三勾"（脸没变 / 身体没散 / 光没漂），那是**一条测试镜**的判据。
**战斗矩阵是它的加强版**：不跑一条，跑**一组**——因为一条过得去可能是运气。

### 3.1 角色：四类测试必须全过

| # | 测试 | 怎么做 | 为什么必须有 |
|---|---|---|---|
| **T1 跨角度** | 至少 3 个角度（正 / 3/4 / 侧，或含背面） | 各跑一条静态图 + 一条短测试镜 | 正面过得去不代表侧面不换人 |
| **T2 跨景别** | 同一角色至少在**近景与中远景**各一条 | 近景看脸、中远景看体型与比例 | 景别一变，脸在画面里的像素量差几倍，模型给的脸也不一样 |
| **T3 真实光** | **用这个角色实际要出现的那场戏的光**，不是资产图的中性光 | 照该场戏的动机光源与光比生成 | 中性光下的脸好看，进到暗厨房可能整张脸陷进阴影（→ `asset-consistency-part2.md` §八 的原例正是死在这里） |
| **T4 同框** | 与**每一个会同框的搭档**各跑一条二人镜 | 两人同画框、有既定的空间关系 | **同框是漂移最严重的场合**：模型要在两个身份之间分配注意力，还要防"双胞胎"（→ `updream-workflow.md` §七 第 6 条的防双胞胎句） |

> **T4 最容易被漏**，因为资产阶段是**一个人一个人出的**，出场顺序上根本看不见"两人同时在场"这件事。
> **做法**：出资产时就把**同框关系表**列出来——谁和谁在同一场、谁和谁在同一框——然后按表逐对做 T4。
> 单主角片、或全片无同框的片，T4 记为"不适用"（不是"通过"）。

### 3.2 场景与道具：三类测试

| # | 测试 | 怎么做 |
|---|---|---|
| **S1 跨机位** | 正反两个机位（已有纪律，见 `asset-consistency.md` 3.2）各跑一条 | 180° 自检问句答不出 = 不过 |
| **S2 带角色** | 场景 + 该场主角一起跑一条 | 场景单独好看 ≠ 人景光影接得上 |
| **S3 带真实光** | 照该场戏的实际时段与光源跑 | 避免"照片里光 OK，动起来死板" |

**道具**：沿用 `asset-consistency-part2.md` §八 的豁免（"物件不是演员"），**但"与角色的尺度关系"要验**——尺度错的工具拿在手里会像玩具（→ 见第五节"尺寸参照"）。

### 3.3 量化放行线

定性三勾（脸没变 / 身体没散 / 光没漂）保留，**再加一条量化线**：

> **重复性测试：同一资产、同一条件，连跑 **5** 条。**
> **5 条全部成立 → 通过（5/5）。有一条不成立 → 不通过，回 draft 查变量。**
> 不允许"5 条里 4 条好就锁"——那第 5 条的状态会出现在成片里。

**为什么是 5 而不是 10**：本库按 **2–4 次**为单镜基础预算（`platform-matrix.md` §四），资产阶段的验证成本必须**低于**它所保护的镜头成本（指该角色全部镜头总成本，见下成本账），否则纪律会被人绕开。5 条足以暴露"这是个偶然产物"，10 条会让验证本身吃掉预算。
**跑法**：低分辨率、短时长、纯静态或极简动作——**验证的是身份与光影的稳定性，不是表演**。

**成本账**：一个角色的四类测试，**条数随角度与搭档数浮动**（光 T1"至少 3 个角度、各跑一条静态图 + 一条短测试镜"就 ≥6 条；T4 每个同框搭档各一条）。听上去多，但它保护的是**这个角色出现的所有镜头**——按"单镜 2–4 次 + 全片素材 ×3"算，一个主角几十个镜头，止损远超成本。

## 四、止损门（第几次不过就该换方案）

`updream-workflow.md` §六 已有"连续两批同一错误无改善即停"。**本节的增量是给它一个可数的触发点，并指定"停机后做什么"。**

| 累计生成次数 | 动作 |
|---|---|
| **1–3 次** | 正常试错区间。每次**只改一个变量**（改参考图不动提示词，改提示词不动参考图） |
| **第 4–5 次** | **判责任层**（→ `key-decisions.md` E11）：是**提示词问题**（换写法）还是**素材问题**（走素材层定向工具：重打光 / 调色 / 扩图 / 派生新机位——经新建图像节点引用原图实现） |
| **第 6–8 次** | **换实现路径，不换词**：单机位镜 → 分段镜；纯文字 → 走 `motion-control.md` 的参考视频 / 首尾帧路径 |
| **★ 超过 8 次仍不过** | **这镜需要的是更简单的镜头，不是更好的词。** 改结构：拆成两个更短更简单的镜、换更简单的机位、换景别（近景改成中景反而更容易稳）、或把这一镜的功能**转移到相邻镜**去做 |

> **为什么把上限设在 8**：`platform-matrix.md` §四·补 的难度系数表里，**最高档（打斗 / 特效 / 快速运镜）是 9–15 次**——止损上限 8 设在最高档下限之下，即**还没进入"最高难度"区间就先停手**。**若一镜的预算被吃满而仍不过，继续加注的期望收益是负的**，因为失败原因大概率是结构性的（动作太复杂 / 机位太刁），而结构性原因**不是重抽能解决的**。
> **纪律：不允许"再抽最后一次"**。这句话出现过的地方，实际都抽了不止一次。

**与 E35 的关系**：止损不等于放弃创作意图。**命题不变，换的是实现手段**——"他必须显得孤独"这个判断不因为拿不到全景航拍就作废，可以改成"他在画面里很小 + 长时间不动"（→ `direction-reasoning.md` 第五节"同框还是分开"同构：**意图守恒，手段可换**）。

## 五、尺寸参照资产（用一个实物锁多主体的比例关系）

**问题**：两个主体之间的**相对大小**是最容易崩的一类关系——人和巨型物体、成年人和孩子、同一个角色的两种状态（正常 / 巨大化）。**用形容词写不住**（"巨大的""矮小的"），因为模型不知道基准。

**做法**：**把比例关系交给一张资产图，而不是交给文字**——同一个机制早在本库别处用过：`sequence-craft.md` 用"带标注俯视图"锁位置，这里用"参照图"锁尺寸。

| 场景 | 参照物怎么选 | 怎么用 |
|---|---|---|
| **人与物** | 该物旁边放一个**已知尺寸的常见物**（一张椅、一个门框、一个易拉罐） | 出成**一张资产图**（人 + 物 + 参照物同框，且是**正交视角**），锁定后在每镜里引用它 |
| **人与人** | 两人并排、**同一基线**、**同一景别** | 出成一张"并排对照图"作设计稿；**不作为参考素材喂视频**（两张脸＝两个主体，见 `asset-consistency.md` 3.0）——只用于**指导比例判断** |
| **人的两种状态** | 两种状态**同框并排** | 同上：作设计稿，判"大了多少"，然后在提示词里写**具体比例句** |

**落地写法**（比例句必须可测，不许用形容词）：
```
[小主体]的身高到[大主体]的[具体部位：腰 / 胸 / 肩]，约[数字]倍关系
```

**三条纪律**：
1. **参照物必须在最终画面里也说得通**——画面里放一把椅子可以，放一把尺子不行（会被当成道具）。
2. **尺寸关系一旦定下就进冻结块**，与身份锚同等待遇：**逐字复用，禁改措辞**（"两倍"改成"大约两倍"就是漂移源）。
3. **巨物镜头优先用"低机位 + 前景遮挡"表达压迫感**，而不是靠缩小人物——**参照图管的是数值关系，压迫感是构图的事**（→ `shot-craft.md`）。

## 六、生成台账（每一笔都留一行）

**为什么必须记**：不记账的两个后果——① 无法回答"我这型镜头真实的命中率是多少"，只能引用公开数据（那是别人的项目）；② 超支无法归因，下次照错。

### 6.1 台账格式（一次生成 = 一行）

| 字段 | 记什么 | 例 |
|---|---|---|
| 日期 | — | 09-13 |
| 镜号 | 对应分镜表 | S07 |
| 资产版本 | 用到的 locked 资产与版本号 | 陈默@v002 / 老宅@v001 |
| 尝试序号 | 这一镜的第几次 | 3 |
| 结果 | **保留 / 淘汰 / 被过滤 / 生成失败**（报错、节点未生效——单列，**不计入命中率分母**，否则污染 6.2 的统计） | 淘汰 |
| 淘汰原因 | 按 `qa-failure-codes.md` 归类 | 指纹崩 |
| 改了什么 | **只写一个变量** | 改参考图 |
| 花费 | credits 或 ¥ | 6 |
| **平台** | 走的是哪条通道（**命中率必须分平台算**——同一提示词在两条通道上命中率不同，混算等于把两台机器的误差平均掉） | LibTV / WorkRally |
| **线索号** | 能指回那一次调用的平台 ID：`task_id`（`--count>1` 时是 **task_ids 数组**，逐个留）· `story_id` · `asset_id` · 画布节点 id。**取处 → `workrally-workflow.md` §6** | tsk_9f2 / st_31 / asset_881 |

**"被过滤"必须与"淘汰"分开记**——过滤是**审核层**拒绝（内容策略），淘汰是**质量不合格**。两者的解决方向完全相反：过滤要改内容表述或换模型，淘汰要改提示词或素材。**混在一起记，会得出"提示词写得不好"的错误结论。**
**★ 平台侧未暴露幂等键时（如 WorkRally）**：**重复提交的防线只剩"提交前先写进台账"**——
所以**线索号必须在提交那一刻就落格，不能事后补**；否则"这笔钱花了几次"永远查不回。

### 6.2 台账怎么用（三项产出）

1. **命中率（每保留一条要花几条）**
   `命中率 = 保留数 / 总尝试数`——**按镜头类型分别算**（静止单人 / 对话 / 手部 / 走路 / 打斗），不要算全片平均值（全片平均会掩盖最贵的那一类）。

2. **喂回预算表**：拿**你自己的**实测命中率，去替换 `platform-matrix.md` §四 的公开难度系数。**公开数据是别人的项目**，你自己的项目连续跑 30–40 行之后才有资格谈"经验值"。

3. **识别结构性失败**：同一个**淘汰原因**在**同一类镜头**上反复出现（≥3 次）→ **这不是提示词问题，是结构问题**：回去改 brief、换参考、拆镜（→ `prompt-ops.md` 第一节的判据同构）。

### 6.3 台账纪律

- **每一笔都记，包括成功的**——只记失败会算不出命中率。
- **淘汰原因用封闭枚举**（照 `qa-failure-codes.md` 的码），不要自由文本——否则统计时归不了类；**编号见 `qa-failure-codes.md`，引用时用编号不用中文名**。
- **样本少时要标 `low-n`**，不要报精确百分比（→ `pitfalls.md` PF5：报占比必须给样本取法、样本量、分类规则）。
- **账本是给下一次用的**，不是给这一次交差的。项目结束后**把命中率抽出来写进下一次的排期**，原始行可以不留。

## 七、速查（一页）

| 时刻 | 必须做的核对 |
|---|---|
| **开一场戏的生成之前** | 这一场涉及的每个资产**都读到 locked** 了吗？有一个 draft 就整场不开工（第二节） |
| **资产锁定之前** | 战斗矩阵**全项通过**了吗（角色四类 / 场景三类）？重复性 **5/5**？（第三节） |
| **角色资产** | **同框关系表列了吗**？每个搭档都跑过 T4 二人镜了吗？（3.1） |
| **一镜生成到第 6 次** | 换实现路径（单机位 → 分段镜 / 文字 → 参考视频），**不是换词**（第四节） |
| **一镜生成到第 9 次** | **改结构**——拆镜 / 换机位 / 换景别 / 转移功能。**不许"再抽最后一次"**（第四节） |
| **两个主体大小关系重要时** | 出**尺寸参照资产**，比例句写**数字**不写形容词（第五节） |
| **每次生成之后** | 台账**加一行**（含成功）；"被过滤"与"淘汰"分开记（第六节） |
| **一类镜头跑够 30–40 行** | 算**该类**命中率，喂回自己的预算表（6.2） |

## ★★★ 官方「音乐驱动广告」产线的放行门与所有权边界（**官方 `music-driven-product-ad/SKILL.md` · 一手 · 162 行 / 20,533 字符 · 2026-10-15 读**）

> 本册此前只吸收了该产线的**分册**（preflight / 参考职责 / 花钱边界 / 合成）。**主文件本身含一套完整的阶段闸与三条证据分离**，本轮补齐。

### 一、时长 D 的传导与"改音乐怎么办"

- **默认 D = 20 秒**；用户显式指定覆盖**本次项目**，**不改写保存的默认值**；**D 必须从头传到尾**：编曲 → 视觉时间线 → 模型参数 → 合成片段 → **回放时长核对**；
- **★ 完整乐句与衰减必须落在 D 之内**：**不许把整首曲子塞进广告、不许切掉正在发声的终止式**；**保完整段之后，可以用一小段静音尾巴补满剩余时长**；
- **★★ 视频已提交后用户改音乐**：**继续监控那个确切的 job**；先录好并验证替换的 cue，再更新合成；**绝不"只因为换了配乐"就重提视频**；
- **★★ 用户明确要求"音乐还在改就先起视频"**：按已同意的方案**把获授权的视觉 job 准备并提交**；待新 WAV 验证后再回头对时序，并**显式标明哪些同步尚未验证**；否则**先把音乐做完再生成**。

### 二、所有权边界（哪一部分归我方，哪一部分不外包）

- **音轨来源不是"用户可选的岔路"**：必须走官方那套演奏/录制/下载流程；**若平台不可用或 WAV 无法验证 → 停下并报阻塞，不许静默换成别的音乐生成器**；
- **不在 LibTV 里生成音乐**；也**不要问用户"用哪个音乐生成源"**；
- **不要问用户选模型**：视频默认用指定模型，**只有在用户显式改派时才偏离**；**若在线路线不可用 → 停下报告**；
- **不做创作规划的委托**：不要把风格/节奏/分镜/产线规划交给画布侧 Agent；确需走 Agent 路线时用**显式的"不用 Skill"路径**；
- **视觉形态默认固定**（一个不变的产品 / 一个向右的载体 / 3–5 个共地平线的空间 / 每处接缝一条无遮挡竖直硬边 / 固定远景侧视机位无消失点 / 无切无叠），**只有用户显式覆盖才改**；
- **不擅自重画已有可用参考**：用户给的可复用资产**要分析复用，不要"为了干净"重画**；缺失或不可用时才生成，且**生成后必须先检视再往下走**；
- **作曲口径**：默认原创；用内置曲目时**要标明作品与改编**——**"曲库节选"不是原创作品**。

### 三、§4 音乐段的四条硬纪律（本册此前没有）

1. **短试听约 5 秒/次**（除非用户另指长度）；**比较音色时保持同一段乐句**；**已获认可的方向不要再索要同一次批准**；**★ 短试听不等于最终 D 秒音轨**；
2. **★ "准备好的音符数据"本身不算完成这一步**——必须**真机演奏、录音、下载**；
3. **校验本地 WAV 的身份、时长、格式、体积，以及"可听见的音符内容"**；只裁掉不需要的首尾静音并**保留源文件**；**若为了凑 D 会切到音乐收尾，就回去改演奏**；
4. **★ 只用"已验证的 WAV"分析时长/强拍/瞬态/乐句/能量/断点/终止式；不许拿临时或想象的波形定下连续运动时间线**。

**★ 记一条"带音乐角色"的时间戳映射**（官方示例：`00:03.240 — first strong downbeat — product release and camera start`）；**精度留在内部产物里，不把毫秒级时序或音乐语言暴露进给模型的提示词**。

### 四、§5 时间块的取整规则（新增一条精确判据）

- **模型侧时间块取整到整秒**、**相邻区间连续且精确覆盖 `00:00–D`**；
- **★★ 若两个边界坍缩到同一秒 → 重新分配秒数并简化内部动作节拍，但不得删掉任何已规划的空间**；
- 每个空间配**一句具体可听的几何句**（**不能只写"侧视"这个词**），**每个地标只在背景出现一次**、每空间**至多一个额外向右运动物**、**2–3 个"差一点"动作**。

### 五、§6 提示词的两条禁令（本册此前没有）

- **不把模型、时长、画幅、分辨率写进散文式提示词**——**这些在实时界面里设**；**但整秒级时间线要留在提示词里**以控制连续动作；
- **提示词里不提音乐/节拍/卡点**；要求**不生成 BGM / 人声 / 旁白**，并逐空间点名环境声与平滑过渡。

### 六、★★ §8 三条证据必须分开（可直接当验收表）

| 证据类 | 要检什么 |
|---|---|
| **视觉** | 一镜到底无中断 · 远景侧视无消失点 · 地平线在下四分之一 · 接缝无遮挡无叠化 · 尺度一致 · 向右运动 · 地标单次使用 · **产品身份与文字不外溢** · 主角身份 |
| **可听** | 配乐在场 · 环境声连续与平衡 · 与运动对齐 · 收尾 · **无意外静音 / 生成音乐 / 人声 / 旁白** |
| **元数据** | 时长 · 时间戳 · 节点配置 · 模型/job ID · 项目身份 |

**★★ 两条禁语（本册此前没有）**：**不得凭 `audioVolume` 这类字段声称"可听同步"；不得凭提示词文本声称"产品保真"——必须去看对应产物。**
**交付要含**：成品或项目链接 · 音乐/运动理由 · 已验证的时长与格式 · 已知限制 · **最小有用修订选项**。
