# 人物一致性（形象 / 特征 / 设定在全片不漂）

> **何时读**：**剧本定稿、进资产之前**先读一遍（定"哪些特征要锁"）；**每写一镜之前**再查一次（查"这一镜有没有丢锚点"）。
> **读完回哪**：回 `asset-consistency.md` 出图；回 `quality-layer.md` 写进提示词。
>
> **与 `asset-consistency.md` 的分工**（重要，两份都要读）：**那边管资产与多视图，这边管全片五条一致性线**（身份·造型·位置·情绪·状态）；**本篇凡与那边重合的条目，一律压成一行指针**，不复制其出图工艺。
> - `asset-consistency.md` 管 **"资产图怎么出得不漂"**（出图工艺、参考图分工、局部编辑）；
> - **本篇管 "人物在整部片里怎么不漂"**——**跨镜的状态、特征、表演如何追踪与守恒**。

> **★ 一句话总纲**：**人物一致性不是"脸像"，是"五条线同时不漂"。**
> 脸只是第一条。**状态、服装、空间位置、情绪轨迹**漂起来，观众同样会觉得"不是同一个人/不是同一部片"。

---

## 一、★ 五条一致性线（模型最差的正是后三条）

**有实测支撑**：把单镜与跨镜的一致性分开测，**跨镜显著低于单镜**——视觉质量降约 **25.6%**，
而**情感表达降约 50%**。所以：

| # | 线 | 管什么 | 模型表现 | 我们要做什么 |
|---|---|---|---|---|
| 1 | **身份** | 脸、骨相、发型、发色、标志特征 | 相对最好（有参考图时） | 参考图 + 冻结身份块 |
| 2 | **造型** | 服装、配饰、身上物件、脏污状态 | 中 | 造型状态追踪表（§三） |
| 3 | **空间位置** | 上一镜在哪、朝向哪、和谁的距离 | **差**（可低至 0.48） | 每镜显式写"位置与朝向"（§四） |
| 4 | **情绪轨迹** | 情绪在全片怎么演进，不是每镜重新起算 | **最差**（低至 0.34） | 写**情绪弧线表**，每镜标注"从哪到哪"（§五） |
| 5 | **表演与身体状态** | 身上的物理状态（湿、汗、伤、喘）与表演基调 | **差**（面部动作时序 0.38–0.56） | 状态守恒清单 + 表演基调锚（§六） |

> **这张表的用法**：**模型普遍得分低的项，就是我们必须显式写进提示词的项。**
> 这与"AI 味检测清单反过来用"完全同构——**模型的短板表 = 我们的必写清单**。

## 二、身份锚：冻结块与"不许同义替换"

### 2.1 冻结身份块（40–70 字）

→ **权威定义（40–70 字、字段顺序、逐字复用）见 `asset-consistency.md` §三「推荐资产包」③ 与 `asset-consistency-part2.md` §八 工作流第 1 步**；本篇只补跨镜用法：**它是"身份"线在全片的唯一比对基准，每镜必带**。本库示例（照格式写，非模板）：

```
脸型偏窄、颧骨明显；眼距略宽、双眼皮很浅；黑色短发向后梳，
左眉尾有一道旧疤；身形偏瘦、肩窄，锁骨突出。
```

### 2.2 ★ 改写措辞本身就是漂移源（最容易被忽略的一条）

→ **权威定义与自检表见 `asset-consistency-part2.md` §七 常见错误第 5 条（冻结词汇表）与 §八 工作流第 1 步**（**冻结块是全片唯一的"人像定义"，任何镜次都不许同义改写、不许精简、不许润色、每镜必带**）。**本篇只补"跨镜"这一个角度**：同一件衣服这一镜写"黑色皮夹克"、下一镜写"深色外套"，**模型会当成两件不同的衣服**——所以 §三 造型追踪表里每一行的措辞也要全片冻结。

> **自检**：把全片的身份句抽出来排在一起，**应当完全一致、连标点都一样**。

## 三、造型状态追踪表（跨镜不漂的第二条线）

**同一个人在不同场次，衣服可以换，但"换的逻辑"必须连贯。** 建一张表，**每场戏一行**。

| 场 | 服装 | 配饰 | 脏污/破损 | 随身物 | 与上一场的差异是否有交代 |
|---|---|---|---|---|---|
| 1 | 深蓝工装外套 + 灰 T | 皮带手表 | 干净 | 钥匙串 | —（起点） |
| 2 | 同上 | 同上 | **右袖沾了油** | 同上 | **有**（场 1 修车） |
| 3 | **换成白衬衫** | 手表摘下 | 左手指节有伤 | 钥匙串 | **有**（场 2 结尾受伤） |

**三条纪律**：

1. **脏污与破损只能累积或"有交代地重置"**——场 2 沾的油不会在场 3 自然消失。
2. **换装必须有因**——要么是时间过去了，要么有事件；**没交代的换装＝漂移**。
3. **配饰是身份的副锚点**——手表、戒指、耳饰这类物件**换了就是另一个人**；它们也要出独立资产。

> **与 `asset-consistency.md` 的接口**：配饰与"随身物"要进**子地标**机制（≥2 镜出现就要单独出资产；**高频出镜的才单出**——偶现配饰靠冻结措辞保一致即可，防过度生产）。

## 四、空间位置守恒（第三条线：跨镜不"瞬移"）

**跨镜最常见的低级错误：人物换了位置、换了朝向，但没人交代他是怎么过去的。**

**每镜必写的三件事**：

| 写什么 | 例子 |
|---|---|
| **他在画面的哪里** | `画面左侧三分之一、靠后` |
| **他朝向哪** | `面朝画面右侧、侧对摄影机` |
| **他与谁/什么的关系** | `离门两米、背对桌子` |

**再加两条"轴线"纪律**（与 `cinematic-grammar` 类同源）：

- **视线方向**：A 看画面右 → 切到 B 时 B 必须看画面左（**视线匹配**）。
- **动作轴线**：一旦定了"从哪往哪走"，**不许在切点换边**（越轴）。

> **判据**：**把相邻两镜首帧并排放，人物的左右位置与朝向能接上吗？**
> 接不上 = 观众会感到"跳到别处了"，即使脸一模一样。

**提示词写法**（不要写"他在房间里"，写具体）：
```
人物位于画面左侧、靠墙站着，面朝画面右侧，离门约两米，背对窗。
```

**生成参数落法（跨镜位置连续，2026-09-30 补）**：上一镜**实际生成的尾帧**抽成 image 节点后作下一镜首帧引用（续接纪律 → `motion-control.md`；LibTV 编排层首尾帧字段 → `libtv-op-manual.md`）——**文字只描述落点与朝向，不代替帧传递**；纯文字写"他保持原位"跨镜必漂。

## 五、★ 情绪弧线（第四条线：最脆弱的一环）

**模型最差的一项就是这个**（实测基线可低至 0.34）。原因：**它每镜重新起算情绪，把每镜都演"满"。**

**做法：开拍前画一张情绪弧线表**，每场标注"**从哪 → 到哪**"，而不是只标"是什么"。

| 场 | 起始情绪 | 结束情绪 | 幅度 | 身体信号（写在提示词里的） |
|---|---|---|---|---|
| 1 | 平静 | 不安 | 小 | 手指开始搓裤缝 |
| 2 | 不安 | 压抑的怒 | 中 | 下颌收紧、语速变慢 |
| 3 | 怒 | 崩溃 | 大 | 呼吸变浅、肩膀垮下来 |

**三条写法纪律**：

1. **禁止每镜都演满**——**情绪有起伏才叫弧线**；全场都是"悲伤到极致"＝没有弧线。
2. **给出"从哪来"**——这一镜的情绪是**上一镜的延续或反应**，写清楚。
3. **幅度与身体信号挂钩**——情绪不是形容词，是**身体在做的事**（对接 `performance-craft.md`）。

> **反 AI 味的直接作用**：**AI 默认"每镜都情绪饱满"**——这是"表演假"的头号来源。
> **写"他还在忍"比写"他很愤怒"有效得多。**

## 六、表演与物理状态守恒（第五条线）

### 6.1 物理状态必须"记账"

**人物身上的可累积状态**——汗、湿、伤、喘、灰尘、冷得发抖——**要跨镜守恒**。

| 状态 | 守恒规则 |
|---|---|
| **湿** | 淋过雨就一路湿到有理由干；**不许下一镜衣服干了** |
| **汗** | 运动后持续；**领口与后背先湿** |
| **伤** | 位置固定、**随时间变化但方向单调**（红肿→淤青→结痂），不许转移 |
| **喘** | 剧烈动作后延续至少一镜；**振幅逐渐减小** |
| **尘 / 血 / 污** | 只增不减，或"洗过"要交代 |

> **与 `physical-feedback.md` 的分工**：那边管**单镜内的力学**（质量/惯性/接触），本篇管**跨镜的守恒**。

### 6.2 表演基调锚（"同一个人"的表演层）

同一个角色在不同镜头里的**表演基调必须一致**——不能这一镜克制、下一镜夸张。

在角色主档案里写一行 **表演基调**（对接 `performance-craft.md` 的主档案）：
```
表演基调：话少、动作慢半拍；情绪从不外露，靠手部小动作与呼吸节奏表达。
```

**每镜写表演时，先看这一行**，再决定这一镜给多少。

**台词侧的 voice 一致性（2026-09-30 补）**：同一角色跨镜走平台 TTS 时，**声线母档＋当句台词一并写入音频节点 prompt**（→ `sound-craft.md` 声线母档）——母档逐字复用不重写，台词表演线才不漂（本册五条线之外的台词侧配套，不计入五线）。

## 七、失效症状 → 根因 → 修法

| 症状（你看到的） | 真正的原因 | 修法 |
|---|---|---|
| 脸像，但**换了个人**（气质不对） | 表演基调与情绪弧线漂了 | §五 情绪弧线表 + §6.2 基调锚 |
| 脸像，但**衣服每镜都不太一样** | 造型状态没记账；或措辞被改写 | §三 追踪表 + §2.2 逐字复用 |
| 人物**突然站在别处** | 空间位置没写 | §四 每镜写"位置 + 朝向 + 关系" |
| **换了装/伤好了**，没交代 | 物理状态没守恒 | §6.1 状态记账 |
| 上一镜淋透了、下一镜干的 | 同上 | 同上 |
| A 看右、B 看右（对不上） | 视线/轴线没锁 | §四 两条轴线纪律 |
| **每镜都演得很满**、很累 | 情绪曲线是平的 | §五 纪律 1：禁止每镜演满 |
| 同一角色**前紧后松**、状态跳 | 采样时没有回头对齐 | §八 采样时的三查 |

## 八、采样时的三查（每批生成后必做）

生成不是一次性的——**每批出来之后要回头对齐**，否则漂移是"累积"的。

| 查什么 | 怎么查 |
|---|---|
| **① 查脸** | → **权威定义见 `asset-consistency-part2.md` §5.0（只有一处不对时禁止重 roll）与 §八 第 10 步（全尺寸对比锚图、别看缩略图）**；本篇只加一句：**查脸的比对基准是 §2.1 冻结块 + 身份锚图**，比的是"跨镜同一个人"，不是单镜好不好看 |
| **② 查状态** | 对照 §三/§6.1 的表：**这一镜的状态与上一镜接得上吗？** |
| **③ 查弧线** | 对照 §五 的表：**这一镜的情绪是"从哪来"的？** |

**组装核对（2026-09-30 补）**：以上三张表＋§二冻结块 / §四位置 / §6.1 状态，**每镜组装 prompt 时逐表过一遍**——该用插桩引用的（参考图 `{{...}}` 位次）按 `libtv-prompt-house-style.md` 的插桩纪律上，该逐字粘贴的逐字粘；**表停在文档层＝没送到提示词里**。

**回灌纪律** → **权威定义见 `asset-consistency-part2.md` §八 工作流第 8 步**（每批留最像的一张，回灌作下一次的新参考）。**跨镜回灌三步（2026-09-30 补）**：① **更新参考节点**——新最佳图入画布、指回同一身份；② **下游作废重跑**——凡以旧图为参考的镜全部作废重生成（级联作废口径 → `libtv-official-qa-part5.md` §17.8）；③ **凭证反查**——新参考的提示词与参数归档，接续可查。
**凭证纪律** → **权威定义见 `asset-consistency-part2.md` §八 工作流第 10 步**（保存提示词与参数作为一致性凭证）；本篇只补跨镜用法：**凭证要能反查"这一镜的情绪与状态是从哪一镜接过来的"**，否则查不出漂移发生在哪一镜。

## 九、自检七问（开机前 + 交付前各问一遍）

1. **冻结身份块**定了吗？全片**逐字一致**吗（连标点）？
2. **造型状态表**建了吗？每一处差异**有交代**吗？
3. 这一镜写了**"他在哪、朝哪、和谁什么关系"**吗？
4. **情绪弧线**标了"从哪到哪"吗？还是每镜都写"很愤怒"？
5. **物理状态**（湿/汗/伤/喘/脏）与上一镜**接得上**吗？
6. 相邻两镜的**视线与轴线**对得上吗？
7. 这一镜的**表演基调**与角色主档案一致吗？

> **零命中 ≠ 合格**：七问只保证"没踩已知的坑"。

## ★★ 官方「两图身份锁定」规格（**LibTV 官方 `music-driven-product-ad/references/product-lock.md` · 一手 · 2026-10-15**）

> 官方把"**只用两张视觉参考图**"写成了硬规格：`@图片1` 锁唯一产品、`@图片2` 锁首尾同一主角；**地标、光线、空间形态、接缝全部用视频 prompt 定义**——理由是"**避免额外参考图把透视机位或错误景别带进来**"（与上文"参考图会带自己的机位"同一条）。

**① 定脸图（`@图片2`）规格**：**3:4 竖版头肩近景** · **纯白无缝背景 `#ffffff`** · **真实可见的细腻肤质与健康光泽、避免塑料感** · 五官/骨相/妆感/发型/发色/表情/眼神清楚 · **不出现 Logo 与无关配饰**。
**通用出图 prompt 要点**（Seedream 5.0 Pro 档）：`real not plastic` · `no logo, no accessories` · `plain seamless pure white background #ffffff` · `head-and-shoulders portrait, vertical 3:4`。
**★ 职责边界（本库此前没有这条措辞）**：**定脸图只负责五官、发型、肤质**；**服装在视频 prompt 里完整描述，不依赖资产图服装来锁**；视频 prompt 还必须写明"**不采用参考图背景**"与"**开头与结尾为同一人**"。**只生成 / 提交一张定脸图。**

**② 产品图（`@图片1`）规格**：单个产品**平铺或正面** · 1:1 或原始比例 · **完全展开且无裁切** · **纯白无缝背景 `#ffffff`** ＋ 柔和均匀棚拍光 · 颜色/图案/材质/形状/标志性结构/文字清楚 · **不出现额外产品、额外文字或无关配件**。

**③ 产品定义必写六项**：类别与独特轮廓 · 几何比例/材料/表面处理/颜色 · 图案/缝线/接口/扣件等识别细节 · **文字或 Logo 的位置、方向与准确拼写** · **产品与人物的相对尺度** · **不允许出现的错误颜色/错误材质/额外配件/复制品**。
**★ 产品文字防串（本库此前零记录）**：带文字/Logo 的资产图**生成后要逐字核对**；视频 prompt **必须声明这些文字只出现在产品上**，不得复制到建筑/交通工具/标牌或其他物体。
**★ 全片唯一性**：**全片始终只有这一件产品**；它离开主角 → 穿越空间 → 回到主角时，**外观、比例、文字必须连续，不能消失、复制、替换或变形**。

**④ ★ 尺度必须用数字锁（因为定脸图不提供全身尺度）**：官方给了一组可直接照抄的数字——全片**大全景**；**站立人物高度占画面 1/4–1/3**；**载体完全展开宽度不超过人物身高 1/3**；运动中**通常约人物头部大小**。

**⑤ 官方自带的 6 条验收检查（可作门禁）**：`@图片1` 是否只有一个完整产品且颜色/材质/文字准确 · `@图片2` 是否清晰的 3:4 头肩纯白定脸图且肤质真实 · 视频 prompt 是否**另外**写清主角服装且首尾一致 · 是否有**产品文字防串规则** · 产品离手/运动/接回是否**保持同一件的小尺度与连续性** · 是否**只**提供这两张视觉参考图（无地标/场景/光线参考图）。

## ★★★ 角色卡的官方接口族（**登录态编辑器 bundle 静态 · 一手 · 2026-10-15 读**）

> **这条直接回答本库长期挂着的"角色卡能不能跨项目复用"（原先标待验）**：**能，而且有正规通道**。

### 一、★ `userCharacterParse`：**"角色解析"＝产出一段可复用的 `generation_prompt`**

| 项 | 内容 |
|---|---|
| 方法 | `POST` |
| 请求体 | **`{ prompt?, imageUrl? }`**——**两者至少要给一个**，**都不给直接抛错**：`Character parse requires prompt or imageUrl` |
| 可选项 | 支持 **`AbortSignal`** |
| **响应校验（客户端逐条）** | **必须有非空字符串 `generation_prompt`**；若顶层没有，则要求 `profile` 对象里带它；**缺了就抛错**：`Character parse generation_prompt is missing` |
| 归一后返回 | **`{ profile: { …profile, generation_prompt: <trim 后> } }`** |

**★ 意义**：**"给一句人设或一张图 → 得到一段 `generation_prompt`"是平台自己定义的"角色卡解析"**。这段 prompt 就是**跨项目复用的载体**——**比让我方从零拼人设描述更可靠**。

### 二、角色卡的 CRUD（同一族，逐条）

| 操作 | 方法与请求体 |
|---|---|
| **建** | `POST` **原样透传入参** |
| **列** | `POST` **原样透传入参** |
| **改** | `POST` **原样透传入参**（并带上入参里的 `characterUuid`） |
| **查** | `GET`，params **`{ characterUuid }`** |
| **删** | `POST`：`{ characterUuid }` |
| **标记已用** | `POST`：**`{ characterUuid }`** |

**→ 结构读法**：**只有"查"是 GET（且只吃 `characterUuid`），其余全是 POST**；**建/列/改三个是"透传"** ⟹ 字段集由服务端定义，**客户端不做本地校验**（与下面那条形成对照）。

### 三、★ 公共角色库（`character-library/*`）＝**防御式归一**，不抛错

| 操作 | 方法 | 归一行为 |
|---|---|---|
| 列表 | `POST`（透传） | **响应不合法时返回 `{ list: [], total: 0 }`，不抛错** |
| 详情 | `GET { characterUuid }` | 返回 `detail` |
| 最近列表 | `POST` | 同上归一为 `{ list, total }` |
| **加最近** | `POST` | 读 **`lastUsedAtMs`**（数字），非法则返回 `undefined` |

**→ 与 §一/§二 的对照**：**同一个"角色"主题下，"我方角色卡"走严格校验并抛错，"公共角色库"走防御式归一静默给空**。
**★ 排查含义**：**公共角色库"看起来是空的"可能只是响应被判为不合法**（例如权限/风控场景返回了别的结构）——**先怀疑响应形状，再怀疑库里真没数据**。

### 四、★★ 由此可写的三条作业纪律

1. **跨项目角色一致性，优先用"角色卡 + `generation_prompt`"这条通道**（`parse` 产出 → `create` 存卡 → `list`/`detail` 取回），**不要每次从零手写人设**；
2. **`parse` 的成功判据是"拿到非空 `generation_prompt`"**——**没有它就不算解析成功**（客户端就是这么判的）；
3. **区分两个入口**：**"我的角色卡"会抛错、"公共角色库"会静默给空** ⟹ **为空时先查响应形状与权限，别先认定"平台没有角色"**。
