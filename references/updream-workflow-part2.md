## 七、参考素材纪律（来自火山方舟官方文档 · Seedance / 即梦系）

> 这一节的几条**推翻了常见的教程做法**，按官方口径来。

### 1. 人物参考：**大头照 + 全身照，不要多视图**

官方明确：**不建议使用人物多视图（三视图 / 六视角）作为参考素材**——模型容易把同一人物的不同角度**识别成多个不同主体**，反而**加剧 ID 漂移**，并诱发"双胞胎"。

- ✅ 推荐：**一张只含头部的人脸特写（大头照，无表情最佳、背景干净）** + **一张全身照**
- ✅ 提示词里分工写清：`面部特征参考图片1（大头照），妆造参考图片2（全身照）`
- ❌ 把六个视角拼成一张图当参考

**这对我们的影响**：角色设定板（十个分区）**仍然是好的设计稿与视觉基准**，但**不要直接拿它当参考素材喂图生视频**——它属于"多视图混排"。要出片时，从设定板里另出（或裁出）一张干净大头照 + 一张全身照作为参考。

> ⚠️ **边界（2026-09-11 划清）**：这条只管**人物**。**无生命道具的多角度拼图不受此限**——道具没有面部身份漂移问题，多角度只增信息不增风险，官方资产课把"道具多角度"写进标准流程。判据一句话：**有没有脸／会不会被当成两个主体**。见 `asset-consistency.md` 3.0。

> ⚠️⚠️ **适用范围（2026-09-13 补充）**：**本条只适用于"参考图平铺"的输入方式（Seedance / 即梦的 `reference_image`）。有「主体 / 元素」封装层的平台结论相反**——**可灵官方**："一个主体至少 2 张参考图、最多 4 张"，并支持 **AI 自动补全多视图**。
> **判据**：**这几张图是打包成一个「主体」喂的，还是当独立参考图平铺喂的？** 前者 → 多角度越多越好；后者 → 本条成立。**不要把"Seedance 的注意事项"当成"所有平台的通用规律"**——对照见 `platform-matrix.md` §7.7 与 `asset-consistency.md` §3.0。

### 2. 重要素材前置

越需要精准参考的素材，**放在提示词里越靠前**。这也是"关键句前置"的官方依据。

### 3. 参考图里不要有文字

参考图片/视频里带文字 → 生成结果里会**莫名其妙出现字幕**。
先把参考素材里的文字清掉（用图片编辑能力处理），再作为输入。
另外：**横屏比竖屏出现字幕的概率明显低**——竖屏交付可以在横屏生成后再裁。

### 4. 不要直接把完整剧本当提示词

文案过度冗余会造成模型理解混乱、指令失焦。
剧本是给人和流程看的；**喂给模型的必须是精简过的镜头指令**。
整合式交付 ≠ 把剧本塞进提示词。

### 5. 参考人物不超过 4 人

超过 4 人时输出稳定性明显下降（少人 / 多人 / 重复）。
人数多就**分组**：每组 ≤4 人分开生成图，再用多张分组图去生视频。

### 6. 防"双胞胎"全局约束句（画面里有多个角色时加）

```
视频全程禁止出现外形、着装、配饰完全一致的人物，
禁止生成同款分身、双胞胎效果，同一画面中仅保留单个对应人物。
```

并在提示词里**给每个角色标注对应参考图**（`张三（对应图片1）`），格式统一。

### 7. 时长与截断

单镜控制在 **≤15 秒**；豆包 App 端锁 5s / 10s，**不要在豆包上承诺 15s**。
多镜序列 **≤8 镜**，超过就分批。

### 8. 延长视频的拼接

用延长功能续写后，衔接处常跳变。官方做法：
**前一段末尾删 6 帧、后一段开头删 1 帧**，逐个衔接点处理；
续写时**以转场切镜的时刻结尾**，下一段从新场景开始。

### 9. 特效不要靠文字描述

"数字 2999 以倒计时动画出场"这种，文字描述出来常是无序跳变。
**给参考视频**（`数字出场方式参考视频1`）比写十句描述都准。

### 10. 风格漂移的处理

参考图是写实、想要动漫风 → 会漂回写实。**先把参考图转成目标风格，再去生视频**——这一步比在提示词里喊风格有效得多。

## 八、平台原生机制（2026-09-13 补 · 落地必读 · **前七节讲怎么写提示词，这一节讲本 skill 怎么在平台上跑起来**）

### 8.1 ★ 本 skill 可以**直接作为 updream Skill 上传**

- **「上传技能」支持 zip 技能包 或 单个 `SKILL.md` 文件**；也可「创建技能」用对话生成（不写代码）；编辑器支持 HTML / Markdown。**流程**：创建 → **「未公开」**（仅自己可测）→ **画布测试**（激活后新建项目调用；也可后台对话调试）→ **「公开发布」**提交审核；**改内容需重新发布更新版本**
- ⚠️ **待核（上传前必做）**：updream 对 `SKILL.md` 的 **frontmatter 规范**（本库现为 `name / description / metadata`，来源标记 `agent_created` 保存在 `metadata` 内）——**以平台模板为准，不要假定兼容**

### 8.2 ★ 平台原生机制：把本库的线上概念对上号

| 本库概念 | updream 原生机制 | 怎么用 |
|---|---|---|
| **资产 draft → locked** | **资产图节点右下角锁形图标**：点击**永久锁定**，后续镜头复用同一底图；**不锁则每镜重新抽卡** | **出完立刻锁**——这就是"locked 才能开工"的平台落实 |
| **资产先于镜头**（硬门） | 「角色一致性强化」模块自动提取人名、关联资产库；**未提前上传角色图 → 该步报错中断** | 平台的"报错"就是本库的放行门 |
| **参考图一张只承担一个任务** | **图片节点 → 文本节点连线**建立「视觉→语义」关联；**断开会角色漂移** | 每个资产节点都要连到它的语义节点 |
| **白模 / 线稿预演** | **「预演台」3D 白模片场** → 精准运镜 | 与官方"白模参考视频"同源（→ `motion-control.md` ①·补） |
| **统一提质层** | **风格记忆 + 批量统一 Skill**（一键统一多张分镜的光影 / 色调 / 画风） | 批量统一后**仍要逐张核"像不像同一次拍摄"** |
| **Skill 本体的加载** | **必须在画布中激活**，激活后**绑定当前画布上下文，换画布需重激活**；未激活＝当普通对话处理 | **每开新项目都要重新激活** |

**平台集成与默认值（截至 2026-09）**：集成 **Seedance 2.0 · Kling · Vidu**；默认 **SeeDream 5.0 / 16:9 / 2K**；支持首尾帧过渡控制、局部重绘、扩图、超分、多镜头拆分、截图抽帧。官方精选 Skill 名（可作定位参照）：**「精品分镜工坊」·「AI短剧资产设计师」**。

### 8.3 ⚠️ 两条**未采**的说法（标待核）

1. "锁定角色**三视图**后全片复用**同一张底图**" → 与本库＋火山官方口径（同身份多视图平铺会被识别为多主体）**可能矛盾**，且没说清"三视图"是一张拼图还是三个独立节点 → **不据此改本库**
2. "运动笔刷**仅 1.0 模型支持**" → 出自 1.5 时期文章，**是否延伸到 3.0 未知** → **以平台界面为准**；**image2 的"≤16 张参考图"与"不能参考图锁脸"两说冲突** → 见 `storyboard-platforms.md` **H5**，**实测前按"描述为主、参考为辅"写**
