## 一、流程层最常见错误（**按发生频率排序**）

| # | 错误 | 症状 | 提前发现 | 正确修法 |
|---|---|---|---|---|
| **①** | **引用节点未生效就点火下游（最高频）** | 下游任务直接失败 / 引用图为空 / 生成结果里没有参考形象，或被校验拦下 | `read_node` 看上游：**状态是否已生效、产物 `url` 是否非空**；`validate_generation_plan` 点火前返回引用未就绪类错误；建边后回读下游，确认 `imageList` 非空且 `imageListOrder` 与 `left` 顺序一致 | **先点火上游 → 确认生效（`url` 非空）→ 再建边/点火下游**；**不要拿"已创建"当"已生效"** |

| **④** | **改了锚点/上游，没重做下游（高频）** | 下游画面仍是旧形象/旧设定；结果与最新锚点不一致 | **维护依赖图**；上游 key 或内容版本变化时**沿 `left` 边找出全部下游**；回读下游产物时间/版本是否早于上游最新生效时间 | 上游变更后把受影响下游标记待重做并重新点火；**同一产物保持单一已生效节点，旧节点标废弃** |
| **⑤** | **顺序 / 拉回位置错误（中高频）** | 多参考图主次颠倒 · **首帧/尾帧接错** · 续写从错误帧开始 | 回读 **`imageListOrder` 是否等于预期 `left` 顺序**；续写类节点核对 start/end 帧引用与上游产物帧 | **严格按"主参考在前"构造 `left`**；续写只引用**上一镜真实尾帧**节点；顺序错就 `leftRemove`/`leftAdd` 重排后**重新校验再点火** |
| **⑥** | **引用了废弃/失败节点（中频）** | 校验报错或生成出残缺参考；链路里挂着无 `url` 的节点 | 回读每个 `left` 上游的状态与 `url`；**台账中标记为废弃/失败的 key 不得出现在任何 `left` 中** | **失败节点不原地重跑**，新建节点替代并把引用整体切到新 key，旧 key 标废弃；批量扫描"`left` 中是否含废弃 key" |
| **⑦** | **并发超限 / 超时后错误收尾（中频）** | 提交返回限流/并发上限错误；**超时后盲目重试导致重复任务** | 提交返回码（限流/并发/超时）；回读节点实际状态 | 控制在途并发数，**有依赖链的严格串行**；**★ 超时先 `read_node` 确认任务是否其实已在跑/已完成，再决定是否用同一幂等键重试** |
| **⑧** | **交接不一致：分镜表/台账与真实节点脱节（中频）** | 账上写的 key/顺序/状态与画布实际不符；下游按错表接线 | 用 `read_project`/`get_project_snapshot` 拉实际节点，与台账**逐行对 key、`left`、状态、`url`** | 每次创建/生效/废弃**立即回填台账**；**台账只记录事实，点火计划以"快照 + 校验"为准，不以记忆为准** |

## 二、★ 点火前最常见的 5 个"自查动作"（逐个做）

1. **查上游生效状态**：对每个 `left` 上游 `read_node`，确认**已生效且产物 `url` 非空**（**不是"已创建"**）。
2. **查引用边与重算结果**：确认引用是通过 `left` 建的；回读 **`imageList` 非空 · `imageListOrder` 与预期 `left` 顺序一致 · 没有手填残留**。
3. **跑校验**：`validate_generation_plan`（必要时 `get_model` 确认模型/模式可用），确认无"引用未就绪 / 参数非法 / 模式不匹配"。
4. **查当前节点状态与幂等**：`read_node` 确认目标节点**不在 `generating`、本次尚未产出**；准备好**稳定幂等键**。
5. **对台账与快照**：`get_project_snapshot`/`read_project` 核对节点 key、`left`、状态与分镜表一致，且 **`left` 中无废弃/失败 key**。

---

## 三、顺序类错误的表现

- **引用未生效就跑**：校验直接拦截，或下游生成时参考为空 → **成品无参考形象/场景**；回读会看到**上游 `url` 为空而下游已被提交**。
- **引用顺序错**：多参考时**主形象被次要参考覆盖**、角色脸/风格串台；**回读 `imageListOrder` 与预期不一致即可定位**。
- **拉回/续写位置错**：首尾帧接反、从上一镜开头或错误帧续写 → 画面跳变/重复；**表现为续写节点引用的帧不是上一镜真实尾帧**。

---

## 四、引用链类错误如何提前发现

- **改锚点没重做下游**：维护**"上游 → 下游"反向索引**；锚点 key/版本一变更，列出全部下游，**比对下游产物生效时间是否晚于上游最新生效时间**——**早于即作废重跑**。
- **★ 重复引用同一节点**：**扫描 `left` 是否有重复 key**；回读 `imageListOrder` 是否出现**重复项**（**重复会放大权重或引发校验异常**）。
- **引用废弃节点**：点火前**批量校验每个 `left` key 的状态与 `url`**；**台账废弃集合 与 实际 `left` 集合 做差集，命中即阻断点火**。
- **通用手段**：点火前统一过一遍 `validate_generation_plan`——**它能在提交前暴露大部分断链/未生效引用**。

---

## 五、点火类错误：避免与收尾

- **没带幂等键**：每次提交必须带**稳定幂等键**（key ＝ 业务唯一意图，如 `节点key + 内容版本`）；**网络重试复用同一 key**。
- **重复点火**：点火前 `read_node`，**`generating` 或已有本次产物则不再提交**；以回调/轮询结果为准。
- **并发超限**：限制全局在途数量；**有依赖关系的节点严格串行**，无依赖的才有限并行；遇限流**退避重试，不堆提交**。
- **★ 超时收尾**：**超时不等于失败**。先 `read_node`/查任务确认真实状态：**在跑则继续等 · 已成功则直接回填 · 确认未受理才用同一幂等键重发**；**绝不一超时就新建任务**。

---

## 六、交接类错误如何防

- **分镜表与实际节点不一致**：**以画布快照为唯一事实源**。创建节点拿到真实 key 后**立刻写表**；每次接线（`leftAdd`/`leftRemove`）后**回读并更新表中的 `left`/顺序**。
- **台账没回填**：把**"创建 / 生效（`url`）/ 废弃 / 重做替换"四个事件做成强制回填步骤**，**未回填不进入下一节点**；定期用快照与台账对账（**key、状态、`url`、`left` 四列对齐**）。
- **失败重建时**：**旧 key + 失败原因 + 新 key 必须同时入账**，保证引用链可追溯。

## 七、★★ 点火前必查清单（Checklist · 逐项打勾）

- [ ] **所有 `left` 上游均已生效**：状态完成且 `url` 非空（**不是仅"已创建"**）。
- [ ] **引用全部通过 `left` 建立**，**无手填 `imageList`**；回读 `imageList` 非空。
- [ ] **`imageListOrder` 与预期 `left` 顺序一致**（主参考在前；续写引用**上一镜真实尾帧**）。
- [ ] **`left` 无重复 key、无废弃/失败节点 key**。
- [ ] 已跑 **`validate_generation_plan`**（并用 `get_model` 确认模型/模式），无报错。
- [ ] 目标节点**当前不在 `generating`**，且本次尚无产物。
- [ ] **已带稳定幂等键**；重试复用同一 key。
- [ ] **在途并发数在上限内**；依赖链节点串行、无依赖才并行。
- [ ] **台账/分镜表已与 `get_project_snapshot` 对账**：key、`left`、状态、`url` 全部一致。
- [ ] **明确收尾路径**：超时先查状态再决定，**不盲目重复点火**；结果生效后**立即回填台账**。
- [ ] **★「插桩完整性」三查（R23）**：每个被引用节点必须**同时**满足 —— ① 出现在引用字段里（`left` / `referenceImageNodes` / 起始帧·尾帧字段）② 在 prompt 里以插桩占位符出现 ③ **该节点已生效（有产物）**。**三者缺一即不得点火**（只在 prompt 文字里提到＝无效引用）。**（口径桥接**：源文件 `libtv-official-qa-part6.md` §R23 第 10 条把**本条 + 下一条**合称「插桩完整性 + 声音开关」**双查**；本册把两者拆成两条独立勾选项，故本条按其自身三条子项称"三查"——**两者不是矛盾口径**。）
- [ ] **★「声音开关」逐镜确认（R23）**：**默认是 `on`** —— **不显式关就会生成对白/环境音**，后期返工。逐镜确认 `enableSound` 已按要求写死。
- [ ] **★ 首尾帧镜专查（R23）**：首帧与尾帧两个 image 节点**都已生效**，且**没有互挂成环**。
- [ ] **★ 续写镜专查（R23）**：若某镜以"上一镜落幅"为起点，**必须先把该落幅抽成一张已生效的 image 节点再引用**（**不可只在脑子里认为"就是上一镜最后一帧"** —— 这是代价最大的单点，见 `libtv-official-qa-part6.md` §R23 第 2 条）。

## ★★ 画布提示词体检（点火前必跑 · 2026-09-24 补）

> **立规原因**：2026-09-24 实战画布体检，5 个 `node prompt` **门禁 `rc=1`**——
> **12 块全缺** · 每块 **10–30 处 `**` 装饰符** · 写实下限 **0 处写脏** · 微表情 **0 处「部位+动作」** ·
> 字符量**只有早前交付稿的约 1/4**。根因：**把"拓扑演练画布"当成了可以不按标准写的豁免区。**

### 铁律一条
> **凡写进画布 `node prompt` 的文本，与交付稿同标准——没有"演练画布可以写简版"这回事；若确实只写骨架，必须①在节点名或卡内标明"骨架·非交付稿"②明确约定何时补成标准稿。**

### 四项逐块检查（**rc≠0 不许点火**）
- [ ] **① 块名用库标准块名，不用自造名**：`【本镜目的】【镜头规格】【构图】【人物与环境】【光位与影调】【时间线】【运镜】【声音】【过渡压力】【后期特效】【统一提质层】【风险移除】`。
  **自造名（如【流程留痕】【关键参数】【画面】）会被门禁判 12 块全缺（FAIL）。**
- [ ] **② 正文零装饰符**：**不许有 `**` / `★` / `✅` / 圈号①②③** —— **块内一切都会被当提示词执行**，这些是纯噪声。要强调就写完整句子，要编号就用 `1.`。
- [ ] **③ 不写"流程留痕/工序词"**：阶段名、模型名、"给人看"、"下一步被谁引用"、"对应编排" **＝白写清单项**，且**挤占开头最宝贵的实体确立位**。
- [ ] **④ 静帧类与镜头类分别过门禁**：
  - 镜头类 → `audit_prompt.py blocks`（要 12 块齐 + 声音行 + 结尾留白）
  - 资产/黑白故事板 → `audit_prompt.py blocks --asset` / `--storyboard`（静帧类豁免声音行与留白）
  - 空话词/字符量 → `ai_smell_check.py`（`电影感` 这类空话词换成具体器材/行为/材质）

### 逐层「硬下限」速查（本次全部踩空过）
| 层 | 下限 |
|---|---|
| **场景 / 道具** | **写脏 ≥2 处**（每处：位置＋形态＋尺寸）· **材质受光响应**（哑光/吸光/不反光/接触阴影） |
| **人物** | **三条下限**：生理活性 ≥2 种 · 静息微动 ≥1 · **面部「部位＋动作」微表情**（只写部位会被身份锚点骗过） |
| **皮肤（写实）** | 落在**肤色层次 + 哑光 + 无油光**（平光下毛孔会一起隐形，别靠毛孔） |
| **镜头规格** | **必须声明起始景别**（九级选一）；焦段 **度打头、毫米进括号**（`48°（约 40 毫米）`） |
| **构图** | **主体位置或留白**（二选一必须写） |
| **运镜** | **四要素**：起始观察点 · 主运动 · 锁死项 · 结尾落点 |
| **训练线（时间线）** | **四相齐**（起始/触发/主动作/反应与呼吸）；**5 秒只放 2–3 相位** |
| **过渡压力** | 写成**尾帧具体停在什么状态**，不写"压力/悬念/情绪张力" |
| **长度** | 镜头层 **150–350 字**（上限 500）；**400–500 可接受，600+ 收益递减** |
