## 三、时长限制如何反过来决定叙事

1. **5 秒是"单机位"的原子单位，10 秒是"单机位"的安全上限**；超过 10 秒，**单个机位**的一致性显著下降。
2. **铁律分两种模式**（`segmented-shot.md`）：
   - **单机位镜**：≤10 秒，超过就拆镜。
   - **分段镜**（一条内多景别 / 多机位）：可到平台上限（15 秒；Seedance 2.5 可 30 秒）——
     但内部是**多个硬切**，**不是让单个连续动作变长**。**单个连续动作段仍 ≤3 秒**（`motion-control.md`）。
3. **8 秒是"故事感 × 完播率"的最佳平衡**（短视频爆款多落在 7–9 秒；10–15 秒完播明显下滑）。
   ⚠️ 这是**成片节奏**的结论，与**单条生成上限**是两件事，不要混。
4. **AI 友好的 8 秒结构**：钩子 0–1s + 悬念 1–3s + 转折 3–5s + 高潮 5–7s + 留白 7–8s——信息在第 3–5 秒集中爆发，结尾不交代。
5. 需要 15–30 秒时**有两条路**：① **一条分段镜**（同场景同光、只换机位 / 景别）；
   ② **分镜生成 + 剪辑拼接**（跨地点、跨时间、有对白口型）。判路与试错成本算术见 `segmented-shot.md` 第一节。
6. 情绪越紧镜头越短，越舒缓越长——**镜头长度要随情绪曲线走**。

## 四、成本与抽卡预算

```
单镜预算 = 2–4 次生成（难镜 3–5 次）
全片素材量 = 镜头数 × 3（真实可用率约 30–40%）
```

- **高消耗低产出（排期时要预警）**：打斗 / 法术特效 / 快速移动 / 多人交互 / 手部 / 口型 / 走路 / 液体布料 / 画面文字。
- **低成本镜头**：面对面对话、静止单人、空镜、风景。
- 降本手段：结构化提示词 + 角色锁定参考，可把单镜耗时与可用率明显改善（实测有"单镜 15 分钟 → 5 分钟、可用率 25% → 60%"的记录）。
- **分级跑**：低清 / 短时长试错 → 高清 / 长时长定稿。

### 四·补 把"抽卡预算"折算成钱与时间（2026-09-11 补）

**为什么要折算**：说"按 2–4 次生成预估"用户没有体感；说"这一镜要花多少 credits / 多少分钟"用户才能做**取舍决策**（要不要为这一镜的刁钻构图多花 3 倍钱）。**口径关系**：§四开头「单镜 2–4 次（难镜 3–5 次）」是**常规档**口径；下表各难度行是**含试错与极端难镜的全口径**——**报价与排期以下表为准**。

**折算公式**（交付时按此算给用户）：

```
单镜成本 = 生成次数 × 单次单价（credits 或 ¥）
生成次数 = 基础 2 次 + 失败加权
失败加权 = 难度系数（见下表）

全片成本 = Σ 单镜成本 + 后期工时 + 素材冗余（另加 30–40% 废料）
```

| 镜头难度 | 生成次数（含试错） | 说明 |
|---|---|---|
| 静止单人 / 空镜 / 风景 | **2 次** | 一次过概率高 |
| 面对面对话（两人） | **3 次** | 视线与口型要挑 |
| 手部动作 / 小幅物理 | **4–5 次** | 见 `ai-artifact-control.md` 五·补 |
| 走路 / 多人同框 | **5–8 次** | 见 `feasibility.md` |
| 打斗 / 特效 / 快速运镜 | **9–15 次**（＝每镜 3–5 次 × 3 倍素材量，`feasibility.md` 2.4） | 见该册 §2.4 |

**两条纪律**：

1. **先小成本验证再铺量**：全片开拍前，先用**最低成本档**（低清 / 短时长）把**最难的那一镜**跑一遍。**难镜过不了 → 改结构，不要先拍简单的再发现难镜无解。**
2. **预算要写进交付说明**：给用户"这一镜预估 N 次 / 约 X credits"，让用户能**主动砍镜头**。**不写预算的交付 = 把风险全留给用户。**

## 六、踩坑清单（11 条）

1. **Sora 2 已停用**（app 与 API 均已关停），不要作为长期基座。
2. **即梦禁真人人脸上传**，须走活体校验建"分身"；AI 生成的写实人脸同样可能被拦。
3. **即梦 / 可灵的语义与风格归属词会误伤**（"神似某某""某某画风"）——删 IP 名，改泛化描述。
4. **中文提示里不要混裸英文词**，要写完整短语（如 `dolly tracking shot`）。
5. **负向字段按平台与入口核对**。本册历史记录按 §7.3 分流，使用前复核当前接口的字段与写法要求。提示词落地另见 `quality-layer.md` 第四节。
6. **时长与分辨率互相制约**：4K 与长时长更慢更贵，按"低清短时长试错 → 高清定稿"分级跑。
7. **参考素材多 ≠ 好**：Seedance 单次 ≤12 文件，优先传影响最大的素材，且**最需精准的放最前**。
8. **多镜单条的失败成本更高**（一次失败＝**整条**重抽，不是重抽一段）→ **稳镜可合，难镜必拆**：
   同场景、同光区、主体少、动作简单的镜可合成一条**分段镜**；
   含难点（手部 / 走路 / 液体 / 多人 / 对白口型）的段**单独拆出来**（`segmented-shot.md` 第一节）。
9. **视频内文字渲染都不可靠**，文字一律后期加。
10. **方括号运镜指令是 Hailuo 专有语法，不可跨平台照搬**：Hailuo 2.3 认 15 条方括号指令
   （Truck / Pan / Push / Pedestal / Tilt / Zoom / Shake / Follow / Static，共 9 族）——
   **同一括号内＝同时执行、逗号分隔、最多 3 个**；**写在提示词不同位置＝顺序执行**。
   官方特别强调 `[Zoom in]` 与 `[Push in]` **不是同一个动作**（与我们"视差判据"同源）。
   **即梦 / Seedance 不吃这套**，照搬会被当普通文字稀释。常用组合：`[Pedestal up,Pull out]` 升起变广（**`Pull out` 未在上方 9 族名单内，族归属待核一手源**）·
   `[Push in,Tilt down]` 逼近脸部 · `[Truck right,Pan left]` 揭示房间。→ 族定义见 `camera-movement-library.md`。
11. **画幅＝固定取值 + `adaptive` 自适应，取值集合随平台而变**（见 §7.4）——**引用时必须写明是哪个平台**：**火山方舟是六值**（固定比例六值 + `adaptive` 共七取值：`16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 21:9`）；**image2 是八值**（含 `3:2` / `2:3` / `auto`、缺 `3:4`，见 `storyboard-platforms.md` §5.3）。**图生视频默认就是 `adaptive`**，按首帧比例自动取最接近值；**文生视频必须显式写**该平台取值之一。
    **本库惯用的 `2.39:1` / `1.85:1` 是艺术意图写法**：交付文档里保留，同时给落地值（`2.39:1 → 21:9`、`1.85:1 → 16:9`）。**真会翻车的是另两处**：**首尾帧画幅不一致 → 尾帧被拉伸**；**所写比例与首帧不一致 → 首帧被居中裁剪（切掉边缘构图）**。

## 七、输入组合与写法的硬约束（2026-09-13 补 · 以**平台官方文档**为主）

> **本节的来源等级高于第六节**：第六节含社区实测；本节**除注明外均为官方文档原文提炼**。
> 写法差异见 §7.3，**画幅落地值见 §7.4（本库必须看这一条）**。

### 7.1 ★ 三种输入场景**互斥**（火山方舟官方原文）

> **"图生视频-首帧、图生视频-首尾帧、全模态参考生视频（包括参考图、视频、音频）为 3 种互斥场景，不可混用。"**
> **"全模态参考生视频可通过提示词指定参考图片作为首帧 / 尾帧，间接实现「首尾帧 + 全模态参考」效果。"**

**落地含义**：**不能既指定 `first_frame` 又平铺一堆 `reference_image`。**
若既要首尾帧又要多参考 → 走**全模态参考**路径，在**提示词里**点名某张参考图充当首/尾帧。

### 7.2 role 取值（官方）

| 场景 | role |
|---|---|
| 图生视频-首帧 | 1 个 image_url，`first_frame` **或不填** |
| 图生视频-首尾帧 | 2 个 image_url，**必填**：`first_frame` / `last_frame` |
| 图生视频-参考图 | 每张 = `reference_image`（**必填**） |
| 视频延长 | `reference_image` / `reference_video` / `reference_audio`（提示词触发词：**向前/向后延长 · 延续 · 续写**） |

- **首尾帧画幅不一致**：以**首帧**为准，尾帧**自动裁剪适配**（2.5 指南另称"会被拉伸"）→ **首尾帧必须同画幅**
- 传入的首尾帧**可以相同**（做"几乎不动"的镜可用）
- 图生视频默认 `ratio = adaptive`（跟随首帧）

### 7.3 负向词：**不只"有没有字段"，还有"写成什么形式"**

| 平台 | 字段 | **形式要求** | 审核特征 |
|---|---|---|---|
| **Veo 3 / 3.1** | ✓ 专用字段 | **纯名词**罗列（`extra limbs, glitch morphs`）；**禁用 `no` / `don't` 命令式**——会反效 | 严；**同时扫提示词与画面帧** |
| **可灵 Kling** | ✓ 专用字段 | **只放稳定性瑕疵**（滑脚 / 多指 / 形变），**不放泛泛的 "quality" 词** | **生成前违禁词过滤，一词命中即拒整条**（无害的身体/接触词也可能误封） |
| **Hailuo / MiniMax** | ✓ | **厂商建议少用**，只对特定瑕疵，不作主要手段 | 中 |
| **Wan** | ✓ 稳健 | 默认值可含 `morphing, warping, face deformation, flickering` | 宽松（本地自托管无过滤器） |
| **Runway Gen-4/4.5** | **✗ 不支持** | **`no X` / `avoid X` 会产出相反效果**——"`no distorted hands` 可能召唤出畸形手"。**迁移提示词时的头号错误** | 严 |
| **Pika 2.5** | 部分 | — | 中 |
| **Sora 2** | **✗ 无字段** | 只能**护栏式措辞**（`original characters only, no logos or text`） | **三条**审核；**抓"描述"不只抓名字**（`spiky-haired ninja in an orange jumpsuit` 仍触发匹配） |

> **对本库的意义**：`quality-layer.md` §四的"禁止项三类分诊"是**内容层面**的分诊；
> **这是一层前置**——**先判"这个平台有没有负向字段、字段要什么形式"，再决定分诊怎么落**。
> **无字段的平台（Runway / Seedance / Sora）**：禁止项要么改写进正文的**肯定状态句**，要么用**护栏式措辞**，**绝不写 `no X`**。

### 7.4 ★★ 画幅：**固定六值 + `adaptive` 自适应**（2026-09-13 二次修正）

**火山方舟官方 `ratio` 可选值（仅此七个 = 6 个固定比例 + 1 个 `adaptive`）**：
```
16:9   4:3   1:1   3:4   9:16   21:9   adaptive
```

**★ `adaptive`（自适应）是图生视频 / 首尾帧的默认值**——官方适配规则逐字：
| 任务类型 | `adaptive` 怎么选 |
|---|---|
| **文生视频** | 根据输入的**提示词**，智能选择最合适的宽高比 |
| **首帧 / 首尾帧生视频** | 据**上传的首帧图片比例**，自动选择**最接近的**宽高比 |
| **多模态参考生视频** | 按提示词意图判断；若属首帧 / 编辑 / 延长，则**以该图 / 视频为准**选最接近的 |
| 模型默认值 | Seedance 2.5 / 2.0 系列 / 1.5 pro：**默认 `adaptive`**；1.0 pro：文生视频默认 16:9，图生视频默认 `adaptive` |

> **⚠️ 官方两处表述不一致（如实标出，用前以平台界面为准）**：
> - `docs/6492/2595411`（API 参数说明）：首帧 / 首尾帧 → 自动选**最接近的**宽高比
> - `docs/7048/1520757`（创建任务）：首帧 / 首尾帧 → **自动保持与 first_frame 一致**
> **实务上取两者的公约数**：**把首帧就做成目标比例，两条规则下的结果都一样**（见下方操作建议）。

**因此"本库惯用的 2.39:1 该怎么办"，答案分三条路**：

| 路径 | 该写什么 | 结果 |
|---|---|---|
| **图生视频 / 首尾帧**（本库主流程） | **`adaptive`（默认，通常不用改）** | 按首帧比例自动取最接近值。**首帧做成 2.39:1 → 得到 21:9（≈2.33）** |
| **文生视频**（无首帧） | **必须显式指定六个之一** | 不指定且正文写着 `2.39:1` → 模型按提示词**自己猜**，可能不给宽银幕 |
| **交付文档 / 方案包**（写给人看的） | **保留艺术意图写法，并给出落地值** | `2.39:1（落地 21:9）` · `1.85:1（落地 16:9）` |

**⚠️ 真正的风险不在"取不到值"，在另外两处**：
1. **首尾帧画幅不一致** → 官方明示：**尾帧会被拉伸**（另一处说会**居中裁剪**）→ **首尾帧必须同画幅**
2. **图生视频所选比例与上传图不一致** → 方舟会**对输入图居中裁剪** → 构图边缘会被切掉，**首帧构图要为裁剪切留余量**

> **本库此前的表述错在哪（留痕）**：只写了"固定六值"，**漏掉 `adaptive`**，于是把"图生视频自动适配"说成了"用户必须手改，否则吃默认"。
> **修正后的判据**：**"这一镜有首帧吗？"** 有 → **留 `adaptive`，但首帧要按目标比例做**；没有 → **显式写六个之一，别让模型猜**。


**分辨率与时长取值（Seedance，官方）**
- 输出分辨率：480p / 720p / 1080p / **4K**
- Seedance 2.0 系列时长 **4–15s**；1.5 pro 4–12s；2.5 编辑任务 4–30s
- `duration` 与 `frames` **二选一，frames 优先**；`duration = -1` = **智能选择**
- `duration` 的返回值为**约数**（与计费相关）
- **SeeDream 生图**：**输出图最大数量 = 15 − 输入图数量**（官方公式；常查：输入 0→15 · 1→14 · 6→9 · 9→6 · 10→5）；分辨率 2K / 3K / 4K

### 7.5 入口决定上限（同模型不同前端，上限不同）

**实测口径**：Seedance 2.0 在**豆包 App 被锁在 5s / 10s 预设按钮**；完整 4–15s 只在**即梦 / Dreamina 网页 + 火山引擎控制台**。
→ **承诺时长之前先确认用户用的是哪个入口。**（本库"剧本 → 节拍表秒数"必须与入口上限对齐，否则节奏表从第一步就是废的。）
→ 同类：**Hailuo 分辨率与时长互斥**（1080p ≈ 6s / 768p ≈ 10s），**按镜取舍**；**Veo Extend 每次 +7s，但 4–5 次扩展后画质劣化**。

### 7.6 被误封的**正确**修法

**可灵官方 Skill 口径（`seedance-filter`）**：
> **"Repairs false positives by clarifying legitimate production context, never by hiding intent."**

→ **被误封时，做的是"澄清正当制作语境"，不是"把意图藏起来"。**
→ 具体：补写这是**虚构作品 / 拍摄场景 / 服装道具**语境，而不是删掉关键描述词去绕过。

## 八、平台原生音频与「参考声线」（2026-09 复核 · **含源间矛盾标注**）

> **★ 先记一条方法论**：本轮站外学习时，**同一批参数在不同来源之间互相矛盾**——
> Seedance 2.0 最长 **12s vs 15s** · Sora 2 **12s vs 25s** · Kling **10s vs 15s**。

| 能力 | 谁有 | 对我们的用法 |
|---|---|---|
| **原生音频（同步出）** | **在役平台已普遍支持**：Seedance 2.0 / 2.5 · Kling 3.0 · Veo 3.1 · Hailuo H3 · Wan 3.0（Sora 2 曾支持、**已停用，仅存档**） | 模型路由见 `audio-tools.md` §2 |

3. **凡本册写「截至/快照」处，都是「用前核一遍」的意思，不是「照抄」。**
