# 交接范围判据：**哪些板块能交出去"定稿"**（2026-09-22）

> **为什么单列一册**：用户问「**按照现在这种方式，看工作流程其他板块如资产提示词（所有的不同资产）、分镜提示词是否要更换这种方式**」。
> **一句话答案**：**不一刀切**——**验收靠人眼的板块可以交出去定稿；验收靠脚本机检的板块只交"维度"，不交"定稿权"。**
> **读完回哪**：`script-agent-handoff.md`（剧本那套的完整流程）· `block-spec.md`（12 块思考层）· `libtv-prompt-structure.md`（输出层 5 块主干）· `asset-prompt-spec.md` · `run-sheet-part2.md` 站 4/5/6。

---

## 一、判据（**一句话**）

**看"验收靠什么"：**
- **靠人眼审美 / 是开放文本** → **可以交出去定稿**（它的强项是结构规整、维度齐全）
- **靠脚本机检 / 含库内专有名词** → **不交定稿权**，**只取它的"维度与骨架"**（清单、列、检查项），成品仍由我方写

**★ 为什么这条判据成立**：我方有 **8 个能自动判的门禁**（`audit_prompt.py blocks`〔含 `--asset` / `--storyboard`〕· `storyboard_lint.py` · `script_lint.py` · `sound_lint.py` · `shotlist_lint.py` · `ai_smell_check.py` · `lib_health.py` · `lib_doctor.py`）。**把定稿权交给一个没读过我们库的 Agent，等于把机检标准交给它猜**——它的产物过不了 `blocks`（缺块即 FAIL），门禁就形同虚设。

## 二、逐板块裁决（**2026-09-22**）

| 板块 | 验收靠什么 | 裁决 | 依据 |
|---|---|---|---|
| **剧本**（题材/大纲/初稿） | 人眼审美 + 少量格式检查 | ✅ **已定为「我方起手 → 它定稿」** | 开放文本；实测它的结构/逐镜运镜/伏笔编号更规整（见 `script-agent-handoff.md`） |
| **资产提示词**（场景 / 角色 / 道具 / 光源 / 照片） | **脚本机检**（`blocks --asset`）+ 库内专有名词（三系量级 / **写实缺陷层** / 皮肤规则 / 色板 RGB） | ⚠️ **只交"维度"，不交"定稿权"** | **它在资产上有强模板生态**（实测命中：Cast Builder 三路线定脸 / 角色三视图锁定脸部 / 七视图 / 造型细节卡）→ **可取它的"维度清单"**（定脸路线 / 定妆 / 细节卡 / 三格资产）**补进我方资产册**；**但色彩、光位、材质受光响应、逐处写脏 ≥2 处，一律我方写且不许它改** |
| **分镜提示词**（每镜视频提示词） | **脚本机检**（`blocks` 缺块 FAIL / 缺元素 WARN）+ **用户铁律**（逐块完整 · **按镜序不写秒数** · 生理三下限 · **不写纹名**）+ 逐镜引库内专有名词 | ❌ **不换**。**只吸收它的"运镜与机位"一列** | 它的价值集中在**逐镜运镜与机位**（实测比我们模板规整）→ **取这一列**；全文仍我方写。**R23 已证它会混淆两侧工具面**（把 `create_node`/`read_node`/`left`/`enableSound` 判为"不存在"）→ 交给它改写风险高 |
| **故事板**（黑白单镜图） | **脚本机检** `storyboard_lint.py`（张数 ≤ 平台上限 / 五段骨架 / 纯灰度 / **不拼版**）+ 用户铁律（一镜一张） | ❌ **不换** | 图像产物，且"不拼版 / 纯灰度"是踩过坑才立的规 |
| **声音**（后置独立制作） | `sound_lint.py` | ❌ **不换** | 我方已定"**分镜阶段 No BGM、声音后置**"；而它**恰恰会混入 BGM**（实测："心跳般的低频鼓起"） |
| **镜头表 / 排镜**（时长与节奏数学） | `shotlist_lint.py` | ❌ **不换** | 时长是**可算的**，且它**自述时长与逐镜加总不符**（实测 32s vs 35s） |

## 三、可复用的四条规则

1. **门禁先于交接**：凡有 `*_lint.py` / `blocks` 能判的产物 → **不交定稿权**。
2. **它只做加法，不做改写**：让它**补一列 / 补一张维度清单**，不让它**重写全文**。
3. **专有名词是红线**：库内的器材型号 · 胶片与印片 · 方案包 · 风格编号 · 运镜名 · 磨损项 —— **它不知道**，一改就错。
4. **它的角色降一级**：除剧本外，它从"**定稿者**"降为"**第二双眼睛 / 补列者**"——这正是 R20 / R23 已验证有效的用法（**它挑错、我方决定采不采**）。

## 五、待验（下一轮 · **用数据定，不靠推断**）

1. **★★ 实测"它的提示词产物缺哪些块"**：挑**一镜**让平台 Agent 做"提示词定稿"，拿回来跑 `audit_prompt.py blocks` —— **看缺块率**。若缺块率高 → 上面"❌ 不换"的裁决由**推断**升级为**实测**；若意外全过 → 再议资产与分镜是否可部分交出。
