# 世界状态与变更传播

日期：2026-10-07  
状态：A 路共享契约 v1

## 1. 为什么需要世界状态

提示词正确不等于跨镜一致。镜头之间还需要记录：

- 人物身份、位置、服装、伤势、情绪和视线
- 道具是否存在、损坏、被带走或被使用
- 地图、路线、门、旗帜、设施和资源状态
- 台词锁定、声音启用和字幕状态
- 首帧、尾帧和续写来源

这些信息不能只散落在 prompt 中。

## 2. Production Record 中的状态

`world_state_delta` 记录本镜头结束时相对上一状态的改变：

```json
{
  "door": "closed",
  "marker": "in_Evan_hand",
  "basin_control": "red",
  "casualties": 1,
  "treaty_page": "blank"
}
```

原则：

1. 只记录可观察、可绘制的状态。
2. 开始状态从上一镜头继承，结束状态写入 delta。
3. 心理状态若不能被看见，不直接写进世界状态；转为表演或台词。
4. 未发生的状态变化必须显式写 `unchanged`，不能默认消失。

## 3. 状态类型

| 类型 | 示例 | 谁负责 |
|---|---|---|
| identity | 角色身份、脸、服装基线 | 资产与角色连续性 |
| physical | 位置、接触、伤势、破坏 | 镜头与现实逻辑 |
| prop | 道具存在、状态、位置 | 资产状态版本 |
| world | 地图、门、资源、设施 | 场景与剧情 |
| dialogue | 台词和声音锁定 | 剧本与声音 |
| frame | 首帧、尾帧、续写 | 图计划与平台 |
| approval | 预算、点火、交付批准 | 台账与人 |

## 4. 变更传播矩阵

| 变更 | 直接受影响 | 可保留 | 必须回读 |
|---|---|---|---|
| 剧本文字 | 场景、镜头合同、台词 | 已锁定且未变的资产 | 新旧版本差异 |
| 角色身份资产 | 引用该角色的 storyboard、shot | 不相关场景与道具 | 资产版本、引用边 |
| 场景资产 | 该场景所有镜头与构图 | 不相关角色身份 | 场景版本、空间状态 |
| 道具状态 | 使用该状态版本的镜头 | 其他状态版本 | 状态版本与引用 |
| 镜头合同 | 对应 Prompt Package、Graph Plan | 上游剧本与资产 | shot version |
| Prompt Package | 对应生成计划 | 图结构 | prompt hash |
| 模型/参数 | 新生成任务 | 旧结果，但标为旧参数结果 | taskParams |
| 世界状态 | 后续镜头继承 | 之前镜头历史状态 | delta 与 source revision |
| 分组/布局 | 人审视图 | 节点内容与依赖 | group membership |

## 5. 失效级别

```text
none       = 无需处理
review     = 回读确认
invalidate_plan = 计划失效，但已有媒体不删除
invalidate_output = 输出需重新生成，需批准
archive    = 旧版本归档，不冒充当前版本
```

任何失效都必须有：

```text
source_record_id
affected_record_ids[]
reason
evidence
next_action
```

## 6. 传播算法

1. 找到变更源记录和 source revision。
2. 沿 reference、dependency、assembly、lineage 边向外遍历。
3. 根据变更类型套用传播矩阵。
4. 对每个受影响节点计算失效级别。
5. 更新 Production Record 和 Graph Plan 版本。
6. 生成 gate result，标明哪些是计划失效、哪些需要重新生成。
7. 付费动作等待用户批准。

## 7. 三作校准

- W1：资产与边/参数集合可作为引用回读校准。
- W2：timeline、videoList/order、edges 三层变更必须分别传播。
- W3：text 母本、语义资产、params 顺序和长片状态链提供高密度压力测试。

三作不提供一个统一的“变更后必须重建多少节点”数字。

## 8. 验收问题

- 世界状态是否只写可观察事实？
- 每个变更能否找到直接受影响记录？
- 分组变化是否被错误当成内容失效？
- 计划失效、输出失效和归档是否分开？
- 付费重生成是否仍需显式批准？
