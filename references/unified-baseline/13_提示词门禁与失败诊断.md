## 0. 读退出码是第一步

**两个体系，别混。** 本库所有门禁都遵循「**没扫到 ≠ 通过**」。

| 脚本 | 退出码 |
|---|---|
| `audit_prompt.py` | 0 全过（且扫到了东西）｜1 有 FAIL｜2 用法错误｜**3 没扫到东西（≠通过）**｜4 只有 WARN |
| `ai_smell_check.py` | 0 未检出｜1 检出错（含 FAIL 级）｜2 用法错误｜**3 未找到任何提示词块** |
| `lib_doctor.py` | 0 全过｜1 有问题｜2 用法错｜**3 没扫到（≠通过）** |
| `lib_health.py` | 0 全过｜1 有问题（悬空指针 / 孤立 / 越界）｜2 用法错｜3 没扫到 |

**门禁纪律（`thinking-pipeline.md` §13 SOP-A）**：rc=0 才算完；**rc=3 必须显式说明「没验到」**，不许写成「通过」。

**这一条是本册最重要的防伪**：`audit_prompt.py blocks` 对空文件 / 没围栏 / 贴错文件一律返回 3 ——早先版本会把「文件写错了/没贴内容」误判为「结构合格」。

### 0.1 与 A 路 `gate_result.schema.json` 对齐

门禁结果落盘时按 A 路冻结的 schema 填，**六种退出码都在枚举里**：

~~~text
exit_code     0 通过 | 1 检出问题 | 2 用法错误 | 3 没验到 | 4 只有 WARN | 5 不适用
debt_class    none | existing | new_regression | not_verified | not_applicable | unknown
new_regression 布尔
interpretation pass | fail | not_verified | not_applicable | warn
~~~

**两点必须写清**：

1. 任务单 §3.5 只列了 `0 / 1 / 3 / 5`，而**实际脚本会吐 2 与 4**（`audit_prompt.py` 的 4 = 只有 WARN，`ai_smell_check.py` 的 2 = 用法错误）。A 路 schema 已把 2 与 4 纳入枚举 —— **以 schema 为准**；
2. `exit_code=4` 不等于通过。**分账纪律**：既有债务标 `debt_class: existing` 且 `new_regression: false`，**不写成本批回归**（任务单 §8.3）。

## 1. 门禁清单（提示词侧）

| 门禁 | 命令 | 查什么 | 用在 |
|---|---|---|---|
| 结构门禁（镜头） | `audit_prompt.py blocks <file>` | 12 块齐 + 各块必需元素 + 声音行 + 结尾留白 + 归属去重 + 真实感下限 + 景别 + 运镜四要素 + 人物三条下限 | 视频包 |
| 结构门禁（资产） | `audit_prompt.py blocks --asset <file>` | 静帧类：跳过声音行与结尾留白；仍查真实感下限与材质受光 | 资产包 |
| 结构门禁（故事板） | `audit_prompt.py blocks --storyboard <file>` | 静帧类：跳过声音行与结尾留白 | 故事板包 |
| 时间轴门禁 | `audit_prompt.py timeline <排镜表>` | 无空档 / 无重叠 / 首镜从 0 起 | 排镜表 |
| 观测门禁（AI 味） | `ai_smell_check.py <file\|dir>` | 空话词 / 文件腔 / 块内元说明 / 双语并列 / 口水副词 | 所有提示词包 |
| 及格线 | `lib_doctor.py --grade <file…>` | 按 `acceptance-check.md` §五·补四项直接判及格 / 不及格 | 交付前 |
| 交付件全门禁 | `lib_doctor.py --deliver <file…>` | 全部门禁 + 跨块矛盾核 | 交付前 |
| 节奏 | `lib_doctor.py --rhythm <排镜表>` | ASL 与节奏密度：平 / 机械 / 过短 / 过长 | 排镜表 |
| 衔接 | `lib_doctor.py --linkage <分镜表>` | 景别序列 / 切点是否写全 / 情绪曲线 | 分镜表 |
| 设计感 | `lib_doctor.py --design <分镜表>` | 直白：装置有无与种类 / 连续默认款 / 母题复现 | 分镜表 |
| 剧本 | `script_lint.py` | 剧本模块契约 | 剧本 |
| 分镜 | `storyboard_lint.py` · `shotlist_lint.py` | 故事板与排镜表 | 分镜 |
| 声音 | `sound_lint.py` | 声音表 | 声音包 |
| 库体检 | `lib_doctor.py` · `lib_health.py` | 索引 / 悬空指针 / 孤立文件 / 行号越界 / 台账撞号 | 改库后 |

**规格文档守卫**：`audit_prompt.py blocks` 对 `references/` 与 `evals/` 下的 `.md` 会**主动 SKIP**（那里装的是模板与示例，套提示词规则会稳定产出假 WARN）。

> **推论（写本文档时踩到的真坑）**：**非提示词的代码片段不要用 ``` 围栏** —— 脚本只把 ``` 当提示词块。用 ``` 装公式 / 清单，会被当成一个提示词块扫。**用 `~~~` 装非提示词内容。**

## 2. 结构门禁：12 块的契约

**块齐备**（缺哪个点哪个名，FAIL）：全片通用 3 块（后期特效 / 统一提质层 / 风险移除）+ 单镜版 9 块（本镜目的 / 镜头规格 / 构图 / 人物与环境 / 光位与影调 / 时间线 / 运镜 / 声音 / 过渡压力）；段落版对应 `本段 X` 与 `全局约束`。

**每块必需元素**（缺什么点什么，WARN）：

| 块 | 必需元素 |
|---|---|
| 本镜目的 / 本段目的 | 三选一（改变情绪 / 推进动作 / 施加压力）+ **必须有变化**（从什么变成什么 / 代价是什么） |
| 镜头规格 | 焦段；**必须声明起始景别**；异味对照：度在前、毫米在括号里 |
| 构图 | 主体位置或留白；方向必须标参照系（「画面左侧」不是「左侧」） |
| 人物与环境 | 身份锚点句（含年龄或性别，**不许写气质词**） |
| 光位与影调 | 光源出处；动机光源一到两个 |
| 时间线 | 单镜：起始 / 主动作 / 反应与呼吸 / 定格；段落版：先 / 随后 / 最后 |
| 运镜 | 起始观察点 + 主运动 + 锁死项 + 结尾落点 |
| 声音 | 音乐立场（无配乐 / NO BGM，或明写有配乐并交代它与对白的关系） |
| 过渡压力 | 接法（切 / 匹配 / 声音桥 / 景别落差） |
| 统一提质层 | 器材行或痕迹行；型号必须译成效果 |
| 风险移除 | 禁止出现清单 |

**人物三条下限**（`shot-craft.md` 第 7、9 块明写「不许省」）：

1. 生理活性 ≥2 种（瞳孔 / 眨眼 / 呼吸 / 泪膜 / 喉结），**且不是恒定节律**；
2. 静息微动的体态句（重心 / 起伏 / 手指 / 肩 至少一处）；
3. 面部「部位 + 动作」**≥2 处** —— 只出现一次＝**静态表情，没有变化**。

## 3. AI 味门禁：查什么、不查什么

**查五类**（`ai_smell_check.py`，只扫 ``` 围栏内的提示词正文）：

1. **空话形容词**——电影感 / 电影质感 / 大片感 / 高级感 / 唯美 / 氛围感 / 细腻 / 完美 / 震撼 / 超高清 / 4K / 8K / HDR…
2. **文件腔连接词**——综上所述 / 值得注意的是 / 旨在 / 呈现出 / 使得 / 从而 / 进而…
3. **块内元说明**（FAIL 级）——`另注：` / `注：` / `（改成你的…）` / `*可选*` / `示例：`…
4. **双语并列**——中文短语后面硬跟一个英文括注；
5. **口水副词**——非常 / 极其 / 渐渐地 / 缓缓地 / 静静地…

**不查什么**：不判提案质量、不判结构完整（那是 `audit_prompt.py` 的活）、不预测生成效果。

**零命中 ≠ 提示词好**，只是「没踩这几个已知的坑」。

**两条豁免机制**（写稿时要知道，否则会写出假阳性）：

- **否定语境豁免**：出现在「禁止 / 不要…」清单里的词，是「要避免的东西」，不算正面使用；
- **程度副词 + 可测结果 = 正当**：「被低角度光照得格外明显」放行；裸的「非常」照报。

## 4. 及格线（量化阈值）

> 来源：`acceptance-check.md` §五·补（2026-09-19 补）。**这是一条库规，不是平台规则。**

### 4.1 单镜提示词（四项全机检）

1. 结构门禁 `FAIL=0`；
2. 观感 / AI 味 `FAIL=0`；
3. **跨块矛盾 0 处**；
4. 声音表 `FAIL=0`。

一条命令：`lib_doctor.py --grade <文件…>` → 直接给及格 / 不及格。

### 4.2 一条片

拼接点四查 4/4 · 全片响度按渠道达标 · 交付包六件齐 · **「表演可信 / 道具可达 / 画面好看」机器判不了，只能看片 —— 不许声称已验**。

### 4.3 抽卡与效率（人工台账，阈值写死）

单镜生成次数 ≤6 次（超了就改结构，不加次数）· 一次通过率 ≥70% · **返工责任层里「提示词层」问题 ≤30%**。

### 4.4 三条纪律

1. **及格 ≠ 好** —— 及格线是「不许交出去的底线」，不是目标；
2. **机检过 ≠ 能交付**；
3. **阈值不许悄悄放宽**，要改必须写进记账并说明。

## 5. 失败诊断：先判责任层，再决定改什么

> 来源：`qa-failure-codes.md` §一 + §二·补。**答非所写 ≠ 随机质量差。**

| 责任层 | 典型症状 | 回哪修 |
|---|---|---|
| **资产层** | 人物长得不像、道具形态错、场景结构错 | 重出资产 |
| **镜头契约层** | 主体位置错、多出人、该近景给了远景、越界 | 改分镜 |
| **提示词层** | 光影不对、质感不对、缺声音行、量级不统一 | 改提示词 |
| **动作层** | 步态不对、周期动作崩、僵硬脸、拖物无反馈 | `motion-control.md` |
| **平台适配层** | 时长被截、被 IP 过滤拒稿、负向字段用法错 | 平台册 |
| **安全降级** | 有产物但内容与 prompt 不一致（局部模糊 / 重绘 / 回避 / 偏移） | **先查回执 safety 类提示，勿当随机质量问题重抽** |
| **随机性** | 前六层都没问题，只是这一条不好 | 改 seed 重抽 |
| **后期** | 细节软、闪烁、色偏、颗粒不统一 | 后期解决，不要重生成 |

## 6. 五类问题的定位判据

用户问的「怎么判断是结构、表演、物理、风格还是模型问题」，对应下图。

| 类 | 症状 | 判据（看什么） | 处方 |
|---|---|---|---|
| **结构** | 该切没切 / 镜内景别自己变 / 多出人 | 单镜镜内是否写死「景别与焦距完全不变」；分段镜是否写死「恰好 N 个镜头 N-1 个切点」 | 改结构，不要换词。**「只会缓推」＝拿单机位模板去写多景别**（模板的【运镜】显式排除了同族运镜） |
| **表演** | 塑料脸 / 匀速机械 / 演员痒 / 凝视陷阱 / 反应迟到 | 是否有面部「部位 + 动作」≥2 处；是否有眼落点；动作是否写「节奏不均匀 + 呼吸有深浅」 | 回【人物与环境】表情句与【时间线】反应行；**眼睛要有变化**（不是静止注视） |
| **物理** | 动作无重量 / 拖拽物像贴图 / 二级动作凭空发生 | 二级动作有没有「因」（被谁带翻）；影子方向是否随光源 | 补动作链（准备→发力→接触→反作用→落定）；补因果 |
| **风格** | 质感像概念图 / 漫剧感 / 调色跑偏 | 【统一提质层】型号有没有译成效果；风格编号是否库内真实存在；量级系是否声明 | 换方案包 / 补风格声明；**同一部片只用一个调色族** |
| **模型（能力）** | 周期动作崩 / 手部细节崩 / 画面内文字崩 | 前四类都无问题，且失败集中在**已知能力边界**上 | **模型做不到的不要写进提示词**；换路径（参考视频驱动 / 后期贴字 / 拆镜） |

**归因纪律（跨作品裁决 §1.4 R-AI-4）**：**归因在提示词层，不在模型层**。模型按几何正确翻转了左右，那是它唯一可能的选择 —— 先回读自己写了什么。

## 7. 提示词正文 vs 内部 QA 的分工

**唯一判据**：**这条内容模型需要知道吗？**

| 内容 | 归属 |
|---|---|
| 身份锚点句 / 禁止项清单 / 时间线相位 / 声音层 | **正文** |
| 12 块块名本身 | **QA 规范**（平台不认块名，整串交给模型） |
| 「（改成你的…）」/「另注：」/ `*可选*` | **都不属于正文**，属内部备注（进正文＝FAIL） |
| 排镜表秒数 | **QA / 规划**（唯一进正文的秒数是首行总时长） |
| 器材型号 | 正文，但**必须紧跟一句「它拍出来什么样」** |
| 参考图角色分工 | 正文（图 N 供什么 + **明文不许它供什么**） |

**两个高频越界**：

1. **把 agent 的客套话烧进提示词**（「收到！」「终极完整版」「定稿」）—— 对生成零帮助，还可能污染语义；
2. **把秒数写进段落版块内** —— 段落用相位组织，写秒数会把模型的节奏钉死。
