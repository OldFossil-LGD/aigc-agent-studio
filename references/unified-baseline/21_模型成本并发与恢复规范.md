## 1 · 模型路由

### 1.1 `modeType` 语义表（【已验证】——**选型依据是语义，不是输入数量**）

| `modeType` | 语义 | 输入区间 | 典型用途 |
|---|---|---|---|
| `text2video` | 只吃文字 | 0 | 无参考的纯文字镜头 |
| `singleImage2video` / `image2video` | 一张图当起点 | 1 | 图生视频 |
| **`frames2video`** | **"这张图就是起始帧"**（首帧驱动） | 1–2（第 0＝首帧、第 1＝尾帧） | 精确起止画面、转场桥接 |
| **`mixed2video`** | **"这些图是混合参考"** | 1–15（图 ≤10 · 视频 ≤5 · 音频 ≤5） | 角色＋场景＋道具多参考 |
| `videoExtend2video` | 视频续写 | 1–15 | 单镜延长 / 接上一段 |
| `image2image` | 图生图（资产派生） | 0–14（**逐模型核**） | 关键帧、去脸、改光 |

⭐⭐ **最容易赔钱的一条（2026-10-03 平台实测）**：把首帧图喂给 `mixed2video`，
产物第一帧里主体会跑到画面另一侧 —— **模型压根没把它当首帧**。
**判据**：语义是"从这帧开始"就用 `frames2video`；语义是"多张图一起参考"才用 `mixed2video`。
**选错必拍错，且换词修不好。**

⚠ 输入区间**不是跨型号通用承诺**：`image2image` 的 0–14 来自特定模型 schema，
`frames2video` 只连 1 图时**没有 `left` 边可挂**（插桩无源 → 只能写纯文字）。
**用前按 §2 现场复核。**

### 1.2 各模型会变的字段（每一条都必须逐模型核）

| 字段 | 已知取值范围差异 |
|---|---|
| `prompt.maxLength` | 有的 **3000**，有的 **1500** → 同一段提示词长度结论不同 |
| `duration` | 有的 **2–30 整数步进**（4.5 秒填不了），有的是**枚举 `[5, 10]`**（3／12 秒提交不了） |
| `resolution` | 有的 **480P/720P/1080P**（**没有 4K**），有的只 **720P/1080P** |
| `ratio` | 与资产图必须**统一**，别混用 |
| `enableSound` | **默认 `on`** —— 不显式关就会生成对白/环境音，后期返工 |
| `extendPrompt` | 默认 1（开）＝平台会**扩写**提示词；关掉官方注明"效果大概率下降" |
| `multiClip`（多镜头） | 只出现在部分模型的 `advancedSettings`；**有就显式写死开/关**，别指望提示词里的"镜1／镜2"驱动切换 |

**平台层 vs 画布层是两套参数名**：`settings.quality` 只收 `low/medium/high/xhigh/max`；
`1K/2K/4K` 属 `resolution`。混用报 `NODE_VALIDATION_FAILED`。

### 1.3 ⭐ 探测字段真相的三步法（**不依赖任何人**）

```text
① search_models(action="search", nodeType="video"|"image"|"audio")  → 真实模型清单
② get_model(model="完整展示名 或 modelKey")                          → 该模型完整参数 schema
③ validate_generation_plan(...)                                      → 把计划丢进去校验，报错直接指出字段名与取值
```

**→ 以后凡"字段叫什么、能填什么"，一律走这三步；不要问、不要猜。**

⚠ 两条使用纪律：

- **空 `query` 不是全量目录**：实测空 query 返回 29 个，而按族定向查能查出它漏掉的
  （中英文命名混存，两边都会漏）→ **要"目录有多大"别用模型计数回答**；
- **要"某模型在不在池子里"必须定向 `query` 核**。

**目录会过期，字段契约不会** —— 引用清单必须带月份，并注明"非全量"。

### 1.4 路由默认值（【库规】，可覆盖；VIP/白名单状态以现场为准）

| 环节 | 首选 | 备选 | 判据 |
|---|---|---|---|
| 资产图 / 关键帧 | `lib-image-2.5-s`（参考图上限高） | `mj-v8.2`（需白名单） | **"上新"≠"更强"**：新模型参考图上限可能只有 3 |
| 故事板 | 图像模型 + `prompt_template` 枚举 | 导演台 `capture`（几何精确） | 要"调度几何"用 capture；要"情绪美术"用图像模型 |
| 镜头（多参考） | `mixed2video` 家族 | `frames2video`（首尾帧锁死时） | 见 §1.1 语义判据 |
| 声音 | 走**后置独立音频节点** | 视频 `enableSound` | 见"声音解耦" |
| 合成 | `video-clip` + 导出 `clips` | `edit_video_v4`（要转场/字幕/调色时） | 字幕与转场导出层不支持，别在平台内加 |

**声音解耦（【库规】）**：分镜阶段统一 `enableSound = off` → 声音后置独立制作 →
合成时 `video_volume = 0` 叠三轨（人声最高 · 环境垫底 · BGM 最低）。
**收益：改台词只重音频、不重视频。**

## 2 · 成本边界

### 2.1 按动作分列（【已验证】）

| 免费（0 成本） | 计费 |
|---|---|
| `read_project` / `read_node` / `get_project_snapshot` / `browse_project_media` / `inspect_media` | **`create_node(run=true)` / `update_node(run=true)` / `generate_video(run:true)` / 生成提交** |
| `create_script_v2` / `read_script_v2` / `edit_script_v2` / `check_continuity`（明写"不生成内容或媒体"） | **合成 / 剪辑 / 音频编辑**（平台 Agent 明确：合成/剪辑消耗积分） |
| `read_timeline` / `apply_timeline_edit`（含 apply —— "editing never starts a render"） | **导出**（走 `media-platform` 合成器，属"合成"） |
| `export_readiness`（只校验素材可读） | |
| `validate_generation_plan` / `generate_video(run:false)` | |
| `search_models` / `get_model` / `recommend_video_models` | |
| `create_node(run=false)`（只写参数、不运行） | |

**一句话：结构、读取与预检免费；媒体生成、合成、剪辑、音频编辑和导出计费。**
→ **抽卡克制，剪辑大胆**（但剪辑/导出仍需按 §2.2 报数）。

### 2.2 报数与止损（【库规】）

1. **每一笔付费调用之前先报数**：说清"这一步要花什么（模型 / 时长 / 清晰度 / 条数）· 为什么值"；
2. **能免费的一律先免费**（上表左列）；
3. **压缩到平台硬上限内再投**：先数 `prompt.maxLength`；压缩顺序是**先删形容词与重复复述，
   绝不删计数约束与不变项**。

**止损线（写死，不许现场松）**：

| 累计 | 动作 |
|---|---|
| 1–3 次 | 正常试错；每次**只改一个变量** |
| 4–5 次 | **判责任层**（提示词问题 vs 素材问题） |
| 6–8 次 | **换实现路径，不换词**（单机位→分段镜；纯文字→参考视频/首尾帧） |
| **> 8 次** | **改结构**：拆镜 / 换机位 / 换景别 / 把功能转移到相邻镜。**不许"再抽最后一次"** |
| **同一产物 3 次**（平台硬止损） | **平台更严**：同一产物最多重建 3 次（v1→v2→v3）→ **3 次不过就改结构/改锚点** |

### 2.3 余额与退分

- **平台没有余额/流水接口**（`account_user` 不暴露余额）→ **成本不可自证**；
  实际消耗读不到时**按任务号请用户回查**，**回查前不再增加付费调用**；
- **退分口径（R24，较晚较细，以它为准）**：**生成失败 / 审核拒绝 / 超时全额原路退；
  手动取消看阶段**。20-09-20 版"只有生成失败才退"的旧口径作废；
- **量级（平台侧口径，非报价）**：8 秒 480P ≈ 几十积分 · 1K 图 ≈ 个位数到十几积分。
  **要算钱必须由外部把单价带进来**（`--prices` / overlay 的 `price_per_second`）。

## 3 · 并发与锁

### 3.1 三层颗粒度（不要混）

| 层 | 规则 | 依据 |
|---|---|---|
| **节点级互斥** | 同一节点同一时刻只允许一个写/生成；`generating` 期间重复点火直接失败 | 契约明文 |
| **画布级写串行** | **同画布任何写操作都要排队**，并发发多个 `create_node` 只有一个成功（`PROJECT_WRITE_BUSY`） | 实测 |
| **Agent run 占位** | 平台 Agent 有活跃 run 时，画布写入被拒（`AGENT_RUN_ACTIVE`）；**stop 后不立即释放** | 实测 |

**读操作不持写权**，可与写并发、可在活跃 run 期间照做。

### 3.2 批量与批的边界

- **无依赖调用可并行，一次最多 5 个**；**有依赖必须串行**；
- **"批" ＝ 同一轮里的一个并行调用块**，不是"外层 for 循环跑一次"；
- **`ask_human` 必须单独调用**（不能与其他工具同批并行），且会暂停等待；
- **强制单独调用的还有**：`Skill` · `skill_assistant` · `composite_video`（平台侧）。

### 3.3 多画布

账号级"同时打开画布数"**契约未规定**。**工程建议（经验，非平台承诺）**：
**2–3 个活跃画布并行**，每画布每轮 ≤5 个无依赖调用；把后端限流当未知、用保守值规避。

## 4 · 幂等与 revision（中断恢复的地基）

| 项 | 纪律 |
|---|---|
| 幂等键格式 | `^[A-Za-z0-9._:-]{8,255}$`；**同键同文**，换内容必须换新键 |
| 幂等重放 | 同 `idempotencyKey` 重发 → `replayed: true` + 同一个 `task_id` + **revision 不推进** |
| `update_project` 乐观锁 | 取**上一次 `update_project` 返回的 `projectRevision`**；`expectedRevision` 格式 `^sha256-[a-f0-9]{64}$`，**可不传**（不传＝不加锁） |
| 冲突 | `REVISION_CONFLICT`（文案："Project changed; read the current state before updating"）→ **重读 + 字段级合并 + 新 revision 重提**；**禁止同 payload 盲重试** |
| 其他写接口 | 按各自 schema 是否必填处理；**冲突时拒绝盲重试** |

## 5 · 失败分类与恢复

### 5.1 ⭐ 三阶段审核（拦截点不同，处置相反）

| 阶段 | 典型码 | 拦截点 | 扣费 |
|---|---|---|---|
| **① 提交前**（参数/计划校验） | `INVALID_ARGUMENT` / `PARAM_OUT_OF_RANGE` | **入队之前，任务根本没创建** | 不扣或计费前拒绝 |
| **② 生成中**（安全策略命中） | `CONTENT_POLICY_VIOLATION` / `MODERATION_BLOCKED` | 已提交、在流水线中被拦，任务终止 | 按 R24 口径退 |
| **③ 产物审核**（生成后复检） | `OUTPUT_REJECTED` | 已产出但成品未过审 | 按 R24 口径退 |

**判"审核拒绝 vs 生成失败"三判据**：看 `error_code` 所属域（`MODERATION`/`CONTENT_POLICY`＝审核域；
`INFRA`/`TIMEOUT`/`RESOURCE`＝技术域）· 看 `review_stage`（技术失败一般没有）· 看可重试性
（技术失败常 `retryable=true`；**审核拒绝 `retryable=false`，必须改 prompt**）。
→ **审核拒绝的节点标"已废弃"，改内容后新建 v2，不在原节点反复撞审核。**

### 5.2 ⭐ "答非所写"是**安全降级**，不是随机质量差

**请求没被拒、有产物，但画面与 prompt 对不上** → 先怀疑安全降级，**而不是无脑加重抽次数**。

| | 硬拒绝 | 安全降级 |
|---|---|---|
| 产物 | **无** | **有**（可播放/可查看） |
| 报错 | 政策/安全类硬错误 | 可能带非致命 safety 提示（或什么都没有） |
| 节点状态 | 未生效/失败 | **成功**，只是局部被处理 |
| 正确动作 | **改内容 → 新建节点重提** | 若不可接受 → 调整措辞后重新生成 |

**不要试图绕过**（改拼写变体/谐音通常仍被拦）——**要"改成本就合规的表达"**。

### 5.3 断线接续：四步姿势

```text
1. 重连后先只读：读各节点是否已有产物（已生效）/ 无产物（未完成或失败）
2. 已有产物 → 直接复用 node_key，不重跑
3. 无产物且确认失败 → 新建节点（v2/v3）再点火，不在原节点反复硬撞
4. 状态不明 → 先轮询只读，等它落到确定态，再动作
```

**`submitted_task_lost_on_disconnect = false`**（已被接受的任务绑在持久节点上），
但**契约未明文承诺送达/不重复** → **以重连后读回的实际产物为准**。

### 5.4 ⚠ 超时 ≠ 失败

实测**至少 7 例 `timeoutReported:true` 与 `status:2`（成功）并存**。
**遇"失联"必须多轮 `task_status` / `read_node` 确认，不可据超时直接重跑**（重跑＝又一笔积分）。

### 5.5 死锁 run 的解绑出口（按优先级）

```text
① 只读核实状态（很多"卡死"是状态未知而非真死锁）
② 等待自然超时/回收（不重复点火，只读轮询）
③ 换节点续作（最稳的主动出口）：新建节点跑，旧节点标废弃
④ 换画布隔离（把后续工作放到新画布推进，不销毁旧画布）
⑤ "新建 run 顶掉旧 run"：契约未暴露，不要依赖
```

**已知死锁形态**：一个"未真正启动"的 run 会同时①占画布锁 ②不能 steer ③不能 stop
（`AGENT_ACCEPTANCE_UNKNOWN`）→ **发现在同一画布起不来时，直接换画布**。

## 6 · 审批闸：**点火这一步必须有人在场**（【已验证】）

> 平台原文：**"The runtime holds `run_node` back until the user approves on such a card;
> each approval covers one run of each listed node."**

| 事实 | 内容 |
|---|---|
| 授权边界 | **按"节点 × 次数"核销**，不是按请求 ID、也不是按时间段 |
| 预授权 | **不存在** —— `ask_human` 入参里没有任何 TTL / 时间窗 / scope / pre-authorize 字段 |
| 批量 | 只是"一张卡列多个节点、每个各一次"，**不是"按总量自动免审"** |
| 外部触发 | 契约**没有暴露任何外部 HTTP 入口 / webhook / 宿主 SDK** → **外部编排者无法触发审批，也拿不到预授权** |

**→ 我方自动化的"点火"只有两条路**：

1. **由人在客户端审批卡上点一次批准**；
2. 依赖平台另行开放外部 API（**当前未映射**）。

**这与本库 L7"批准必须显式"完全一致**：`创建 / 读回 / 校验` 可全自动；**`点火` 必须有人在场**。
门禁全绿 / 生成成功 / agent 自己的判断 **都不算批准**。

> ⚠ 附带纪律：**导演台 `capture` / `record` 的计费规则与是否走同一审批：未映射** →
> **不要凭推测放开用**（建议先小范围试并核对实际扣费）。

## 7 · 恢复路径速查表

| 症状 | 责任层 | 处置 |
|---|---|---|
| 下游生成时参考为空 | 引用未就绪 | 回 §20 §2.3：查上游是否已生效（`url` 非空） |
| 参考顺序错（主形象被次要参考覆盖） | 边/位次 | 回读 `imageListOrder` 逐位核；**位次事后不可改 → 只能重建节点** |
| 改了参数但生成用旧值 | params 语义 | 回读 `taskParams`（不是 `params`）；检查是否把字段包进 `settings` |
| 提交返回限流/并发上限 | 并发 | 降到 ≤5/轮；有依赖严格串行；退避重试不堆提交 |
| 超时/失联 | 观测 | **先只读确认**，不重复点火 |
| 审核拒绝 | 内容 | 标废弃、改内容、新建 v2 |
| 有产物但画面与 prompt 不符 | 安全降级 | 按 §5.2 改措辞，不加重抽次数 |
| 画布写被拒 | 锁 | 先 `get_agent_status` 确认无活跃 run；同画布写串行发 |
| run 起不来又 stop 不掉 | 死锁 | 直接**换画布**继续 |
| 改锚点后画面仍旧 | 变更传播 | 沿 `left` 链作废重做；合成最后重合成 |

## 8 · 校验入口与清单

```powershell
# 成本门禁（单价必须外部带入；不带则记"不适用"，脚本不编单价）
python3 scripts/graph_plan_lint.py gate --plan <plan.json> --overlay <overlay.json> --out gate_results.json
```

```text
点火前
☐ 每一笔付费调用已报数（模型/时长/清晰度/条数 + 为什么值）
☐ 已跑 validate_generation_plan 且无引用未就绪类错误
☐ 幂等键已就位（同键同文）
☐ 在途并发 ≤5，有依赖已串行
☐ enableSound 逐镜显式写死（默认是 on）
☐ duration / resolution / ratio 已用 get_model 现场核过
☐ 目标节点不在 generating，本次尚无产物

点火中/后
☐ 超时不等于失败：先只读确认，再决定是否重试
☐ 回读 taskParams（不是 params）确认"这次到底吃了什么"
☐ 失败/拒绝节点标废弃、新建 v2/v3（同一产物最多 3 次）
☐ 台账回填（任务号 · 参数快照 · 结果路径 · 判据结果）
```
