# 图语法：节点、边、分组与参数

日期：2026-10-07  
状态：A 路共享契约 v1  
边界：本文定义统一图语义；具体平台字段和合法边由 C 路编译与校验。

## 1. 节点角色

| role | 作用 | 典型 node_type |
|---|---|---|
| `source` | 剧本、规则、母本、台账 | text/script |
| `asset` | 角色、场景、道具、风格、帧 | image |
| `storyboard` | 结构和构图 | image/storyboard |
| `shot` | 单镜或分段镜生成 | video |
| `audio` | 人声、环境、点状事件 | audio |
| `composite` | 时间线、拼接、合成 | video-clip |
| `qa` | 验收、回读、技术证据 | text |
| `archive` | 交付与历史版本 | text/video-clip |
| `group` | 组织与可视分区 | group |

节点身份使用稳定 ID；展示名只供人类阅读。名称不能推导运行状态、身份或版本。

## 2. 四类边

| kind | 含义 | 典型方向 | 是否携带顺序 |
|---|---|---|---|
| `reference` | 身份、场景、道具、风格、首尾帧进入生成 | asset/storyboard → shot | 可能，取决于 authority layer |
| `dependency` | 上游必须先有效，下游才可计划 | source/asset → downstream | 否 |
| `assembly` | 片段或音频进入合成 | shot/audio → composite | 是 |
| `lineage` | 版本、派生、重做和血缘 | old → new 或 source → derived | 否 |

边不是万能语义。禁止：

```text
用边表达 group 归属
用边代替 timeline
用边代替 prompt 中的引用插桩
用展示名推导节点身份
把派生字段当人工输入
```

## 3. 分组

group 是组织和可视分区，不是运行语义：

```text
source / assets / storyboard / shots / audio / composite / qa / archive
```

规则：

- 一个节点可有明确 `group_role`。
- group 不替代父依赖或引用边。
- 组内坐标、组框和阅读顺序要服务人审，不承担生成逻辑。
- 组变更不自动改变节点版本；节点内容变更才传播失效。

## 4. 权威层

Graph Plan 必须声明每类顺序或状态的权威层：

| 内容 | 可选权威层 | 说明 |
|---|---|---|
| 参考身份 | `edge` 或 `params` | 平台和 profile 决定 |
| 参考顺序 | `edge` / `params` / `prompt` | 必须显式声明，不能猜 |
| 装配顺序 | `timeline` 或 `assembly edge` | 只在有装配层时存在 |
| 台词和锁定文本 | `prompt` 或 `source record` | 以结构化源为准 |
| 身份、版本、审批 | `ledger` | 画布是镜像，台账是正本 |

统一规则只说“先声明权威层，再校验”；不能写死“只看边”或“只看 params”。

## 5. 派生字段

以下字段由平台或执行层派生，计划中只登记、不手填：

```text
imageList
videoList
audioList
mixedList
*ListOrder
status
taskInfo
resourceMeta
derived urls
group child bounds
```

若平台要求通过边重算，C 路负责给出具体接口；A 路只保证 Graph Plan 不把派生字段伪装成可写输入。

## 6. 版本与失效

每个节点至少有：

```text
node_id
role
version
source_record_id
source_revision
derived_fields
```

变更传播：

- `script` 变化 → 场景、资产清单、镜头合同、故事板、提示词、图计划重新对表。
- `asset` 身份或状态变化 → 使用该资产的 storyboard、shot、composite 标记受影响。
- `shot` 合同变化 → 对应 Prompt Package、Graph Plan、生成任务计划失效。
- `model/settings` 变化 → 旧生成结果保留，但不能当作新参数结果。
- `world_state` 变化 → 后续镜头继承新状态，不回写旧镜头。

## 7. 图计划不变量

编译前必须通过：

```text
1. node_id 唯一。
2. edge 两端存在且类型组合合法。
3. group 成员存在且 role 明确。
4. reference_order 与权威层一致。
5. 派生字段没有被当成人工输入。
6. 每个 shot 至少能追溯到 production_record_id。
7. 每个 composite 的输入顺序可解释。
8. 图中没有未标记的循环依赖。
9. 每条强制边都有用途，不以“连得多”为正确。
10. profile 例外显式标注，不伪装成统一规则。
```

## 8. 三作只提供 profile

- W1：边和 params 引用集合一致，结构简洁。
- W2：timeline、videoList/order、edges 多层并存。
- W3：params 顺序与正文引用重要，边不能独立推导全部顺序。

三者共同支持的是“必须声明权威层并回读”，不是某一种固定连线方式。

## 9. 验收问题

- reference、dependency、assembly、lineage 是否能区分？
- group 是否被错误当成运行边？
- 每个顺序字段是否声明了权威层？
- 派生字段是否被错误写入计划？
- 变更后能否指出受影响的下游节点？
