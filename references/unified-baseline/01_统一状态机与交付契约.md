# 统一状态机与交付契约

日期：2026-10-07  
状态：A 路共享契约 v1  
适用：任意题材、任意时长、任意平台；具体平台动作由 C 路编译。

## 1. 输入模式

| 模式 | 用户输入 | 允许终点 |
|---|---|---|
| full_film | 目标、时长、画幅，可无剧本 | `delivered` |
| prompt_only | 只要剧本/分镜/提示词 | `shot_contract_ready` 或 `graph_plan_ready` |
| single_shot | 单镜或批量图 | `prompt_package_id` 生成并通过门禁 |
| rework | 某镜失败或用户不满意 | 按失败责任层回退 |
| platform_build | 已有结构化计划，只建画布 | `preflight_passed`，生成仍需单独批准 |

用户没有剧本时，Agent 负责生成 `script_draft`；用户没有详细 brief 时，Agent 先生成带默认值的 `brief_locked` 草案，只在真正不可推导处提问。

## 2. 状态表

| 状态 | 进入条件 | 必须产物 | 放行门 | 禁止事项 |
|---|---|---|---|---|
| `intake` | 收到任务 | 原始意图与约束 | 识别交付终点和验收人 | 不开始写剧本 |
| `intent_locked` | 意图可复述 | 一句话命题、时长、画幅、类型 | 可反转测试或等价命题测试 | 不把题材当命题 |
| `feasibility_passed` | 风险已扫描 | 难点镜头与绕法 | 手/走/多人/剧烈动作/画面文字等风险有结构方案 | 不删掉题材核心动作来规避风险 |
| `brief_locked` | 五项 brief 齐全 | 时长、主旨、交付物、难点、风格 | 风格和交付终点明确 | 不带“风格待定”进入资产 |
| `script_draft` | 剧本初稿完成 | M1-M12 或明确的 L0/L1/L2 档位 | 秒数、人物、台词、交接契约可检查 | 不写最终分镜 |
| `script_locked` | 剧本门禁通过 | 锁定剧本、场景表、资产派生清单 | `script_lint` 或等价结构检查通过 | 上游未锁定不动下游 |
| `style_locked` | 风格与量级系确定 | 风格编号、量级系、方案包、三条锚点 | 参照与校准路径存在 | 不凭“电影感”进入资产 |
| `assets_draft` | 资产清单生成 | 角色/场景/道具提示词与状态版本 | 一张图一个任务；状态变化单独版本 | 不静默降级为文生视频 |
| `assets_locked` | 所需资产完成锁定 | `locked` 资产集合、动测证据 | 本场所需资产无 draft | 有一个 draft 不开工 |
| `storyboard_ready` | 每镜结构已定 | 黑白故事板或结构化分镜记录 | 构图、人物位置、明暗与视频合同一致 | 不把故事板直接当首帧 |
| `shot_contract_ready` | 每镜合同完成 | Production Record + Prompt Package | 静态门禁通过 | 不自由重写上游锁定文本 |
| `graph_plan_ready` | 图计划完成 | Graph Plan | 节点、边、分组、引用顺序通过校验 | 不把 group 当运行语义 |
| `preflight_passed` | 平台预检完成 | dry-run、模型 schema、预算 | 结构/引用/模型/成本门禁通过 | 不提交付费任务 |
| `generation_authorized` | 用户显式批准 | 批准记录、幂等键、预算 | 批准必须显式 | 沉默、成功或门禁不算批准 |
| `generated` | 任务终态回读 | taskParams、任务号、结果路径 | 终态和引用回读完成 | 不把自述当事实 |
| `reviewed` | 分层验收完成 | 结构、指令、技术、创意四层结果 | 缺证据标不可判定 | 不把技术通过写成审美通过 |
| `assembled` | 音画和片段合成 | 时间线、合成计划、容器检查 | `export_readiness` 或等价预检通过 | 不在平台内做不支持的转场/字幕 |
| `delivered` | 用户验收 | 交付包、证据链、授权清单 | 用户显式确认 | 机器全绿不代替用户验收 |
| `failed` | 任一门禁失败 | 失败责任层、证据、回退目标 | 已定位回退状态 | 不盲目重试 |
| `recovering` | 失败已有责任层、证据和恢复计划 | 恢复范围、复用资产、重入状态、剩余门禁 | 恢复计划已核对且付费动作另有批准 | 不从失败点直接跳到交付 |
| `archived` | 交付或终止归档 | 版本、哈希、撤回与债务记录 | 可恢复或明确终止 | 不删除历史证据 |

## 3. 主路径

```text
intake
→ intent_locked
→ feasibility_passed
→ brief_locked
→ script_draft
→ script_locked
→ style_locked
→ assets_draft
→ assets_locked
→ storyboard_ready
→ shot_contract_ready
→ graph_plan_ready
→ preflight_passed
→ generation_authorized
→ generated
→ reviewed
→ assembled
→ delivered
→ archived
```

`prompt_only` 在 `shot_contract_ready` 或 `graph_plan_ready` 停止。`single_shot` 可以从 `brief_locked` 直接进入资产/单镜路径，但命题和可测目的不能跳过。

## 4. 回退规则

| 失败层 | 回退状态 | 处理 |
|---|---|---|
| 命题/意图 | `intake` | 重新确认命题和交付终点 |
| 可行性/题材 | `feasibility_passed` | 改结构，不删核心动作 |
| brief/风格 | `brief_locked` | 重新定风格或交付范围 |
| 剧本 | `script_draft` | 修结构、人物、时长或台词 |
| 资产 | `assets_draft` | 修参考、身份、状态版本或锁定 |
| 故事板/分镜 | `storyboard_ready` | 修构图、拆镜或镜头合同 |
| 提示词 | `shot_contract_ready` | 修结构、表演、物理或风格 |
| 图计划 | `graph_plan_ready` | 修节点、边、引用、分组或权威层 |
| 平台预检 | `preflight_passed` | 修模型、参数、引用或成本 |
| 生成结果 | `generated` | 按责任层决定重试、换模型或改结构 |
| 审片 | `reviewed` | 证据不足标不可判定；审美问题交人 |
| 合成/导出 | `assembled` | 修时间线、音频、规格或导出契约 |

失败时先定位责任层，不默认增加抽卡次数。同一产物超过既有止损线时改结构或路径，不写“再抽最后一次”。

恢复路径固定为：

```text
failed
-> recovering
-> 最后一个仍然有效的上游目标态
-> 重新执行该目标态的放行门
```

`recovering` 必须说明哪些产物可以复用、哪些计划失效、哪些输出需要重新生成，以及从哪个状态重入。恢复只解决“怎样继续”，不替代付费生成、导出或交付的显式批准。

## 5. 审批点

必须显式审批：

```text
付费生成
合成/导出
不可逆的内容或权利决定
交付验收
删除、覆盖或改变用户锁定内容
```

可以内部推导但要留痕：

```text
默认时长档位
镜头拆分方案
资产必要性
模型候选
提示词结构
读取、结构校验、dry-run
```

## 6. 最小核心

即使任务很小，也不能裁掉：

```text
开工前对上游定稿和关键约束对表
结构化记录
提示词/图计划门禁
结果回读
失败责任层与回退动作
```

裁剪必须在开工前声明，并写明本任务不改变哪些状态、字段和交付物。

## 7. 验收问题

- 任意简单输入能否进入状态机而不缺关键字段？
- 每个状态是否都有产物、门禁和禁止事项？
- prompt-only、full_film、single_shot、rework 是否有明确终点？
- 失败是否能回到正确状态，而不是一律重试？
- 批准点是否没有被沉默、成功或门禁替代？
