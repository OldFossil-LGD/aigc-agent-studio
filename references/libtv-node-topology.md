## 一、节点类型与它们能连什么

### 1.1 四种节点（【画布实证】180 节点实测分布）

| type | action | 数量 | modeType |
|---|---|---|---|
| video | video_generate | 130 | mixed2video / text2video / videoEdit2video |
| image | image_resource | 33 | 无（上传） |
| image | image_generate | 9 | text2image / image2image |
| group | — | 19 | — |
| audio | （3 个，仅通过 video 的 audioList 观察到） | 3 | — |

- `action` 说节点类别，`modeType` 说生成方式 —— 两层，不要混。
- `image2image` 不是一种 action，`action` 仍是 image_generate（`i-HxjjAc67TO`）。

### 1.2 连线合法性矩阵（【接口实测】）

| 从 到 | image | video | audio |
|---|---|---|---|
| **image 到 video** | — | 可连（1–15 张） | — |
| **video 到 video** | — | **实测被拒**（⚠ 见下 · **不是"平台拓扑禁止"**） | — |
| **video 到 image** | **被禁** | — | — |
| **audio 到 video** | — | 可连 | — |
| **image 到 image** | 可连（0–14 张参考） | — | — |

> **⚠ 2026-10-16【REA静态】补正（`outputs/libtv_rea_20261014/64_连线合法性客户端实现.md`）**：
> 本表上方的 **"video 到 video 被禁"是本册的【接口实测】口径**（真在画布上被拒过），**不要删**；
> 但**客户端静态读表**里 **`video_generate → video_generate` 是 `true`**，与本库 `libtv-canvas-anatomy.md` §2.2 的 2026-10-03 修正**仍不一致**；
> **"客户端允许" ≠ "某个模型接受"**（客户端在查完表后**还会按目标模型的素材能力再判一次**）。
> **→ 写这句时必须带限定语"实测环境里被拒"**；**要定案需一次受控连线（写操作，需显式批准）**。**`type → action` 映射与 action 层的五行全 0 / 两条短路特例见 `libtv-node-types.md` §四。**

两条禁行是整份规格的物理基础：

1. **video 到 video 被禁** → 段落之间的衔接只能靠提示词文字。
   这就是「最后一帧块」「动作匹配切」「续接三件套」存在的唯一原因。
2. **video 到 image 被禁** → 「后一镜首帧 = 前一镜尾帧」这条血缘画布上连不出来，
   只能截成图片节点后用 left 连。

## 二、`{{Mixed N}}` 的唯一权威规则（【画布实证】五例交叉验证）

> **模型收到的"图1" = mixedListOrder 里的第 1 个。不看提示词里 {{}} 出现在第几位。**

三条硬规则：

1. imageListOrder / mixedListOrder **由 left 边序生成**，不按提示词顺序重排。
2. **N 必须等于该 key 在 mixedListOrder 里的 1-indexed 位置。**
3. **N 在文字里出现的先后顺序不影响。**

### 2.1 五组实证

| 实证 | 证明了什么 |
|---|---|
| v-7k4vIqNQRh / v-hVI4Vdoffl | {{Mixed 11}} 写在 {{Mixed 10}} 前面仍全对 |
| 同上 | 序号跳号（2,3,4 → 7 → 5,6,10,11）仍全对 |
| v-0DtTZq6PfG 对 v-8mZNyNjxF0（正文逐字相同） | 头部插入一条参考后，后续序号整体 +1（怪兽 2→3、自卫队 4→5、鹰派高层 5→6、尾帧 6→7），两节点均成功 |
| v-gdTOFMOnHl | 12 个语义角色插桩被删成纯文字，节点仍成功 |
| v-FzZP4gouSs 等四节点 | 12 个角色全是纯文字，mixedListOrder 里确实没有对应图 |

### 2.2 三个必须避免的错误

| 错误 | 正确做法 |
|---|---|
| 靠"上次是几号"推算 | 每次 leftEnsure 后先回读 mixedListOrder，再据此重编全部 {{Mixed N}} |
| 只改提示词文字不改 left | 图序号仍然是错的 |
| 靠插桩后的语义名反查是哪张图 | 必须回读 mixedListOrder |

第三条实证：第一段 8 个节点逐字重复 {{Mixed 7}} 鲸鱼 与 {{Mixed 8}} 海洋动物群像，
但底层两张图实际是「鲸鱼」与「魔鬼鱼+鲨鱼」。

### 2.3 插桩的三种合法形态（【画布实证】）

| 形态 | 判定 |
|---|---|
| 插桩 + 有 left 边 | 正常引用 |
| 插桩 + 有 left 边 + 文字声明"本场不出现" | **有意预埋**，合法且成功（v-XIpmHOrXWU） |
| 插桩但没有 left 边 | **真错误** |

注意：frames2video 只连 1 图时没有 left 边可挂，插桩无源，只能写纯文字。

## 四、建链顺序（⭐ 这里必须分清来源）

### 4.1 画布上验证过的：资产必须先于段落存在（【画布实证】反证）

【画布实证】**四个 asset image 节点缺失（悬空）**，
其中 `i-Mu2dzClPz9`（上司的脸）被第七段引用、`i-lbndv27pYl`（银枪）被五个节点引用。

结果：**这些段落全部 status:2 成功。**

这说明：
- **画布不强制"资产必须先建"** —— 可以先建 video 再补资产
- 但模型会**按提示词里的语义名即兴生成**，造型没有真实锚点约束
- ⚠ 所以"先建资产"不是平台门禁，**是质量手段**

### 4.2 从技能库拿的建链顺序（【库规】本画布未验证）

技能库给的链路是：
`分镜卡(text) → 故事板(image) → 首帧(image) → 镜头(video) → 合成`

⚠⚠ **这一条与画布实证不符**：
《弥寿计划》的 130 个 video 节点**没有一个接首帧节点**，
也没有一个故事板节点 —— 全部是"资产图 + 文字"直出。

⭐ **画布的真实做法是**：
`资产图 → video 节点`，中间没有分镜卡 / 故事板 / 首帧三层。

### 4.3 ⭐ 我该怎么做：分清"平台要求"和"我的偏好"

| 环节 | 画布上真实存在吗 | 平台强制吗 |
|---|---|---|
| 资产 image 节点 | ✅ 大量存在 | ❌ 不强制（悬空仍能生成） |
| 分镜卡 text 节点 | ❌ 一个都没有 | ❌ |
| 故事板灰度 image | ❌ 一个都没有 | ❌ |
| 首帧 image → frames2video | ❌ 一个都没有 | ❌ |
| video → video 衔接 | ❌ 连线被禁 | — 必须靠文字 |
| 尾帧/截图 image 节点 | ✅ 4 个（`frameCaptureSourceNodeId` 可验证） | ❌ 但这是唯一的血缘手段 |

⭐⭐ **结论：技能库那条 11 步链路是【库规】级推荐，不是【已验证】的平台要求。**
我此前把它写成"目标工作流程"，**这个措辞把它说成了硬要求，是我的问题。**

## 五、点火顺序

### 5.1 画布实证：同节点重跑多次，全部成功

【画布实证】至少 7 对节点正文逐字相同但 `taskId` 不同，
`status:2` 全部成功 —— 说明重跑是被支持的常规动作。

### 5.2 从技能库拿的点火纪律（【库规】）

| 规则 | 说明 |
|---|---|
| 沿依赖链串行 | 资产图 → 首帧 → 镜头 |
| 空 url 期间不要触发下游 | 会产生失败节点，要按 v2 重建 |
| run=true 的批量上限 5 | 留 1 个余量 |
| 只读回读，绝不重新发起 | 查 task_status 不花钱；重新点火 = 又一笔积分 |

### 5.3 ⭐ 时间顺序 ≠ 节点顺序（【画布实证】）

【画布实证】第十一段 `v-ekvZ8VOk7W` 的提示词第一行是
`4、正文：分镜执行动作（23—42镜）`，镜号从 23 开始且没写时间码。

⭐⭐ **读节点的第一步应该是看标题行**，它告诉你这个节点负责哪一段镜号。
**节点在画布上的 x/y 位置与叙事顺序无关** —— 位置只表示分组归属。

| 手段 | 出处 | 原文特征 |
|---|---|---|
| **最后一帧块** | `v-hZFvxC7qmz` | `场景6最后一帧：…巨掌阴影压满画面的瞬间，硬切进入场景7` |
| **首帧匹配转场** | `v-rHiu030NkZ` | `承接上一场海面下的红色控制光点，硬切到战术终端上一颗断续闪烁的红点` |
| **动作匹配切** | `v-iZnO2O1DtH` | 单独一行 `动作匹配切——`，同族有亮度匹配剪辑、遮挡转场 |
| **续接三件套** | `v-ST9Cb3uUtd` | mixed2video + 上一段截帧 image + `{{Mixed 1}} 从这里开始延续。` |

⭐⭐ **续接三件套是成本含义最大的一条**：
5 秒插入镜的成本远低于 20–30 秒整段重跑（16–25 分钟）。
**定点补镜优先用这种方式，不要重跑整段。**

⭐ 续接三件套的关键细节：
1. 用 `mixed2video`，**不是** frames2video
2. 截帧点选在"动作进行到一半"的位置（19.666 秒落在上一段 18.6–20.2 秒那镜中间）
3. `{{Mixed 1}} 从这里开始延续。` **放在插桩行末尾**（人物/道具在前）

## 八、分组的分组学：客户端硬约束（【REA静态】CLI 载荷 ~427600–441000 · 2026-10-16）

> **未建组、未解绑**；以下全是**客户端实现**证据，**不是服务端规则**（服务端是否接受"子节点相对坐标 + parentKey"**未验证**）。出处：`outputs/libtv_rea_20261014/48_CLI分组绑定布局实现.md`。

**基准**：`CANVAS_NODE_WIDTH_DEFAULT` / `CANVAS_NODE_HEIGHT_EMPTY_DEFAULT` ＝ **350 / 350**（空节点按 350×350 计）；`GROUP_NODE_BIND_PADDING` ＝ **20**；流尺寸取 **`measured ?? width ?? 350`**。
**★ `position` 是相对父节点的**（`getAbsolutePosition` 逐层"父绝对＋自身相对"）⟹ **跨层算 bbox 必须先递归求和**，直接读 `position` 当绝对坐标会错。

**★ 打组前的五条逐字拒绝**（`validateBindTargets`）：

| 触发 | 逐字报错 |
|---|---|
| 去重去空后无目标 | `至少指定一个要绑定的节点` |
| 目标不在画布 | `未找到节点: <id>` |
| 目标是分组自身 | `不能把分组自身作为绑定目标: <id>` |
| **目标是组类**（`group` / `video_group`） | `不能将组类节点打入组: <id>` ⟹ **组不能嵌组** |
| **目标是脚本/分镜** | `脚本/分镜表节点不支持打组（与画布多选打组一致）: <id>` |

第 5 条判定 `isScriptLikeNode` ＝ `type==="storyboard"` **或** `data?.type==="script"` ⟹ **脚本/分镜想归筐只能用命名或工作流，不能靠分组。**

**bbox / 新建 / 并入**：bbox ＝ 各目标**绝对位**＋流尺寸求并集，**四周各留 20 px**，**宽高下限 1**；**新建** ≥1 节点、落位＝bbox 左上角、`zIndex:-1001`、样式 `var(--canvas-group-bg)`／`var(--canvas-group-border)`、默认名 **`分组 <N> 个节点`**。
**并入**要求目标是**普通分组**（`type==="group"` 且**无 `sourceScriptNodeId`**），否则逐字 `目标必须是普通「分组」节点（type=group，且无 sourceScriptNodeId）；不支持视频组、分镜组等` ⟹ **`video_group` / 分镜组不能当并入目标**；子节点**并集去重**（幂等）、**不覆盖已有名**。

**★★ 打组会重写子节点坐标（画面位置不变）**：组新位置 **有父＝bbox − 父绝对位 / 无父＝bbox 绝对位**；组的 `width/height/measured` **全部由 bbox 反写**；**每个子节点 `position = 绝对位 − bbox 左上角` 且 `parentId = 组 key`**。
⟹ **打组后存储坐标变了、画面位置没变**；**解绑是严格逆操作**（`position = 绝对位`、`parentId = void 0`）。

**★ 一个节点只能属于一个普通分组**：绑定会把目标 key **从其他普通分组里摘掉**（`pushUnbindFromOtherPlainGroups`，只摘不复制），**`video_group` 不在清理范围** ⟹ **打组是"迁移"不是"复制"**。

**解绑校验**：前置 `projectUuid 不能为空` · `groupNodeKey 不能为空` · **`至少指定一个 --node-rm 节点`**；逐节点 `不能把分组自身作为解绑目标: <id>` · `未找到节点: <id>` · **`节点不在该普通分组内: <id>`**。
