# 资产一致性（角色 / 场景 / 道具跨镜不漂）

> **何时读**：出资产图、以及要把资产复用到每个镜头时。**读完回哪**：回到 `updream-workflow.md` 落地到具体平台。
>
> 一句话：**一张参考图只承担一个任务。** 身份图只给脸、风格图只给风格、场景图只给空间——
> 混排是 ID 漂移的第一号原因。
>
> **★ 数量 / 档位 / 主锚点已由 `asset-standard.md` 收敛（2026-10-31）**：本册保留"为什么"与实测记录，**冲突处以那一册为准**。人物投喂＝七件库（脸＋前后左右俯＋无头）＋**每镜只挂一张带脸图**；场景主锚点是平面图，3/4 与正对中轴都只是机位选择。
>
> **★★ 第一性原理（2026-09-20 补 · 先记住这句再往下读）**：
> **资产的唯一职能就是做一致性。** 它不是"美术设定稿"，是**一致性链条上的中转站**——
> **一致性靠"传实物"，不靠"传描述"**（传递优先级 `上一镜尾帧 > 静态图 > 文字描述`，见 §四·补）。
> **所以资产的全部规格（灰底 / 柔光无影 / 3-4 角度 / 三处偏离平均 / 逐处写脏 / 锁色板 / locked）都是"引用友好度"的判据，不是美术判据**：
> 灰底与柔光是为了**不让背景与光污染下游**；多角度是为了**下游有机位可用**；偏离平均与写脏是为了**让身份可区分、可验伪**；locked 是因为**资产是契约，契约不能中途改**。
> **不先做资产 = 下游每一镜只能吃最弱的一档输入 = 必然漂。**

## 一·补 · 资产图自身的三条硬规格（出图时就定死）

资产图不只是"内容对"，它的**背景、光位、角度**决定了它能不能当下游参考活下来。

| 规格 | 怎么写 | 为什么 |
|---|---|---|
| **① 纯中性灰背景** | 角色 / 道具设定图一律写"纯中性灰背景、无环境元素" | 主体背后零杂物 = 没有东西和角色抢注意力，**下游可用比例高得多**；杂物还会被模型当成场景一起继承 |
| **② 柔光、近乎无影** | 写"柔和均匀的光、几乎不产生投影、头发无高光斑、眼里有眼神光" | 设定图的光**会被继承进每一条下游生成**。硬光/强侧光/大面积阴影的图"再像也没用，它会污染下游每一条" |
| **③ 场景要有纵深（3/4 见两面墙是常用手段，不是硬规则）** | 每条场景 prompt 都写"3/4 角度视图，同时可见两面墙的交角" | 这是补救纵深感最便宜的办法。正对墙生成 = 一张压平的背景板，后续无法运镜 |　**★★ 分工与裁决（2026-10-01）**：本内容本身有张力 —— **④ 要 3/4 斜角**，而 **⑤（平台口径）要「正面、无强透视」**。`libtv-official-qa-part2.md` §R3.6 给了裁决：**【场景 3/4 图与「全片正对中轴」不匹配**（模型可能把 3/4 透视带进成片、破坏对称）。**→ 落地为两张图分工**：**① 主场景锚点 = 正对中轴、单点透视**（同成片机位，支一刻对称）；**② 另出一张 3/4 空间参考图**（只作 `reference_nodes`，**不当首帧、不当主锚点**）承接④的运镜空间感。**两条各对一半：主锚点＝与主力机位一致的机位视图，3/4 只作参考图**；**正对中轴只是"主力机位恰好正对"的特例**（2026-10-31 由 `asset-standard.md` §5 收敛）。 |
| **④ ★（平台口径 2026-09-20）"中性、正面、无强透视、无复杂光影"** | 同上四条合并成一句写 | **★ 平台给的成因（建议回抄进判据）**：**"这样它作为参考时，不会把奇怪的构图带进每个镜头"** —— 本库①②③三条规则的**统一理由**就这一句 |

**★ 补两条平台口径（2026-09-20 · 本库此前没有）**

**① 派生锚点（换装 / 换姿势 / 换站位时）**
- **规则**：**引用父锚点 + 只写新增特征**——`generate_image_v3`，`reference_nodes: ["父锚点 key"]`，prompt 写 `{{父}} + 只描述变化的部分`（例："同一人物，改为侧身坐在办公桌前，双手交叠"）。
- **★ 不要重写父锚点已锁定的特征**（脸 / 发型 / 服装颜色）——只写新增的姿势、站位、构图。
- **为什么**：比新建独立锚点**省一次完整生成，且一致性更好**；派生锚点内部已继承父锚点，镜头引用它即可。
- **台账**：分镜表里**每镜记录它实际引用的锚点 `node_key`**（引用的是父还是派生，要写清）。

**② ★ 尾帧拉回（连续用尾帧衔接会累积误差）**
- **节奏：每 3 镜拉回一次**——10 镜的片，**第 1 / 4 / 7 / 10 镜以资产图为准**。
- **普通衔接镜**：`start_frame_image_node = 上一镜的尾帧`（保连贯）。
- **拉回镜**：**不用尾帧**，改为在 `reference_nodes` 里**重新放入主体锚点资产图 key** ＋ prompt 同步 `{{}}` ——**用定妆图重新锚定人物，抵消累积漂移**。也可用 `end_frame_image_node` 显式指定某镜结尾回到锚点构图。
- **判据**：**每镜生成后检查人物是否漂；漂了就对该镜改用资产图拉回重做，并把分镜表里该镜的 key 更新为最新生效节点。**
- **平台给的原因**：尾帧续接会**继承**上一镜的画质、光影、构图偏差，**误差会累积**。

**③ ★★ 参考要"按景别加权"，不能每镜固定挂同一组（2026-09-21 平台评审 · 极实用）**
| 镜别 | 挂什么 |
|---|---|
| **全景 / 拉回镜** | **场景正面图为主** · 角色图为辅 · **道具图弱挂或不挂** |
| **特写镜** | **道具图 / 角色局部为主** · **不挂或极弱挂场景全景图** |
| **中 / 近景** | 角色＋场景；**道具按"是否入画"决定** |

**为什么**：① **特写挂"场景全景图"→ 模型把纵深塞进特写**（多余桌面延伸、背景过实、道具比例与全景不一致）；
② **全景挂"道具图"→ 道具被放大/加高光/"悬浮强调"**，**提前剧透道具、削弱结尾力度**；
③ **无差别挂全组 ＝ 把"一致性"做成"每镜都在强调那个道具"**——**与克制基调相悖**。

**④ ★ 声音开关必须"逐镜显式"关**：只在合成端静音不够——**某镜默认 `on` 时平台仍会生成环境音/拟音，与本地音轨叠加会产生相位/底噪问题**。**纪律：每个视频节点显式 `sound=off`（MCP 侧 `enableSound:"off"`），不依赖默认值。**

**筛查顺序（重要）**：**先看光，再看像不像。** 光不对的图直接淘汰，不要因为它"长得像"就留下。

## 二、多参考图的分工铁律（跨模型通用）

**一张图只干一件事**：

- 身份图 → 只给**脸**（干净大头照）
- 风格图 → 只给**风格**（独立一张，不混入身份图）
- 场景图 → 只给**空间**
- 道具图 → 只给**物件**

**提示词里显式声明参考范围**：`仅参考图片1的面部特征，不继承其服装、背景、构图与光线`。
**最需精准的参考图放最前**（位置权重最高）。

### 参考素材的「双层角色」（缺一层都不行）

| 层 | 是什么 | 值域 | 给谁看 |
|---|---|---|---|
| **语义用途** | 这张图在本镜**负责什么** | **身份 / 造型状态 / 地理 / 构图 / 尺度 / 效果 / 起始帧 / 结束帧 / 风格**（封闭枚举，不得自创写法） | 人 + 提示词正文 |
| **技术角色** | 这张图在**平台参数里叫什么** | 各平台自有：`image` / `start_image` / `end_image` / `video` / `audio` / `image_references` / `video_references` 等 | 平台 API / CLI |

**为什么两层都要**：语义用途是人能读、能被写进提示词的；技术角色是**机器能验的**——平台会在提交前就拒掉角色用错的调用（"这个模型只接受一张参考图"这类错误是本地报的，不用等生成失败）。

**常见映射**（同一"用途"在不同平台叫法不同）：

| 语义用途 | 常见技术角色 |
|---|---|
| 起始帧 | `start_image` / `image`（单图模型） |
| 结束帧 | `end_image` |
| 身份 / 地理 / 构图 / 风格 / 效果 | `image` 或 `image_references`（多图模型） |
| 前序镜头连续性 | 上一个任务 id 或实际尾帧文件（见 `motion-control.md` 的续接纪律） |

**一条硬纪律**：**不确定某平台接受哪些角色，就查它的模型 schema（例如"模型详情"命令），不要猜参数名。** 猜错要么被本地拒、要么被静默忽略。

**参考素材的数量上限**：各平台差异很大（单图模型 1 张、多图模型可 4–14 张），写之前查 `platform-matrix.md`，**别按"越多越好"来堆**——超出上限的参考反而让模型困惑。

## 三、多视图到底能不能用（交叉验证结论）

| 说法 | 证据 | 结论 |
|---|---|---|
| ❌ 多视图**拼在一张宫格**里当参考 | 火山方舟官方明确"不建议使用人物多视图——会被识别为多个不同主体，反而加剧 ID 漂移"；人脸占比过小更严重 | **不要拼成一张** |
| ⚠️ 视角越多一致性越差 | 实测：2–3 视图最好，6–8 视图开始降，9+ 崩 | 控制在 **2–3 视图** |
| ✅ 视图**分开存、分开喂** | 同一批实测中，多视角作为**独立文件**输入可提升身份保持率 | **拆成多张独立图** |

**推荐资产包**：
① 一张**中性正脸大头照**（身份锚，反复抽卡到满意）· ② 一张**全身照**（独立文件）·
③ 一段 **40–70 字冻结身份块**（脸型 / 眼距 / 发型 / 发色 / 标志配饰）· ④ 一张**独立风格参考图**。
**★ 三视图不在这个包里**：它默认是设计板或结构辅助，不进投喂集（`asset-standard.md` §3.3）。

### 3.0 ★ 人物 vs 无生命道具：多视图禁令的适用边界（2026-09-11 划清 · **2026-09-13 补平台前提**）

#### ★★ 前置判断：平台有没有「主体 / 元素」封装层？（不判这一步后面全错）

**打包成一个「主体」**（可灵主体库 / updream 锁定资产 / **LibTV 主体库**）→ **✅ 推荐多角度**；**平铺为多张独立参考图**（火山方舟 `reference_image`）→ **❌ 禁同身份多视图平铺**。
**★ LibTV 侧属哪一侧：未核**（它同时给"角色三视图"与"主体库"，但**三视图到底是走封装通道、还是被当多图平铺喂进去，没有一手证据**）→ **未核前一律按平铺那一侧从严处理**：同一身份只给「一张干净正脸 + 一张全身」两张独立文件（§3.5），**不赌**。判据与验证动作 → `platform-matrix.md` §7.7·补。
**判据**：**"这几张图是打包成一个『主体』喂的，还是当独立参考图平铺喂的？"** → 完整平台对照与官方原文见 `platform-matrix.md` §7.7（本库此前把"一家平台的注意事项"当成了"通用规律"，这是本次修正的核心）。

**★★★ 实测反例（2026-09-20）：七环跑通 ≠ 全流程跑通——资产不进参考，一致性必然崩。**
在 LibTV 上"分镜表→资产→图→视频→时间线→预检→导出"**每一环都跑通了、成片也出来了**，但**人物与场景全不一致**，原因是**每一镜都是 `text2video` 从零生成，`resolvedReferences.image` 全程为空**——**资产图根本没进参考**。
实测数字（同一块墙面区域的平均色）：**T2 视频 `RGB(165,146,146)` · 场景图 `RGB(102,110,94)` · 多角度板 `RGB(184,168,149)`** → **三处互不相同，所谓"同一间办公室"其实是三个房间**；人物同理——**角色三视图只做了男角一个**，且每次视频生成都是**新的随机脸**。
**→ 两条纪律**：① **"流程跑通"必须包含"资产 → 参考图 → 镜头"的闭环**，只把各环各跑一遍＝**七条独立的文生**，不是一条流程；② **每一镜都要用同一张资产图驱动**（`referenceImageNodes` + `singleImage2video` / `mixed2video` / `frames2video`），**"提示词里写了身份锚点"不等于锁住了身份**。

**平铺模式下，人物与无生命道具结论相反**：

| 对象 | 多视图（**平铺模式**） | 原因 |
|---|---|---|
| **人物身份图** | **禁**。不许出现第二个角度的脸 | 同一批参考里有两张有效脸 → 模型不知道锁哪一张 → 逐镜漂移 / 混脸 |
| **无生命道具** | **允许，且应当**。多角度 + 材质分解 + 内部构造 + 与角色的尺度关系 | 道具不是演员，没有"身份脸"可抢；多角度反而让它跨镜不漂 |

**★ 一条最容易漏的工程细节**：若因平台限制，只能提交一张"人物拼表"（特写 + 全身正面），而**全身面板也露脸**，那么这一批参考里就有**两张有效脸**——下游每一条生成都会继承这个漂移。
**修法**：进编辑模型，**把全身面板的脸抹掉或遮挡**，其余（身高、体型、服装、姿态）全部保留。每个有多视图表的角色都要做这一步，配角也一样。

> **⚠️ 边界（2026-09-13 补 · 按 R6 仲裁统一）**：**拼版（含"分镜九宫格"）禁令管的是「故事板 / 镜头图」——每个镜头必须能单独拿到一张全分辨率的图**；**资产图里的无生命道具多角度设定板是另一类，允许拼**（无面部身份风险，多角度只增信息）；**人物设定板不适用这条豁免**。**判据：图里有没有"同一身份的第二张有效脸"**——有则禁。九宫格分镜只在**喂给下游当结构参考**时按例外放行（须标注 H6），**不得当故事板交付物**（官方示例 `image1: 九宫格分镜参考…` 属于此列）。

**道具的"多角度"给几个？** 按"这个道具在画面上实际要展示什么"决定，够用即可，不多给。例：一个背包只给 3/4 + 正视两张，够承载帆布纹理、刺绣贴与抽绳即可。

### 3.1 ★ 缺机位的正解不是"多视图"，是"从已锁定的图生成新机位"

多视图被否掉之后，"资产图只有一个角度、做分镜时不够用"这个需求**仍然存在**。官方的平台化答案是**用生成工具从一张已锁定的图派生新机位**（而不是拼多视图当参考）：

| 工具 | 做什么 | 为什么这条路径对 |
|---|---|---|
| **Higgsfield Angles 2.0**（`/apps/angles`） | 官方描述：`Generate new camera angles from a single photo` | **身份来自那张已锁定的原图，机位是派生出来的**——不引入"第二个主体"的风险，绕开了多视图的病根 |
| **Higgsfield Shots**（`/apps/shots`） | 官方描述：把**单张参考照片变成一串分镜镜头**，用电影级基础机位快速可视化叙事 | 它本身就是分镜生成器；用它出**构图草图**，再照构图写镜头提示词 |
| **Higgsfield Zooms**（`/apps/zooms`） | 一张静帧 → 一组变焦变化（微距到远景） | 补"同主体不同景别"最省的做法 |

**执行顺序（替代旧的多视图流程）**：
```
中性大头照（身份锚）→ 锁定
   ↓
用 Angles 从这张图派生 3/4 侧、正侧、背面（每张都源于同一张锚图）
   ↓
需要全景时用全身照；需要变景别时用 Zooms
   ↓
参考图仍遵守"一张只承担一个任务"，仍遵守每批 ≤6、每批只改单点变量
```

**注意**：Angles / Shots / Zooms 是 Higgsfield 平台的能力。**在 Updream / 即梦里没有同名入口**，但可以做**等价操作**——把已锁定的图当参考图，只改"机位"这一个变量重复生成（即"复用提示词改关键词"的老办法）。**能力等价，实现路径不同**，别去即梦里找"Angles"这个名字。

### 3.2 ★ 场景资产：必须给"正反两个机位"（跨镜地理不漂的根本解法）

**只出一张场景图 = 只要镜头回头看，背景就靠模型现编。** 这是跨镜地理漂移的第一号原因。

**做法**：同一个空间出**两张朝向相反的独立场景图**——
- 一张 **正面地标视角**（本场戏的"标志物"那一面）；
- 一张 **故意空着的反向视角**（摄影机转 180° 后看到的那一面，画面里可以没有人）。

**180° 自检问句（开生成前必答）**：
> **如果摄影机现在转 180 度，哪一张已批准的参考能描述这个画面？**
> 答不出来 = 地理还没锁，**不许开生成**。

**凡是有正反打、有机位翻转的对话或对峙场，这条是硬要求**；空间只在一镜里出现且不回头时，可以只出一张。

**与 3.0 的边界**：3.0 管的是"**人物**多视图"（会引入第二张脸）；这里管的是"**同一空间的不同机位**"（提供空间蓝本，不涉及身份）。两者的共同禁令只有一条：**都不许拼成一张宫格，必须存成独立文件。**

### 3.3 ★ 场景清洁：标 safe / risky / unnecessary，且跑完动态要再删一次

出完场景图、开生成之前，把背景里每个细节过一遍，标成三类：

| 标记 | 是什么 | 处理 |
|---|---|---|
| **safe** | 承载剧情、跨镜必须保留的 | 留 |
| **risky** | 文字、杂物、远处车辆、密集小元素 | **开生成前删掉** |
| **unnecessary** | 与剧情无关的装饰 | 删 |

**⚠️ 关键一条：跑过一次动态之后，还要再删一次。** 实测中远景车辆会在生成时**克隆成主车的复制体**——静态图上看不出问题，动起来才暴露。

> 这条补的是 `qa-failure-codes.md` 的空白：那边只覆盖了"字迹崩坏 / 画面冒字幕"（文字类），没覆盖"**物体克隆**"这一类。

### 3.4 ★ 子地标单独出资产（"绿洲法"· 2026-09-11 补）

**问题**：一个场景里常有**一个反复出现的关键局部**——一扇窗、一台机器、一块招牌、一棵树、桌上的一只杯子。它每次出现都跟着整张场景图生成，于是**每次都不太一样**，观众会感觉"这不是同一个地方"。

**做法**：把这个反复出现的局部**当成独立资产单独出一版**（就像沙漠地图里单独标出一块绿洲），跨镜引用它，而不是指望整张场景图每次生成都对。

| 判据 | 处理 |
|---|---|
| 该局部在**≥2 个镜头**里出现，且观众**会认出**它是同一个 | **单独出资产**（独立成图，形态、比例、表面细节写死） |
| 只出现一次的背景装饰 | 不单独出，跟着场景图走 |
| 与人交互的物体（门把、开关、杯柄） | **必须单独出**——它同时是 `ai-artifact-control.md` 的"接触面" |

**纪律**：子地标资产的**背景规格**与场景图一致（同色温 / 同光位），但它可以单独出图（不必与整张场景在同一张图里）。**引用时是"场景图 + 子地标图"两张一起给**，不是把子地标 P 进场景图。

**为什么有效**：模型在没有独立参考时，每次都会"重新设计"这个局部；给了独立资产，它才有一个**固定靶子**去对齐。

## 四、角色一致性的技术手段（按"要不要训练"分）

| 手段 | 需要什么 | 效果 | 备注 |
|---|---|---|---|
| **多图参考**（Seedream / Nano Banana） | 1–2 张干净参考 | 换脸换景最稳 | **首选**，免训练 |
| **IP-Adapter** | 1 张图 | 脸相似 70–85% | 权重 **0.5–0.6**，高了会"太像原图" |
| **InstantID / PuLID** | 单图 | 写实身份强 | 开源生态 |
| **ControlNet** | OpenPose 等 | 只锁姿势 | 与 reference-only(0.5) 搭配注入外观 |
| **LoRA** | 15–30 张多角度干净图 | 最强 | rank 32–64、lr 1e-4、1500–3000 步；**20 张优于 10 张，>30 收益递减**；注意风格污染（身份 LoRA 权重降到 0.4–0.5 让风格 LoRA 生效） |

**顺序**：多图参考 → IP-Adapter / InstantID → ControlNet → 最后才训 LoRA。

## 四·补 · 前序素材传递律（跨镜一致性的唯一机制）

**一致性靠"传实物"，不靠"传描述"。** 传递优先级是**硬性的**：

```
实际生成的视频（尾帧）  >  静态图  >  文字描述
```

**每写下一镜（或下一段）之前，手上必须有这三样**：
1. 上一镜的提示词；
2. 本镜要用的资产图；
3. **上一镜实际生成出来的视频，或它的尾帧**。

**用文字描述前情 = 必定漂移**——每传一代就漂一次，三代之后就是另一个人。

> 对应 `motion-control.md` 的"续接纪律"：同机位连续内容用尾帧链式续接。这里把它**从特例升为全片默认**——只要上下镜有连贯要求，前三样缺一不可。
