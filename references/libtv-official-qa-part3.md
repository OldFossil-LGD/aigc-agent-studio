## R6 · 真实性与物理一致性（11 问）

**1）"光只有一个来源"＝弱遵守**（模型可能自行加补光）。强化写法：**"唯一光源为画面右侧百叶窗，无其他光源，无补光，暗部为自然衰减"**；关键镜用首帧图锁光位。

**2）光的方向不会自动保持** → **三锁**：① 每镜 prompt **复述同一光位**（"光从画面右侧斜下约 45°"）② 出一张**光位参考图**，每镜引用 ③ **首帧图锁第一镜光位，后续镜用尾帧续接传递**。

**3）★ 每镜写同一套光位"不会显得重复"**——**"重复的 prompt ≠ 重复的画面；光位是约束，不是内容"**。画面变化靠景别/动作/构图。**→ 放心每镜都写。**

**4）接触关系**：部分能、不可靠（遮挡与投影变化是模型弱项）。**提高命中：把接触写成"可见结果"**——"**手背在桌面投下阴影，亮带在手腕处断开**"，而非"手压住桌沿"；关键镜用首帧/分镜图锁。

**5）★ 比例用"相对比例"，不用绝对数值**——模型对相对关系响应更好：
- "**桌高约到成人腰部**" 优于 "桌高 75cm"
- "**门框顶端高于头顶约一掌**" 优于绝对厘米
- "坐姿时眼睛略低于桌面"

**6）时间连续性要写，每镜复述**："下午四点，窗光角度不变，光色为中性冷白"；**时间词放光线描述附近，不要放句尾**。

**7）环境细节**：**跨镜需一致的特征（桌沿磨白/柜底踢白/墙脚起泡/门前踩亮）每镜必写**；只是氛围的可不写。

**8）道具守恒不会自动** → ① 每镜 prompt 明确写状态（"钥匙仍在桌面原处，位置未变"）② **道具锚点每镜引用** ③ **末镜特别强调**（"钥匙仍在桌面，未被移动、未被拿走"）。

**9）平台最常出问题六条**：**① 道具消失/移位（最常见）** ② 光源方向漂移、多出补光 ③ 手部结构错误（手指数量/关节）④ 接触/遮挡关系错误（影子不对）⑤ 空间比例漂移（门、桌忽大忽小）⑥ 镜面/文字/屏幕内容错误。

**10）尾帧续接：物理一致性更好，但会继承偏差**——好处是空间/光位/道具位置被锁；坏处是**上一镜的错误（手型、道具位置）会延续**。**→ 要求第一镜必须干净，否则错误累积。**

**11）平台没有自动物理一致性检查** → 需我方成片后人工或程序比对。

## R7 · 表演与调度（11 问）

**1）微表情支持＝弱到中等**：**大表情（笑/皱眉/张口）可表现；细微表情（眉内端压、鼻翼张）命中率低，运动中易丢**。
→ **★ 微表情只作辅助，关键情绪靠"大动作 + 姿态 + 视线"承载。**

**2）"部位+动作"写法部分读得懂，但**：**一镜最多写 1–2 个部位**（多了互相打架）；用可见描述（"眉头向中间收拢，下唇被牙齿轻压"）；**命中率非 100%，别把叙事全押在微表情上**。

**3）★★ "消退先快后慢、不同部位不同时回落"不能可靠执行**——**模型基本做匀速或突变，不支持精细时间曲线**。
→ **改写：用两个镜头表现**（一镜表情明显，下一镜表情已回落），**靠剪辑节奏模拟**，而不是在一镜内写曲线。

**4）生理活性写 1–2 种即可**（"轻微呼吸起伏""偶尔眨眼"）；**写多了（眨眼+呼吸+瞳孔+吞咽）→ 顾此失彼、僵硬或丢失**。
→ **★ "瞳孔变化基本无效，删"。**

**5）"静息微动"写进镜头描述里的"动作部分"**（"她静止坐着，肩部随呼吸轻微起伏，手指在膝上微微移动"），不放器材段。

**6）走位要逐镜写清起点与终点**（无对白片里走位就是叙事）；**跨镜走位要接得上：上一镜终点＝下一镜起点**；关键走位用首帧图锁。

**7）视线写"看什么＋落点"**："视线落在桌面钥匙上，头部略低，眼睛向下约 30°"；**一镜只写一个主视线方向**。

**8）零群演不一定空**——单场景单人物是 AI 友好型；若显空，**加"环境暗示"（窗外声音、门外光、桌上其他物件），而不是加人**。**加群演会大幅提高一致性成本，不建议。**

**9）★ 负向约束不如正约束可靠**（"手不做手势"有一定效果）→ **更稳是写正约束**："双手自然放在膝上，静止不动"；**正负一起写效果最好**。

**10）表演与运镜冲突时：优先保表演**（表演是叙事核心，运镜是辅助且 AI 运镜易崩）→ **机位锁死，让表演在固定画框内完成**；必须运镜时用极慢单向、幅度小到不干扰表演。

**11）★ 平台不识别 0–5 表演量表**（写了无效）→ 改用**可见强度词**（轻微/明显/剧烈）或**身体结果描述**（"肩部大幅起伏""手指用力到指节发白"）；**量表只留我方文件**。

**⚠️ 纠正本库/本片**：① 本库"表情时间结构（消退先快后慢）"**要求一镜内执行 → 平台做不到，要改为"跨两镜用剪辑模拟"**；② 本库"生理活性 ≥2 种含瞳孔"**→ 删瞳孔**；③ **微表情一镜不超 1–2 个部位**（我 S4 写了三步，要削）；④ **负向约束一律配正约束**。

## R8 · 声音设计（11 问）

**1）★ 关闭平台声音、声音回本地做 → "推荐，且是本片最优解"**（无对白片的声音是"环境床+静默"的精细活，本地可控性远高）。
→ **但注意：生成时别把 `sound` 关成 `off`**（那会**永久丢音轨**）；可**生成后在合成/交付时不用它的音轨或本地替换**。**若确定完全不要平台音，可 `sound=off` 省资源。**

**2）开着声音生成 → 模型会自行加环境音、拟音甚至人声；且每镜各生成一次，环境音不连续（切点处断）。**

**3）无对白片可能被自动加人声/喘息/叹气/旁白**——模型倾向"填满"音轨。**→ 这是关闭平台声音的强理由。**

**4）★ "钥匙不响"（负向声音约束）不能可靠理解，且可能反向触发（越写越响）** → **本地做声音时靠人工混音实现，不进 prompt**；若必须写，用正约束："**画面上手未触碰钥匙，无金属碰撞声**"。

**5）★ `audioEffects` 字段**：平台 Agent 说"**平台没有 audioEffects 这个字段**"，音效只能① `generate_audio_v3(type=sound_effect)` 单独生成音效节点，或②在 `edit_video_v4` / `composite_video` 的 `audio_list` 里叠加。
**⚠️ 与本库记录冲突，需标注**：**我用 MCP 的 `create_script_v2` 建表时，schema 里确实有 `audioEffects` 属性**——**两者可能都对**：**分镜行有这个字段（可存），但它不驱动音频生成**。**→ 结论：`audioEffects` 当"我方备忘"可以，别指望它让平台出声。**

**6）"同一环境床"会因批次而变**（每次独立采样）→ **生成一次环境床音频节点，全片复用**（`audio_list` 多次引用同一节点，或整段铺底）。

**7）音频生成**：`generate_audio_v3`，`type` 选 **`tts`（人声）/ `music`（音乐/BGM）/ `sound_effect`（音效）**；**`sound_effect` 必须用户明确要求才用，不要自行推断**。成本按次计费、随模型与时长浮动，**无固定公开价**。本片声音本地做 → **此项成本 0**。

**8）静默收尾会被填满** → **末镜生成时 `sound=off`**，或本地做时末镜音轨留空。

**9）混音比例不要写进提示词**（对平台音轨无效）→ 混音在本地或 `audio_list` 的 `audio_volume` 里控制。**唯一有效的 prompt 写法：`need_bgm=false`。**
**★ 更正注（2026-09-28 落库 · A 级）：上句判错——`need_bgm` 不是 prompt 写法，而是节点入参**：`get_model("Wan 3.0")` 的 `originalField` 确有 `needBgm`(bool) 与 `bgm`(bool)，是平台侧真实字段，`generate_video.params` 里填不进去。**把它当"提示词里的一句话"写进 prompt 是无效操作** → 要无配乐请设**节点入参 `needBgm` / `bgm`**；混音比例仍走 `audio_volume`。

**10）音频桥**：`composite_video` 的 `audio_list` 每条音轨可设 `start_time` / `end_time`；**把同一音频节点跨越多个视频片段铺设（提前 start、延后 end）＝声音压过画面切点**。`edit_video_v4` 支持更细的音频编排（BGM/SFX 定位到输出秒、音量淡入淡出）。

**11）平台没有音频一致性检查。**

**⚠️ 纠正本片《钥匙》**：① **末镜必须 `sound=off` 或音轨留空**（防被填满）；② **"钥匙不响"改成正约束写法，或干脆靠本地混音**；③ **环境床要生成一次、全片复用**；④ **混音比例别写进 prompt**。

## R9 · 美术风格与参考（11 问）

**1）★★ 平台"没有风格编号概念"**——风格只能靠① prompt 文字描述 ② 风格锚点图。**直接写导演名有合规与识别风险，且模型响应不稳定。**
→ **转译成可拍特征**："低饱和、硬边光、固定机位、灰绿冷调、无配乐"。
**→ 结论：写特征句 ＋ 引用一张风格锚点图，比写导演名有效且安全。**（**纠正本库"风格编号"在平台侧的用法**）

**2）`style_display_board`（图像模板）产出的那张图 ＝ 你的"风格锚点节点"**；用法：**先出风格板 → 作为 `reference_nodes` 被每镜引用**。

**3）全片风格统一＝两者都要**：引用风格节点（视觉基准）＋ **每镜 prompt 复述风格关键词**。**只靠节点会忽略，只靠文字会漂移——节点＋文字双保险。**

**4）情绪板词要转成可拍描述**（否则是空话）：
- **冷** → "色温 5600K 偏冷，暗部中性灰蓝"
- **克制** → "主体动作幅度小，机位静止，无运镜"
- **空** → "画面留有大量空白区域，主体占比小于 1/3"
- **硬边** → "光比大，阴影边缘清晰，无柔光扩散"
**抽象词只留文件，prompt 里必须落成上述具体句。**

**5）"墙上无字"这类禁忌每镜都写**（禁忌不跨镜传递），写成负向约束："墙面干净无文字、无海报、无标识"；关键镜用首帧图锁。

**6）★ 室内现代物品禁忌清单**（**模型会"默认补上"，必须显式排除**）：**电源插座/开关 · 空调 · LED 灯 · 现代家具 · 塑料收纳盒 · 饮水机 · 显示器 · 手机 · 印刷体标签 · 现代门锁**。

**7）避免年代剧 / 样板间**：**不要写"复古""怀旧""上世纪的"**，改写**具体物件**（"磨白的木桌沿、铁皮文件柜、钨丝台灯、百叶窗"）；**加使用痕迹**（桌面划痕、墙脚起泡、地面踩亮）。
**→ 关键：用"物件清单 ＋ 磨损细节"定义时代，不用年代词。**

**8）★ 平台没有独立负面提示词字段** → 负面约束**写在主 prompt 里**，用"**非…、无…**"句式。
例："写实摄影质感，**非插画、非描边、非平涂、非赛璐璐、非卡通渲染、非 3D 渲染**"。

**9）参考图策略**：**主锚点全用自产**（可控、无版权风险、跨镜一致）；**外部图仅作风格参考，且不直接当首帧**。

**10）平台没有"图片反推提示词"工具**（`analyze_video` 是视频分析）；图片信息可用 `get_canvas_node_details` 读节点参数。**真正的反推需我方自实现。**

**11）★ 先定风格，再出资产**（风格决定色彩/光/质感，资产必须服从风格；先出资产会浪费）→ **顺序：风格板 → 角色/场景/道具资产 → 分镜首帧。**

**⚠️ 纠正本库/本片**：① **"待定的风格编号"要转成"可拍特征句 + 一张风格锚点图"**（平台不吃编号）；② **情绪板必须落成具体句**；③ **负面提示词没有独立字段 → 全部写进主 prompt**；④ **现代物品清单要显式排除**。

## R10 · 生成参数与交付（12 问 + 总问）

**1）三段式**：**480p 跑构图/动作样板（最省）→ 720p 定稿档（多数交付足够）→ 1080p/4k 仅最终成片或大屏**。视频模型档位 `480p/720p/1080p/4k`；图像另有 1K/2K。

**2）★★ 模型最短时长限制（决定 3–4 秒镜能不能用）**：
| 模型 | 时长范围 |
|---|---|
| **Seedance 2.0 / 2.0 Fast** | **4–15 秒** |
| Seedance 2.5 | 4–30 秒 |
| **Seedance 1.5 Pro** | **枚举 `[5,10]` 二档（3/4 秒提交不了）；`modeType` 仅 `singleImage2video`——不支持首尾帧/续写** |
| **Kling O3 / 3.0 / Minimax H3** | **5–15 秒** |
| **Wan 3.0 / Prime** | **2–30 秒** |

**→ 建议选支持 4 秒档的模型（如 Seedance 2.0）；用 Kling 则 3–4 秒镜会被强制到 5 秒。**

**3）平台不暴露帧率**（由模型/合成决定，通常 24 或 30fps），**API 侧无法指定**；改帧率需外部工具、会重编码（画质损失）。**建议接受默认，不折腾帧率。**

**4）★★ 平台不暴露 `seed`** → 复现靠：**① 保存该镜完整参数快照（prompt + 引用节点 + 模型 + 时长 + 分辨率）② 用首帧图锁定（比 seed 更可靠）③ `continue_from` 尾帧续接保持连续**。**→ 快照落地手段（2026-09-28 补 · 2026-09-29 改写工具名）**：**我方 MCP 侧用 `read_node`** 读该节点的 `agent_task_params` 即可取回完整入参快照（`get_node_details` 是它侧同名写法，勿照抄）（参见本轮 R10.8「节点 `agent_task_params` 可读、无自动导出」）。

**5）没有独立负面字段** → 负面约束与主 prompt 同字段。

**6）"一次最多 5 个并行"＝"单次批量上限"**（图片/视频节点一次最多 5 个工具同时执行），**不是画布总数限制**（画布可有远超 5 个节点）。

**7）`composite_video` 会重编码**（拼接必然重编码）→ 避免画质损失：**源视频用最高可用分辨率生成** · **合成时不指定 `resolution`/`aspect_ratio`**（省略＝跟随源，避免重缩放）· **不在合成阶段做多余处理** · **要调色就用 `edit_video_v4` 一次到位，避免多次转码**。

**8）交付六件，平台能自动产出的**：**成片 ✅（`composite_video`/`edit_video_v4`）· 资产 ✅（`save_asset`）**；参数快照 ⚠️ 部分（节点 `agent_task_params` 可读、无自动导出）；**分镜表 ❌（需我方 `write_file_v2` 维护）· 证据清单/台账 ❌（需我方维护）**。

**9）导出**：**分辨率可指定**（`generate_video_v3` 的 `resolution`；`composite_video` 省略则跟随源）；**码率不可指定**；**帧率不可指定**。

**10）"生成成功但不满意"不退**——只有**生成失败**的节点返还积分。**内容不满意属"成功生成"，不退。**

**11）★ 平台没有"批量验收"机制** → 需逐镜查看（`get_canvas_node_details` 逐个读或人工看画布）。

**12）无公开固定价**（随模型/分辨率/时长浮动）→ 粗估＝10 镜×每镜成本 ＋ 合成成本 ＋（可选）音频。**省法：样板 480p · 资产中等质量 · 声音本地做。**

## §末 · ★★ 它点出"我最可能做错的三件事"（**全套最重要的一段**）

**第一件：把"文学层"和"可拍层"混着写进 prompt。**
命题（"有些等待的终点，是不拿"）· 人物弧光 · 情绪基调 · **表演量表（0–5）** · **"全片唯一一次"这类全局/抽象约束**——**平台都不理解**。写进去只会稀释有效信息、让模型自由发挥。
→ **必须把它们全部留在剧本文件，只把可拍内容、镜位、光位、物件状态、时长送进分镜行和 prompt。**

**第二件：指望"文字约束"锁住跨镜一致性。**
道具守恒（钥匙不消失）· 光位方向 · 色彩三色板 · 禁忌元素（墙上无字）· 道具磨损——**这些不会自动跨镜传递，纯文字命中率低**。
→ **真正该依赖的是"锚点图 + 首帧图 + 尾帧续接"这套视觉锁，文字只是复述强化。**
→ **"若你只写文字不建锁，最后会得到 10 个『各自成立但拼不成一部片』的镜头。"**
**★ 这一条与本库的实测事故（E108：七环全绿、人物场景全不一致）完全同因——它一句话说中了。**

**第三件：在声音和参数上按"平台会帮我做好"来规划。**
平台**会自动加环境音、加人声、填满静默**，且**跨镜音频不连续**；平台**没有 seed、没有负面字段、没有帧率/码率控制、没有批量验收、没有一致性检查**。
→ 既然决定"声音回本地做"，就必须**在生成阶段主动关掉/忽略平台音轨（末镜尤其）**，并接受**"复现靠参数快照＋首帧图、验收靠人工"**的现实。
→ **"把平台当『能自动兜底』的伙伴，是这 10 轮里成本最高的一次误判。"**
