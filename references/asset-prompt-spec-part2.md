### 3.3 ★ 资产板的背景与布光：**18% 中性灰 + 完全平光**（2026-09-17 地毯式搜索后补）

**缺省值**：**所有"起参考作用的板子"**（脸锁 / 角色全身 / 三视图 / 服装板 / 道具板）都用
**18% 中性灰无缝背景 + 完全平光、无投影**；**纯白是例外**，只在用户明确要一张"可交付的白底成图"时才换。

**★ 为什么是灰不是白（机制，很硬）**：
纯白（和纯黑）会造出**最大的"主体—背景"对比**；**视频模型最容易在高对比边缘放大错误**——
**光晕（halo）、边缘"呼吸"、轮廓不稳**都是在那里被烤进去的，而且**会被下游每一次生成继承**。
中灰把对比降下来 → **边缘提取更干净、继承下来的塑料感与对比更少**。
> 这与"有雾的场景板读起来更有纵深"是**同一个原理**：**降低层与层之间的对比**。灰底＝"平板版本的那一剂药"。

**★ 平光的三要素（缺一个，板子就会带回"造型光"）**：
1. **背景平**——一个统一的 18% 灰值，**四角一致**，无接缝线、无渐变、无热点、无暗角、无明暗过渡；
2. **无影照明**——**相机位一个巨大的正面柔光源**，左右上下等量补光；**无主副光比、无造型光、无轮廓光、无发丝光、无高光点**；
3. **零投影**——背景上**不落任何影子**，脚下与衣摆下**无接触阴影、无环境光遮蔽**。

**★ 为什么必须"平"（比灰更重要）**：
**板子是"参考"，不是"成片"。** 任何被烤进参考的阴影（颧骨三角、鼻影、脚下接触阴影、背景明暗）
**会被下游每一次生成继承并放大**，而且**会和这一场真正想要的布光打架**。
→ 所以角色板**携带零布光信息**：**不写主光方向、不写阴影面、不写投影、不写背景衰减**；
**形体只用"骨骼结构 + 发丝 + 衣褶"描述**，布光交给后面的镜头提示词。

**★ 背景中性、主体不中性**：灰底**不要暖偏**；同时**皮肤必须是真实自然肤色、服装是真实自然色**
（明写"不被背景拉冷 / 洗白 / 变淡"）——**背景中性是为了让主体"真"**。

> **证据强度**：**单源**（273 份语料里 5 份，`2%`）。**走「机制可独立论证」门槛**——
> 上面的边缘放大与阴影继承都是**可观测的因果**，不依赖来源权威。**按 L6 记「拟订」**。
> **来源**：`banana-pro-director-3-0`（18% GRAY SEAMLESS + FLAT GRADE，锁定默认）。

### 3.4 ★ 三视图的**像素预算**与**跨面板一致性**（2026-09-17 地毯式搜索后补）

> **★ 本节只管"设计板"**（给人看的设定稿）。**投喂用的参考图另有规格**：见 `asset-standard.md` §3——**设计板的任何一格都不承担下游身份**。

**★ 三格胜过六格（可量化的判据，只对设计板成立）**：一张图的**像素预算是固定的**。
六格把预算分成六份，**脸落进太小的格子，装不下真实身份细节**；三格让**每格分辨率大约翻倍**。
→ **设计板默认三格**；六格只在用户点名时才做，且**要先说清分辨率代价**。
**★ 它不推出"所以三格能当身份锚点"**——身份锚点永远是那张独立的定妆正面图。

**★ 如果这张板同时要"看结构"**：用**正 / 侧 / 背，各格正常带头**——平台的 turnaround 模板就是这个形状，脸留在格子里反而更容易判断"是不是同一个人"。

**★ "去头正面格"是设计板的一种变体**（只在"想单看服装与轮廓、不想被人脸干扰"时用）：
要**保留完整头顶留白**——头是**从身体上被移除**，**不是被画框裁掉**。
**去头按领口分两型**（`banana-pro-director-3-0` 的 HEADLESS CUT）：
- **A 幽灵人台**（有真实领口：T 恤 / 圆领 / 高领 / 帽衫 / 衬衫）→ **无头、无颈、无发**；
  领口保持立体形状，开口是**看向衣物内部的空黑洞**，能看见内侧背面的布料；
- **B 干净颈切**（抹胸 / 吊带 / 深 V / 大露背等没有真实领口）→ **颈从肩膀升起一小段，
  在喉部终止于干净、平坦、锐利的水平边**（像无头人台）。
- **两型共同的抑制栈**：不模糊、不淡出、不溶解、无发丝、无烟、无重影、身体不透明、无残端、
  切口无解剖细节、无血。**头发跟头一起走**。
- **不进参考**：去头格没有身份信息，放进 `reference_nodes` 只会让模型少一张脸可用。

**★ 跨面板/跨视图一致性条款（强制，否则背面会漂）**：
1. **肤色一致性**：明写"**皮肤在脸、背、手臂、手上，明度与色相一致**"——
   **背面格会自己漂得更深/更黑**，没有这句就会前后不是同一个人；
2. **背景与布光贯穿所有格**（同一灰值、同一平光、每格都无投影）；
3. **每格显式标位置**（左 / 中 / 右），模型才会正确组网格；
4. **身份与服装段落写一次、适用于所有格**，**每格只描述"不同的"东西**（角度 / 取景 / 有无头）。

> **证据强度**：**单源**（像素预算 `7/273`、`3%`；肤色一致 `3/273`、`1%`）。
> **走「机制可独立论证」门槛**：像素预算＝**固定的画布像素除以格数**（算术，不是观点）；
> 背面漂深是**观察类**证据（`L6` 四证据之「观察」）。**按 L6 均记「拟订」**。

## §11·补 ★ 拿到参考图先"读"成字段，再动笔（2026-09-17 外部学习后补）

**为什么要先读**：参考图直接塞进提示词，模型只能"模仿"；**读成字段**之后，你才能**逐字段决定要不要它**。
> **来源**：Higgsfield 官方开源 skill `higgsfield-youtube-thumbnail` 的 concept gate（读参考图 → 抽 11 个字段 → **用户指令逐字段覆盖**）。

**★ 读图清单（照着填，缺的写"无"）**：
`brief`（它一句话在说什么）· `subject_pose_action`（**泛化的**主体姿态与动作，**不带身份**）· `elements`（关键元素）· `location` · `composition` · `background` · `split`（是否分屏）· `split_count` · `person_count` · `emotion` · `emotion_detail`。

**★ 三条纪律**：
1. **参考图供"艺术方向"，绝不许供"某个具体身份"**——读完的字段里，**人物一律写成泛化描述**（"一个侧身站着的成年男性"），**不许把它的脸当成你要的人物**。
2. **用户指令逐字段覆盖参考**——用户说了的字段，**以用户为准**；参考只填用户没说的那些。
3. **读出来的字段要落到块上**（对齐 `block-spec.md` §三·补 归属表）：`composition`/`background` → 【构图】· `emotion*` → 【人物与环境】+【时间线】· `subject_pose_action` → 泛化后进【人物与环境】的**姿态**行（**动作过程仍归【时间线】**）。

**⚠️ 一条刻意"不照抄"的差异（如实登记）**：该 skill 规定**风格参考图只做视觉分析、绝不许传入**（它的平台下传入会被抄走身份与构图）。
**本库不采用这条"一律不传"**——我们的主力平台（即梦 / 可灵 / Updream）**支持"风格参考图"作为独立输入槽**，一律不传等于自废一个可用的机制。
**我们采用它的判据而不是它的禁令**：**风格参考照 §11 表走——借色板 / 颗粒 / 渲染方式，明文写"不许它供主体与构图"**；**做不到这句声明的，就不许把风格图传进去**。
