# 后期与成片（把一堆 AI 片段变成能看的东西）

> **何时读**：素材生成完之后——选片、修复、超分、调色、合成、剪辑、字幕、交付。**读完回哪**：回到 `studio-workflow.md` 第三步收尾。
>
> 一句话：**AI 短片的 60–70% 工作量在后期**。只教到"图生视频"为止，等于只做完了三分之一。

---

## 一、选片（4–10 条候选怎么挑）

**三桶分类法**：`hero`（运动最好、无可见瑕疵）/ `backup`（可修可用）/ `reject`（手融化、物理崩、logo 变形）。
**全分辨率过一遍**并标记瑕疵帧区间，形成修复清单——10 分钟筛选省下数小时无效打磨。

量化参考：拉普拉斯方差 200–2000（够清晰但不过锐）· 美学分 >4.5 · 光流幅度 1–20（<1 过静、>20 过动）。**⚠️ 这些是经验值**：强依赖分辨率、算子参数与评分器（拉普拉斯方差在 720p 与 4K 下可差数倍；美学分未标评分器名）——**只作同批素材内部排序用，不作跨项目绝对标准**（我方经验值，未做大样本验证）。
入选标准：**光线色调最接近基准片 + 动作完整 + 运镜平稳**。
生成量按 **2–3 倍**准备（可用率约 30–40%）。

### 1.1 ★ 作业方式升级：按 beat 采矿 + 跨生成拼接

**不要按"这条好不好"选，要按"这条里哪几秒的哪个 beat 对了"选。**

- 一条长生成里通常**只有 1–3 秒可用**；
- **没有任何一次生成能把整场戏一次拍干净**——正解是像剪 dailies 一样，**从每个生成里挖它那一个好镜头**，多条混合才能剪出一场戏。

**配套管理**：素材按 `shot 编号 + beat 编号` **双索引**命名，不要按"第 3 次生成"命名（那样一个月后就找不到哪个 beat 在哪）。

> 这把"真实可用率 30–40%"从**损失**改写成了**工作流设计**——不是浪费了 60%，而是每一卷里各取所需。
> **预期管理话术也跟着改**：交付时说的不是"要拍 30 条只挑 10 条"，而是"**每条里挖几秒，拼成片子**"。

### 1.2 单条结果的深度验收 → `review-passes.md`

上面这一节管**多条候选中怎么挑**。**单条生成结果怎么结构化过一遍**（六个 pass + 证据式笔记）是另一件事，见 `review-passes.md`。两者是不同的轴，都要走。

## 二、修复与超分

- **超分**：Topaz Video AI（Proteus 通用 / Iris 人脸，版本为 2026-09 时点）速度快、时域稳定性一般；
  **ComfyUI + SeedVR2** 时域更稳但更慢；Resolve Super Scale 可在调色页一趟完成。
  **720p → 1080p 用 2x，不要一步 4x**（幻觉过多），用 2x + 2x 分步。
  铁律：**源必须高码率**，重度压缩源上超分＝放大瑕疵。
- **去闪烁**：亮度闪 → 时序降噪（阈值 10–15，软件内部刻度，跨软件不可迁移）；结构性"沸腾" → 光流对齐后平均，或 3–5 帧时序中值。
  **⚠️ 先分两类，别把真颗粒一起抹掉**（→ `carrier-artifacts.md` §三·★）：**细纹理沸腾**（纹理位置漂移、结构变形）→ 按上面处理；**胶片颗粒的帧间重排**（原地抖、不漂移、粒径不变）**属于介质真实，不是抖动**——**抹掉它得到"时域干净的颗粒"，那是最强的 AI 味之一**。判据一句话：**"漂移变形"修，"原地抖"留**。
- **结构崩坏无法后修** → 回生成：降运动强度、固定 seed、缩短时长。
- **脸部崩坏**：换脸回填 / ComfyUI FaceDetailer 局部重绘；最省事的替代是**裁切或景别后移让崩坏出画**。

## 三、补帧与变速

- **补帧是双刃剑**：会顺滑抖动与降噪，但**跨剪辑点会拖影**——**只在连续镜头内补，先剪掉切点**。
  RIFE 通用最好；大运动/快摇用 FILM；DAIN 不要用。
- **慢动作**：**优先在生成时就写"超慢动作 + 特写"**；后期补帧做慢动作＝4x 补帧 + 0.25 倍速。
- **25 → 24fps**：直接丢帧每秒错一帧，走路与摇镜必跳。
  正解是**变速 96%（25→24）/ 104%（24→25）**并同步修音高。

## 四、色彩统一（多片段最容易翻车的地方）

**先建色彩管理，再调色**：Project Settings 选 **DaVinci YRGB Color Managed**（Input 按素材标、Timeline 用 DaVinci Wide Gamut、Output Rec.709 Gamma 2.4）；高端流程用 ACES。

**拉齐顺序**：定一条**基准片** → 用 **Shot Match / Color Match** 自动对齐其余 → 示波器人工微调 → 最后才加创意 LUT。
⚠️ 不同模型的默认色调不同（有的偏暖饱和、有的偏冷高对比），**混剪必跳**。
⚠️ **超分前先做基础色彩归一**（输入色彩空间打标 / 曝光归一；**不是**镜头匹配——那在 §十 第 7 步）——否则放大器会把色偏逐帧强化。

### 4.1 两处"定向修补"通道（比整镜重抽便宜得多）

这两件事以前我们只能**重写提示词重生成**整镜，其实有定向工具：

| 病 | 工具 | 怎么做 | 为什么值得 |
|---|---|---|---|
| **人景光影不接**（人像贴上去的、光的方向与场景不一致） | **Relight / 重打光**（Higgsfield `AI Image Relighter`；达芬奇侧可用 HSL + Power Window 手工压；LibTV 画布内无等价定向补光——回提示词层或导出后桌面工具处理） | 手动指定**光的方向、色温、阴影**，只改光不改构图 | 官方描述：`Take full control of your image's atmosphere and lighting. Manually adjust light direction, color temperature, and shadows` —— 这是"人景光影不接"的**定向补救**，我们此前没有这条通道 |
| **多段色温 / 对比不一致** | **AI Color Grading**（Higgsfield，实时 WebGL 预览）或达芬奇 Shot Match | 选一条基准片段 → 逐段对齐 | 把"每段看起来像不同的片"一次性拉齐，不必重生成 |

**纪律**：**先判责任层**——如果光影不接的原因是"提示词里光源没有动机 / 人物光影块没写"，那该回提示词层重生成，而不是靠 Relight 硬压。**Relight 是止损，不是修复。**

## 五、合成与遮挡

- **AI 自动抠像**：Resolve **Magic Mask 2**（一次点击跟踪人与物，穿遮挡可用，约 90% 场景够用；2026-09 时点）。
- **用法**：前景遮挡（文字 / 物体穿插进场景）、换背景、局部调色隔离。
- **多余物体 / 消失物体**：Object Removal、内容感知填充；前景遮挡补救＝冻结最干净的一帧合成到被跟踪主体之后。

## 六、剪辑节奏（**已迁出 → 见 `editing-rhythm.md`**）

**剪辑节奏的权威源现为 `editing-rhythm.md`**——本册不再复述。那边有：
**ASL 与节奏密度（两个可量的词）· 情绪→公式→ASL 照填表 · 节奏诊断四问 · J-cut / L-cut · 节拍对位 · 三种衔接 · 180 度线与 30 度原则 · 六种失败模式**。

**★ 一句话记住**：**节奏在本库过去是个形容词，现在是个可量的东西**——**先算 ASL，再看节奏密度曲线上有没有起伏**。

## 七、字幕与包装

- **中文规范**（NRTA GY/T 357-2024；**编号与数值待核标准原文**）：字体**黑体为主，楷体限旁白 / 书信等特殊语体**（避免宋体细横画）；对白字幕**白色**；
  高度＝有效画面垂直高度的 **5%（±1%）**；两行以内、居中、底部安全框内。
- **可读性**：每行 **≤15 汉字**，单条显示 2–5 秒，最小间隔 2 帧（24fps 口径，防粘连下限），阅速上限约 9 字/秒。
- **片头片尾**：4K 片名字幕 ≥80 像素；字幕区不超出画面 80% 对称区域；片尾滚动不闪烁。
- **画面内文字一律后期覆盖**（AI 渲染文字不可靠）。

### 7.1 精度与码率：画面密集时才吃得到 10-bit（2026-09-11 补）

**问题**：写"10-bit 色深 / HDR"看起来专业，但**分辨率与码率不够时，10-bit 的好处完全吃不到**——渐变仍然断层、暗部仍然糊。

**判据**：**画面密集**（多人同框 / 细密纹理 / 大面积渐变天空 / 暗部有细节）才需要往上堆；**简单画面（单人、纯色背景、空镜）用不到**。

| 场景 | 分辨率 | 码率倾向 |
|---|---|---|
| 单人对话 / 空镜 / 纯色底 | **1080p 够** | 标准即可 |
| 多人同框 / 细纹理 / 复杂环境 | **4K** | **高码率**（不然 4K 只是更大的糊） |
| 大面积渐变 / 暗部有戏 | **4K + 高码率** | 才吃得到 10-bit 的断层优势 |

**三条纪律**：

1. **10-bit 是"锦上添花"，前置条件是高码率**——低码率下 8-bit 与 10-bit 观感几乎无差。
2. **不要在提示词里写"10-bit / HDR / 4K"**——这是**后期与交付规格**，写进提示词只会污染画面描述（属于 `quality-layer.md` 的"空洞词"）。
3. **超分前先保证源码率**（第二节铁律的延伸）：压缩源上超分＝放大瑕疵，4K 也一样。

## 八、交付规格

- **响度**（**口径不同，勿混比**；全表见 `mix-loudness.md` §1）：
  - 流媒体上传参考：**整合响度约 −14 LUFS**（YouTube 等；Spotify ≈ −14 · Apple Music ≈ −16 · Amazon Music ≈ −14），真峰值 **< −1.5 ~ −1 dBTP**；
  - 广播/欧洲交付：EBU R128 整合 **−23 LUFS**；北美电视 ATSC A/85 **−24 LKFS**；
  - **Netflix：对白锚定（dialog-gated）−27 LKFS——非整合响度，勿与 −14 直接比较**；
  - 播客约 −16 LUFS（立体声；按平台）。
- **平台参数**（2026-09 时点经验值，上传前核平台最新规范）：
  - 抖音/快手竖屏：1080×1920、30fps（最稳下限；高帧率亦可）、8–16 Mbps、H.264、AAC 128–192k
  - B站横屏：1080p 10–20 Mbps 或 4K 35–50 Mbps、H.264/H.265、AAC 320k
  - YouTube/Vimeo：4K 40–60 Mbps（VBR 2-pass）、保持源帧率、AAC 48kHz
- 通用：48kHz/24bit 音频；**先出高码率 Master，再按平台分别导出**。
- **AI 生成标识**：按发布平台勾选 AI 生成声明（片尾标识**不能替代**平台声明，漏标有限流 / 下架风险）；条件允许时写入 C2PA 元数据；国内按《人工智能生成合成内容标识办法》加显式 / 隐式标识（法规细则以发布时最新要求为准）。

## 九、常见后期错误（8 条）

1. **逐段独立调色** → 拼接处跳变；应先定基准片再统一匹配。
2. **过度锐化** → 边缘光圈、噪点变脏、"AI 感"更重（锐化控制在 20–50%，人脸 10–15%；软件内部刻度，跨软件不可迁移）。
3. **补帧跨剪辑点** → 撕裂 / 拖影；只在连续镜头内补帧。
4. **多轮增强叠加**（降噪→锐化→超分→再降噪）→ 幻觉倍增；宁可一趟做好。
5. **用低码率源超分** → 放大压缩瑕疵；必须高码率中间码。
6. **音频电平不统一 / 响度超标** → 平台二次限幅失真。
7. **25/24fps 混用不处理** → 每秒跳一帧。
8. **字幕超长 / 盖主体 / 无安全区** → 手机端被裁。

## 十、后期工作流清单（按顺序）

```
1  归类：按场/镜编号整理全部生成素材
2  选片：全分辨率过一遍，三桶分类 + 标注瑕疵帧区间
3  修剪首尾：每条裁掉前 0.5–1s / 后 0.5–1s
4  修复：时域降噪、局部重绘、换脸回填、Object Removal；结构崩坏的重生成
5  超分：高码率源 → 2x → 出 ProRes 中间码
6  粗剪：先对结构、后对细节（选一套节奏公式）
7  调色统一：建色彩管理 → 定基准片 → Shot Match → 创意 LUT
8  合成：Magic Mask 抠像 / 遮挡 / 换背景 / 补前景
9  补帧变速：只在连续镜头内补；25/24 用 96%/104% 变速并修音高
10 音频：对白 → EQ 降噪 → 音乐/SFX 混音 → 归一 −14 LUFS
11 字幕包装：按 5% 高度、白色、≤15 字/行、安全框
12 终审：全程播两遍记问题点；手机小屏 + 耳机双检
13 交付：出高码率 Master，再按平台参数分别导出；加 AI 生成标识
```

**步骤属性**（先排人力）：1/3/5/9/13 可脚本化 · 7/10/11 半自动 · **2/4/6/8/12 必须人工**——脚本给不了 beat 级取舍与创作判断。
