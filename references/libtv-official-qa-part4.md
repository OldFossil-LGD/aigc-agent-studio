## R12 · 字段级硬规则与参数字典

### 12.1 ★★ 硬规则总表（**它侧真实存在的 16 条**）

| 2 | **引用必插桩**：字段里传的每个 node_key **必须在 prompt 中以 `{{node_key}}` 出现，并写明该引用的用途** | 双向约束 |

### 12.2 它侧的**真实字段名**（与我 MCP 侧**不同**）
- `create_image_node`：**`title`**(必填) · **`prompt`**(必填) · **`tag`**(必填) · **`aspect_ratio`**(条件必填，token 如 `16:9`，**不传像素**) · `reference_nodes` · `ai_model`(默认 **Lib Image 2.5 Pro**) · `prompt_template` · **`quality_spec`**(**自然语言**，如"resolution 2K, medium quality")
- **★★ 它侧没有 `name`（叫 `title`）、没有 `params.settings.ratio/quality` 这种嵌套路径** —— **`params.settings.*` 是 MCP 侧的封装**；**我方 `quality` 的 `low/medium/high/xhigh/max` 是 MCP 侧枚举**，它侧是 `quality_spec` 自然语言。
- **参数按桶归类**（它侧是**摊平的一级字段**，无统一 `params` 桶）：模型桶 `ai_model` · 画幅桶 `aspect_ratio` · 画质桶（图）`quality_spec` /（视频）`resolution` · 时长桶 `duration_sec` · 引用桶 `reference_nodes` + `start_frame_image_node` + `end_frame_image_node` · **声音桶 `sound`(on/off) + `need_bgm`(布尔)** · 动作桶 `video_action_type`(仅 extend) · 内容桶 `prompt`/`title`/`tag` · 音频专属 `type`(tts/music/sound_effect) + `settings_spec`。

### 12.3 `create_video_node` 参数表（它侧）
`title`(必填) · `prompt`(必填；**台词逐字 `{}`、引用 `{{}}`**) · **`reference_nodes`(工具签名要求必填数组**；续写时必含被续视频) · `aspect_ratio`(**16:9/9:16/1:1/4:3/3:4/21:9/adaptive**；extend 时忽略) · **`duration_sec`(整数秒，可传 `-1` 让后端自动选)** · `resolution`(480p/720p/1080p/4k；**Kling 上 720p↓=Standard、1080p=High、4k=4K**) · `ai_model` · **`sound`(on 默认/off)** · **`need_bgm`(布尔，默认 false)** · `start_frame_image_node` · `end_frame_image_node` · `video_action_type`(仅 extend) · `tag`(自由)
**★ 精确化**：**`need_bgm` 是"它（平台编排层）"的一级参数**；而 **MCP/模型层（`get_model(Wan 3.0)`）里没有它，只有 `enableSound`** → **两套字段不同**（不是矛盾）。

### 12.4 时长区间表（它侧确证）
| 模型 | 区间 |
|---|---|
| Seedance 2.5 | **4–30** |
| **Wan 3.0 / Wan 3.0 Prime** | **2–30** |
| Seedance 2.0 / 2.0 Fast（默认） | **4–15** |
| Kling O3 / Kling 3.0 / Minimax H3 | **5–15** |

**★ 时长估算规则**：**台词自然口播时长 ＋ 无台词画面节拍**（建立/转场/动作），**不要只按画面估**；**不能为了凑而压到模型下限以下**。

### 12.5 `reference_nodes` 上限 / `{{}}` 校验 / tag 语义
- **上限**：**它侧工具契约没写数字**；经验 **2–5 个**（主角+配角+主场景+关键道具+可选风格图）；**太多会稀释主体一致性 + 增加级联耦合**。
  **★ 探法：用 `validate_generation_plan` 放 6/8/10 各试一次，取首个被拒值。**
- **`{{}}` 校验**：**会做一致性约束（生成前硬性要求）**；**反向（prompt 写了 `{{x}}` 但字段没传 x）→ 占位不被解析＝引用失效**；错误码它不能确证，**最可能落 `NODE_VALIDATION_FAILED`**。
- **`tag` 不决定"能否被引用"**（那取决于节点类型与是否生效）；**`keyframe` 可作参考/首帧**；但**把 `keyframe` 当实体参考时，模型可能强绑定其构图与光影——这是特性不是 bug**。

### 12.6 `node_key` 前缀
`i-` 图片 · `v-` 视频 · `a-` 音频 · **`n-`（Director Console 节点）** · **`r-`（revision，不是 node_key，别混用）** · **`b-` 它没见过、不背书**（"可能是 MCP 侧自定义"）。
**→ 实测补充**：**我这边确实有 `b-`（`script-v2` 节点）** → **`b-` 是 MCP 侧特有前缀**。

### 12.7 分镜表字段全集（它侧是 `write_file_v2` 的工作资产，**无平台强类型**）
- **事实/内容层**：镜号 · 画面/情节 · 动作 · 场景 · 出场角色 · **台词（逐字）** · 旁白 · 时长估计 · 机位/景别 · 音效/BGM 需求
- **关联层**：引用锚点 `node_key` 列表 · **续镜锚点（上一镜视频 node_key）** · 首帧/尾帧 `node_key`
- **★ 状态层（建议自建）**：`index` · **`status`（`planned`/`created`/`effective`/`discarded`）** · `node_key`（本镜生成节点） · `version` · `notes`
- **谁写**：内容/事实字段＝创作稿；**`node_key`/`status`/`version` 这类系统字段由推进方回填**（创建→回填 key；运行→改 status；失败→标废弃+换新 key）。**平台不自动维护这张表。**

### 12.8 `task_create_v2` 字段
`subject`(必填，交付物短名) · `id`(可选，`[A-Za-z0-9_-]`) · `status`(仅接受 `planned`) · `task_content`(轻量备注：**工作文件路径 + 最终输出 node_key**)
**★ 不要把锚点集/分镜表正文塞进 `task_content`**（那些走 `write_file_v2`，这里只存路径指针）。

### 12.9 字段规则文档在哪
**它侧没有可导出的"字段规则文档"**。权威优先级：**① MCP `tools/list` inputSchema ② `validate_generation_plan`（跨字段硬规则的运行时权威）③ 它侧工具契约 + 编排 spec（不对外）④ 平台开发者文档 API Reference**。

## R13 · 错误码与异常处理（**它明说这些码不在它函数表内，以下为可靠推断**）

### 13.1 错误码总表（我踩过的 10 个 + 它补的高概率 13 个）
**高概率会遇**：`MODEL_NOT_FOUND`（模型 id 错/下线 → `search_models` 取有效 id）· `MODEL_NOT_SUPPORTED`（模型不支持该操作/参数 → 换支持该能力（首尾帧/extend/4k）的模型）· **`DURATION_OUT_OF_RANGE`** · **`REFERENCE_NOT_READY`**（引用节点未生效 → 等引用方先成功）· **`UNRESOLVED_PLACEHOLDER`**（prompt 有 `{{x}}` 但没传 → 补引用或删占位）· **`RATE_LIMITED / 429`** · `QUOTA_INSUFFICIENT` · **`CONTENT_POLICY_VIOLATION`** · `UPLOAD_TICKET_EXPIRED` · `UPLOAD_INCOMPLETE` · `TIMELINE_INVALID` · **`EXPORT_NOT_READY`** · **`CONCURRENCY_CONFLICT`**（乐观锁/版本冲突 → 重读最新版本再改）· `PERMISSION_DENIED` · `INTERNAL_ERROR`。

### 13.2 ★ `NODE_VALIDATION_FAILED` 的 12 类诱因（很实用）
① `quality` 枚举不符 ② `aspect_ratio` 用了像素或非法 token ③ **`duration` 越界/非整数** ④ `resolution` 与模型不兼容（如某模型无 4k）⑤ model id 错/不支持该节点类型 ⑥ **引用字段与 `{{}}` 不匹配（多传/少传/未插桩）** ⑦ 引用了**未生效或跨项目**节点 ⑧ **`extend` 没带被续视频，或带了 `aspect_ratio`** ⑨ 必填缺失（`title`/`tag`/`prompt`）⑩ `tag` 不在枚举 ⑪ 类型错（字符串传成数字）→ 有时直接掉 `-32602` ⑫ **首尾帧引用的不是 image 节点**。

### 13.3 幂等规则与**幂等性表**
- **规则**：幂等 key 用于"同一逻辑意图的重试去重"；**同 key 同内容重试＝安全**（返回首次结果/同一在途任务，**不会重复扣费**）；**改内容必须换新 key**；**TTL 它无法确证**（稳妥：重试沿用同 key，新意图一律新 key）。

| 操作 | 幂等？ | 备注 |
|---|---|---|
| `read_*` / `search_models` / `get_model` / `browse` / `inspect` / `validate` / `export_readiness` / `task_status` | **幂等** | 只读 |
| `create_node`（只建不跑） | **条件幂等** | 带 key 且同 body 才安全 |
| **`generation_submit`（点火/扣费）** | **靠幂等 key 保证** | **无 key 重试可能重复扣费** |
| `update_node` | **非幂等（但收敛）** | 重复同值结果一致；并发更新需防版本冲突 |
| `delete_node` | 幂等 | 删第二次返回"已删" |
| **`apply_timeline_edit`** | **多数非幂等** | 重复执行可能重复叠加 |
| **`composite` / `export_video`** | **靠幂等 key** | **重复导出可能重复计费/产生多份** |
| `upload_ticket` / `upload_complete` | **票据一次性** | 重发可能过期/冲突 |
| `task_cancel` | 幂等 | |
| **新起 agent run** | **非幂等** | **可能撞 `AGENT_RUN_ACTIVE`** |

### 13.4 关键异常的处置
- **`AGENT_QUESTION_PENDING`**：正路＝回答问题；**旁路＝取消当前 run 后新起一个不带追问的 run**（代价：丢失中间状态、可能撞 `AGENT_RUN_ACTIVE`）。
  **⚠️ 它的判断有一处错**：它说"你 MCP 列表里没有明显的 answer_question 工具"——**因为我给它的清单里漏列了 `answer_agent_questions`（我实际有）** → **★ 我的清单不全，导致它误判**。
- **`AGENT_RUN_ACTIVE` 释放时机**（推断）：run 到**终态**（`succeeded`/`failed`/`cancelled`/`superseded`；**挂起通常仍占位**）；**查法：`task_status` 或 `get_project_snapshot`（看活跃 run/锁标记）**；**工程做法：收到 ACTIVE 不要硬抢，轮询到终态再发起**。
- **超时**：图像**秒级~1 分钟**；**视频常见 1–5 分钟**；超时置 `failed(timeout)`、无产物；**建议保守上限 10 分钟**。
- **`task_status` 枚举（高概率）**：`pending`/`submitted`/`running`/`succeeded`/`failed`/`cancelled`/`timeout`/`blocked`/`superseded`。
- **★ 重试退避**：**指数退避 + 抖动：2s → 4s → 8s → 16s → 30s，最多 4–5 次**；**可重试＝429/5xx/超时/网络**；**不可重试＝参数校验/审核拒绝/积分不足/幂等冲突**；限流优先读 `Retry-After`；**生成类用轮询代替反复提交**。
- **★ 断线重接**：**先查状态**（服务端很可能还在跑）→ 仍活：**不要新起**、重绑原 run；已终态：读结果；挂起：回答；**确认已死但所有权未释放：取消/等终态后再新起**。**核心：绝不盲目重起。**
- **★ 退费判定**：**通常退**＝服务端渲染错误/基础设施错误/无产物失败/5xx；**超时无产物**＝可能按失败；**审核不过＝通常不退**（别默认会退）；**有产物 或 用户取消/改参重抽＝一般不退**；**提交前被拦截（凭证/参数错）＝根本没进入计费**。

## R14 · 审核边界 · 成本 · 批次验收（**Q1–Q9，Q9 被截断**）

### 14.1 审核边界（**它明说这是行业通用红线，不是平台逐字政策**）
- **文本**：未成年人性化/性剥削 · 可执行的违法犯罪指导 · 仇恨/骚扰/极端主义 · **真实人物的诽谤与深度伪造（尤其政治人物/公众人物）** · 侵权（大段照搬受保护歌词/IP）。
- **图像**：上述的视觉化 · 写实色情 · 极端血腥 · **未经授权的真人肖像（名人/政治人物换脸、裸体合成）** · 受版权保护角色/Logo 商用 · **未成年人任何性化零容忍**。
- **视频**：**标准通常最严**（因为"以假乱真"）：真人 deepfake · 政治人物伪造讲话 · 写实暴力血腥 · 色情 · 危险行为模仿。
- **★ 差异要点**：**虚构/风格化（动漫、历史虚构、明显非写实）通常比写实真人宽松**；**公众人物/政治/在世真人是最敏感区**；**CN 区更严**。

### 14.2 整条拒绝 vs 部分降级
高风险**整条拒绝、不产出**；**"静默替换内容"一般不应发生**（合规上应明确告知）。
**★ 但模型层可能有"安全滤镜/自动模糊/局部重绘"**——**这属模型行为，不是审核替换**；**成片与 prompt 关键内容不符时，优先怀疑被安全降级，应看任务回执有无 moderation 标记**。

### 14.3 ★ 成本**相对系数**表（它不给绝对值——"给假表比不给更糟"）
- **视频**：**480p ≡ 1.0（基准）· 720p ≈ 1.5–2 · 1080p ≈ 2.5–4 · 4k ≈ 5–10**；**时长 4s→8s→15s ≈ ×1 / ×2 / ×3.75**
- **图像**：**1K→2K ≈ ×1.5–2.5**；**不同模型档位价差可能大于分辨率差**（旗舰 vs Fast 可差数倍）
- **音频**：TTS 最低 · **音乐（带人声演唱）明显更贵** · 音效居中
- **取真数的方法**：`get_model` 是否回计费单位/单价 → `validate_generation_plan` 是否回显预估积分 → **最可靠是各档小额实跑一次记录扣费（10 分钟标定自己的表）**

### 14.4 ★★ 容易忽略的花钱操作（本节列出 8 条）+ 省钱关键
① **重抽/重新生成（同节点重跑＝再次全额扣费，不是"修补免费"）** ② 合成/导出（尤其高分辨率/长片/多音轨）③ **转码/改规格（降分辨率、换封装、重编码）** ④ **续写 extend**（按新增时长计费）⑤ **失败后自动重试成功（最终成功一般计费）** ⑥ 高分辨率素材分析 ⑦ **音乐生成（带人声、多次重抽）比直觉贵** ⑧ **批量里少数失败后整批调整重跑**。
**★★ 省钱关键**：**先用 720p + Fast/默认模型把"全片跑通定剪"，最后才对定稿镜头升 1080p/4k——不要一上来全 4k。**
（**→ 这是本库"先低清样板"的更精确版本：先全片跑通定剪，再升档。**）

### 14.5 ★ 批量验收（可做，且不该一镜一查）
1. **`get_project_snapshot`＝批量验收主入口**（全项目节点树 + 各自有无产物/状态）；
2. `read_project`（项目级结构汇总）；
3. **用自己的分镜表做 join**：以分镜表为左表（含 `index`/`node_key`/`status`），**左连快照里的 node 状态** → 一次列出"**有媒体 / 缺媒体 / 生成中 / 失败 + 参数**"；
4. **导出前再用 `export_readiness`**——它本身就是"批量检查能否导出"的**官方验收闸**；
5. 若 MCP 支持过滤，按 `节点类型=video + 父节点（分镜组）` 批量拉，避免全量。

### 14.6 prompt 长度与负面写法
- **它侧工具契约没写字符上限**（所以此前"无 3000 上限"指它那层）；**模型层有 token 上限，值随模型而异**。
- **实操安全区**：**视频 300–800 中文字 / 200–500 英文词**；**图像 80–200 词**。**超长不会更听话，反而关键信息被稀释。**
- **★ 负面提示词**：**它侧没有独立 `negative_prompt`**（都走主 prompt）→ 用"**避免：…**"**放 prompt 末尾、单列一段**；**控制 3–8 项短句**；
  **★ "过多否定有时反而『提示』了不想要的概念"**；**更稳是"正向描述替代否定"**（"手部清晰、五指自然" 优于 "不要六指"）——**与 R7 的"负向不如正约束"一致**。

### 14.7 中英与参考图清晰度

## R14·补 · 缺的三问 + 两条关键确认（**★ 经"读回协议"直接读到 · 无人工搬运**）

> **获取方式**：`run_agent` 要求它"建一个 image 节点但不要 run、节点名 `Agent交付_R14补`、答案写进 `prompt` 字段" → 我用 `read_node("Agent交付_R14补")` 读到全文（节点 `i-2u29uk4pukhv`，`taskId:""`/`status:0`＝**没生成、零成本**）。

### 补.1 多主体同框防认错（5 条）
① **每个主体建独立锚点图**（定妆/三视图），**逐帧插桩**，prompt 里**显式标注谁是谁、站位、服装色**；
② **加不可混淆差异特征**（发色/服色/身高/道具），**每镜复述站位**（左 A 右 B）；
③ **构图分离**：前后景、高低、不同朝向，**减少脸贴脸**；必要时**拆过肩/正反打，而不是硬塞同框**；
④ **用首帧图把多人位置摆好再图生视频**，比纯文字稳；
⑤ **同角色全片复用同一锚点，不换参考图**。

### 补.2 ★★ "全片最稳、最不漂"的可复制配置（它给的整套）
- **模型**：**Seedance 2.0（非 Fast）**；**锚点用 Seedream / 高质量图像模型出图**；
- **模式**：**图生视频、首帧锁定优先**；**严卡结尾用"首＋尾帧双锁"**；

- **参考挂法**：**每角色一张定稿锚点**；`reference_nodes` 挂**该镜出场角色 + 场景**；**prompt 内每个引用都插桩并写明用途**；**跨镜复用同一 key**；

### 补.3 ★ 它给的"只记 5 句话"
1. **一角色一锚点，全片复用同一 `node_key`**；

### 补.4 ★★ 关键差异确认（**它承认了抽象层的存在**）

## R15 · ★★ 方案评审（它对我的《钥匙》10 镜方案的挑错 · 极具可操作性）

> 来源：把方案全貌（40 秒/10 镜/写实/无对白/单角色/正对中轴/每 3 镜拉回/2 个运镜/3 参考）给它，请它挑错。**以下四条是可复用的通用规律，不只对本片。**

### 15.1 ★★ 通用规律一：**参考要"按景别加权"，不能每镜固定挂同一组**
- **全景 / 拉回镜**（S1/S7/S10）：**场景正面图为主 · 角色图为辅 · 道具图弱挂或不挂**；
- **特写镜**（S4/S6）：**道具图 / 角色局部为主 · 不挂或极弱挂场景全景图**；
- **中近景**：角色＋场景；**道具按是否入画决定**。
**为什么**：① **特写挂"场景全景图"→ 模型把纵深塞进特写**（多余桌面延伸、背景过实、道具比例与全景不一致）；② **全景挂"道具图"→ 道具被放大/加高光/"悬浮强调"**，**提前剧透道具，削弱结尾的力度**；③ **无差别挂全组 ＝ 把"一致性"做成"每镜都在强调那个道具"**——与克制基调相悖。

### 15.2 ★★ 通用规律二：**运镜方向必须与"景别意图"一致**
- **反例（我犯的）**：让 **S7 同时承担"第 3 次资产拉回（回到开场全景）"＋"全片唯一 push_in"** —— **push_in 是"更近"，"拉回全景"是"退远"，方向相反** → 结果常见"起幅不是全景、落幅停在中景、单点透视轴线在运动中漂移"。
- **修法**：**要么"起幅严格全景、极缓慢 push_in、落幅不超过中景"**；**要么让该镜保持静止全景，把推进动作移到下一镜**。
- **★ 传播后果**：**运动镜一旦轴线出错，会向后传染**（后续镜在一个已偏移的空间关系上继续）——**所以运动镜要么放对位置，要么不放**。

### 15.3 ★ `enableSound` 必须**逐镜显式**关，不能只在合成端静音
若某镜默认 `on`，平台侧仍会生成环境音/拟音 → 与本地音轨叠加 → **产生相位/底噪问题**。**→ 纪律：每个视频节点都显式 `sound=off`（或 MCP 侧 `enableSound:"off"`），不要依赖默认值。**

### 15.4 ★★ `frames2video`（首尾帧）的坑与适用判据
**坑**：① 只强约束"起/落"两个静态画面，中间由模型补 → **运动节奏前松后紧，或最后 0.5 秒"瞬移/急停"**；② 首尾帧的透视/光照/焦距若不完全一致 → 模型中途做**隐蔽的"重新对焦/轴线修正"**（**正对中轴的风格最怕这个**）；③ **尾帧会锁死构图**（想推进或想拉出揭示空间反被限制）；④ 对**道具接触关系**是双刃剑——能固定起止位置，但**中间手部运动可能穿模（手指穿过钥匙）**。
**适用**：**起止构图都要精确、运动简单的镜**（如"开场：首帧=资产图／尾帧=主角已坐定等待的全景"；"收尾：首帧=上一镜落幅／尾帧=人与道具同框、手未伸向道具"）。
**绝对不要用**：**"过程本身就是表达"的运镜镜**（如 push_in）**不要给死尾帧**；**大特写若中间有细小手部动作，慎给尾帧**（急停/穿模）。

### 15.5 ★★ `videoExtend2video`（续写）的坑与适用判据
**坑**：① **严格继承源视频尾帧的构图/机位/光线** → **"擅长延续、不擅长跳变"**（从特写续出全景 → 开头不自然的快速拉远或畸变）；② **误差累积**——链式续写（A续B、B续C）逐段漂移，**第 3、4 次续写后中轴透视线与面部明显劣化**；③ **时长/运动不自由**（沿用源片段运动惯性，源静止它也偏静）；④ **风格"黏住"上一镜**（上镜景别/情绪不对会被带下去）。
**适用**：**同向、同机位、景别接近的相邻镜**（中→中近、中→近这类递进）。
**绝对不要用**：**跨景别的大跳**（特→全、近→全）**绝对不要靠续写硬拉**；**不要做超过 2 段的长链**；**"拉回镜"应回到"资产锚定的独立生成"，而不是从上一镜续写**（这样才能重置累积漂移）。
**★ 一句分配法**：**跳变与揭示 → 资产锚定 / `frames2video`；相邻同向递进 → 可用续写；跨景别大跳与长链 → 一律不要续写。**

### 15.6 ★ 非 VIP 约束下的模型选型（它给的分工方案）
- **主力：`wanx3.0-prime`**——写实质感与**多图参考遵从**在非 VIP 三者中最稳（对"场景正面图"的中轴/透视线保持、对定妆人脸还原优于标准版）；**首尾帧/参考驱动更强**；**指令遵循更细**（微表情与手部更少夸张、更少多余运动）——**适合克制基调**。
- **备选 A：`seedance-1.5-pro`**——**只把运镜镜交给它**（若 Prime 上运动僵硬/透视漂移）；**代价：跨模型的人脸/光线匹配要靠资产定妆图强拉齐，且必须先单镜测试**。
- **备选 B：`wanx3.0`（标准版）**——**做产能/节奏预览**（跑中近景、压力小的镜）；**不建议承担锚点镜与接触特写**。
- **不建议全片用标准版**（中轴一致性与道具接触是它最容易松的两点）。
- **落地**：默认 Prime 跑全部静态镜与锚点镜；**先各出 4 条（锚点/拉回/两个特写）做风格/透视/接触验证**；仅当运镜镜不达标再单点替换；**每次替换后重新核对中轴透视线与道具比例**。
