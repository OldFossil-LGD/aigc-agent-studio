# 混音与响度：**目标、顺序、交付**

> **何时读**：片子要交付了、要定"声音多大"、要给对白做处理、要交分轨时。
> **读完回哪**：回 `sound-craft.md` §五（混音手段与阈值的权威在那边）；音效设计方法见 `sound-design-craft.md`。

## §1 ★ 响度目标表（**按发行渠道对表**）

**这张表是硬数据**：`LUFS`（＝`LKFS`，只是 EBU 与 ITU 两套叫法）是**感知响度**，不是峰值。

| 发行渠道 | **目标（整合响度）** | **真峰值上限** | 备注 |
|---|---|---|---|
| **欧洲电视/广播**（EBU R128） | **−23 LUFS**（法规档 ±0.5 LU；R128 s1 实操 ±1 LU） | **−1 dBTP** | **法规级**；不合规会被退回 |
| **北美电视**（ATSC A/85） | **−24 LKFS** | **−2 dBTP** | 美国 **CALM 法案**强制 |
| **日本**（ARIB TR-B32） | **−24 LKFS**（上限口径） | 以 ARIB 原文为准 | |
| **YouTube / 音乐平台** | **−14 LUFS**（播放参考） | −1 dBTP | 平台**播放时归一化**；**Spotify ≈ −14 · Apple Music ≈ −16 · Amazon Music ≈ −14（建议 −2 dBTP）**——播放参考会变，交付前复核 |
| **播客** | **−16 LUFS 立体声** / **−19 LUFS 单声道** | −1 dBTP | **常见建议口径（业界另有 EBU R128 播客档）**；单声道另有一档 |
| **有声书（ACX/Audible）** | **ACX 口径不用 LUFS**：RMS **−23 ~ −18 dB** | 峰值 ≤ **−3 dB** | **底噪 < −60 dB RMS**；**Audible 侧近年另引入 LUFS 口径，提交前以当期 ACX 帮助页为准** |
| 在线课程/教程 | −16 ~ −14 LUFS | −1 dBTP | 优先"清晰"而非"大声" |

**★ AI 成片流程怎么落地**（生成/合成节点不保证播出级响度，表中的数字全在**导出之后**达成）：
1. **LUFS 校准在导出后做**：用外部响度表（Youlean / Insight / Pro-L 2）或 `ffmpeg loudnorm` 测整合响度并校准到目标——生成节点内没有播出级 LUFS 表；
2. **真峰值在导出后限制**：先过真峰值限制器（或 loudnorm 的 TP 参数），**AAC/Opus 编码后复测 dBTP**；
3. **四条分轨要在合成前保留**对白/音乐/音效/环境的独立轨道——成片一旦混音导出，**事后拆不出分轨**；
4. **音量配比（对白/音乐/环境）在生成与合成时就设对**——对应 §2「一开始就混到目标」的纪律，**不要导出后整体限幅硬压**；
5. **侧链闪避默认不会自动发生**——需在剪辑/DAW 工具里手工配置（值仍引 `sound-craft.md` §五）。

**★ 分轨交付已成标准**：影视后期除最终母版外，**另交四条分轨**——
**对白 dialogue · 音乐 music · 音效/拟音 effects/Foley · 环境 ambience**。
Netflix、Amazon Prime 与各电视台普遍要求；这样对方能按自己的响度目标重混、做口述影像版、或单独调对白音乐比。
**广播交付规格**：通常 **BWF/WAV · 48 kHz · 24-bit**。

## §2 五个必须分清的概念（**它们混起来就是业余**）

1. **LUFS ≠ dBFS**：dBFS 是**瞬时峰值**，LUFS 是**按人耳加权的、对时间积分的感知响度**。
   → **两个文件归一化到同一个峰值，听觉上可能差 8 dB。**
2. **归一化 ≠ 校准**：把导出文件拉齐到 −3 dBFS **什么也没校准**；**要用 LUFS 校准**。
3. **整合 / 短期 / 瞬时（integrated / short-term / momentary）**：
   **整合＝全片目标**（定交付用）· **短期**＝看某一段是不是太响/太轻 · **瞬时**＝抓突变。
4. **真峰值（true peak / dBTP）**：**普通峰值表会漏掉采样间的过冲**——
   **碰到 0 dBFS 再编码成 AAC/Opus，就会爆音**。**所以看 dBTP，不看峰值表。**
5. **★ `−14 LUFS` 是"播放参考"，不是"制作目标"**：
   平台**播放时会归一化**——**你混到 −8，平台会把它拉回去，只剩下被压扁的动态**。
   **混到目标音量区间即可，把动态留给音乐。**

**★ 一条纪律**：**一开始就混到目标，不要"先混大、最后限幅压到目标"**（后者听起来明显更差）。

## §3 ★ 三层平衡（**可以直接照抄的数字**）

```text
对白   最响 —— 峰值 −12 ~ −6 dBFS；广播模式下对白在 −24 LUFS 附近
音乐   让路 —— **比对白低 12–18 dB**（对白密集或长镜头时退到 −28 ~ −24 dBFS）
音效/环境  填在对白与音乐的缝里，不抢字
```
**★ 判据一句话**：**"闭上眼，我第一个听清的是人话吗？"** 不是 → 音乐或音效太前。
**★ 侧链闪避的具体值**见 `sound-craft.md` §五（阈值 −20 dB / 比率 4:1 / 起音 10 ms / 释放 200 ms）。
**★ 输出前最后一步是校准，不是调整**——**"同一个声音按 −23 LUFS 交给电视台、按 −14 LUFS 交给 YouTube，不是混得不一样，只是最后出口处校准得不一样。"**

## §4 ★ 对白处理链（**顺序本身就是知识**）

**照这个顺序，顺序错了效果全变**：

```text
① 降噪 / 修错（先修源问题：底噪、嗡声、喷麦）
② 扩展器（不是噪声门！）——范围 6–8 dB、低阈值、长恢复
   ★ 一个"在句子之间啪地一下开合"的噪声门，比它要去掉的噪声更吵
③ EQ（给后续让路）——见下
④ 压缩——把持续的压下去，但不碰短瞬态
⑤ ★ 去齿音（de-esser）——**必须在压缩之后，绝不能在之前**
   为什么：压缩先去压了持续声却没动短瞬态，而存在感提升（presence lift）正好落在齿音带的下沿
   怎么设：单听检测路径找带（**低音色 5–7 kHz / 亮音色 6–9 kHz**，应听到"嘶/嘘"而不是整字）；
          阈值设在**峰值上 3–6 dB 衰减**（表大部分时间是静的）；**优先分频段（split-band）而不是宽带**——
          宽带会在每个齿音上把整个声音都压一下，听起来像"反向大舌头"
⑥ 用 LUFS 校准到目标（§1 的表）
```

**★ EQ 起步值**：**音乐/伴奏轨在 2–5 kHz 削 3–6 dB 给人声让位；人声 2–4 kHz 提；整体高通 80–100 Hz 去轰鸣。**

## §5 交付前自检（七条）

- [ ] **目标渠道定了没有**（广播 −23/−24 还是网络 −14）——**没定就别开始混**
- [ ] **整合 LUFS 读到了目标**（用符合 ITU-R BS.1770 的表；iZotope Insight / Youlean / FabFilter Pro-L 2 或 DAW 自带）
- [ ] **真峰值 ≤ −1 dBTP**（母带**响于** −14 LUFS，或交付 Amazon Music，则 ≤ −2 dBTP）
- [ ] **没有削顶、动态是留着的**（不是被限幅压平的）
- [ ] **对白是最清楚的一层**；音乐比对白低 12–18 dB
- [ ] **四条分轨已导出**（对白 / 音乐 / 音效拟音 / 环境）
- [ ] **换设备回听**（监听 + 耳机 + 手机喇叭）

## §6 常见错误（六条）

| # | 错误 | 正解 |
|---|---|---|
| 1 | 拿 −14 LUFS 交付广播 | **差 9 LU**，EBU R128 直接退 |
| 2 | 把 LUFS 与 LKFS 当两个东西 | **数值等价**，只是叫法不同 |
| 3 | 用普通峰值表 | 用**真峰值**表（漏采样间过冲） |
| 4 | 忘了看 LRA（响度范围） | 部分广播规范对 LRA 有要求 |
| 5 | 交 44.1 kHz 给要 48 kHz 的电视台 | 广播**通常 48 kHz** |
| 6 | **想靠"混大声"赢** | **平台会拉回来**，只剩压扁的动态 |
