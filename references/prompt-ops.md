# 提示词运营（迭代 · 评测 · 归因 · 沉淀）

> **何时读**：要返工、要对比两版提示词、要判断"这次改动到底有没有用"时。**读完回哪**：回到 `studio-workflow.md` 第三步重写成品。
>
> 一句话：**"感觉更好"不算证据。** 提示词要当代码来管——一次只改一个变量、有基线、有版本、有变更记录。

---

## 一、迭代纪律（四条铁律）

1. **一次只改一个变量**——同时改光影 + 动作 + 镜头，出了好结果也不知道是谁起的作用。
   **典型用法（资产选型）**：同一条提示词，每次只换主角、或只换场景，**绝不两个一起换**；2 主角 × 2 场景 = 跑满 4 次并排比。（用引用绑素材的平台，**换引用节点才是换变量**——只改文字里的名字，变量根本没换。）
2. **批次判读：先看"是否重复"，再看成功率**（成本最低的一层判据，一批 3–4 条就能判**重复/结构信号**；判"系统性 vs 随机"见铁律 3，需 5–10 条）：
   | 现象 | 判断 | 动作 |
   |---|---|---|
   | **失败跨批次重复出现** | brief 或参考图的问题（结构问题） | **改结构**（改 brief / 换参考 / 拆镜） |
   | **动作已经成立，只在某一条上出的缺陷** | 随机性 | **换一条重抽**（**每次重抽＝一次独立计费的 run**——对照实验的每一条都各占一个节点 / 一次生成费，预算按条数×单价算，→ `libtv-billing.md`） |
3. **单条对比没有意义**——同一个提示词跑 3 条就下结论，等于抛硬币。
   **至少 5–10 条**才能判断"这是系统性错误还是随机性"：
   - 失败率 **≥60%** → 强信号：提示层真的有 bug，停跑改结构
   - **30%–60%** → 疑似系统性：先按铁律 2 看"是否跨批重复"再定改结构还是重抽
   - **<30%** → 随机性（多抽几次即可）
4. **换模型必重跑基线**——同一条提示词换模型效果可能断崖（有实验记录 99% → 68%；来源：`key-decisions.md` 实验账）。

## 二、版本管理（提示词也要有版本号）

- **语义化版本**：MAJOR（改结构/换模型/改核心逻辑）· MINOR（加约束加示例）· PATCH（错别字、参数）。
- **变更记录写"行为意图"，不写"改了哪几个字"**：
  - ✅ `增加身份锚点前置，解决跨镜换脸；可用率 25% → 60%`
  - ❌ `改了第二段`
- **保留失败实验**（归档并写明为什么废弃）——它是机构的记忆，能防止重复踩坑。
- **生产版打 tag**，实验走分支。

## 三、评测：怎么判断一版比另一版好

**先用确定性检查，再用人（或模型）评主观项**：

```
第一层 确定性校验（零成本、必做）
  人数对不对 / 有没有文字 / 长度是否在限内 / 禁用词有没有出现 / 时长是否超
第二层 打分（视觉/视频方向的可操作维度）
  一致性（人物与资产是否同一个）· 动作成立度（有没有崩）· 光影合格度 ·
  物理可信度 · 与故事板的构图吻合度 · 声音层是否齐
第三层 人工抽检
  高风险与分歧样本必看；每 50 条抽 5 条复核
```

**用模型当评委（VLM-as-judge）的规则**：适合**粗筛 + 描述性反馈**，
**不要单独用于高风险判定**（二值判断实测只有约 69% 准确，且**视频越长越不准**；来源：`key-decisions.md` 实验账）。
要做就要求**"先给理由再给分"**，并**交换 A/B 顺序**消除位置偏好。

## 四、失败归因：四层定位 + 消融

**四层责任归属**（把坏结果落到可改的那一层）：

| 层 | 症状 | 怎么验 |
|---|---|---|
| **① 信息缺失** | 模型不知道你要的东西 | 补上信息看是否改善 |
| **② 指令歧义** | 用了形容词、判断、模糊词 | 换成精确规格再看 |
| **③ 约束冲突** | 两条要求互相打架（如"静止"+"风吹动"） | 统一冲突项，或写明优先级 |
| **④ 能力上限** | 上面三层都没问题还是不成立 | 换模型 / 拆步 / **设计绕过** |

**消融法**：从能复现失败的最小提示开始，**逐段删**，删掉后失败消失的那段就是元凶。
**自述法**：让模型先说明"它理解的任务与关键约束"——常直接暴露被误读的指令。

## 五、反模式清单（被反复证明无效或有害）

| 反模式 | 为什么 |
|---|---|
| **堆砌形容词**（"电影感 / 震撼 / 精致 / 4K"） | 形容词≠具体，模型无法执行；换成可测约束（器材 / 动作 / 材质 / 时长） |
| ⚠️ **"近义变体"漏网**（`电影质感` / `大片质感` / `细腻` / `高级感`） | **只禁原词会被变体绕过**——`电影感` 被禁了，`电影质感` 照样出现在风格标签行。见下方**空话词黑名单（含变体）** |
| **块内混入元说明**（"另注：…""注：""*可选*""（改成你的…）"） | 块内一切文字都会被当成提示词执行；**思考过程绝不能进块**。脚本 `blocks` 会报，必查 |

**★ 元说明的边界在哪（2026-09-13 实测划定）**——不是所有"总结性的话"都是元说明：

| | 写法 | 判据 | 处置 |
|---|---|---|---|
| **✅ 收束句**（可留，非必须） | 具体事件写完之后，末尾一句概括**事件弧线**："整体呈现从紧张失误到冷静完成比赛的完整叙事" | **删掉它，前面的具体描述是否已完整？** 完整 → 它只是收束 | 可留。**脚本只报 WARN（文件腔），不报 FAIL** —— 现有行为已正确 |
| **❌ 元说明**（必删，FAIL） | ① 给自己看的备注（"另注：""注：""*可选*""（改成你的…）"）② **无具体内容、纯抽象情绪堆叠**（"氛围压抑，情绪复杂，内心矛盾"） | 删掉后**内容塌了**，说明它在撑内容而不是收束 | 清零 |

**为什么这条边界必须写下来**：官方（Seedance 2.0 发布博客）自己的 demo 提示词就用了收束句——若不划清，用户会以为"官方都这么写所以我也可以写元说明"，而元说明是会被当真执行的。
| **否定句管画面瑕疵**（"不要多手指"） | 会**激活该概念**（粉红大象效应）；改成风险移除句／肯定状态句 |
| **内容类别否定**（"不要 CGI 感 / 不要像游戏 / 不要廉价特效"） | 只拒绝一个类别，**没告诉摄影机拍什么**——纯粹的消耗。见下方替换表 |
| ⚠️ **反向少数派：漏写"同族动作排除"** | 动作歧义靠**排除同族**锁定（写了推镜就排除拉/摇/移/环绕/变焦）——官方 Prompt Bank 每条都写，这不是"否定句"问题 |
| **自相矛盾约束**（"详尽"又"简洁"） | 模型二选一，静默丢弃另一条 |
| **超长导致注意力稀释** | 关键指令落在中段最容易被丢（lost in the middle）；关键信息放**首尾** |
| **把判断写成描述** | "她很疲惫"不可测；写成可见痕迹 |
| **多任务塞一条** | 拆成链式多步 |
| **过度礼貌 / 用名人当角色** | 稀释指令；应给**职能**而非"模仿某人风格" |
| **只测顺境** | 必须用边界与失败案例做回归 |

### 内容类别否定的替换表 → 指针

**替换表不在本册重列**（2026-09-17 去重）：权威源 = **`quality-layer.md` §四 1c**（三行：不要像游戏 / 不要廉价特效 / 不要轻飘飘 → 各换成"该拍什么"；行号随版本漂移，以小标题为准）。
本册只记**它与本册的关系**：上表第 2 行那条"内容类别否定"就是**指针**——它属"三类方向各异"的第 ③ 类，**否定与状态句都走不通**，只能改写成"该拍什么"。

### 空话词黑名单（含变体 · 2026-09-11 实测补）

**为什么要有变体表**：实测发现 `电影感` 被禁后，**`电影质感` 照样漏进风格标签行**——只禁原词等于没禁。以下词**一律替换成可测约束**：

| 空话词（含变体） | 换成什么（可测） |
|---|---|
| `电影感` `电影质感` `大片感` `院线感` | **具体器材**（本片方案包的「器材」行——例 P13 `ARRI ALEXA 35 配 Cooke S4/i`、P08 `35mm + VISION3 500T`）或**具体摄影行为**（变形宽银幕的水平椭圆焦外） |
| `细腻` `精致` `高级` `质感十足` | **具体行为或部位**：`细腻颗粒` → **暗部成簇、中间调细**；`皮肤细腻` → **哑光、毛孔与胡茬可见** |
| `震撼` `史诗感` `视觉盛宴` `极具冲击力` | **具体规模与对照**（参照物在画面里的比例、主体与环境的明暗差几挡） |
| `唯美` `氛围感` `氛围拉满` | **光的出处 + 色调 + 空气介质**（暖橙钨丝主光、冷雾、浮尘） |
| `超高清` `4K` `8K` `HDR` | **删掉**——这是交付规格，不是画面描述（→ `post-production.md` 7.1） |

> ⚠️ **白名单例外**（这些是真术语，不算空话）：`中间调细腻颗粒`（颗粒结构术语）、`细节插窗`（设定板分区名）。判据：**这个词后面跟了可测对象吗**？跟了 → 保留；独立当形容词 → 换。

**★★ 最高频的漏网位置：首行的「风格槽」**（2026-09-15 实案）。
`写实电影风格` 这种写法**等于把"电影感"换个词塞了回去**——**而它的后果比"没说清楚"更糟**：模型会按训练数据里最"电影"的那一套给（**高饱和 + 浅景深 + 青橙 + 均匀布光**；→ `color-narrative.md`：**模型一听到"电影感"就给你青橙**）。
**★ 后果是"首行与后文打架"**：日式文艺段落要的是**高调过曝、低对比、几乎单色**，牛仔要的是**天空过曝成浅黄而不是饱和蓝**——**一句"写实电影风格"正好把这两个方向都拧反**。
**★ 正确写法：风格槽一律换成"技法名词句"**（不许留笼统词，也不许写编号或片名）——
`日式日常静观：高调过曝、低对比、几乎单色偏暖白，机位几乎不动` · `美式经典西部的荒原：土黄与赭石、天空过曝成浅黄，地平线压到画面下缘`。
**它从哪来的**：模板首行原本是 `[写实电影]风格` 的**方括号占位符**——**占位符是最容易被一代代当正文带走的东西**，四个模板（`shot-craft.md` / `segmented-shot.md` / `block-playbook.md` / `run-sheet.md`）**已全部改成 `[风格槽]` 并附警告**。

**自检一句**：把提示词里所有形容词划掉，**剩下的是不是全是名词与动词**？不是 → 还有空话。

> ⚠️ **不要一刀切**：这不等于"一律禁写否定"。官方技术块里仍保留 `NO CGI. NON-IP.` 这类**风格与合规限定**——该删的是**正文里反复出现的类别否定**。三者并存，各管一段：
> ① **瑕疵否定** → 改肯定状态句；② **同族动作排除** → 必须写（消歧）；③ **内容类别否定** → 换成"该拍什么"。

## 五·补 · 复用与增量（三条成本纪律）

**① 全片样式头 + 只写 delta**
把不随镜头变的东西封成一份**样式头**：光 / 镜头 / 表演风格 / 物理 / "无配乐只留环境音"。
写每镜时 = **样式头 + 本镜的 delta**，**不再每镜重述**。

> ⚠️ **注意落地形态**：样式头是**写作时的内部约束**（全片从同一份取值），**不是交付物里的共享前缀**。
> 因为我们每镜的提示词块必须**独立可提交、块内纯净**（Updream / 即梦是单条提交，粘不了共享前缀）。

**② 同类 beat 在已跑通的提示词上做增量，不要从零重写**
换了场景但 beat 结构相同 → 复制已成功那条，**只加/改那一个点**（"在上一版基础上增加更多技巧"、"只在结尾那一条上加一个轻微动作"）。

**③ 建立废料池**
没被用上的强生成、以及旧场景砍掉的 take，**登记进池**，新场景优先在里面找。
> "这一场没用上的强生成，常会在后面某一场复活。"

## 六、跨模型分层（同一份提示词换平台怎么不失灵）

拆成**两层**写：

1. **可迁移语义层**——目标、约束、内容、示例语义。这部分跨模型可靠迁移。
2. **模型相关结构层**——负向字段有无、`@` 素材绑定、标签风格、参数、上下文顺序。
   **这部分必须按目标平台特化**（→ `quality-layer.md` 第四节、`platform-matrix.md`）。

**只优化不可迁移的那部分**，共享核心语义层。

## 七、迭代闭环（照着跑）

```
1 冻结基线：当前最佳版标 vX.Y.Z；建 5–10 条用例集（正常 / 模糊 / 边界 / 最难的）
2 写下假设：我判断问题在___层（信息 / 歧义 / 冲突 / 能力），预期改动能改善什么
3 单变量改动：只改一处
4 评测：确定性校验 → 打分 → 分歧样本人工看
5 判定：主指标升 + 硬性违规为 0 + 无回退 → 采纳；否则回滚并归档失败原因
6 沉淀：更新变更记录（前后可用率）；把新的失败案例加进用例集；更新反模式清单
```

**改动前的检查项**：
- [ ] 任务意图无歧义，输出要求显式
- [ ] 没有自相矛盾的两条约束
- [ ] 关键信息在首尾、没有冗余 token
- [ ] **只改了一个变量**
- [ ] 用例集覆盖了之前踩过的坑
- [ ] 硬性违规为 0，且没有把以前能用的镜头改坏

## 八、LibTV 落地注记（2026-09-30 补）

本册的迭代方法落到 LibTV 平台时，另有四条平台侧事实（细节见各实测册，此处只导航）：

1. **结果三态记账**：每次生成的结局是**保留 / 淘汰 / 生成失败**三态——**报错与节点未生效单列，不计入成功率分母**（→ `production-ledger.md` §6.1）。
2. **每次生成＝独立计费**：重抽不是免费的，对照实验的每一条各占一次生成费，预算按"条数 × 单价"先算再跑（→ `libtv-billing.md`）。
3. **改参数重跑有两条路**：`update_node` 改参数后在**原节点**重跑（覆盖历史、省节点），或**新建节点**重跑（保留全部对照样本）——取舍得看是否需要留对照，不要反复硬跑（→ `libtv-official-qa-part5.md` §16.8④）。
4. **失败 ≠ 多抽**：先按本文铁律 2/3 分诊"随机 / 结构"，结构问题改结构；安全降级产物按 `qa-failure-codes.md` F32 处置，不当随机质量重抽。
