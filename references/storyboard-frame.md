# 故事板生成提示词（板块一 · 平台自适应 · 可迭代）

> **何时读**：写板块一（故事板）时，**动笔前先读第三节选路径**。
> **读完回哪**：`studio-workflow.md` 第三步写板块二。
> **配套册**：平台规格、来源分级、待验证假设 → `storyboard-platforms.md`。

分镜这一步**固定交付两个板块**：**板块一 = 故事板**，**板块二 = 视频提示词**，两块分开给、各自可复制。
**本板块自 2026-09-14 起改为"平台自适应 + 参数化"**——旧版"一镜一张、绝不拼版"在 image2 / 即梦 4.0 / 可灵 Omni 3.0 / Runway Story Panels 之后**已过时**（依据见 `_learn3/02`）。
**默认平台按 image2 写**（用户的主动用平台；`n` 上限 8/4、官方 storyboards 用例 → §4.0）。

---

## 一、目标与适用场景（先对齐这两条，再动笔）

**目标**：在**花钱生成视频之前**，用最便宜的一步把六件事**钉死并可交付评审**——
**景别 / 机位 / 构图 / 人物位置与朝向 / 明暗结构 / 动作的那一瞬间**

| 适用场景（三条） | |
|---|---|
| 多镜叙事片（≥3 镜）、需向他人交付评审 | **该做**——故事板是沟通工具，不只给自己看 |
| 单镜 / 一条过的简单生成 | **不必做**——直接进板块二更省 |
| 角色跨镜反复出现、一致性是难点 | **必做**——它是"这角色在这几镜站哪、朝哪"的唯一图纸 |

**★ 前置检查（两条都过再动笔）**：
1. **导演推理做完了吗**——六问（命题 / 人物 / 戏剧任务 / 冲突形状 / 能量 / 参数）没答完就画构图，
   是这条纪律最常见的失效方式（→ `direction-reasoning.md`）。
2. **叙事职能定了吗**（建立 / 推进 / 揭示 / 反应 / 过渡 / 峰值 / 收束）——它决定"框多大、站哪、
   要不要留负空间"（→ `sequence-craft.md` §8.4）。

---

## 二、★★ 一条禁令拆成两条（旧版最大的坑）

旧版写「**一镜一张，绝不拼版**」。**这句话把两件不同的事混成了一件**，代价是**把平台最好用的入口一起禁掉了。**

| | 做法 | 判据 | 结论 |
|---|---|---|---|
| **允许多文件** | 一次请求 → **N 张独立图片**（image2 多图批量 / 即梦"生成6张分镜" / 可灵组图 / Runway） | 每张是**独立文件**、各自满分辨率 | **✅ 允许，且推荐**——平台原生能力，内容关联由模型保证 |
| **禁止单画布多格** | 一次请求 → **1 张画布内含 N 格**（九宫格 / 四格一张 / 拼版） | 多镜挤在一张图里，靠**裁切**才能拿到单镜 | **❌ 禁止**——每格只剩 1/N 分辨率，各格构图互相牵制 |
| **★ 第三条路径：平台原生切分**（2026-09-20 补 · 如 LibTV 的"宫格切分"） | 一次请求 → 1 张画布含 N 格，**平台自带"切分"**（点选任意格 → 生成**独立图片节点**） | 切出来的是**独立文件**、**各自满分辨率**（**未核**：若实为裁切则掉分辨率） | **⚠️ 有条件下放行**——**只有实测确认"切分＝独立满分辨率文件"才放行**；**未核之前按 ❌ 处理**（落法 → `storyboard-platforms.md` §五·补） |

> **禁单画布多格**：① 分辨率除 N，后期无法当首帧；② 各格须互相妥协（负空间会被邻格压掉）；③ 裁切偏移让"构图与视频完全一致"失效。**放行多文件**：连贯性由模型保证（可灵官方"重点提升**分镜组图**的构建逻辑连贯"；image2 官方用例就叫 storyboards）。

## 三、★★ 三条路径（选错路径 = 提示词写对也没用）

**先选路径，再写提示词**——三条路径的结构、长度、参数全都不同。

| 路径 | 什么时候走 | 平台 | 提示词骨架 |
|---|---|---|---|
| **A · 原生组图** | **默认首选**。多镜、要一次拿齐 | **image2（`n`=8/4）** · 即梦 4.0 · 可灵图片 Omni 3.0 | **声明组图 + 逐格一句 + 一致性锚点行** |
| **B · 原生 Storyboard** | 要看到运动与切点（动效故事板 / 预演） | 可灵视频 3.0（Smart / Custom）· Runway Story Panels | **不给逐格全描述，给"镜头清单 + 每镜一句"** |
| **C · 一镜一请求** | 该平台**没有**原生故事板层 | Midjourney · SD · 及任何无原生层的平台 | **一镜一份完整提示词** + `--sref` / 种子锁一致性 |

> **选路判据（一句话）**：**平台有原生故事板层 → 走 A 或 B，把连贯性交给模型；没有 → 走 C，自己用参考图与种子扛。**（路径 C 没写错——它是旧版描述的那个世界，**只是不再是唯一答案**。）
>
> **★ 用 image2 的话**：它**官方用例就明写 storyboards / sequential scenes**，**默认走 A**；
> `n` 上限**先确认模式**——**普通档 4、Thinking 档 8**（完整规格 → `storyboard-platforms.md` §五）。

## 四、路径 A · 原生组图（默认首选）

### 4.0 平台规格速查（完整表与来源在 `storyboard-platforms.md` §一）

| 平台 | 上限 / 取值 | 长度 |
|---|---|---|
| **image2 · GPT Image 2** | **`n` = 8（Thinking）/ 4（普通）**；官方用例明写 **storyboards** | 可长；**须显式关掉文字渲染** |
| **即梦 4.0 / Seedream** | **`输出上限 = 15 − 输入图数`**（火山官方接口文档原文） | 可长 |
| **可灵 图片 Omni 3.0** | 组图模式，官方示例 **6 张分镜** | 可长 |
| **Runway Story Panels** | **恰好 2 panels**（不可调，见 H2） | **≤1000 字符** |

**即梦五个入口的解（同一条公式）**：0 图→15 · 1 图→14 · 6 图→9 · 9 图→6 · 10 图→5。

> **纪律**：社区帖说的 6 / 9 / 10 / 14 / 15 **全都对，也全都错**——它们是**同一条公式在不同入口下的解**。
> **只写公式，不抄数字。** 遇到"同一能力多个数字打架"，先找**能同时解释所有数字的那条公式**。
> **image2 同理**：社区说 1–10 张，**官方是 8/4 分档**——**先找档位，不要在数字里挑**。

### 4.1 输出模式声明（**必写首行**）

```
输出模式：原生组图 | 平台=image2 | 模式=Thinking | 张数=[N] | 单张比例=[16:9]
```

- **为什么必写**：`张数`是**跨平台唯一会直接撞墙的变量**——Runway 固定 2、即梦可到 15、image2 分 8/4，
  **同一条提示词换平台就超限**。显式化之后才可能被脚本查、被参数改。
- **`模式=` 只对 image2 有意义**：不写按**普通档 4** 判（保守）；要用 8 必须写 `模式=Thinking`。
- **张数怎么定**：`N = 本场的镜数`；超过平台上限 → **拆成两批**，不硬塞。
- **比例**：见 `platform-matrix.md` §7.4（固定六值 + `adaptive`）；**出故事板固定 16:9**（防下游裁剪）。
### 4.2 提示词骨架（五段固定）

```
[第一段 · 输出模式声明]        输出模式：原生组图 | 平台=… | 张数=N | 单张比例=…
[第二段 · 风格锚点行]          全组统一：<画法族>，<明暗结构一条>，<构图纪律一条>
[第三段 · 一致性锚点行]        全组统一：<角色身份锚点>；<场景锚点>；<关键道具与接触关系>
[第四段 · 逐格一行]            第1格（景别｜职能）：…一句话…
                              第2格（景别｜职能）：…一句话…
[第五段 · 全组禁止项]          全组不出现：<现象清单>
```

| 段 | 只写 | **不写** |
|---|---|---|
| 2 风格锚点 | **画法族**（写实灰度 / 线稿）+ 明暗结构、构图纪律各一条。**★ 实测（2026-09-20）：只写「线稿」仍会掉进日式动画**——必须**同时排除**：`这是黑白电影分镜稿，不是动画、不是卡通、不是漫画分格` | 具体描边、网点、做旧技法（技法属成片色彩层） |
| 3 一致性锚点 | 身份、场景、道具**逐字复用的那几句** | 颜色三值、摄影机运动 |
| 4 逐格一行 | **景别 + 职能 + 这一格画面** | 情绪形容词、时间轴、声音（故事板没有这些） |
| 5 禁止项 | 现象清单 | 单画布的拼版线（已在 §二 说明） |

### 4.3 逐格一行怎么写（**每格只准一句**）

**句式**：`第N格（景别｜职能）：<谁> + <在哪> + <朝哪/什么姿态> + <关键道具与接触关系>`

```
第1格（大远景｜建立）：骑手只剩一个黑影立在镇口路中，面朝镜头左前方的酒馆，马在他右侧低头。
第2格（大特写｜揭示）：他的右手食指在枪套搭扣上，指节发白，搭扣的金属边缘反光最亮。
```

**三条硬规则**：① **"多格"不等于"多细节"**——每格加长一句，模型把注意力均摊，**总信息量没变但每格都变糊**；
② **一致性锚点行只写一次**（第三段），**不要每格重抄**——重抄＝把漂移源写进提示词，
而**改写措辞本身就是漂移源**（→ `character-continuity.md`）；③ **格间变化靠景别与站位，不靠风格词**。

## 五、路径 B · 原生 Storyboard（要运动与切点时）

| 平台 | 模式 | 怎么写 | 输出 |
|---|---|---|---|
| **可灵 视频 3.0** | **Smart**：给概念，AI 导演自动规划切点与景别；**Custom**：逐镜自定义 | Custom 时**逐 shot 一行**：`镜N｜景别｜动作｜时长` | **≤6 shot → 一条视频** |
| **Runway Story Panels** | 无模式选择 | **≤1000 字符 focused 描述** + **1 张必填参考图** | **恰好 2 panels** |

**Runway 的特别提醒**：官方明说「optimized for this use case, so **a focused description is enough**」——
**它要短**。把路径 A 的长骨架搬到 Runway，会**既超 1000 字符又降低效果**。

> **长度策略按平台分流**：Runway **要短**；image2 / 即梦 / 可灵**可长**。**不存在"越长越好"这条通则。**
> **可灵视频侧**：`≤6 镜` 与库内"单镜 2–3 秒"能对齐到 **约 15 秒一条**——**待验证假设，非结论**（§十二 H3）。

## 六、路径 C · 一镜一请求（无原生层平台）

适用于 **Midjourney / SD**，也适用于**任何没有原生故事板层**的平台（Veo / Wan / Hailuo 等直接进视频提示词）。
**骨架**：§七 的**单镜模板**，**每镜一份、各自独立生成**。**不做九宫格**（理由见 §二）。

**一致性靠三样**（这是路径 C 的全部难点）：① **风格锚点句逐字复用**（第一镜定稿后，后面每镜**一个字不改**地复制）；
② **参考图机制**：MJ 用 `--sref` + 同一 seed，SD 用 ControlNet 结构参考；③ **先出"风格样张"再开工**——一张图钉死画法、明暗、构图纪律，后续照它对齐。

## 七、单镜模板（`[ ]` 替换 · 路径 A/C 通用）

路径 A 的"逐格一行"是**压缩版**；路径 C、或需单独评审某一镜时，用这份**完整版**。
```
一张黑白故事板画格，横版16比9，纯灰度，全画面只有黑、白、灰三种明度，
像高质量的黑白电影分镜稿，一个镜头，不拼版（一张画布只此一格；**一次出 N 张独立文件不算拼版**）。

画面内容：[本镜的景别与机位一句话]，[人物身份锚点一句话]，
[姿态与动作的那一个瞬间]，[关键道具与接触关系：谁的手、握在哪、接触面]；
画面里只有[他/她]一个人，[镜面/倒影]里没有人；[场景物件两三件]。

明暗结构（黑白故事板只讲明暗）：主光从画面[方位]来，
[亮部在哪、亮到什么程度]，[暗部沉到哪、暗到什么程度]，[中间调在哪]；
光比大约[几比几]；明暗交界是一条柔和的过渡带，不是硬边。

构图：主体在画面[左/右]三分之一，[对峙元素]占[另一侧]；
[引导线]把视线从[A]引向[B]；[方向]留出大片暗部负空间。

质感：像铅笔与炭笔叠出的细腻灰度过渡，暗部有颗粒般的质感；
人物形体与手部结构简单，动作单一。

画格左下角留一条空白标签条，条内不生成文字。

风险移除：画面里始终只有[他/她]一个人、一只手在做简单的动作；
画面内不出现任何文字与数字，需要文字时后期贴。

禁止出现：彩色，颜色，彩色滤镜，色温，暖色，冷色，彩色光晕，
分格，拼版，漫画分格线，文字，数字，字幕，水印，
[画风按量级族切换：写实片写「动漫，卡通，漫剧感」；风格化片写「照片写实，真实皮肤毛孔」],
高饱和，第二个人，多余的影子轮廓，换脸，左右翻转，畸形关节，悬空的手。
```

**★ 2026-10-02 关闭【待确认项】**：**两份文件现在都是「明暗交界是柔和过渡带、不是硬边」**，已实测逐行核对两边（本内容与 `examples/delivery-samples.md` 板块一的提示词块）。**裁定**：**描边系故事板不走硬边**——故事板画的是**明暗结构块面**；硬边只是**成片**板块二（美漫描边「暗面直接沉进硬边色块」）的风格需要，两者不冲突。**本行与 `examples/delivery-samples.md` 均无需再动**。

> **★ 方括号纪律**：`[ ]` 是**占位符**——`scripts/audit_prompt.py` 会把
> **含中文的方括号**一律当成"未替换的占位符"报警。填完**必须把 `[ ]` 去掉**
> （写成 `主体在画面左三分之一`），**不要**写成 `[主体在画面左三分之一]`。
> 整块保持占位符状态时脚本识别为骨架模板、不报警。

### 7.1 画法按量级族切换（**两族，别写错** · 故事板是灰度的，**但画法要跟全片一致**）

| 全片量级 | 故事板画法 | 禁止项里该写 |
|---|---|---|
| **系一 写实系** | 写实灰度（铅笔与炭笔质感） | 「动漫，卡通，漫剧感」 |
| **系二 描边系**（美漫描边 / 赛璐璐 / 卡通渲染） | **线稿风**（手绘描边 + 平涂灰块） | 「照片写实，真实皮肤毛孔，均匀渐变」 |
| **系三 工艺渲染系**（2026-09-15 补 · 这一行原先漏了） | **先问它是"拍的"还是"画的"**：**定格 / 微缩 / 实物剧场 → 写实灰度**（材料是真的、明暗是真的光）· **木刻 / 水彩 / 油画 / 水墨 / 剪纸 / 像素 / 沙画 → 线稿风**（成片是线条与色块） | **两族都要排**：「照片写实，真实皮肤毛孔」＋「美漫描边，赛璐璐平涂」（→ `style-library.md` §二 系三） |

> **写错的代价**：风格化片的故事板会生成成一张**写实灰度照**，跟后面的成片对不上。**与 `stylized-look.md` 的边界**：这里只切**画法族**（写实 / 线稿），**不是**具体技法（描边粗细 / 网点 / 做旧；技法属成片色彩层 → §4.2 段 2）。

## 八、★ 失败处方表（"不合格怎么改"——旧版只有 6 条勾选项：知道不合格，**不知道改哪句**）

| 症状 | 根因 | **改哪一句** |
|---|---|---|
| 整幅只有一种色调（棕褐 / 灰 / 单色） | 黑白故事板被**直接当成了首帧** | **不是提示词问题**——改路径，回 `key-decisions.md` E4 三条正确用法 |
| 画面出现色彩（哪怕一点点偏色） | 「纯灰度」没写死，或风格锚点行漏了 | 补强第一段：`纯灰度，全画面只有黑、白、灰三种明度`；**逐字复用**风格锚点行 |
| 同一张图里出现多格 / 分格线 | 平台按"漫画分格"理解，或踩了 §二 的禁用路径 | 走**原生组图**（路径 A）；禁止项补 `分格，拼版，漫画分格线` |
| **image2 出图里出现了文字** | **它的文字渲染是强项**（95%+），不写就自己加 | 禁止项**逐字补**：`文字，数字，字幕，水印，标签条内不生成任何文字`（`storyboard-platforms.md` §五·子节 4.4——**该册子节编号 4.1–4.4 ＋ 5.5 混排待整编，本指针按实际位置写**） |
| **image2 要 8 张却只出了 4 张** | 走的**普通档**（上限 4） | 首行声明补 `模式=Thinking`；或**拆两批**（4+4） |
| 多格里角色不像同一个人 | 一致性锚点行**每格重抄**、措辞不一致 | 锚点行**只写一次**（第三段）且**逐字复用**；改措辞本身就是漂移源 |
| 每格都很糊、信息量低 | 格数超过模型能稳撑的量，或逐格写得过长 | **降格数**（宁出 6 张清楚，不出 15 张糊）；**每格砍回一句** |
| 提示词被截断 / 平台报超限 | 长度策略没按平台分流 | Runway 类：**砍到 ≤1000 字符**只留 focused 描述；image2/即梦/可灵可长 |
| 生成数量不是我要的 | 用了"智能适配"，它自己推理了数量 | **改为手动指定张数**；智能适配的稳定性是待验证假设（H4） |
| 人物位置与板块二不一致 | 两块的构图没对齐 | 故事板是**图纸**——改板块二去对齐它，**不是**改故事板 |
| 风格化片的故事板成了写实灰度照 | 量级族选错（§7.1） | 切换画法族与禁止项**成对**改，不能只改一边 |

## 九、可迭代机制（四件东西，缺一不可）

| 机制 | 形态 | 作用 |
|---|---|---|
| **① 参数块** | 四旋钮：`路径 / 张数 / 长度档 / 风格锚点来源` | **迭代＝调旋钮**，不是重写全文 |
| **② 输出模式声明** | 首行一句（§4.1） | 把"数量"变成**可被脚本读的变量** |
| **③ 失败处方表** | §八 | 把"不合格"变成**"改哪一句"** |
| **④ 实测回写位** | 交付文档末尾 `【实测回写】` | 让经验**有地方落**，否则随对话消失 |

**参数块模板（复制进交付文档头）**：
```
—— 故事板参数 ——
路径：A 原生组图 / B 原生 Storyboard / C 一镜一请求
平台与张数：<平台>=<N>          # image2 要 8 张须另标「模式=Thinking」
长度档：长（image2·即梦·可灵）/ 短（Runway ≤1000 字符）
风格锚点来源：<第一镜定稿后逐字复用 / 资产图风格样张>
```

**回写位格式（每次实跑后填一行）**：
```
【实测回写】
2026-09-14｜平台=image2｜模式=Thinking｜张数=8｜结果=7张可用/1张崩手｜有效句=「一致性锚点行逐字复用」｜建议=张数降到7
```

**迭代纪律**：**一次只调一个旋钮**——同时改路径 + 张数 + 长度，出问题**无法归因**。

## 十、与板块二的衔接

| 板块 | 定什么 | 不定什么 |
|---|---|---|
| **板块一 故事板** | 景别 / 机位 / 构图 / 人物位置 / 明暗结构 / 动作的那一瞬间 | 颜色、色温、材质色彩、调色 |
| **板块二 视频提示词** | 光源与色温 / 统一提质层量级 / 动作相位时间线 / 运镜 / 高光颗粒行为 / 人物表演 | 不重新改构图与人物位置 |

**顺序纪律**：先出故事板定构图与明暗 → 再照它写视频提示词。两者的**人物位置与构图必须完全一致**——故事板是视频的**图纸**，不是另一版设计。

### ⚠️ 故事板**不能**直接当图生视频的首帧（实测翻车 · 一字不改保留）

黑白故事板是**灰度**的。一旦直接喂给图生视频，整片会锁死在单色 / 棕褐色调里，后面所有色彩描述都拉不回来（出片整幅只有一种土黄色调）。

| 做法 | 怎么操作 | 适用 |
|---|---|---|
| **A 只做图纸**（最稳） | 故事板只用来定构图与明暗；彩色首帧**用板块二的提示词重新出一张**，构图照故事板对齐 | 通用 |
| **B 结构参考** | 工具支持"参考图 / 结构参考 / ControlNet 类"输入时，把故事板当**结构参考**，颜色全由板块二给 | 工具支持时首选 |
| **C 灰阶首帧再上色** | 先出灰阶首帧，再走一次图生图上色；一致性差、废片多 | 不推荐 |

**判断标准**：出片后整幅画面只有一种色调（棕褐 / 灰 / 单色）＝ 用了错误的首帧路径，回到做法 A。
**路径 B（可灵 Storyboard）补注**：它输出的**已经是视频**，**不受本条约束**；但**它内部仍以你的故事板为构图依据**，"两块的构图必须一致"照旧。

## 十一、判定标准（处方式 · 不合格看末列）

**★ 先跑机器门禁**：`python3 scripts/storyboard_lint.py <故事板文件>`——查**输出模式声明**（缺则 FAIL）· **张数 ≤ 平台上限** · 五段骨架 · 纯灰度 · 拼版 · 参数块与回写位（**逐块查**，故多批不漏；退出码与另两个脚本同义）。
> **⚠️ 它只吃「故事板文件」——不要把板块二（视频提示词）合在同一个文件里**（2026-09-15 实测）。
> 脚本逐个检查故事板提示词围栏，参数块与实测回写块会排除，正文要求也只从提示词围栏取。视频提示词围栏混入时仍会按故事板检查，可能报告缺输出模式声明或彩色词告警。
> **判据**：**一条 FAIL/WARN 若指向视频提示词块，那是口径问题、不是内容问题**——把**故事板块单独存一个文件**再跑（这也正对上"两块分开给、各自可复制"）。
**上限取值**：image2 `8`（要 8 须标 `模式=Thinking`）/ 即梦 `15 − 输入图数` / 可灵 6 / Runway 2（→ §4.0）。**脚本只查结构，不判质量**——下面 12 条仍需人工过。

| # | 检查 | 不合格 → |
|---|---|---|
| 1 | **输出模式声明在首行**，张数 ≤ 平台上限（image2 要 8 须标 `模式=Thinking`） | §4.1 |
| 2 | **张数上限按平台算过**（image2 8/4 · 即梦 `15 − 输入图数`） | §4.0 |
| 3 | **长度档与平台匹配**（Runway 短 / image2·即梦·可灵长） | §五 |
| 4 | 没有"单画布多格"（N 张独立文件是允许的） | §二 |
| 5 | **纯灰度**，画面里没有任何颜色 | §八 行 2 |
| 6 | **一致性锚点行只写一次**，未逐格重抄 | §八 行 4 |
| 7 | 每格**只有一句**，没有堆细节 | §八 行 5 |
| 8 | 明暗结构可读：亮部 / 暗部 / 明暗交界 / 光比都能一眼看出 | §七 第三段 |
| 9 | 主体位置符合本镜构图要求，暗部负空间在 | §十 顺序纪律 |
| 10 | 画法族与全片量级**成对**（风格化片 = 线稿风 + 禁写实词） | §7.1 |
| 11 | 无文字、无数字，标签条是空的 | 模板「风险移除」段 |
| 12 | 交付文档里有**参数块**与**实测回写位** | §九 |
