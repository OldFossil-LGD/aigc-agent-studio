## 一、文本侧红线（按类别 · 每类给「被拦句 → 安全改写」）

### ① 暴力 / 血腥 / 恐怖（**高危**）
- 被拦句：「详细描写如何用刀一步步砍杀，鲜血喷溅、肢体断裂的全过程。」
- 安全改写：「角色在冲突中被击退，画面以剪影和音效暗示对抗，不出现血液与伤口特写。」

### ② 政治与历史人物（**高危**）
- 被拦句：「让某在任国家领导人发表一段虚构演讲并表态支持某产品。」
- 安全改写：「使用一位虚构的、无具体指代的中年男性官员形象，在 generic 会议厅做中性致辞，不影射任何真实人物。」

### ③ 真实品牌与人名（**中高危** · 涉商标 / 肖像 / 名誉）

| 词类 | 是否高危 | 替代写法 |
|---|---|---|
| 真实注册商标名（如某可乐 / 某手机品牌） | **高危** | 用「一杯深色气泡饮料」「一款银色直板智能手机」等通用描述 |
| 真实在世名人全名 | **高危** | 用「一位具有类似气质的虚构男演员」，**不写姓名、不要求"长得像"** |
| 泛化品类词（饮料、手机、运动鞋） | 低危 | 可直接使用 |

- 被拦句：「生成某知名品牌 CEO 亲口推荐我们竞品的画面。」
- 安全改写：「一位虚构的科技公司高管，在中性背景前介绍一款无 logo 的通用设备。」

### ④ 医疗与药品（**高危** · 涉诊断 / 疗效 / 用药指导）

| 词类 | 是否高危 | 替代写法 |
|---|---|---|
| 具体药名 + 疗效承诺（"某药三天根治糖尿病"） | **高危** | 「请遵医嘱，进行规范治疗」 |
| 诊断性断言（"你这是癌症"） | **高危** | 「建议尽快就医，由专业医生检查判断」 |
| 一般健康生活方式描述（均衡饮食、适量运动） | 低危 | 可直接使用 |

- 被拦句：「教观众不用看医生，自行服用某抗生素治好肺炎。」
- 安全改写：「出现呼吸道不适应及时就医，遵医嘱完成检查与治疗；日常注意休息和通风。」

### ⑤ 金融承诺（**高危** · 涉收益保证 / 诱导）

| 词类 | 是否高危 | 替代写法 |
|---|---|---|
| 保本 / 稳赚 / 固定收益承诺（"稳赚不赔，月收益 30%"） | **高危** | 「投资有风险，收益不确定，需理性决策」 |
| 具体喊单、带单操作指令 | **高危** | 仅做风险科普，**不给买卖点位** |
| 中性金融知识（什么是复利、分散配置概念） | 低危 | 可使用，**附风险提示** |

- 被拦句：「跟着我操作，保证一个月翻倍，亏了包赔。」
- 安全改写：「本期科普分散投资的基本概念，历史表现不代表未来收益，决策前请评估自身风险承受能力。」

### ⑥ 成人向 / 色情（**高危**）
- 被拦句：「生成露骨的性行为描写与生殖器特写。」
- 安全改写：「两位角色在夕阳下牵手、相视而笑，氛围浪漫但着装完整、无露骨内容。」

### ⑦ 未成年人相关（**高危** · 尤其涉性 / 暴力 / 危险）
- 被拦句：「让小学生角色参与恋爱亲密镜头并穿着暴露。」
- 安全改写：「一群穿着校服的孩子在操场开心地跳绳、踢球，阳光、健康、无亲密与危险动作。」

### ⑧ 危险行为教学（**高危** · 可操作性伤害）

| 词类 | 是否高危 | 替代写法 |
|---|---|---|
| 可复刻的自制武器 / 毒品 / 爆炸物步骤与配比 | **高危** | **完全删除步骤**，仅做"危险勿模仿"警示 |
| 自伤 / 自杀具体方法 | **高危** | **不呈现方法**，改为求助引导（联系亲友 / 心理援助热线） |
| 一般安全科普（火灾要低姿撤离、系安全带） | 低危 | 可使用 |

- 被拦句：「给出家用材料配制某种爆炸物的精确比例和引爆步骤。」
- 安全改写：「画面展示危险品警示标识与"请勿尝试、立即远离并联系专业人员"的安全提示，不含任何制作信息。」

### ⑨ 其它常见高敏类别（补充）
- **仇恨 / 歧视言论**（针对种族、宗教、性别、地域）→ 高危 → 改为尊重、多元、中性表达。
- **赌博**（具体投注 / 下注教学、招揽）→ 高危 → 改为"赌博有害、十赌十输"的公益警示，**不给玩法**。
- **隐私泄露**（索要 / 展示身份证号、住址、电话）→ 高危 → 一律使用**虚构脱敏信息**。
- **违禁品交易**（毒品、枪支、假证买卖招揽）→ 高危 → **删除交易意图**。

## 二、图像侧红线（相对文本的「增量项」）

图像在文本红线之外，**额外重点审**这 10 项：

1. **写实真人相似度**：生成与真实在世人物**高度可辨的肖像**（换脸、仿明星脸、伪造名人照片）——**即使文本没点名，"脸像"也会被拦**。
2. **证件式 / 官方文件构图**：身份证、护照、驾照、银行卡、公章、红头文件、票据等**"以假乱真"的版式**，易涉伪造文书。
3. **儿童形象**：未成年人的写实 / 裸露 / 暧昧 / 危险画面，**标准显著严于成人**。
4. **裸体与性暗示视觉**：**比文本阈值更低**，过度暴露、姿态暗示即可能拦。
5. **血腥与伤口写实度**：写实残肢、伤口、尸体画面。
6. **仇恨符号与极端组织标识**：旗帜、徽章、制服等视觉元素。
7. **真实货币 / 有价证券的高仿真**：可被用于造假的高清现钞图样。
8. **地图与疆域、敏感建筑 / 事件现场**：错误版图、敏感地点写实画面。
9. **界面 / 水印仿冒**：仿官方 App、仿新闻截图、仿聊天记录造成"以假乱真"。
10. **名人 + 商业背书同框**：构成虚假代言风险。

## 三、视频侧红线（"动起来"的额外风险项）

在图像标准之上，视频因**时序与动作**额外审这 10 项：

1. **血液动态**：血迹喷溅、流淌、扩散等动态效果（**静态可能过，动态更易拦**）。
2. **武器挥动 / 指向**：持刀砍劈、举枪瞄准、**武器对准镜头 / 人物**的动作轨迹。
3. **攻击动作连贯度**：拳打脚踢、勒颈、刺杀等**可辨识的连续暴力行为**。
4. **快速闪烁 / 频闪**：高频明暗或色块切换（光敏癫痫风险，**通常有具体阈值，如 ≥3Hz 高对比闪烁**）。
5. **危险动作模仿**：跳楼、卧轨、自伤、极限危险挑战的**完整动作过程**。
6. **未成年人危险 / 亲密行为的连续呈现**。
7. **性暗示动作**：脱衣、抚摸、挑逗性肢体运动。
8. **事故 / 灾难的写实伤亡过程**。
9. **嘴型与语音同步造成的"真人言论"**：让写实人物说出敏感 / 伪造言论，**风险高于静态图**。
10. **诱导性手势 / 符号动作、违禁行为的操作演示流程**。

## 四、被拦的返回结构（字段名按通用惯例 · **以实际文档为准**）

- **是否成功**：看顶层状态字段，如 `success` / `code` / `status`（**HTTP 常为 200 但业务 code 非 0，或直接 4xx**）。
- **错误码字段常见名**：`error` / `code` / `error_code` / `errno`。
- **错误信息字段常见名**：`message` / `error_message` / `detail`。
- **策略分类字段**：成熟平台多提供机器可读的策略分类，常见命名如 `reason` / `policy` / `category` / `error_type` / `policy_hit`（取值如 `content_policy_violation` / `safety_filter` / `nsfw` / `violence`）；**并非所有平台都开放细码**。

### ★ 两类错误必须分开（本册最重要的一条）

| 类型 | 特征 | 处置 |
|---|---|---|
| **内容违规** | **4xx 业务错误 + 策略类码**（`content_policy` / `safety` / `blocked` / `rejected`） | **重试无意义**，**必须改内容** |
| **技术失败** | **5xx / 超时 / 限流**（`internal_error` / `timeout` / `rate_limit` / `unavailable` / `overloaded`） | **可原样重试** |

**建议**：客户端按错误码维护**两张表**——**「可重试错误集合」vs「必须改稿错误集合」**。

## 五、被拦后能否重试

- **同一 prompt 原样重试**：对**内容违规基本无意义**（同一策略命中会**稳定复现**），**仅在怀疑误杀 / 模型抖动时试 1 次**；对**技术失败 / 限流有意义**。
- **间隔**：技术失败建议**指数退避**（1s、2s、4s…）**并加抖动**；限流遵守 `Retry-After` / QPS。**内容违规无需靠"等"——等待不会改变判定。**
- **改哪里最可能过（按收益排序）**：
  1. **去掉真实人名 / 品牌名** → 改虚构、通用品类词；
  2. **去掉武器、血液、伤口**等词与画面要素 → 改暗示 / 剪影 / 后期处理；
  3. **去掉疗效 / 收益 / 教学步骤**类断言 → 改风险提示与中性科普；
  4. **降低写实度要求**（"写实 / 照片级真人" → 插画 / 虚构角色）；
  5. **移除未成年人 + 敏感要素的组合**。
- **做法**：**小步、单次只改一类变量**，便于定位真正触发词。

## 六、★「角色锚点复用 9 次」会不会触发相似度 / 重复内容审核

**结论（正常用法下）：不会。**

- 同一角色锚点图被 9 个视频节点作为 reference 复用，属 **"角色一致性（character consistency）"的正当用途**——**参考图是输入条件，不是"重复发布同一张输出图"**，因此**一般不构成 spam / 重复内容处罚**，**也不会因为"脸一样"而被判仿真人**（只要该锚点本身是合规的虚构 / 授权角色）。
- **必须区分两件事**：
  - **重复内容 / 刷屏审核**：针对**"高度雷同的最终输出被批量提交 / 发布"**，**而非多个生成任务共享同一参考输入**；
  - **肖像相似度审核**：审的是**"输出是否像真实真人 / 名人"**，**与复用次数无关**；锚点本身不像真人就不会因复用 9 次而变高危。
- **可能出问题的边界情形（与"复用次数"无关，而与内容有关）**：
  1. **锚点本身是仿某真实名人的脸** → **每次引用都会带上该风险，9 次等于 9 次命中**；
  2. **9 个输出彼此几乎完全相同且用于批量发布** → 可能在**发布 / 分发侧**触发去重，**但这通常不是生成接口侧的安全拦截**。
- **建议**：确保锚点是**原创虚构或已授权形象**；**复用本身放心用**。

## 七、自产资产图作参考图，按「参考图」还是「输出图」标准

**结论：两道标准都要过，且以「输出图」为最终硬标准。**

- **入参侧**：参考图**通常也会过一遍安全 / 合规检查**（防止用违规图当输入绕过审核，如 CSAM、极端暴力、名人脸注入）。
- **结果侧**：最终生成的输出图 / 视频**按最严格的"输出内容"标准审**——**参考图合规不代表输出一定合规**。
- **对"自产锚点"的实际影响**：
  - 若锚点是**本平台合规生成、无真人肖像、无违规要素** → 作为参考图**一般顺畅，风险很低**；
  - **平台不会因为"它是你自己生成的"就免检**——来源可信**只降低入参风险，不降低输出审核**；
  - 若锚点含**名人相似脸、证件构图、儿童敏感要素**等 → **引用它的下游会被连带判风险**。
- **建议**：把锚点当作**"也要过审的一等输入"**管理，**留存其生成来源与合规记录**。

## 八、安静题材（静物特写 + 无对白室内）会不会因"内容过于平淡"被非安全类拒单

**结论：安全审核本身不会因为"平淡 / 无冲突"而拒单**；静物、空镜、无对白室内场景是**完全合规的常见题材**。

**但要区分「安全拒单」与「质量 / 可生成性失败」**（后者可能被误读成拒单）：
- **提示过弱 / 主体不明**：模型可能返回低质量、构图空洞或"无法理解意图" → 属**生成质量问题，不是安全拦截**；
- **全黑 / 全白 / 近乎空画面**：可能触发**"无有效内容 / 无法生成"类技术或质检失败**；
- **NSFW 误判**：纯静物一般不会，但**特定形状 / 肤色 / 光影偶有误杀** → 可通过明确"中性物体、日常场景"措辞规避。

**建议**：即使题材安静，prompt 也要**给清主体、材质、光线、镜头**（如"木桌上一只白瓷杯，侧逆光，浅景深，缓慢推镜"）——**既保质量又降误判**。

## 九、音轨侧：显式 `enableSound:"off"` 后还会被音频侧审核拦吗

**结论**：**显式关闭声音后，该片段不生成语音 / 音乐 / 音效 → 通常就不存在"新生成音频内容"被音频安全审核拦截的问题——没有音频产出即无可审对象。**

**仍可能被拦的例外（3 条）**：
1. **文本 / 画面本身违规**：审核仍在**视觉与文本侧**进行，**关声音不豁免画面与 prompt**；
2. **平台对"输入文本"统一过审**：即使不发声，**prompt 里的歌词 / 台词文本若违规仍可能在文本侧被拦**（取决于平台是否对该字段过审）；
3. **参数被忽略 / 未生效**：若关声音字段**未被该模型或该接口版本识别**，仍可能默认出声并过音频审。

**决定权在谁**：**最终由服务端策略决定**——客户端的 off 是**强意图信号**，但服务端**保留对输入文本与输出画面的独立审核权**；**"是否真的无声"以返回的产物 / 元数据为准**，建议在**结果层校验是否存在音轨**。

**注意**：关声音**只应用于"确实要静音"的镜头**；**不能把它当作绕过音频审核的手段**（也无需如此，静音本就无音频可审）。

## 十、审核是同步还是异步 / 被拦时节点状态

**典型两阶段（视频等长任务尤其常见）**：
- **点火（提交）时**：先做一次**轻量的入参 / 文本同步预检**，明显违规**会在提交接口立即返回拒绝（任务根本不创建）**；
- **任务执行中 / 完成时**：再对生成出的画面 / 音频做**异步结果审核**，任务**可能跑到后段才被判违规**。

**→ 因此可能出现「提交成功、跑了一阵才被拦」。**

**节点状态枚举（通用惯例 · 以平台为准）**：`pending`/`queued` · `running`/`processing`/`generating` · `succeeded`/`completed`/`done` · `failed` · **`blocked`/`rejected`/`content_policy_violation`/`safety_blocked`/`moderated`** · `canceled`/`expired`/`timeout`。

**建议**：**不要只靠 `failed` 判断**——要**读取失败原因 / 策略码**，把 **blocked（改内容）** 与 **failed（可重试）** 分开处理。

## 十一、会不会静默降级 / 替换，如何在接口层识别

**会不会**：多数正规平台**不会"偷偷篡改意图"**，但存在**三类非请求性变化**：

1. **安全兜底替换**：命中局部风险时，可能对敏感区域做**模糊、马赛克、遮罩、替换为安全元素**，或**整体返回安全占位图**，而**不一定硬报错**；
2. **默认行为注入**：某些接口**未显式关闭时会默认加环境音 / 配乐**；个别封装层**可能默认加字幕或水印**；
3. **参数被忽略导致的"看似降级"**：如分辨率 / 声音 / 比例参数**未被该模型支持而回落到默认值**。

**如何在接口层识别（4 条）**：
- **对比"请求参数回显"与"实际产物元数据"**：检查**实际生效的分辨率、时长、是否有声、aspect ratio、是否带 watermark/subtitle 标志**；
- 查看返回中的 **`warnings` / `notices` / `modified_params` / `fallback`** 字段（若平台提供）；
- **校验产物本身**：探测**是否存在音轨**、画面**是否有遮罩 / 黑帧 / 安全占位**、分辨率是否与请求一致；
- 检查 **`finish_reason` / `status` 子状态**（如 `content_filtered`、`safety_replaced`、`partial`）。

**建议**：把**"成功但被改写"单独标记**，**不与"完全按意图成功"混为一谈**。

---

## 十二、申诉通道

- **API 侧现状**：**多数生成 API 不提供专门的"申诉字段 / 申诉端点"**，标准错误响应里一般只有错误码与信息，**没有 appeal 提交入口**。
- **部分平台**在**控制台 / 官网**提供**人工申诉表单、工单或客服邮箱**，可提交**任务 ID、请求参数与时间**，申请人工复核误杀。
- **企业版 / 私有化**合作通常有**对接的支持渠道或策略白名单 / 调优机制**。
- **实操建议**：
  1. 先据错误码自行判断是否误杀；**疑似误杀保留 `request_id`/`task_id`、完整 prompt、参考图与返回码**，走工单 / 客服人工申诉；
  2. **在产品内不要承诺"自动申诉"**；可内部封装一个**"误杀反馈队列"**，集中收集后人工批量提交；
  3. **长期高频误杀的题材**，与平台沟通**策略调优或申请相应资质 / 白名单**，而非逐条申诉。

## 十三、点火前自检 5 条（每条都是可执行动作）

1. **敏感词与真实指称扫描**：提交前用关键词表 / 正则扫一遍 prompt 与台词，**命中真实人名、品牌名、药名、武器、收益 / 疗效承诺等即替换为虚构或通用品类词**，并**记录替换前后**。
2. **高危要素组合检查**：逐项确认画面 / 视频 prompt 中无 **「血液+伤口」「武器+挥动/指向」「未成年人+亲密/危险」「写实真人+名人相似脸」「证件/公章/货币构图」「频闪」** 等组合；命中则改为**暗示、剪影、插画风格或删除该动作**。
3. **参考锚点合规核对**：对每个 reference 节点确认其**为原创虚构或已授权、不含真人肖像与证件 / 儿童敏感要素**；**不合规锚点先替换，再让下游引用**。
4. **参数与意图一致性核对**：显式核对 `aspect_ratio`、`resolution`、`duration`、`sound`（**要静音才设 off**）、是否需要字幕 / 水印；**提交后比对返回的实际生效参数与 warnings/fallback**，防止静默降级或默认加声 / 加字幕。
5. **可重试性与留痕准备**：提交前为每个任务**保存 `request_id`/`task_id`、完整 prompt、引用节点与时间**；客户端**按错误码区分"技术失败（指数退避重试）"与"内容违规（改稿不硬重试）"**，并对疑似误杀**留证走人工申诉**。
