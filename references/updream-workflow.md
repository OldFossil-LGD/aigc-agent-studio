# 平台工作流适配（Updream / LibTV）

> **何时读**：出资产、落地到 Updream 或 LibTV、需要参考素材纪律时。**读完回哪**：回到 `studio-workflow.md` 第二步。

Updream：无限画布 + Skill/Agent 节点的 AI 创作平台，底层调用即梦（SeeDream）/ Seedance 等模型。本节是本 skill 的交付物如何直接落进 Updream。

> **⚠️ 本节的数字都是"截至 2026-09 的快照"，不是永久规格。**
> 涉及数量上限的地方（每批条数 / 组图上限 / 参考人数 / 时长 / 多镜数），**平台随时可能改**。
> 用法：**引用数字时带上"截至某月"**；开工前用平台界面或帮助核一遍；**不确定就说"需核"，不要猜**。
> 反例：我们曾把"即梦单次上限 10 张"当成固定事实——**后来官方公式是 `15 − 输入图数`**（见 `storyboard-platforms.md`），**可见数字必须回一手源、并带版本说**。

## 零、统一提质层怎么落进资产图（本节所有模板共用）

本节的角色 / 道具 / 场景模板**全部带同一套统一提质层**（`quality-layer.md`），差别只在带哪几行（**每个板块该怎么想、写哪一句、模型读不读得懂 → `block-playbook-asset.md`**）：

| 模板 | 量级 | 高光颗粒 | 光 | 运动句 | 皮肤句 |
|---|---|---|---|---|---|
| 批量任务文本 | ✅ 进共享风格锚点 | ✅ | 中性光 | ❌ 不带 | ✅ 身份段末尾 |
| 角色设定版 | ✅ | ✅ | 资产中性光（场景光只在首帧版） | ❌ 不带 | ✅ |
| 道具设定版 | ✅ | ✅ | 摄影棚暗调 | ❌ 不带 | ❌ 不带 |
| 场景设定图 | ✅ | ✅ | 该空间光源逻辑 + 死黑比例 | ❌ 不带 | ❌ 不带 |
| 镜头提示词 | ✅ | ✅ | 场景动机光源 + 人物光影块 | ✅ 带 | ✅ |

**量级统一句**（**这一句决定全片观感；不要照抄任何写死的一套**）：
从 `camera-package-library.md` 的 **17 个主包**（或 `package-extended.md` 的 **17 个补充包 P18–P34**）里选定本片那一包——也可**跨包组合**——把它的**「器材」行**与**「痕迹」行**逐字粘进来：
`用[本片方案包·器材行]拍摄；[本片方案包·痕迹行，至少三项]`
**一片一包；资产图与镜头图必须用同一包**（否则人像会像贴上去的）。选包走三问：① 年代 → 档（低端 P01–P06 / 胶片 P07–P12 / 数字 P13–P17）② 光性质 → 包 ③ 机器谁拿着 → 手持或固定；**三问答不出不许挑默认包**——回 `equipment-selection.md` §六 第 ① 步问"真实感由谁承担"，再按六轴组合。

> ⚠️ **不要再照抄 `ARRI ALEXA 35 + Cooke S4/i + 柯达 2383` 这一套。** 那是旧版写死的默认值，2026-09-12 已废除。
> `quality-layer.md` 原话："以前这个位置写死了 `ALEXA 35 + Cooke S4/i + 2383`，结果 113 个风格、所有项目，器材观感全是一个样——**这是「不够真实、AI 味重」最直接的一个来源**。"
**高光颗粒统一句**（照抄）：`高光平滑滚降、渐进出白不裁纯白，过曝处仍带暖色；暗部是有机银盐颗粒簇，暗部粗、中间调细。`
资产图从同一张量级出发，才有资格在剪辑里跟镜头图接得上——这是"统一"的全部意义。

## 一、批量出图：【批量任务】文本（标准格式）

```
【批量任务】共 6 张，逐条独立出图，不要合成一张

共享风格锚点：[本片方案包·器材行逐字]；[本片方案包·痕迹行逐字，至少三项]；
高光平滑滚降、渐进出白不裁纯白，过曝处仍带暖色，
高反差边缘有极轻的红橙光晕；暗部是有机银盐颗粒簇、暗部粗中间调细，不是均匀数码噪点；
中性灰背景，双向柔和光，16比9，无配乐无字幕

共享身份：56岁东亚男性，方下颌高颧骨，花白寸头，发际线后缩，
左眉中段一道约3厘米的浅白色旧疤，右眼下方一颗深色小痣，
右手食指第一节一道横向压痕，藏青色旧式邮电工作服，袖口磨白；
皮肤哑光，毛孔与胡茬清晰可见，高光只是额头与鼻尖的小点，禁止磨皮与蜡像油光

1 正面全身站姿，双臂自然下垂
2 四分之三侧面，转向他的左侧，机位在他右侧
3 正侧面，面向画面左，耳朵可见
4 背面，只见肩线与发际线，不露脸
5 面部近景，疤与痣清晰可见，可见毛孔与细纹
6 坐姿中近景，坐在木桌前，左耳戴单只旧式耳机，目光向下
```

规则：
- 「共 N 张 / 逐条独立出图 / 不要合成一张」是**触发词**，缺了会拼成九宫格。
- 每批 **≤6 条**（**批量与组图是两回事**：批量＝同风格多张候选，走多次独立出图；组图＝一次请求出 N 张关联图，上限按平台算）。
- 批量内**只改单点变量**（视角/材质/状态），不改身份描述与风格词——否则批量等于换人换景。
- 多视角资产走批量——**分对象**：**人物**的六视角/三视图**只是设计稿与视觉基准、不是参考素材**（当参考会被识别成多个主体、加剧 ID 漂移，见第七节第 1 条），出片时从设定板另出（或裁出）一张干净大头照 + 一张全身照；**无生命道具的多角度拼图可直接当资产图**（无面部身份风险）。手部等高频姿态资产**不走批量**，用复用提示词改关键词，保证是同一只手。
- **共享风格锚点必须含统一提质层**（量级 + 高光颗粒 + 中性光，见 `quality-layer.md` 第二节）；资产类**不带运动句**。
- 身份段末尾**必带皮肤哑光句**——油脂感要在资产图阶段掐掉，不能等到镜头阶段。

## 二、Updream 画布流程（从剧本到成片）

```
第1步 剧本：由本 skill 第一步生成，一份完整文档
第2步 资产批量出图（按序，顺序不可颠倒）：
      场景 → 台灯（先定光源）→ 道具 → 角色（推荐直接出一张角色设定版，见下）→ 照片
      每批 4–6 条，出 6–8 张候选选 1 张锁定为参考图
第3步 参考图锁定：角色设定版设为全局资产（命名如"陈默@v001"），
      后续所有镜头 inherit 身份、exclude 构图机位背景光线
第4步 逐镜首帧：每镜先出**黑白故事板**（板块一）审构图与明暗 →
      再按它出彩色首帧（板块二），人物位置与构图必须与故事板一致
第5步 图生视频：把板块二的整合提示词整段喂给图生视频节点
第6步 选片：每镜 4 条候选，按选片检查挑
第7步 不合格镜头回第 4 步重做，不靠加负面词救
```

## 角色设定版（单段整合模板 · 五段式协议）

十个编号分区一张板：主视觉 / 全身三视图 / 服装分层 / 色板 / 材质微距 / 细节插窗 / 面部特写 / 表情表 / 发型细节 / 签名道具。设定板内人物天然同板一致，一致性优于多张批量。

骨架（五段式协议 · `[ ]` 替换）：

```
【置景】一张完整的角色设定板，超宽横版排布十个编号分区，分区之间用细白线分隔，
浅灰白色干净背景；全板统一光照：柔和的顶部中性光加一点暖色边缘光。
美学调性：[类型] / [时代] / [全片时段] / 角色资产图。

核心元素：所有分区中是同一位[身份锚点句——年龄/脸型/发型/疤痣标记/服装/随身物]；
皮肤始终哑光，毛孔与胡茬清晰可见，高光只是额头与鼻尖的小点，禁止磨皮与蜡像油光。

分区1 主视觉：[角色在场景中做签名动作，带本片核心道具，低机位、主体偏画面一侧、留出负空间]
分区2 全身三视图：并排站立——正面、左侧、背面，全身入画，双手自然下垂，穿完整服装
分区3 服装分层：[每件服装平铺展示，磨白/补丁/磨损清晰]
分区4 色板：六列两行网格色块——[本片主要色 6-12 个，即全片调色基准]
分区5 材质微距：[3-4 件关键材质微距]
分区6 细节插窗：一行四个小格——[眼睛/手部与道具接触/耳部或佩饰/衣料细节]
分区7 面部特写：正面与正侧两张面部大图，[特殊标记]清晰
分区8 表情表：一行四个头像——[四个情绪，取自人物弧线]，其余五官与发型完全不变
分区9 发型细节：头顶、侧后、后脑三个角度特写
分区10 签名道具：[核心道具横向排开在浅灰背景上]

【镜头】16比9，写实人像摄影质感，35毫米自然透视，
各分区按设定板版式排布，人物比例跨分区一致，像同一个拍摄日完成。

【光影】全板统一顶中性光加暖色边缘光；皮肤哑光，高光只是小点被毛孔打断，
眼睛各有一粒来自主光方向的眼神光；禁止磨皮与蜡像油光。

【质感与后期】[本片方案包·器材行逐字]；[本片方案包·痕迹行逐字，至少三项]；
高光平滑滚降、渐进出白不裁纯白，过曝处仍带暖色；
暗部是有机银盐颗粒簇、暗部粗中间调细；轻微暗角；
分区标题用简洁的英文小字标签，除此之外画面内无任何文字；无配乐，无水印。
```

要点：
- 表情表只变表情，其余五官发型锁定；四个情绪从剧本的人物弧线里取（如平静/皱眉/震惊/释然）。
- 色板从服装与场景主色取，色板即全片调色基准。
- 锁定后所有镜头 `inherit` 设定板、`exclude` 分区排布与背景。
- 若设定版某分区崩坏：单独重出该分区（图生图 + 局部描述），不重出整板。

## 道具设定版（物品资产图 · 五段式协议 · 一件道具一张图）

角色设定版的下一个节点。同一道具的多视角 + 细节 + 附件组合在一块深色渐变背景上，像博物馆档案拍摄。

骨架（五段式协议 · `[ ]` 替换）：

```
【置景与调性】一张道具资产设定图，同一件[道具名]的多个视角组合在一张深灰褐渐变背景上：
[视角1：45度主视角]，[视角2：正/侧/俯视角]，[视角3：背面或底部]，
[视角4-5：细节特写——最能识别此物的部位]，[附件单独展示：线材/配件/耗材]；
美学调性：[道具的年代与来历，一句话]。

【镜头】写实静物摄影，微距与中距组合，各视角道具比例一致、占画面比例相近，
像博物馆档案的多角度藏品摄影。

【光影】统一摄影棚暗调布光：单一顶光加一侧柔光，背景深灰褐渐变，
道具底部有柔和的接触阴影；逐处写脏：[磨损1]、[磨损2]、[磨损3]；
[材质受光响应：金属哑光带划痕 / 布料吸光 / 塑料留指印]。

【质感与后期】每个视角中道具的比例、颜色、磨损位置完全一致，像同一件藏品；
[本片方案包·器材行逐字]；[本片方案包·痕迹行逐字，至少三项]；
高光平滑滚降、渐进出白不裁纯白，过曝处仍带暖色；暗部是有机银盐颗粒簇、暗部粗中间调细；
无文字，无水印。
```

要点：
- **一件道具一张图**（多件道具不拼同一张）；**同一件道具的多个视角拼在这一张里是允许的**——拼版禁令管的是「故事板 / 镜头图」（每个镜头必须能单独拿到一张全分辨率的图），**资产图里的无生命道具多角度设定板是另一类，允许拼**（无面部身份风险，多角度只增信息）；**人物设定板不适用这条豁免**。
- "像博物馆档案的同一件藏品"是跨视角一致性锚定句，逐视角锁比例/颜色/磨损位置。
- 背景与布光全片统一——所有道具设定图放在一起要像同一个摄影棚拍的。
- 状态有变化的道具（铅笔变短、灯色变红）：每个状态单独一版设定图，版本号命名，不在一张图里画状态变化。
- 无磨损描述 = 模型给你全新塑料；逐处写脏是硬要求。
- 锁定后所有镜头 `inherit` 道具设定图、`exclude` 背景与布光。

## 场景设定图（空间资产 · 五段式协议 · 多角度）

场景与道具同一逻辑：一张设定图含多视角（主视角/反打/侧向/顶部平面），或每视角一段独立提示词。

五段映射：①置景 = 空间布局 + 全部陈设罗列（每样具体到材质状态位置）+ 出入口与边界；②调性 = 类型/时代/时段天气/内外景；③镜头 = 各视角的景别机位构图；④光影 = 场景光源逻辑 + 光池衰减 + 混色脏带 + 死黑比例；⑤质感与后期 = 材质脏 + 大气透视 + 体积雾 + **统一提质层的量级句与高光颗粒句**。完整实例见《加班_场景资产提示词.md》。

一条纪律：**场景资产图里不出现人**——人物由角色资产单独出，场景与人物分开锁定再合成，这是防"人景光影不接"的根本做法。

## 三、一致性操作

- 同一角色跨镜：**同 seed 族**（主 seed ± 2），微调不出新角色。
- 同场景不同机位：同 seed 族 + 环境参考图。
- 图生视频优先：首帧锁死脸与场景再让它动。
- 出现脸漂移：先怀疑参考里混进第二个身份，**不加负面词**。
- 中文字迹一律不要求 AI 生成可读，后期贴图。

## 四、组图触发词（需要一次内容关联的多张时）

组图输出（一次请求 → N 张独立文件）：提示词含「一系列 / 组图 / 帮我生成几张 / 分别」即可触发。适用：情绪图组、材质变体组、**整段故事板分镜**。
**上限按平台算，不要记数字**：image2 `n=8`（Thinking）/`4`（普通）；即梦 `15 − 输入图数`；可灵示例 6；Runway 固定 2。**★ 出故事板时不要用"四格一张"这类单画布多格**——要 N 格就出 N 张独立文件（`storyboard-frame.md` §二）。

## 五、生成顺序门禁（放行规则）

每个资产放行前检查：
- **统一提质层在位**：**本片方案包的量级句**（把选定包的「器材」行 + 「痕迹」行逐字粘上）、高光颗粒句、中性光——三句缺一不放行
- 多视角是同一个人/同一件东西
- 身份不变量全部可辨（疤、痣、压痕）
- 光位与全片一致
- 无第二个同类物体（第二支笔、第二本日志）
- 无可读文字、无配乐、无字幕、无水印

一条不过，回资产层重出，**不许带病进镜头**。

## 六、成本与迭代纪律

- 先 720p/低配测运动与构图，确认后再上高分辨率终稿。
- 每轮只隔离一个变量：改参考图不动提示词，改提示词不动参考图。
- 连续两批同一错误无改善即停：拆镜 / 降复杂度 / 转后期。
- 复杂镜头按 300 条素材量级预估，按难度系数（S×8 / M×16 / L×32 / XL×60）排预算。

### 六·补 止损分档（把"即停"变成可数的动作）· 2026-09-13 补

上面那条"连续两批无改善即停"给了**原则**，`production-ledger.md` 第四节给了**可数的触发点与完整理由**（唯一主场，此处不复述）：**1–3 次正常试错 → 4–5 次判责任层 → 6–8 次换实现路径（不换词）→ 超过 8 次改结构**（拆镜 / 换机位 / 换景别 / 功能转移）。
两条要记住的：**禁止"再抽最后一次"**；**止损≠放弃意图——意图守恒，手段可换**（→ `direction-reasoning.md` 第五节）。

### 六·补二 生成台账（每一笔留一行）

**不记账 = 永远不知道自己的真实命中率**，只能引用别人的公开数据，于是每次都按最乐观预算排片。格式与用法见 **`production-ledger.md` 第六节**（唯一主场）。

## 附、LibTV（哩布哩布 AI）—— 第二个"双入口"平台（2026-09-20 补 · 一手已核）

**为什么写在这里**：它与 Updream 是**同一形态**（无限画布 + 节点式工作流 + Agent 入口），本册的【批量任务】格式 / 五段式协议 / 组图触发词**可以原样搬**；差别只在它有几件能力是**平台原生封装**的。

**★ 形态同构（最要紧的一条）**：它的 Agent 入口吃的就是**一整段自然语言消息**（`POST /openapi/session`，body 的 `message` 即整段提示词）——**与本库"交付一律一段可直接粘贴的整合提示词"是同一个形状**。**所以投喂方式＝把板块二整段贴进去**，不需要为它改写成结构化参数。

**平台身份（已核 · 一手：官方 Skill 仓库 README）**
- 发布方 LiblibAI · 2026-03 上线 · 官方站 `liblib.tv`
- **官方 Agent Skill 仓库**：`github.com/libtv-labs/libtv-skills`（**MIT** · Python 3.6+ 纯标准库 · 遵循 **OpenClaw 技能规范**）
- 鉴权：`export LIBTV_ACCESS_KEY="..."`（HTTP `Authorization: Bearer`）
- 接口四条：`POST /openapi/session`（建会话 / 发消息）· `GET /openapi/session/:id`（`afterSeq` 增量轮询）· `POST /openapi/session/change-project` · `POST /openapi/file/upload`
- 仓库脚本五个：`create_session` · `query_session` · `change_project` · `upload_file` · **`download_results`**（`--prefix` 命名 · `--output-dir` 落盘 · 也可直接传 URL 列表）
→ **`download_results.py --prefix` 正好接 `delivery-engineering.md` 的命名纪律**；会话返回的 `projectUrl` 就是画布链接——**交付时"本地路径 + 画布链接"一起给**。

**★ 逐文件深读官方仓库后的三条元规则（2026-09-20 补 · 一手：`git clone` 后逐文件读源码，非网页摘要）**

**① 一次任务只有一个编排者（最要紧）**
官方 `SKILL.md` 明写「**用户侧不做创作，只做传话**」——用户侧是**搬运工**（上传 / 传话 / 取件），**编排权在后端**（"后端有专门的 Agent 负责理解需求、拆解分镜、编排工作流、选模型、写 prompt"）。

| 场景 | 谁是编排者 | 怎么投 |
|---|---|---|
| **我们编排**（"恰好 1 段 2 画面""机位锁死只变焦"这类本库独有的约束） | **我们** | **整段提示词一条消息发过去，不拆步骤、不另加词**——官方禁的是"**拆多次请求**"与"**替用户加戏**"，**没有禁"用户自己就是创作者"** |
| **它编排**（九宫格推演 / 一句话短剧 / MV） | **它** | **只传原话，不要叠加我们的分镜表** |

**判据一句话**：**先问"这次的任务书是谁写的"；谁写的，另一方只做搬运。**（两个编排者同时上场＝打架，质量掉）

**② "不要拆步骤"与本册 §一 的【批量任务】不矛盾**
官方禁"把生成 9 张拆成 9 次请求"；本册写"共 N 张、逐条独立出图、不要合成一张"。**对齐点＝一次请求里说清张数与"逐条独立"**，由后端决定怎么拆。**本册从未主张发 N 次请求——读的时候别读反。**

**③ 取件的三条硬事实**
结果 URL **域名固定** `libtv-res.liblib.art`；抓取要**同时扫两种角色**（`tool` 消息的 JSON `task_result.images[].previewPath` ＋ `assistant` 正文的 URL 正则）——**只扫一种会漏**；序号来自**提取顺序**，且**无扩展名会一律存成 `.png`** → **落盘后按后缀分诊一次**（落法 → `delivery-engineering.md`）。

**★ 四条实现级硬事实（只有读源码才拿得到）**：① `create_session` **只有 `message` 一个位置参数**，没有模型 / 比例 / 时长 / 张数参数 → **"提示词＝唯一输入形态"是代码事实，不是文档口径**；② **上传端点以代码为准**——README 写 `/openapi/file/upload`，**代码打 `/openapi/upload`**；③ 缺 `LIBTV_ACCESS_KEY` 时 **import 阶段就退出**（连 `--help` 都跑不了）；④ 它的 frontmatter 带 `requires.bins` / `requires.env` / `primaryEnv` **依赖声明**——**本 skill 没有这一层**，将来要上 `npx skills` 生态得补。

**★ 未核升级（重要）**：上一轮"12 块会不会被完整执行"只是猜测；本轮读到官方立场——**后端会"理解需求、拆解分镜、编排工作流"**，所以**它很可能对我们的结构化提示词做再编排，而不是逐字执行**。**这不是结论，是把疑点从"猜"升格为"有官方口径支撑的疑问"**——实测必要性因此更高。

**★ 提示词粒度的两档（2026-09-20 补 · 依据**第三方**教程口径【拟订 · 未实测】）**
- **全量档**（**无参考图 / 未建主体库**）：12 块整段照写——身份、风格、光都要自己说清。
- **精简档**（**已上传分镜图 / 已建主体库 / 已传定妆照**）：**只保留"本镜发生什么 + 硬约束（景别、计数、禁止项）"**，身份与风格交给参考素材。教程原话：*"你有参考图和分镜图之后，视频提示词只干一件事——告诉 AI 接下来发生什么；写成一大段华丽文案是新手最容易犯的错"*。
- **判据（一句话）**：**"这条消息里，有多少字是在描述参考素材里已经有的东西？"** —— 超过一半就改用精简档。
- **不因此改的**：**不写秒数**（用户定案）——即便生态里常见 `镜头1(0-4秒)` 这种带秒写法。**★ 2026-09-28 落库注：这条只约束提示词正文——导演台（Script V2）分镜行的时长字段照填**，秒数走结构化字段，不进提示词。

**★ 导演台与白模：MCP 里到底能做多少（2026-09-20 实测 · 零积分）**

| 层 | 工具 | 成本 | 实测 |
|---|---|---|---|
| **剧本 / 分镜层**（导演台的"镜头列表"） | `create_script_v2`（**1–15 秒/镜**；字段＝景别 / 情节 / 情绪 / 光位与影调 / 声音 / 台词 / **资产绑定**。**★ 2026-09-28 落库注：这个 1–15 秒是 Script V2 的**字段区间**，具体模型收不收这个时长另算、逐模型不同**——如 `seedance-1.5-pro` 的 `duration` 只有 [5,10] 两档；模型×时长逐行对照见 `libtv-official-qa-part3.md` R10.2）· `read_script_v2` · `edit_script_v2` · `check_continuity` | **零**（明写"不生成内容或媒体"） | ✅ **已建成 3 镜表并读回** |
| **时间线层**（导演台的"排镜、切点、导出"） | `read_timeline` · `apply_timeline_edit`（`mode: plan` 免费；支持 insert / trim / split / move / ripple_delete / set_transition / align_audio / set_gain / set_speed / set_transform；**明写"编辑从不触发渲染"**）· `export_video`（**只有这一步花钱**） | 编辑零 · 导出花钱 | 编辑未测（本次未用到） |
| **白模** | **① ✅ 能做**：`upload_ticket` / `upload_complete` 传**白模视频** → 当 `video2video` / `frames2video` / `mixed2video` 的参考（即 `motion-control.md` 的"参考视频驱动"）**② ❌ 不能做**：**3D 导演台里摆白模人偶那种交互是 UI 专属**——9 个业务模块里没有 previs / 白模 | 上传零 · 生成花钱 | 未测 |

**★ 一条重要发现**：Script V2 的每一行里带 **`imageGenerationPrompt` / `videoMotionPrompt`** 两个**派生字段**（留空即报 `STALE_SHOT_PROMPT`）→ **平台的提示词是从"分镜行"自动推导的，不是手写的**——再次印证"编排在后端"，也解释了为什么它欢迎结构化分镜、却不欢迎我们替它写完整提示词。

**★ 它的连续性检查可以直接当我们的又一道门禁**：`check_continuity` 给**逐对相邻镜的 9 类事实对比**（角色 / 场景 / 道具 / 景别 / 情绪 / 运镜 / 光 / 台词 / 声音）+ 9 条"需看片"项 + **3 条明写"没证据不能判"**（屏幕运动方向与轴线 · 视觉身份 · 动作与音画同步）。与我们 `shot-linkage.md`、`editing-rhythm.md`（180 度线）、`character-continuity.md` **同构**——**而它把"不可判"写在明面上，这一点比多数人的自审更诚实。**

**★ 想读它"怎么写提示词"：只能读到一半（2026-09-20 实测 · 零积分）**
- ✅ **能读**：`search_skill_templates` 的**公开模板目录元数据**（一次查"分镜"返回 40 条：名称 + 一句描述 + 版本）· Script V2 的**字段结构**（＝它的提示词骨架）· 派生字段名 `imageGenerationPrompt` / `videoMotionPrompt`。
- ❌ **读不到**：**Skill 的可执行指令**（工具原文"returns metadata, **not executable Skill instructions**"）· 它的 system prompt。**要读它实际写出的提示词，只能花钱让它跑一次，再看被填上的派生字段。**
- **从目录学到的一条可直接用**：生态里**"白模"的落地形态＝火柴人预演**——有现成模板「动作指导—火柴人分镜预演」（`libtv-user-generated/action-previs-…`），做法是**火柴人草稿视频 → 当 `video2video` / `frames2video` 的参考**（正是 `motion-control.md` 的"参考视频驱动"）。
- **两条"我们更硬"的对照（不改）**：① 生态把"生成前强制检查 prompt"做成一个 Skill（建议性），我们是**脚本 + 退出码**（门禁性）；② 导演风格它是**一片一 Skill**（王家卫 / 张艺谋 / 胡金铨各一条），我们是**一个风格库 + 编号路由 + 六把尺子**。
- ⚠️ **证据性质**：目录条目属 `libtv-user-generated`（**社区 Skill，不是官方内核**）——**它反映生态共识，不代表平台官方口径**，引用时标清。

**★★ 全流程实测（2026-09-20）：七环全通，但导出层有两个坑**
- **七环**：分镜表 `create_script_v2` → 连续性 `check_continuity` → 资产（图）→ 镜头（视频）→ 时间线 → **导出预检 `export_readiness`** → **合成导出 `export_video`**。**实测把 T1(2s) 与 T2(8s) 直拼成 10.00s 成片**，拼接点整体平移 +2.000s 一一对应 → **导出是"按列表顺序无损直拼 + 源秒截取"**（`taskParams.nodeKeyOrderedList` 自证）。
- **★ 坑一「能编不能出」**：`export_readiness` 的 `executionContract.unsupported` 明写导出**不支持** `speed · transitions · transforms · subtitles · per_clip_volume · per_track_volume · audio_source_trim`，**而 `apply_timeline_edit` 声称支持 set_speed/set_transition/set_transform/set_gain** → **在时间线上设了转场/变速，导出会静默丢弃**。**交付纪律：转场与变速回本地剪辑软件做，不要在平台内设了就当数。**
- **★ 坑二「强制加音轨」**：两条源视频**都关了声**，成片里却出现 `aac 48kHz stereo 2kb/s`（≈静音）→ **"零音轨"只能要求到源素材层**；交付时别拿"有无音轨"当校验点。**★ 2026-09-28 落库注：要在成片里真静音，在合成入参设 `video_volume = 0`（各镜原声彻底静音，→ `libtv-ignite-ops-fields.md` §1.8），不要依赖"源素材没声"。**
- **成本纪律**：**只有"生成"花钱**——分镜表 / 连续性 / 时间线编辑 / 导出预检**全免费**；**合成导出走 `media-platform` 合成器（非生成模型），大概率不计生成积分**。→ **改结构、重排、重拼、重导几乎不花钱，花钱的只有重新生成素材**（抽卡要克制，剪辑可以大胆）。
- 它自己的边界（原文）：`Sources are readable; rendering and playback are not verified.` → **预检通过 ≠ 渲染正确**。
