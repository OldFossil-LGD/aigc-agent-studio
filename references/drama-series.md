# 剧集层：引擎 · 人物网 · pilot · 文档（**多集 / 长篇专用**）

> **何时读**：要做**剧集或长篇**（含 20–45 分钟单集、多集、系列）时——**立项、写 pilot、做提案、诊断"这更像电影不像剧"**。
> **读完回哪**：单集与季的幕结构 · 卡点 → 见 `drama-structure-models.md` 模型 15 与 `drama-scaling.md` 的剧集档；交付 → `script-module.md`（每集一套 M1–M12）；方法 → `writing-methods.md`。
> **适用**：剧本 / AIGC 写作。**NOT for** 技术文档 · 论文 · 新闻 · 公文（判据见 `writing-methods.md` §0）。
> **口径**：**本册只主编"引擎层"**——即"**凭什么每周都还有故事**"。**单集的拍与秒、镜头与卡点不在本册**。

---

## §0 一句话：电影与剧集不是长度差，是机制差

| | 电影 | 剧集 |
|---|---|---|
| 交付 | **一个答案** | **一台不断产生问题的机器** |
| 主角 | 解决一件事 | **每周做同一件事**（但每次不一样） |
| 观众契约 | 一次性 | **默契契约（tacit contract）**：同一部剧，每周都新 |
| 判据 | 结尾对不对 | **引擎会不会失压** |

> **一句话记法**：**剧集每集仍要交付一部电影的情节量**，但**它的价值在"下一集还有戏"**。

## §1 引擎的四元素（**先有引擎，再谈集数**）

**franchise（可续的引擎）＝ concept ＋ conflict ＋ theme ＋ story pattern**。四件缺一，就会"每周重新发明整部剧"。

| 元素 | 要求 | 反例（诊断信号） |
|---|---|---|
| **concept 容器** | 一句话能说清"这是干什么的行业/处境"；**容器可换**（换职业 / 换地点 / 换时代） | 容器换了却讲不出同一个故事 |
| **conflict 冲突** | **必须能落到人物之间**——抽象概念电视剧演不了 | 冲突留在**一个人内部**（观众感到"空"）；"有容器、无冲突、无主题" |
| **theme 主题** | **禁止单词**；必须是**可争辩的对立命题**（"忠 vs 义"不够；要写成一句话的对抗） | 主题写成"关于孤独""讲人性" |
| **story pattern 形状** | **每集重复的那个形状**，一句话写出；**并在 pilot 的后半段完整跑一遍**；**再挂一句全剧总悬念**（＝硬判据 2 的过程句"X 如何在 Z 的世界里继续做 Y"，跨集不换——§5 装置一的"分解层"全挂在它下面） | 说不出"每周的形状"，只能说"每集不一样的事" |

**三条硬判据**：

1. **咬合测试**：**当场想出第 2 个、第 6 个故事**——每个故事都必须同时碰到 concept 与 conflict。想不出 → 引擎没造好（不是"再想想"）。
2. **核心问题必须是过程句**：写成 **"X 如何在一个 Z 的世界里继续做 Y？"**（"谁杀了那个人"是**答案句**，只能撑一集）。
3. **主题必须回头修正 concept**（顺序别反）：先定一个你真正关心的**时代里的长期争论** → 用主题去改造容器，而不是先定容器再想主题。

**★ 三条"加大"法**（不够大就可能没人抽样）：**换职业** · **换地点** · **换时代**。
**★ 同时保留一条反向立场**："**人物永远赢过高概念**"——**用高概念让审读肯读，用人物让剧活下去。**

## §2 怎么判断"这剧该有多长、什么时候该结束"

**两种判据，先按媒介与订购方式选，不要都跑**：

| 媒介 | 用哪条 | 怎么算 |
|---|---|---|
| **可无限续订的商业剧** | **"还能再跑多少集"** | 能否想出 99 个故事（**个别连作 / 情景喜剧的整季同引擎变体可另计**）；能否撑很多集/多季（**美国广播网的续订经济学判据**） |
| **闭合长篇 · 限定剧 · 迷你剧** | **引擎失压测算** | 写下**物质性情节引擎**（交易、帝国、职位、案件来源、外部压力源），问：**第几集它会开始失压？** 那一集就是该结束的地方——**集数由此"论证"出来，而不是被接受** |

**★ 为什么必须分**：照字面跑"能不能撑很久"会把**封闭空间、一间办公室、一桩旧案**这类**本来就短**的合格项目否掉。
**★ 一条反直觉的证据**：**概念强弱不决定可持续**——概念更炫的那部剧可能只活了几季，而概念更窄的那部拍到十季。**pilot 之后想不出三集的病灶在人物冲突，不在 concept。**

## §3 人物的可持续性：一张能自己产生冲突的网

**三件套（缺一撑不到三五年）**：
```text
① 一个团体 / 家庭的纽带（他们必须在一起）
② 每人预装的、与其他角色必然摩擦的性格属性
③ 一个让他们无法离开彼此的处境（巧合或结构性绑定）
```

**六条可直接用的写法**：

| # | 方法 | 判据 |
|---|---|---|
| 1 | **每部剧都是家庭剧**（无论有没有血缘）；**所有剧中家庭都必须不完美、且在某个层面不满** | 关系网能不能自己长出故事 |
| 2 | **按按钮**："**最爱你的人最知道怎么伤你**"——写两人场之前先写清"他知道对方哪个按钮、这一场按不按" | 写不出按钮表 → 关系是平的 |
| 3 | **交易型家庭**：**寻求老板的认可取代了寻求父母的认可**（还附带薪水）——因此**能力与爱都要靠"批准"发放** | 上位者吝于认可 = 冲突永动机 |
| 4 | **长处同时是负担**：**一个人最大的本事必须同时是他最大的负债**，并让他长期停在这个夹缝里 | 主角只有优点 → 没有可持续冲突 |
| 5 | **觉醒的力量同时是软肋**（grounded superpower = liability）：内心驱动力必须有**物质性后果**，不能只是情绪 | 驱动力不产生代价 |
| 6 | **同一段前史的两次陈述**：**先给一个修饰版，几集之后在更安全或更被迫的场合给真版本——两者之差就是这个人物的羞耻** | 前史一次说完 → 人物用完了 |

**内在冲突必须外化成一圈人**：把一个"内心的"两难，拆成**三个立场不同的人**各自代表一边——**留在一个人心里的冲突产生不了故事**。
**对抗力先定"性质"，再决定它要不要一张脸**：性质（贪婪 / 悲伤 / 恐惧 / 体制）定了，再决定它落到一个人身上还是落成系统。
**反派在自己的故事里是英雄**——他自觉正当、有理有据。
**不要立稻草人**："**propaganda 就是确认你已经相信的东西**"——更值钱的是**让观众喜欢的常规角色彼此不同意、而且每个人都有道理**。

## §4 pilot（试播集）：三种类型与四条判据

| 类型 | 特征 | 适合 |
|---|---|---|
| **premise**（开局集） | 第 1 集发生的事**对"这部剧从第一天开始"是必要的** | 世界规则复杂、必须解释（科幻 / 奇幻 / 高设定） |
| **midstream / non-premise** | **"这是观众的第一集，但不是人物的第一天"** | **人物关系网即引擎**（群像、职场、家庭） |
| **hybrid（混合）** | 高潮开场再闪回/闪前；或**前半设定 + 后半跑一遍 story pattern** | 两者都要 |

**★ 四条判据（命中两条以上，一律走 hybrid）**：① 保守的大众频道 / 轻喜剧 → typical 或半 premise；② 世界设定复杂 → premise；③ 人物网即引擎 → midstream；④ 两个都要 → **前半设定、后半跑 pattern**（**④ 是唯一能在一集里同时交付"设定"与"每周长什么样"的形状**）。

**三条进场硬规则**：
1. **不要把 inciting incident 留到集末**——"不能只有一集长的第一幕"。
2. **"在世界里尽量晚进入，在剧本里尽量早开始"**（某剧原稿委托人第 12 页才进门，成片提前到第 6 分钟）。
3. **前十页决定生死**。

**收尾三条**：① **pilot 的结尾就是剧的开头**；② **要"稳稳落地"**；③ **不一定非要悬念**（刻意不解释机制也是一种选择——不是所有事都非黑即白）。

**pilot 结束时必须交出的东西**：**至少十个让观众揪心的问题**——并**把这十个问题各推成一条未来集的梗概**（一份作业同时完成两件事）。多颗问题与"只追一个问题"的共存挂法 → §5 装置一：**全部挂在同一句总悬念之下作分解层**。

## §5 两种"让每一集都不一样"的装置（**本节是长篇的日常工具**）

**装置一 · 潜台词地雷（story landmines）**
在 pilot 的**潜台词**里埋下、若干集后才引爆的人物冲突。**每个主要人物各埋一枚**（未言明的恐惧 / 欲望 / 矛盾），**并写下预计第几集引爆**。
**必须是人物层面**——"她是警探的女儿"不算地雷，那只是背景。

> **★ 多颗地雷与"只追一个问题"如何共存**（长剧最常见的结构性冲突）：不要减少地雷，而是**改变挂法**——**把全部地雷挂在同一个总悬念之下**，当作它的**分解层**：**每集只揭一层，揭一层立刻补一个带时限的新悬念**。于是观众追的始终是**一个问题**，而你手里仍有八颗定时炸药。排表时给每枚地雷写**两个集号**：引爆集，以及它揭开了总悬念的第几层。

**装置二 · 记账式单元（把"结案"改成"记账"）**
**每集"解决掉"的事，必须在后面某一集留下一笔要兑付的账。**
- 一般案件剧到中段开始重复，原因是**每集结案 = 清零**；改成记账就不会：本集签成的协议、保下的人、压住的投诉，**都在账上留一个条目，由后面指定的某一集兑付**。
- **写法**：排大纲时每条账写成一行 **`第 N 集做了什么 → 第 M 集谁付账`**，**M 必须是具体集号**；**一季 6–10 笔**为宜（太少各集仍是孤岛，太多观众记不住）。
- **与"每集一案"的关系**：**单元照旧闭合**（观众每集拿到结果），**代价不闭合**——这是单元剧与连续剧之外的第三条路。
- **自检**：**随手指一集，说出它欠谁、谁来还、第几集还。** 答不出的那一集，就是一个被清零的集。

**分段用"同一套本事的第几种用法"，不用时间顺序**：
主角的技能不变，**用法换一次就是一个段落**（学着用它赢 → 一边赢一边用它办私事 → 反过来用它并引爆更大的代价 → 放弃原目标、改用它去改规则）。
**好处**：分段线长在人物身上，不长在日历上；每段的收束就是"这种用法的反噬"，不必另设。
**判据**：**说不出这一段里主角对这套本事的用法与上一段哪里不同，这一段就是水的。**

## §6 类型与定位（选错就被锁死）

**八个系列类型**（判定用）：程序剧（闭合）· 连续剧 · 程序+连续的混合（三式）· 情景喜剧 · 迷你/限定剧 · 选集剧 · "迷你剧式系列"（每季换题材同一框架）· 网络短剧。
**情景喜剧的不成文规则**：**人物不变，而且这没关系。**
**限定剧（约 4–10 集）是从电影转剧集最容易的第一步。**

**story-type 判定（问一句）**：**"这一季的主问题从哪里来？"**
- **来自外部** → **情节驱动**（plot-led）
- **来自主角内部** → **人物驱动**（character-led）——**它不需要"反派"，需要一个催化剂人物**
- **来自社会 / 故事世界** → **主题驱动**（theme-led）
- 剧集几乎都多线，所以**要反过来查**：**有没有一个主角、一条在季层成形的主行动线？** 有 → 它不是主题驱动。

**★ 最常见的死法（box-in）**：**人物驱动的剧在第一季把主角的内部问题解决干净了**（这是电影思维）→ 第二季被迫换类型。
**受众位置**：**越靠近马斯洛底层，潜在受众越大**；**必须"垂直探索"**（同一部剧里向上下两端探，而不是横着堆同类）。
**赌注自检**：**任何一集都必须说得出"本集赌注是什么"**，且**各条线必须彼此相连**。

## §7 文档：从 logline 到剧集圣经（**两份都写，只交一份**）

**三级文档**：**创意（concept）→ 系列陈述（presentation）→ 系列文献（bible）**。

| 文档 | 页数口径 |
|---|---|
| bible | 10–85 页（**书面 pitch bible 10–30 页，甜点约 15 页**——**可续订商业剧的行业口径**；闭合长篇 / 迷你剧按需缩减，不必硬套） |
| mini-bible | 约 5 页 |
| treatment | 正剧 10–15 页 / 喜剧 8–10 页 |
| 半小时喜剧 series format | 10–15 页 |
| 口头 pitch | **20 分钟**（务必计时） |
| mythology 文档 + 起源故事 | 合计**一页上限** |

**四套字段清单（挑一套，不要混）**：① 关卡式 guideposts（约 25 字段，可当 bible 目录；**logline 里必须出现"但是"**；**中心问题是关于"未来"，中心谜团是关于"过去"**）② 提案 11 项配方 ③ treatment 10 要素 + 六大问 ④ **一页 17 栏故事地图（同一套栏目在"本集"与"全剧"两个层级各填一次）**。

**★ 最容易写错的五处**：
1. **概览不是 pilot 的摘要**——要写**整部剧的世界与追求**，并在概览里就给出"启动器"。
2. **人物不要列清单**——要把人嵌在故事里介绍。
3. **不要把知道的全说出来**——**被追问才是成功**。
4. **不要过度规划**（把第五季写死 = 自己上锁）。
5. **文风必须与类型一致**。

**★★ 文档的读者（最容易被忽略的一条）**：
> **写作用文档**（地雷表 / 按钮表 / 绑定物 / 故事线文档）与**送审用文档**（logline / 概览 / 人物 / pilot 梗概 / 后续故事）**是两份东西**。
> **平台不会看你的工具表；而把工具表删干净的"提案"又会让你自己在中途断气。两份都写，只交一份。**
> **判据**：**一页纸上如果出现了本册的术语（引擎 / 地雷 / 对立命题 / 形状），它就是给你自己看的。**

## §8 分歧保留表（**同一问题各家说法相反时，本库怎么选**）

**为什么要有这张表**：长篇方法论的最大风险是"两个都对，但你只能选一个"。**先定判据，再选边**，不做和稀泥。

| 争点 | A 方 | B 方 | **本库用法** |
|---|---|---|---|
| 要不要预先规划多季 | 预先规划是傲慢（会把后面的冲突提前解决掉） | 提案时必须给出第一季清晰愿景 + 后续方向 | **提案按 B（要卖），生产按 A（要活）** |
| 进室前知不知道季终 | 写第 1 集时已知季终 | 靠摸索演化 | 群像多线 → A；靠化学反应演化的 → B |
| 先写剧本还是先提案 | 先写剧本（spec） | "剧本也是六十页的拒绝理由" | 无履历按 A；有履历或已包装按 B |
| premise 还是 typical 试播 | typical 更保险 | 不是陷阱，说明清楚就行 | 按 §4 四条判据 |
| 主题的地位 | 主题是四元素之首 | 编剧室里几乎不用"主题"这个词 | **开发按 A（主题是过滤器），写戏按 B** |
| 人物会不会变 | 主角必须变 | **变的是观众对他的感知**；人也会**变小** | **可变的是处境与目标；核心常量由作者定义** |
| 幕是不是结构 | 忘掉三幕 | 幕只是**物流格式**（几根、多长） | **引擎与幕数无关**——引擎先行，幕后配 |
| 要不要高概念 | 不够大没人抽样 | 人物赢过高概念 | **并存**：高概念负责被读，人物负责活下去 |
| 家庭/关系剧引擎是否弱 | 有先天问题 | **每部剧都是家庭剧** | 那种"先天问题"判断限于特定市场与年份；**要配强引擎或制度性摩擦** |

## §9 诊断清单（**立项 / 写 pilot / 提案时跑；改一个已播的单集请整组跳过**）

```text
引擎
① 主题是可争辩的对立命题，不是一个词吗？
② 主题落成两个人之间的冲突了吗（内部冲突外化了吗）？
③ 咬合测试：能当场想出第 2 个、第 6 个故事吗？
④ 核心问题是过程句，还是答案句？
⑤ story pattern 能一句话写出，并在 pilot 后半跑完一遍吗？
⑥ 后续故事来源与结局形态雷同吗？
⑦ 这组冲突按媒介该跑的那条判据过了吗（能续订的量 / 引擎第几集失压）？
⑧ 每集赌注说得出来吗？
⑨ 主角是参与者还是观察者？他有介入他人生活的权限或处境吗？

人物网
⑩ 每个主要人物各带一枚潜台词地雷吗？预计第几集引爆？
⑪ 每个主要人物的两个属性互相干扰吗？
⑫ 有没有把"痛苦"当成冲突（痛苦本身推动不了故事）？
⑬ 对抗力的性质定了吗？定了之后才决定要不要一张脸。
⑭ 反派在自己的故事里是英雄吗？
⑮ 每一对人物的关系"按钮"写出来了吗？
⑯ 主角的长处同时是他的负债吗？
⑰ 有没有一处"同一段前史的两次陈述"？

pilot 与文档
⑱ pilot 是哪一型、为什么（四条判据）？
⑲ 核心谜团被演出来了吗（演出来就废了）？
⑳ 结尾留下十个揪心问题、并推出十条未来集了吗？
㉑ 概览写成 pilot 摘要了吗？
㉒ 文风与类型一致吗？
㉓ 人物驱动剧第一季就把内部问题解决干净了吗（最常见的锁死）？
㉔ 该交的那一份里出现本册术语了吗（出现 = 交错文件了）？

代价与分段
㉕ 每集"解决掉"的事，在后面留下一笔要兑付的账了吗（一季 6–10 笔）？
㉖ 分段依据是"同一套本事的第几种用法"，还是时间顺序？
```

## §10 从点子到剧集圣经（15 步，顺序别倒）

```text
① 研究再造剧：选 arena → 读书与不同立场的文章、看纪录片、采访、跟场
   边研究边答三问：这个世界是什么？住里面的是哪类人？新人物如何与这个世界交错？
② 答三个为什么：为什么是这个点子 / 为什么是我 / 为什么是现在（不要追平台当下的口味）
③ 挖世界：说不出三四个主角就回到这一步
④ 找引擎：定容器类型与"每集启动器"（案件类天然有；家庭/职场类必须设计一个个人的启动事件）
   聚焦动词（调查 / 诊断 / 辩护 / 争夺 / 拯救 / 面对 / 偷 / 复仇）——动词即每集的小任务
⑤ 三元素推导：研究 → 翻转问题（让主角和观众一样是外人）→ 加强冲突 → 人物是"对等者之间的碰撞"
   → 处境（唯一出路是做这件事）→ 冲突必须内在于人物与容器（排除陷害、恶棍老板这类一次性的装置）
   → 提炼主题（时代里的长期争论，且你本人热情关心）→ 用主题回头修正容器
⑥ 定类型：格式 → 系列类型 → 季层 story-type → 每集 story-type → 受众位置自检
   格式自检：能不能从 10×60 压成 8×45？前三分之一是不是前史？第 3 集才好看 → 把前两集压掉
⑦ 建人物网：家庭角色分配 → 每对关系的正负向量 → 专长分工 → 每人一枚地雷 → 对抗力性质 → 属性互扰
⑧ 写一页 17 栏故事地图，当作此后所有文档的地基
⑨ 写 treatment 或 presentation（连续剧写多季弧，单元剧列 10 条集 logline）
⑩ 生成并检验 5–6 个后续故事（来源与结局形态都要不同）——雷同就回 ④
⑪ 每条线写一页故事线文档，对齐成"人物 × 集数"大表，逐条做抽线测试
⑫ 设计并写 pilot：选类型 → 列前十页计划 → 后半跑一遍 story pattern → 埋地雷 → 写结尾十问
⑬ 更新成提案 / mini-bible，附 mythology 文档 + 起源故事（合计 ≤1 页）
⑭ 计时排练 pitch（20 分钟），备至少三个未来集例子
⑮ 卖出后再写投产用 bible，并让它成为持续更新的活文档
```

## §11 训练（七个动作，接 `drama-mastery.md` 的循环）

| # | 动作 | 怎么做 | 判据 |
|---|---|---|---|
| 1 | **引擎反推** | 看一整晚电视，每集结束用 ≤4 行回答"这部剧是关于什么的"（不许挑纯程序剧作弊） | 四条里能答出三条以上 |
| 2 | **同剧三集共性** | 看某剧任意三集，问它们有何共同点、**为什么不能在别的剧讲** | 那就是它的引擎 |
| 3 | **99 个故事** | 30 分钟内写 20 条单集 logline，每条都要同时碰到容器与冲突 | 写不满 6 条 → 回去改引擎 |
| 4 | **过程句改写** | 把五部你喜欢的剧的核心问题各写成一句过程句 | 自己的项目只能写成答案句 → 换容器 |
| 5 | **地雷表** | 每个主要人物一行"未言明的恐惧/欲望/矛盾 + 预计引爆集数" | 有引爆集号才算 |
| 6 | **按钮表** | 主要人物两两配对，每格写"在这段关系里按对方哪个按钮" | 空格超过三分之一 → 群像还没成网 |
| 7 | **引擎失压自检** | 写下本剧的物质性引擎，问第几季开始失压、之后换什么还是结束 | 答得出具体季号 |
