## L8 · 知识权威与 Claim Ledger（三作蒸馏后的统一基准）

**原 skill 不是整体权威，也不是整体旧基线。** 每条进入统一生产基准的断言必须落到以下类型之一：

```text
platform      schema / 接口 / 官方文档 / 当前回读
cross_work    至少两作独立成立的共同机制
work_profile  只在 W1 / W2 / W3 某作成立
craft_prior   人物、动作、灯光、风格、声音等长期工艺
library_rule  本库定义的工程约束
example       单次作品或示范做法
unknown       证据不足、只有相关性或存在冲突
```

权威顺序按领域使用：**平台事实看 schema/接口/回读；创作工艺看多来源工艺共识与可复现观察；三作只证明结构与生产机制，不负责证明微表情、动作或风格的普适性。**

**Claim Ledger**：`outputs/统一基准/claim_ledger.jsonl`。每条必须有 `claim_id / statement / source_type / source_path / scope / status / evidence / replacement / test`。状态只能是 `verified / revised / withdrawn / undetermined`。

**三条纪律**：

1. 单作画像不进入统一内核；跨作内核只收至少两作独立成立的机制。
2. craft prior 必须通过状态机、Production Record、Prompt Package 和审片门禁进入生产，不许退化成无人使用的文章。
3. 撤回项保留“原说法 → 原因 → 新 scope → 证据”；不可判定项不得进入强制门禁。

共享结构记录：`production_record.schema.json`、`graph_plan.schema.json`、`prompt_package.schema.json`、`gate_result.schema.json`。A 路拥有 schema；B、C 只读消费。

## L1 · 任务闭包全量检阅（产出前不得静默遗漏）

<!-- reading-policy: task-closure/v1 -->

**每项任务先列共同约束、任务模式、当前意图触发的规则、直接依赖及适用例外的文件闭包；闭包内逐一完整读原文，不得截断、以摘要或hash代替。** 未覆盖的需求/例外、缺依赖或冲突必须显式未解，不能宣称已完整读取或继续相应交付。

这条定律防的是静默遗漏：只读入口漏例外、凭印象说库里没有、摘要丢限定词仍属违反。目录导航不自动把全库每册变成每项任务的必读内容；但阅读中发现的适用直接依赖和例外必须加入，不能只相信固定路由。

### 怎么算做到了

1. 以真实文件清单列出本任务共同约束、任务规则、直接依赖与例外；逐项说明需求覆盖及未解项。
2. 每个选中来源全文读取，长文件逐页续读；检索只能定位，不能替代原文。
3. 记录文件、来源hash、当前会话、完整读取证据与关键约束。hash/清单/捕获存在本身不证明模型已读或理解。
4. 仅同一会话实际完整读过、内容未变且原文证据可核对的来源可复用；新会话、变化或新增依赖重新读。
5. 未知要求、缺失/越界依赖、适用性未解不能当完整闭包；工具只核机械源证据，不授生产就绪或生成权限。
6. 全库发布另按真实全文件清单检查索引、完整性、依赖与既有门禁，不能用单任务闭包冒充全库覆盖。

用户明确锁定项优先于工艺默认建议；平台事实、用户偏好、工艺建议、历史观察及例子依L6/L8分型。当前平台证据不足时保留未验证，不能以历史百分比或默认值替换用户决定。具体接口见context-reading.md，L2及其余治理条款保持。

### 每次检阅都要专门扫的高发残留点

- **同文件内部矛盾**：示范句与被明令禁止的句式撞车（本库实测：`segmented-shot.md` 的示例句正是它自己判 ❌ 的那一句）。
- **计数漂移**：`11 段` vs 权威 `12 块`——**要搜数字本身，不只搜量词说法**。
- **旧载体词**：`镜几`→`段落 / 组合` · `镜序语法`→`段落语法` · `绝不拼版`→`分画布禁、分文件放行`。
- **把一家平台的限制写成通用规律**：任何「禁令」先问一句——这是全平台规律，还是某家平台在某种输入方式下的注意事项。
- **同文件里前后两处给了同一个事实不同的值**。

## L1·补 · 外部输入的检阅：**提炼式 ≠ 过账式**（2026-09-21 实测）

**事由**：拿回一份 **469 行 / 113 问**的平台答疑，我**提炼式**读了一遍（压成两册摘要）→ 用户追问"你确定一个字一个字看了吗" → **逐字过账后，准确率 108/113（≈96%），但漏掉的那 5 条里有 1 条已造成硬错。**

**三种典型失分（提炼式阅读必然产生）**：
| 失分 | 实例 |
|---|---|
| **"摘要思维"优先保结论、丢掉同句里的限定词** | 我留了"资产图用中等质量"，**丢了同一句里的"`ratio` 必须按成片画幅统一"** → 结果三个锚点画幅各异，按平台口径**引用时会被重新裁剪** |
| **"纠正冲动"放大改动幅度** | 平台只说"别写『窄两毫米』"，**我把整条"左眼略窄"也删了**（过度修正）——**它其实把"左眼略窄"列在正面例子里** |
| **并列项被截尾** | 平台给了三条构图句式/三条比例例句，我只落了一两条 |

**→ 三条硬纪律（对"外部输入"一律适用）**：
1. **例子不是装饰——它们是"允许范围"的边界证据**，必须原样保留（尤其"被列为正面例子"的表述）；
2. **纠正时只改"被点名的那一处"，不动它周围没被点名的部分**；
3. **并列项要数条数**：三条例证 → **必须三条都落**，落不全就标"未落"。

**→ 判据**：**输入能否"复述出它举的例子"？复述不出，就是只读了结论，没过账。**
**→ 何时必须过账**：**当输入将成为"改库/改方案的依据"时**（这类输入错一条就带偏下游）；**纯资讯类可提炼**。

**★★ 第四条（改完必须逐项核验落地）**：**"写了"不等于"落地了"。**
**2026-09-21 实测教训**：我在同一轮里**两次用"删空行"的写法把标题行与正文合并**（把 `## 三、复测与停手规则` 和下一行粘成一行）——**门禁查不出来，只有 grep 结构时才暴露**。
**→ 每次改库后必做三件（缺一不可）**：
1. **跑门禁**：`lib_doctor.py` + `audit_prompt.py --self-test`（必须全过）；
2. **逐项 grep 核验**：把"本次要写进去的关键事实"逐条 `grep` 一遍，**未命中即为未落地**；
3. **查结构是否被破坏**：`grep -rEn '^#{2,3} [^-]*[^-]#[^-]*- '`（标题被合并）· 查行数是否超 300 · 查索引与工位是否都挂上。
**判据**：**"我说的改动"必须能用一条命令查出来；查不出来的，就等于没改。**

**★★ 第五条（追加表格行的锚点纪律，2026-09-22 实测）**：往 markdown 表格**追加一行**时，`old_string` **不能只锚"上一行的行尾单元格"**——那会把**行尾的列分隔符一起替换掉** → 新行内容被**并入上一行**（表结构破坏），且末尾多留一行**孤立行**。**2026-09-22 追加 E118 时正是这样破坏的 `key-decisions.md`**（与 E86/E87 的"锚了标题没写回"同族，已是同类第三次）。
**→ 正解**：`old_string` 必须含 **"上一行末尾换行 + 新行开头"**；或分两步（先只插换行，再写整行）。**改完必查：目标行与相邻行的 `|` 计数是否一致、有无孤立行**（`awk` 打出行尾即可看出）。

## L2 · 整合铁律（精简 skill 库时的三条硬约束）
1. **不得移除任何功能性或强制性内容。**
   判断口径：把这一句读给「会照抄的用户」听，**他会照着做吗？** 会 → 强制层，必须留。
2. **不确定是否必要的，一律保留，并单独标注为【待确认项】。**
   不确定时删除＝把决策偷偷做掉；标注＝把决策交回给人。
3. **合并的正确姿势是「单一权威源 + 指针」，不是「两边各删一半」。**
   重复条目：选一处做权威源，另一处压成一行指针 `→ 权威定义见 X §Y`；**不许两边同时删**。

### 分诊判据（与 L2.1 是同一把尺）

| 读到的句子 | 判为 | 处理 |
|---|---|---|
| 照着做能改变结果 | 引用处（强制） | **必须保留** |
| 已标「旧版废除」的对照句 | 历史处 | 保留——它记录了为什么改 |
| 表格左列的「原表述」 | 对照处 | 保留 |
| 只是复述 WHY、删了不影响操作 | 散文 | 可压缩 |

## L3 · 改完之后回头核

**★ 写完新段落，必须回头核「它与本文其它段、以及本文自己引用过的原文是否一致」。**

历史上最贵的一次错误形态：**在同一份文件里亲手引用了官方原文，又在几十行后写下与该原文相反的结论**——矛盾的另一半，就是自己抄进来的原句。

操作：改完一个文件，**回读自己引用过的原文，再下结论**。

### L3·补 · 动手**之前**先列受影响清单（2026-09-17 补 · 拆卷后行号腐烂逼出来的）

**L3 只管"改完回头核"，漏了前半步**：**没有清单，回头核的时候根本不知道该核哪些地方。**
实例：一次拆卷把 `block-playbook.md` 从 300 行切成 179 + 129，**引用它的行号有 21 处指空**——
其中 **11 处是这次切断的、10 处是更早那次瘦身留下的**，而**两次都没有"先列出受影响清单"这一步**。

**三步硬动作**：
1. **改之前**：`grep -rn '<被改对象的检索键>'` —— 检索键既包括**文件名**，也包括**行号 / 节号 / 计数 / 编号**（`187 条` 这类数字同样是检索键，见 L4·补）。
2. **列出清单**（谁、引在哪、改成什么），**清单没列全就不要动刀**。
3. **改之后**：**同一把 grep 再跑一次**，残留一处即断链；**行号类引用另跑** `python3 scripts/lib_health.py refs`（**超界即 FAIL**）。

**★ 引用写法纪律**（与拆卷配套，写在 `block-spec.md` 页首）：**优先锚「板块号 / 节号」，行号只作辅助**（板块号跨瘦身与拆卷稳定）；
**跨册引用必须写全文件名**（裸 `:NNN` 的归属靠"同一行内最近的前置文件名"，**一行里出现两个文件名时必然串行**——实测就是这么错的）。

## L4 · 数字与来源

- **凡数字必回一手源核**；核不到就标「未证实」或弃用。已实测：内容农场的转述会凭空造数字，且造得「合理」。
- **官方示例的实际写法 > 任何二手结论。**
- 无许可证来源只提炼方法与机制、**不复制文本**；来源清单里**宁可只写类别，也不编造条目**。

### L4·补 · 数字口径（2026-09-15 补 · **先定口径，再有对错**）

**为什么补这一节**：本库到处写「N 条 / N 卷 / N 册 / N 行」，但**从来没有定义过这些 N 怎么数**。
后果实测过两次：① `style-library.md` 曾写「本库 187 条」（真值 247 —— 是**真陈旧**，已修）；② `SKILL.md` 写「完整清单（**46 行**）」，而文件是 **48 行总长 / 37 行正文 / 11 行空行**——**三个数都不是 46，但无法判定哪个才对**，因为口径没定过。
> **★ 2026-09-17 复查**：① 那条 187 当年**只修了正身、没修引用它的地方**——全库还有 **9 处「187 条 / 187 个」残留**（`run-sheet.md` 执行清单第 3 站 · `start-here.md` 两处 · `color-science.md` · `color-narrative.md` · `sources-and-credits.md` · `style-cards-a.md` · `style-library-genre-part2.md` · `style-library-genre-part4.md` 的同类「227 条」），**本次已全部清除**。**这是 L3 缺位的直接证据：改了计数对象，却没回头改引用它的数字。**
> **★ 同次查出的门禁盲区**：`claims` **只扫 `SKILL.md`**——**`references/` 里的数字断言没有任何门禁**。`camera-package-library.md` 的「写实系共 78 条」（真值 157）就是这样静默漂移了整整两天、无人发现。**★★★ 2026-10-01 已补 `--refs`**：`audit_prompt.py claims --refs <dir>` 普查 `references/` 的「N 行」断言。**★ 但它默认只报 INFO、必须显式 `--refs-strict` 才进退出码**——理由是**实测普查的结果**：带册名锚点的「N 行」断言共 **86 处**，其中**语义上是「历史/迁移态」的至少 51 处**（`key-decisions.md` 里「新建 `music-craft.md`（159 行）」记的是**成册当时**的行数，现已 161；「304 → 299」是拆卷前后两个数）。**把它们一律判 FAIL 就是 50+ 条假警报**，而 E23 写死「误报比漏报更隐蔽」。**→ 判据：普查归普查，判错归判错，两件事分开做**；先看清单分诊，确认某条确实是当前态断言、只是没被标记词拦住，再开 `--refs-strict`。
**没有口径的数字，既不能判对、也不能判错。** 以下为**全库统一口径**（`audit_prompt.py claims` 按此自动比对）：

| 写法 | 口径 | 例 |
|---|---|---|
| **`N 行`** | **`len(文本.splitlines())`** —— 含空行，**且末行无尾随换行也算一行**。⚠️ **这与 `wc -l` 不同**（`wc -l` 数换行符个数）：`segmented-shot.md` **本库计 300、`wc -l` 计 299**，两种口径在 300 边界上会给出**相反**的"要不要拆"结论。**`audit_prompt.py` 用的就是本口径** | 「完整清单（48 行）」 |　**★ 2026-10-01 补一条歧义警告**：中文「行」**一词两义**——① **文件行**（本行口径）② **表格数据行**（如 `production-ledger.md` §6.2「连续跑 30–40 **行**之后」＝**台账数据行**，不是文件行）。**两者数字不可换算**，且 `claims --refs` 普查时**会把②误判成①**（实测 4 条待分诊里就有这一类）。**→ 判据：看到「N 行」先问一句"说的是文件还是表"，问不出就不判**——这正是本节开头那句「**没有口径的数字，既不能判对、也不能判错**」的又一个实例。 |
| **`N 条`（风格库）** | **`### 编号 · 名称` 条目数**，跨卷相加去重 | 247 条 |
| **`N 条`（取图册）** | **`^\*\*[★]?\s*[A-G]\d{2}\s*·` 条目行数**，跨册相加去重（**`★` 可选**——`style-sources-c1.md` 与 `style-sources-c2.md` 两册行首无 `★`，**两种格式并存**；只写带 `★` 的单格式正则会**漏数 81 条**） | 取图册 247 条 |
| **`N 条`（表类）** | **表项数据行数**（**不含表头与分隔行**） | `expression-library` 96 条 |
| **`N 条`（自检/自查）** | **可判定的用例数**（`--self-test` 的通过数） | 26 / 29 / 17 / 12 |
| **`N 卷`** | 风格库的**分卷数**（按文件与字母段） | 十三卷 |
| **`N 册`** | **文件数**（不含入口册本身） | 取图册 8 册 · 校准卡 7 册 |
| **`N 包`** | **`#### Pxx` 一/二级标题数** | 主包 17 · 补充包 17 |
| **`N 族`** | 表内**加粗族名行数** | 风格族 12 · 调色族 14 |

**★ 纪律**：
1. **写数字时，口径必须能从本表推出来**；推不出来就**别写数字**（改写成"全库覆盖"这类不含量词的表述）。
2. **改了正文里被引用的计数对象，必须回头改引用它的数字**（否则就是下一个 187）。
3. **`N 行` 一律按 `len(splitlines())` 计**——这是唯一能让"文件行数"与门禁可比的口径（`audit_prompt.py _count_lines` 同源）。**别再另立"内容行 / 非空行"一套。**
4. **无法核实的数字，宁可删掉，不要留一个看起来合理的数**（`prompt-ops.md`：删除比编造安全）。
5. **比对两份"捕获文本"前，先归一化行尾与尾随换行**——**原始字节比对会把 CRLF/尾随换行差异读成内容差异**：
   实测把 40 页 `libtv help` 的现场输出与 10-15 捕获逐字节比，**37 页报"不同"，归一化后 40/40 全同**——
   **差的全是行尾与捕获时多带的一个尾随换行。** **→ 判据：比"内容"不比"字节"，除非你确实要证字节一致。**
6. **跑"会打印中文的子进程"时，显式设 `PYTHONIOENCODING=utf-8`**——**Windows 上 Python 子进程默认按控制台代码页输出**，
   父进程按 UTF-8 解码 ⟹ **中文全变乱码**（实测：一次 154 次门禁扫描里，判定全对、**中文 `reason` 全乱**）。
   **→ 判据：跨进程读文本前先对齐编码；"结论对"不等于"证据读得对"。**
7. **"上限 N"这类口径，以门禁自己的标签为准**——**`lib_health` 把 300 打印成"到上限（必须拆）"，那 300 就是超限**。
   **两条门禁对同一条边界给了不同阈值时，先对齐、再谈数字**（**实测：`lib_health` 显示但不设退出码、`lib_doctor` 用 `> 300`**
   ⟹ **一本 300 行的册两边都 `exit=0`**，见报告 `132`）。**"报了"不等于"拦了"。**

### L4·补2 · 外部采纳的**证据门槛**（2026-09-17 立 · **自己抓到自己规则里的矛盾之后补的**）

**矛盾的来历**：一次外部采纳里，我先写下"**覆盖率 0–2/273 的候选一律撤下**"，
**同一批里却保留了覆盖率同样只有 2/273 的 `NO BGM`**——**两条判据当场打架**。
**这个矛盾暴露了真正的判据不是覆盖率。**

**★ 门槛（下面两条，**任一**成立即可采纳；但**都必须标注证据强度**）**：

1. **多源收敛**：语料全量实测覆盖率 **≥ 约 5%**（**经验阈值 · 拟订**，册内无推导来源，防误杀靠第 2 条替代路径）；或
2. **覆盖率低，但机制理由可独立论证**——即**"它成立不依赖那个来源的权威"**。
   - ✅ 例（可独立论证）：`NO BGM` 的机制是"**裸否定会被模型的强先验覆盖**"——这条推理不引用来源也站得住；
   - ❌ 反例（不可独立论证）：**「40% 说、60% 收」** 是一个**具体经验比例**，**除了那个来源没人能证** → **不采纳**。

**★ 两条附加纪律（不论走哪条门槛）**：
- **一律按 L6 记「拟订」而不是「已定」**，并把**实测覆盖率写进条文**（例：「单源 2/273」）；
- **覆盖率 0 且机制不可独立论证 → 不落库**，只留建议。

**判据一句话**：**"如果这个来源明天消失了，这条规则我还站得住吗？"**
站得住 → **可采纳，但要标强度**；站不住 → **它只是那个来源的个人习惯，不落库。**
> **为什么这条比"一刀切阈值"重要**：**单源不等于错，多源也不等于对**。
> 用覆盖率当唯一标准，会**同时犯两个错**——把**少数派的好做法**误杀，把**多数人的平庸做法**误收。
> 本条与 `L4`（数字与来源）、`L6`（状态与证据）是三件事：**这条管"要不要采"，L4 管"数字准不准"，L6 管"采了之后算什么状态"。**

## L5 · 引用优先律（凡库里有的，一律引用，不许自编 · 2026-09-17 立）

**起因**：一次实做里，【统一提质层】的器材行**是自己编的**（"35mm 胶片质感 + 柯达 5219"）——而库里早有一整套方案包、
**外加一份"可直接复制的成套句"**。**同类问题会出现在任何"库里已有素材"的模块**（风格编号 / 运镜名 / 声音词 / 磨损项 / 调色预设），
所以不补一条检查了事，**立成定律**。

**定律**：**凡库里已有的专有名词，一律"从册里取 + 逐字粘"，禁止凭记忆或手感自编。**

| 模块 | 库里的出处（**★ 取，不编**） |
|---|---|
| **器材 / 胶片 / 印片 / 调制层** | **`camera-package-quickref.md`（§三 三个可直接复制的成套句）** · `camera-package-library.md`（P01–P17）· `package-extended.md`（P18–P34）· **`film-stock-matching.md`（取哪一档：片 / 印片 / 调制层）** |
| 选包与禁忌 | `equipment-selection.md`（六轴正交 · 跨包组合）· `style-package-matching.md`（族级判据与禁忌） |
| 风格 | `style-library.md` 的**编号**（A/B/C/E/G 卷）+ `style-cards-*.md` —— **编号必须真实存在** |
| 运镜 | `camera-movement-library.md`（**六族全谱**） |
| 声音 | `sound-lexicon.md` · `sound-craft.md` |
| 磨损与痕迹 | `carrier-artifacts.md`（介质痕迹机理）· `ai-artifact-control.md`（接触面） |
| 调色 | `color-grading-styles.md` 的预设 |
| 表演与表情 | `performance-vocabulary.md` · `expression-anatomy.md` · `expression-rhythm.md` |

**自查（写完一段就问）**：**这一段里的每个专有名词，我能不能指出它在库里哪一册？**
- **指得出** → **逐字粘过来**（不许改写；**型号必须跟效果句，不许只写编号**）。
- **指不出** → 只有两条出路：**① 删掉它**（多半是可有可无的装饰）；**② 它确实需要 → 先把它补进库，再引用**。
- **⚠️ 第三条路不存在**：**不许"先写在稿里、之后再补库"**——那样库与稿会分叉，**下一次你还是会自编**。

**★ 落地判据（可直接用）**：把稿子里**所有专有名词圈出来，逐个在库里搜**——**搜不到的，就是自编**。
**机器口径**：**风格编号**（`B10` / `E03` 这种形态）若不在 `style-library.md` 与各 `style-cards-*` 里 → `audit_prompt.py blocks` 报 WARN。

## L6 · 状态与证据（四态 + 四证据 · **每条"事实"都要能说出它是哪一种** · 2026-09-17 立）

**起因**：本库到处都是"库里未写明"与 A/B/C 档经验值，**但从来没有一套统一的词**把"这条是谁定的、可不可改、能不能编"说清楚。
后果实测过：一处写"暗部粗中间调细"被当成普适规律、一处把自媒体转述当官方口径——**两者的共同点是"没说清它是哪种事实"**。
> **来源**：Higgsfield 官方开源的两个 skill（`higgsfield-brandkit` 的 Brand Lock `states` + `evidence` 标签）——**机制本身是通识，词表是它给得最清楚的。**

**★ 四态**（任何一条写进交付件或库的"事实"，必须落在其中一态）：

| 态 | 含义 | 操作 |
|---|---|---|
| **已定** `fixed` | **用户给定或已批准** | **不改**；要改须先问 |
| **拟订** `proposed` | 我补的规则 / 参数 | **可改**，但**必须标出来**（默认态——不标就默认它是拟订） |
| **不适用** `n/a` | **有意缺席**（不是忘写） | 写明"本镜不需要" |
| **未解** `unknown` | 没弄清、**且不安全去编** | **只能问，或按"不适用"处理；绝不许编一个看起来合理的值填上** |

**★ 四证据**（"这条凭什么"）：

| 标签 | 含义 |
|---|---|
| **用户声明** | 用户直接给的（品牌名拼写 / 角色设定 / 时长） |
| **实测** | 本库真跑过、有结果可复现（平台行为 / 参数换算） |
| **观察** | 看片或看图得到的（构图习惯 / 质感缺陷）——**可作判据，不可当定律** |
| **推断** | 从规则推出来的——**必须写"推断"二字，不许伪装成实测** |

**★ 三条纪律**：
1. **不标即拟订**——不写状态的事实，一律按"可改"对待；**不许把拟订偷偷当已定用**。
2. **`未解` 不许编**——这正是 L5 引用优先律在"事实层"的同一条：**库里没有就回去补库，不许先写在稿里**。
3. **`观察` 不得升格**——"我发现这样更好看"是观察，**不许写成"必须这样"**。

## L7 · 批准与兜底（两条不许 · 2026-09-17 立）

> **来源**：Higgsfield 官方开源 skill 的失败与批准纪律（`higgsfield-brandkit` / `higgsfield-youtube-thumbnail`）。原文两句最值钱：
> **"Never infer approval from silence, successful generation, or your own preference."** 与
> **"Do not produce a visually different fallback and call it canonical."**

**① 不许把这几样当作用户验收**：**沉默 · 生成成功 · 门禁通过 · 自查清单勾完 · 我自己的判断**。
**批准必须显式**。判据一句话：**"用户还没看过" = "未批准"**，不管我这边的机器有多绿。
> 与本库既有规则的关系：`acceptance-check.md` 是"给用户勾的"，本条的**新增点**在于**明确排除了"程序化通过"这条捷径**——门禁全绿只能证明**结构没坏**（脚本自己也这么打印），**不等于内容能交付**。

**② 不许拿兜底件冒充正规件**：模板 / 工具 / 合同 / 字体 **失败时立即停并披露**，
**不许顺手产出一个"看起来不一样但也能用"的替代品，然后称它为正品**。
- 典型违规：模板渲染失败 → 自己拼一个"差不多"的版本交付，且**不告诉用户它不是模板产物**。
- 正确做法：**报出具体错误 + 说清哪一步断了 + 给"要么修、要么换路"的选项**，由用户决定。
- 与本库既有规则的关系：`production-ledger.md` 的「**止损 ≠ 放弃意图——意图守恒，手段可换**」说的是**换手段是允许的**；
  本条的**新增点**是**换了手段必须声明**——**换路可以，"换完不说"不行**。

**③ 不可机检（如实标注）**：以上两条是**行为纪律**，没有可判别的机器口径——**与 E68 划出的三个维度同类**（动作是否自然 / 表演是否可信 / 道具可达性）。
**不许为了"看起来有门禁"而编一条会产生误报的检查**（误报比漏报更隐蔽，E23）。
