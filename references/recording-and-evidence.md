## 一、演奏 → WAV 的十步（官方流程转写）

1. **用浏览器 UI 控制打开乐器站的演奏页**，**优先复用已开的那一个标签**；**直接用受支持的琴键动作演奏**——**不要打开 MIDI 转换器、不要加"文件转换/导入"步骤**；**把 `/play` 后面还带一段文字粘贴进来的链接当畸形链接，用规范 URL**；
2. **跟随用户指定的乐器**；要求内置预设时默认用 **三角钢琴顺滑预设**（除非方向另有要求）；否则选最贴合已批准方向的内置音色；**★ 等乐器加载遮罩消失后再弹**；
3. 若用户点名现成曲目，**从曲库区载入其谱面并保留旋律 / 伴奏 / 节奏 / 音符时值**；**广告用途默认原创**；**尊重试听或成片时长，且任何曲库片段都要标明"节选"**；
4. **★ 在第一个音之前立刻开站点的录音器**；按**刻意的节奏**直接弹；**最后一个音衰减完再停录**；**能批量就批量下发定时琴键动作——否则工具调用延迟会造成一段很长的静音开头**；
5. **导出前先核对录音结果**：录音器应显示**非零音符数**与**可信的时长**；
6. 走 **`Download recording → Download as WAV / 下载为 WAV`**；**★ 站点的"已下载"提示只能算"导出被触发"，仍要落盘核对文件**；
7. **按"导出前后捕获到的修改时间"在下载目录里认出新建的 `piano-recording-*.wav`**——**★ 不要假定一个更早的同名文件就是本次结果**；
8. 校验它是 **PCM WAV**、**时长可信**、**体积非平凡**；拷到目标目录并给**描述性 `.wav` 名**；**★ 不覆盖已有文件，重名就加数字后缀**；
9. 若站点给的首尾静音明显偏长，跑本技能目录下的 **`scripts/trim_wav_silence.py SOURCE DEST`**——**★ 保留下载原件、只交付清理后的副本**；可选的 **`--target-seconds D` 只会给"偏短的完整音频"补静音，拒绝剪短偏长的音频**；**依赖静音阈值之前，先人工听一遍结尾的安静段**；
10. **报告绝对路径、时长、采样率、声道数**；**在派生"视频节奏图"之前先分析这份已验证的 WAV**；客户端支持时**内嵌绝对 WAV 路径**方便用户直接播放。

## 二、内置预设 `三角钢琴顺滑预设`（逐值 + 四条坑）

| 控件 | 保存值 |
|---|---|
| 乐器 | **Grand Piano / 三角钢琴**（**与"古典钢琴"不同**） |
| 音量 | **55%** |
| Sustain 时长 | **启用；显示总时长 0.6 秒** |
| Sustain 踏板 | **停用** |
| Autoplay Release | **350 ms** |

**★ 四条会咬人的坑（官方实测）**：

1. **Sustain 滑杆是"调整量"不是"绝对时长"**：实测某基线 **10.5 秒**时要 **−9.9 秒**才显示 **0.6 秒总计**——**永远瞄准"显示的总时长"**，**基线一变就要重算调整量**；
2. **Sustain 时长与踏板功能互斥**：改完**要重读开关与显示总时长**；**调整量接近下限时会把 Sustain 关掉、留下 0.0 秒总计——别把这个状态误认成预设**；
3. **UI 把 Release 标为"仅自动播放"**，而手动抬键被描述为**固定 4 秒尾音**——**★ 未经验证，不得假定改 Release 会影响手动演奏或导出的 WAV**；
4. **★ 短促点键仍可能生成极短的录音音符**——**"0.6 秒"这个控件值不能证明录音里存的就是 0.6 秒的音符时值**；判断断句是否连贯，**要把"实际按键保持与重叠"和 Sustain、Release 一起考虑，并回放一小段来评估**；**不许只凭滑杆数值宣称"顺滑"**。

**★ 和弦与快速对比（多键 API）**：`await tab.pressKey("q+e+t+u")` 一次按下 **F3–A3–C4–E4（Fmaj7）**（官方在站点上验证过音符映射与四个音符事件）。**柱式和弦用多键，分解和弦用刻意定时的单键。**

## 三、纯画面录屏（MP4，无音轨）

**只在用户要求"把演奏界面录下来"时才做**。**★ 铁律：音频源仍用站点自己的录音器**，产出**两份独立交付物**：**下载的 WAV** ＋ **纯画面、无音轨的 MP4**；**除非用户显式更改，不要开麦克风/系统声音，也不要把 WAV 混进录屏**。

**① 选窗与取景**
- **从当前浏览器清单里认出"这个任务自己的"演奏标签**——**★ 同 URL 的另一个标签可能属于另一个任务**；**要在抓取或发原生键事件之前就把那一个标签选到前台**；
- **★ 浏览器标签 ID、Chrome 脚本窗口 ID、Core Graphics 窗口 ID 是三个不同的标识**——**录屏器要的是 Core Graphics 窗口 ID**；**绝不沿用上一次会话里的 ID**；
- 预览选中的窗口；**可裁掉浏览器工具栏**，但**必须保留完整琴键与可见的录音控件**；**用当前的窗口尺寸与页面边界，不要用存下来的像素坐标**；**把 LibTV 画布标签按约定留在它的面板里**；
- **★ 先开录、再演奏**：**等 `RECORDING_STARTED`** → 开**站点录音器** → 执行音符计划 → 等收尾音衰减 → 停站点录音器；**★ 前后各留一点预卷与尾卷，免得工具延迟把演奏截掉**。

**② 帮助脚本契约（官方 `scripts/`）**
- 前置：**macOS 15+** 且 Swift SDK 含 `SCRecordingOutput`；**沿用现有的屏幕录制权限、不改权限设置**；**拒绝已存在的输出文件**；**★ 在技能目录之外编译**；
- 参数：

```text
record-piano-window WINDOW_ID OUTPUT.mp4 CAPTURE_SECONDS [CROP_X CROP_Y CROP_WIDTH CROP_HEIGHT]
trim-piano-screen  INPUT.mp4 OUTPUT.mp4 START_SECONDS DURATION_SECONDS
```

- **裁切坐标是"相对所选窗口的点"**；**省略裁切即整窗录制**；**★ `capturesAudio` 固定为 `false`**；录制器**打印观测到的起止时间并验证音轨数为零**；**实际可能比要求的墙上时钟区间多录一点——先看首末琴键事件落在哪，再决定裁切**；
- **裁切脚本只把视频轨拷进新合成**，并在导出后**校验"呈现时长（presentation duration）"与无音轨**；**★ 原始 MP4 的媒体轨时长可能含被 edit list 隐藏的编码器预卷——别把那个值当成播放器时长**；
- 脚本不可用时：**用能隔离窗口/区域并关闭全部音频的现成录屏器**；**★ 不许用"截屏做成的幻灯片"冒充真实录屏**。

**③ 核对与交付**
- **看开头附近、按住音期间、最后一次抬键之后**三段；**★ 要确认页面确实是那台钢琴、琴键状态真的在变——"文件写成功"本身不算证据**；
- 确认画面文件**只有一条视频轨、音轨数 0**，并**报出播放时长**；**若裁到 D，保留完整原始capture**；
- **音乐必须另外走"下载为 WAV"并独立校验——★ 录屏永远不能替代这一步**；
- **分别**返回纯画面 MP4 与站点 WAV 的绝对路径与预览；**★ 不许仅凭墙上时钟时间戳宣称"逐帧同步"**。

## 四、两条可迁移的取证通则

1. **"控件值 ≠ 产物事实"**：滑杆显示 0.6 秒，不等于录音里存着 0.6 秒；录制器显示音符数，不等于导出文件正确。**每一条都要落盘/回放核一遍。**
2. **"成功提示 ≠ 成功"**：站点的"已下载"toast 只代表触发；"文件写成功"只代表写了盘。**判据必须是"可播放 + 可复核的属性（时长/采样率/声道/音轨数）"。**

## 五、音乐方向：从广告 brief 到演奏（**官方 `references/music-direction.md` · 一手 · 2026-10-15**）

**① 总纲**：成片默认 **20 秒**，但**速度 / 拍号 / 律动 / 乐句 / 重音型 / 密度全部来自广告 brief**，**不是一条固定的剪辑网格**；**短试听用来确定音乐方向**；**★ 产品脱手、竖直硬缝穿越、动作重音、接住、停机——这些只能从"已验证的最终演奏"里导出**（不能先定画面再倒推演奏）。

**② 素材三条路**
| 路径 | 规则 |
|---|---|
| **原创（默认）** | brief 没有点名现成曲目时的默认；为一个**动机 + 和声走向 + 节奏身份 + 结尾**服务产品与受众 |
| 已存曲库 | 要点名或明显合适时用；**改编必须标明是改编**，并保留所选曲目**可辨识的旋律、节奏与伴奏**（除用户要求改动） |
| **目标时长改编** | 选一段连贯段落，**另配一个兼容的收束并留出衰减余量**；**★ 助手的 `--seconds 20` 只是"选取一个起音窗口"，它本身不制造终止式、也不保证渲染出 20 秒 WAV**；**不许为了凑时长把整首赶完、机械循环 5 秒、或把正在发声的尾音切掉** |

**③ 参考音频**：先分清**音色 / 节奏起音 / 重音 / 音区 / 乐句 / 释放**，再决定学什么；**★ 必须写明"在学它的哪几项特征"**；**★ 粗糙的律动改编不等于"已验证的逐音转谱"**。

**④ 乐器**：**尊重用户选择**；否则按 brief 与可用音色匹配（**三角钢琴 / 电吉他 / 电贝司都算合法选择**）；**电子/合成类音色只在当前 UI 真的提供时用**；**★ 先显式选定乐器，再套用录制流程的默认回退**；**不许把"顺滑三角钢琴"硬套到电吉他/贝司需求上，也不许把"青春感"硬套到时尚/表演类 brief 上**。

**⑤ 品类起点表（8 类，官方明示"是起点不是硬规则"；品牌调性与用户参考优先）**

| 品类 | 音乐方向与候选音色 | 典型 BPM |
|---|---|---|
| 科技/消费电子 | 极简电子或故障风；电贝司/吉他或可用电子音色 | **95–125** |
| 运动/户外/表演 | trap/DnB 式能量；电贝司/吉他或打击性钢琴 | **125–155**（或可演奏的半速） |
| 奢侈品/时尚/珠宝 | 氛围、慢速、现代古典或利落的吉他/贝司律动 | **70–110** |
| 美妆/护肤/健康 | 有机氛围或轻电子；顺滑三角钢琴或柔和音色 | **75–105** |
| 汽车/出行 | 电影混合或 techno 式驱动；电贝司/吉他或厚重钢琴 | **100–140** |
| 食品/饮料 | funk/house/原声流行；节奏吉他、贝司或钢琴 | **100–128** |
| 家居/家具/建筑 | 温暖极简；顺滑三角钢琴或温暖拨弦 | **70–115** |
| 金融/专业服务 | 克制的极简或现代古典；收敛的三角钢琴 | **80–120** |

**⑥ 按目标匹配**：**权威感（prestige）→ 降节奏密度、留 headroom、少而更有分量的重音**；**功能证明（feature proof）→ 稳定脉冲 + 清晰动机**（余下按 brief 展开）。

## 六、曲谱预设与本地准备（**官方 `references/repertoire.md` · 一手 · 2026-10-15**）

**① 内置八首（含保存的"四分音符 BPM"与大致时长）**：C大调前奏曲 **68 / 2:04** · 小狗圆舞曲 **240 / 1:45** · 雨滴前奏曲 **72 / 4:57** · 裸体歌舞 No.1 **60 / 3:54** · 致爱丽丝 **80 / 2:20** · 婚礼进行曲 **120 / 6:14** · G大调小步舞曲 **120 / 0:48** · 悲怆奏鸣曲第二乐章 **36 / 4:03**。
**★ 口径**：**这些 BPM 是"保存下来的试听选择"，不是作曲家节拍器标记的断言**；**单位是"四分音符/分钟"**。目录文件 `assets/scores/catalog.json` 存**中文名、别名、来源 URL、署名、速度设置、时长、音符数、音域与改编说明**。

**② 本地准备（`scripts/score_preset.py`，Python 3、无第三方依赖、在该技能目录下运行）**

```sh
python3 scripts/score_preset.py list
python3 scripts/score_preset.py build '雨滴前奏曲' --seconds 10 --format events --output <新文件>.json
python3 scripts/score_preset.py build '致爱丽丝' --format events --output <新文件>.json
```

- **★ 助手拒绝覆盖**——必须给一个新的输出名；输出报告会写明**确切作品、范围、时长、音符数、生效速度**；
- **省略 `--seconds`** ＝ 取该预设剩余全部序列；**`--start` 以秒计、按预设默认速度**；**`--seconds` 是"起音窗口"**；
- **`--speed 0.8` 同时放慢"起音与音符时值"**；**`--transpose 2` 仅在被要求时整体升 2 个半音**；
- **`--tail natural` 保留末音书写时值**（所以 5 秒试听结尾可能略长）；**`--tail clip` 强制卡在窗口内**；
- `--format events`（默认）产出可读本地音符数据，含 `metadata` 与 `notes`（每个音有音名 / 时间戳 / 时值 / 力度等）；
- **★ 原始控制器/踏板消息仍留在内置源谱里**；**助手保留书写时值与重叠，但不会把踏板"烘焙"进输出**；
- 快速试听技巧：萨蒂那条 `--start 12 --seconds 10` 正好**从四小节伴奏引子之后、旋律开始前**切入。

**③ 演奏对齐**：**沿用已开的 `/play` 标签**、保持既定的右栏位置、应用指定音色预设、读准备好的音符数据；**把音高映射到当前键盘、把同时发声音符并成和弦、保持既定节奏**；**独立按住多个音要用 macOS 的原生键盘路线**（见 `music-driven-product-ad/references/zen-piano-production.md`）。

**④ ★★ 一条命名歧义（最容易踩）**：**不带限定的"悲怆奏鸣曲"指的是那首奏鸣曲、不是某一个乐章——演奏前必须先确认乐章**；内置的那份是**第二乐章**。（另有官方测过的 25 秒主题改编：`beethoven-pathetique-ii-25s.keys.json`，四分音符 40 BPM、105 个琴键事件。）
