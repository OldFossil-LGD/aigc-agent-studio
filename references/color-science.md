## 一、色彩理论基座（写色板之前的常识）

### 1.1 三属性（一切调色都在调这三样）

| 属性 | 是什么 | 调色里叫什么 |
|---|---|---|
| **色相** | 颜色的"色别"（红 / 黄 / 蓝 / 青 / 洋红） | Hue |
| **饱和度** | 色彩的强度、纯净度（鲜艳 ↔ 灰） | 饱和度 / 色度 |
| **明度** | 明暗程度 | 亮度 / 对比 |

**圆柱模型**：色相＝顶面圆周 · 饱和度＝半径（中心是无彩的）· 明度＝垂直轴。
**同一色相、不同饱和或明度，是完全不同的情绪**——这一点比"用什么颜色"更常用（→ `color-narrative.md` §二）。

### 1.2 加法色 vs 减法色（为什么"胶片模拟"不能简单套 LUT）

| | 三原色 | 三原色相加 | 用在哪 |
|---|---|---|---|
| **加法（光）** | **R / G / B** | 相加 = **白** | 摄影机、屏幕、调色软件 |
| **减法（颜料 / 染料）** | **C / M / Y** | 相加 = **黑** | 印片、滤镜、胶片染料层 |

**为什么这条对 AIGC 重要**：**调色在加法空间（光）里做，但胶片的色彩来自减法（染料层）**——所以"胶片感"不能只靠色相偏移模拟出来，它需要**染料层的非线性**（这就是印片模拟存在的理由）。**写"像柯达 2383"比写"暗部加青"更接近本质。**

### 1.3 色轮的三层

**原色**（红 / 黄 / 蓝）→ **间色**（橙 / 绿 / 紫，由两原色混出）→ **复色**（原色 + 相邻间色，如红紫、黄橙）。

## 二、六类配色方案（含电影案例）

| 方案 | 做法 | 观感 | 电影案例 |
|---|---|---|---|
| **无彩** | 只有黑白灰 | 冷峻、纪录、取消"好看"的退路 | 黑白片（P10 那一类） |
| **单色** | **一个色相**的所有明暗 / 饱和变化 | 统一、执念、被某种东西笼罩 | **《黑客帝国》**（绿——虚拟世界的荧光色）；《银翼杀手 2049》的拉斯维加斯段（单色相 + 明度造空间） |
| **互补** | 色轮对面 | **对比最强**，前景推前、背景退后 | **青橙**（→ `color-narrative.md` §一）·《超人》（红蓝）·《潘神的迷宫》 |
| **邻近** | 相邻色 | **和谐但对比弱**；可加一个跨轮强调色 | **《月光男孩》**（蓝紫洋红，如梦似幻） |
| **三角** | 三等分 | 平衡 + 有对比，但**难驾驭** | **《超人》**（红蓝黄）·**《狂人皮埃尔》**（戈达尔的红黄蓝） |
| **粉彩** | 低饱和 + 高明度 | 精致、怀旧、童话 | **《布达佩斯大饭店》** |

> **★ 一个常见误用**：**黑白片是"无彩"，不是"单色"。** 单色＝一个色相（如全绿）；黑白＝没有色相。

**克制纪律**（`cinematic-look.md` §四 已定，此处只提示）：**一部片通常只有 1 个主色调 + 1 个对立色；主色 70%，点缀 ≤5%。**【待核】此数值回一手源前不要当唯一答案

## 三、校色 vs 调色：**顺序不能反**

| | **校色** | **调色** |
|---|---|---|
| 目标 | 让画面**准确**（人眼看着对） | 让画面**有感觉** |
| 工具 | 一级轮子 / offset / 白平衡吸管 / 示波器 | 曲线 / 限定器 / LUT / 画廊静帧 |
| 做什么 | 曝光 · 白平衡 · 对比 · **镜头匹配** | 情绪 · 风格化色彩 · 胶片质感 · 肤色塑形 |
| **顺序** | **第一步** | **第二步** |
| 何时算完成 | 画面自然、中性 | 画面支撑故事 |

**两条纪律（这是本节的全部价值）**：

1. **校色做得好是看不见的；调色应该被感受到，而不是被注意到。**
2. ★ **跳过校色直接上创意 look，会把画面里所有问题一起烤进最终调色**——绿偏色、过曝的天空、浑浊的暗部，全都会留在里面。**这等于在开裂的画布上作画：下面的问题总会透出来。**

> **对 AIGC 的迁移**：AI 出片没有"校色"这一步（它一次给你成品）。**所以"校色"的责任被前移到了——提示词里的光位与曝光描述。** 这正是 `quality-layer.md` 反复强调"曝光优先保护脸 / 暗面不补光 / 光有出处"的原因：**那几句话在替模型做校色。**

## 四、★ 从实拍流程看 AIGC 该写什么（每一步都有落点）

> **为什么要知道实拍流程**：不是为了让你去做调色，而是因为——**AI 出片把"校色 + 调色"压缩成了一次生成，那些工作在实拍里由谁做、做在哪一步，决定了你在提示词里该写什么、写在哪个位置。**

| 实拍步骤 | 那一步在做什么 | ★ **AIGC 里对应什么** |
|---|---|---|
| **1 色彩管理** | 定工作空间 | **无对应**（创作者不介入）——知道它存在即可，**不要写进提示词** |
| **2 一级调色** | 曝光 · 白平衡 · 对比 · 饱和度 | ★ **提示词里的【光位与影调】行在替模型做这件事**——"曝光优先保护脸 / 暗面不补光 / 光有出处"这几句就是给模型的校色指令 |
| **3 镜头匹配** | 定基准片 → 逐镜对齐 → 示波器微调 | ★ **锚点句逐字复述 + 统一提质层**——机制不同（人是调色，AI 是复述），**目的完全一样：跨镜一致** |
| **4 创意调色** | 推阴影、调高光色相、加颗粒、加暗角 | ★ **【全片配色】行 +【统一提质层】的痕迹行** |
| **5 二级调色** | 限定器选肤色 / 天空 / 物体 + 窗口局部 | ★ **针对性的描述句**（"两颊哑光、鼻翼油光" / "天空比地面冷两档"）——**用文字指定局部，而不是用限定器** |
| **6 输出** | 一致性复查 → 导出 | ★ **交付前的一致性复查**（`review-passes.md`）+ 平台交付规格 |

**标准节点结构**（`输入转换 → 曝光 → 白平衡 → 对比 → 饱和度 → Look → 肤色 → 输出`）——**它的价值在于告诉你：调色的顺序是先准、后美。** 这正是本库提示词层序（光位在前、配色在后）的由来。

**一级调色的具体数值**（**用来审 AI 出片，不是用来调**）：

| 项 | 目标值 | 怎么用到 AI 出片上 |
|---|---|---|
| 黑点 | **0–5 IRE** | 暗部**有细节但接近黑**；糊成一片灰 = 光写得太"亮"了【待核】此数值回一手源前不要当唯一答案 |
| 白点 | **90–100 IRE** | 高光**接近白但不死白**；死白 = 少了"高光平滑滚降"那句【待核】此数值回一手源前不要当唯一答案 |
| 对比 | 温和的 S 曲线 | 不要两边都拉死 |
| 饱和度 | 逐渐加 | **肤色是最敏感的指示器** |

## 五、四个示波器 + 肤色线（"颜色对不对"的客观判据）—— **这一节原本是给调色师看的；AIGC 场景下它的用法是审 AI 出片，落点是本节里「★ AIGC 创作者的"示波器"是什么」那张替换表。**【待确认项：是否把本节整体改写为审片口径，待定】

| 示波器 | 显示什么 | 用来查 |
|---|---|---|
| **亮度波形（Waveform）** | 帧内从左到右的亮度 | **曝光 · 对比 · 死黑 / 死白** |
| **RGB Parade** | R / G / B 三通道分开 | **白平衡 · 偏色 · 镜头匹配** |
| **矢量示波器（Vectorscope）** | 色轮上的色相与饱和度 | **肤色 · 整体饱和度 · 色相定位** |
| **直方图（Histogram）** | 整体分布 | 总览 |

### ★ 肤色线（I-line）——本文件最实用的一条

**矢量示波器上有一条参考线（I-line）。人的肤色应该落在 / 平行于这条线上。**

- 这是"**肤色准不准**"的**客观判据**，不靠眼睛
- 也是跨镜**肤色一致性**的检查手段：**同一场戏的所有镜头，肤色应该落在同一条线上**
- 典型修正：**减品红、加一点自然的红**（不是加橙）

### ★ AIGC 创作者的"示波器"是什么

**你不装示波器——你的示波器是"缩小看 + 换设备看 + 隔一天再看"。** 四项一一对应：

| 传统查 | 你改做 |
|---|---|
| 波形（曝光 / 死黑死白） | **把图缩到很小看**——暗部是否糊成一片、亮部是否死白 |
| RGB Parade（偏色） | **在画面里找一处"本应是中性"的东西**（白墙、灰地、白衬衫），看它是否真的中性 |
| 矢量（肤色 / 饱和） | **放大看脸**——是否偏品红或过橙（＝偏离肤色线） |
| 直方图（总览） | **手机屏 + 电脑屏各看一遍**（对应下面第 5 条错误：在未校准的监视器上调色） |

**并且**：**看了一整天之后不要做色彩判断**（对应下面第 4 条错误）——**隔夜再看**。

**★ 一条对 AIGC 极有用的推论**：AI 生成的人脸最常见的两个毛病——**偏品红**与**过饱和偏橙**——**正好都是"偏离肤色线"的两种方向**。`skin-realism.md` 里"油亮 / 蜡像"是**材质问题**，而**"脸发紫 / 脸发橙"是色彩问题**，两者的修法完全不同：
- 材质问题 → 改**光位**
- 色彩问题 → 改**白平衡与饱和度的描述**

## 六、LUT 的两类与一个致命误用 —— **这一节原本是给调色师看的；AIGC 场景下它的用法是审 AI 出片（检查一个 look 有没有被硬套），落点是本节里「对 AIGC 的迁移」那一段。**【待确认项：是否把本节整体改写为审片口径，待定】

| 类型 | 作用 | 谁提供 |
|---|---|---|
| **技术 LUT** | 把 **LOG 转成标准显示空间**（Rec.709 / DCI-P3），让画面"正常" | **厂商免费提供** |
| **创意 LUT** | 施加美学 look（胶片模拟 / 青橙 / 去饱和惊悚） | 第三方或自己生成 |

### ★ 最常见的致命错误

> **把创意 LUT 直接用在 LOG 素材上，而不先做技术转换。**
> **创意 LUT 是为 Rec.709 输入设计的**——喂给它平坦的 LOG 数据，结果不可预测、通常很糟。
> **永远先归一化，再加创意 look。**

**对 AIGC 的迁移**：AI 的"原始输出"不是 LOG，**它已经是成品**。所以这条纪律在 AIGC 里表现为——
> **不要在提示词里既要求"胶片宽容度、暗部有细节"，又要求"极高对比、深黑"**——那是"用创意 look 覆盖未归一化的素材"的文字版。**先决定"这一场的光是否保住"，再决定"色往哪偏"。**

### LUT 用得不廉价的四个手法（青橙实践的通用化）

1. **降不透明度到 70%**（预烘焙 LUT 推得狠；实剪只需 50–70%）【待核】此数值回一手源前不要当唯一答案
2. **只推阴影，不推中间调**（保住脸）
3. **用滚降对比的变体**——让调色"被感受到，而不是被看到"
4. **给主色的饱和度设上限**（→ `color-narrative.md` §一·4）

## 七、五个最常见的错误（同样适用于审 AI 出片）

| # | 错误 | 后果 |
|---|---|---|
| 1 | **调过头** | "更多不等于更好"——**如果看起来像被重滤镜处理过，就是过头了** |
| 2 | **压死黑位** | 监视器上看着戏剧，**在别的屏幕与压缩格式里会崩** |
| 3 | **肤色过饱和** | **人眼对肤色极敏感：朝品红或黄偏 5% 就不自然**【待核】此数值回一手源前不要当唯一答案 |
| 4 | **忽略示波器** | "**眼睛会适应它正在看的东西；调色 30 分钟后，你就不能相信自己的感知了**" |
| 5 | **在未校准的监视器上调色** | 起点就是错的 |

> **第 4 条对 AIGC 创作者尤其值得记住**：**看了一整天自己出的图之后，判断力会漂。** 隔夜重读（`steelman-protocol.md` 第 6 步）不只是文本纪律，**也是色彩纪律**。

## 八、★ 色彩 → 提示词：模型到底理解什么

> **本节是整份文件的落点。** 前面的理论、配色、流程，**最终都要变成这一节里的句子**——变不成的，就不该写进提示词。

### 8.1 模型理解色彩的方式，和人类不一样

> **色彩名带的是"联想"，不只是色相。**

扩散模型在数十亿图文对上训练——你写"深红（crimson）"，**它检索的不是一个十六进制值，而是一簇联想**：天鹅绒、戏剧、文艺复兴的褶皱、血红、权力。写"樱桃红"拉进的是**另一个邻域**：复古、有光泽、俏皮、中世纪广告。
**所以两个几乎相同的色相，能产出完全不同的图。**

**推论**：**想要什么观感，就写那个观感所属"邻域"的词**，而不只是写色相。

### 8.2 hex 码：是锚点，不是保证

- 模型接受 hex 并能较好遵守，**但不完美**——光照、材质、渲染风格都会移动最终像素
- **换个角度说同一件事（2026-09-13 补 · 第三方独立口径）**：
  *"模型并不逐字解释 hex 码，但**具体性本身传达了你的意图**"*
  → 所以 **hex 的价值有两层**：① 模型真按它取色（部分成立）② **写出精确数值这个动作，本身就把你的色彩意图收窄了**。
  **第二层才是它"总是有用"的原因**——所以才说它是锚点，不是保证。
- 同一个码用在哑光陶瓷上落在几档之内；**用在"铬"上会反射环境，完全不像色卡**
- **最可靠的做法：描述性语言 + 码**
  → `哑光玫瑰粉（#C9A9A6），哑光表面，柔和漫射光` **胜过单独写 `#C9A9A6`**——**周围的词告诉模型"这个颜色该怎么表现"**【待核】此数值回一手源前不要当唯一答案

### 8.3 四层色彩词汇（写色板时按这四层想）

| 层 | 写什么 | 词例 |
|---|---|---|
| **色相** | **具体的色名**（不是色族） | 酒红 · 芥末黄 · 鼠尾草绿 · 钴蓝 · 梅紫 · 赭石 · 石板灰 · 胭脂 · 牛血红 · 玉绿 |
| **温度** | 整体冷暖倾向 | 暖 / 冷 / 中性 / 黄金时刻的暖 / 冰蓝偏色 / 钨丝琥珀 |
| **饱和度** | 强度 | 低饱和 · 去饱和 · 鲜艳 · 霓虹 · 粉彩 · 宝石色 · 粉笔质 · 晒褪色 |
| **明度与对比** | 明暗结构 | 高对比 · 低调 · 明暗对照 · 通透 · 深阴影 · 抬起的黑位 |

★ **一条最高效的替换**：写"红色"给你**正红**；写**酒红 / 深红 / 灰玫红 / 砖红**，分别得到**四种完全不同的色调**。**色彩词的精度，直接决定配色质量。**

### 8.4 色彩在提示词里的固定顺序（顺序对了，模型才好解析）

```
主体 + 色彩角色（主导 / 点缀 / 中性） + 色相词 + hex 锚点 + 光照 + 分级参考
```

**例**：`一位女性穿铁锈橙亚麻西装（主导），背景是低饱和的鼠尾草绿（中性衬底），柔和的窗光，低对比暖调`

### 8.5 ★ 光就是色彩陈述（最容易漏的一条）

> **光照关键词与色彩关键词是同一件工具。**
> "黄金时刻"注入琥珀色与长暖影；"阴天"把一切压平并变冷；"霓虹招牌"把洋红与青加进每一个反射面。
> **如果你指定了色彩却忽略了光照——光照会赢。**

**落点**：本库的层序里，**【光位与影调】行排在【统一提质层】之前不是偶然**。**光写对了，色彩的一半就定了。**（光位的物理原因 → `skin-realism.md` §1.4 与 `light-physics.md`）

### 8.6 情绪配色的色板（可直接抄的起点）

| 情绪 | 色板 |
|---|---|
| 温暖治愈 | 橙 · 黄 · 奶白（夕阳与暖灯） |
| 忧郁冷静 | 蓝 · 青 · 灰（雨天与深海） |
| 神秘高贵 | 紫 · 黑 · 金（夜空与宫殿） |
| 清新活力 | 青 · 绿 · 柠黄（春天与草地） |
| 浪漫梦幻 | 粉 · 紫 · 淡蓝（樱花与晚霞） |

### 8.7 两条"高级感"的底层逻辑

> **用色调统一建立氛围，用对比冲突制造焦点。**

- **限定色板**：`主色 + 辅色 + 一点点点缀`——**一张图的主色不要超过三种**
- **环境色渲染**：`[环境光描述]，环境光反射在皮肤与衣物上`
  ★ **"环境色的存在，是色彩统一且真实的关键"**——一个人站在红霓虹下，**他的皮肤和衣缘必然泛红**。**这一句同时解决了"色彩统一"和"人物像贴上去"两个问题。**
- **冷暖同框**：`暖色主体 + 冷色背景`
  **纯暖调容易闷，纯冷调容易寡淡——冷暖同框才有张力。** 强对比（橙对蓝）＝戏剧张力；**弱对比（暖灰对冷灰）＝高级感**。

### 8.8 色彩分级参考（最省字数的色彩指令）

**电影 / 摄影参考是最高效的色彩指令**：`青橙大片的调色` · `柯达 Portra 400 的色板——暖肤色、柔和的绿` · `韦斯·安德森式的对称粉彩` · `霓虹洋红与青的雨夜都市` · `褪色的宝丽来暖调`

> ⚠️ **但 `quality-layer.md` 第 4 条禁止写 IP 名**（片名 / 角色名 / 演员名）——**上面这些必须翻译成风格描述**：不写"银翼杀手"，写"霓虹洋红与青、雨夜都市、强逆光"。
> **"参考作品"是给创作者看的锚点，进提示词前必须翻译。**

### 8.9 一条总纲

> **"AI 不懂审美，它只懂概率分布。不给它一套严密的色彩逻辑，它默认的输出就是一堆高饱和色素的堆砌。"**

所以色彩在提示词里的作用**不是装饰，是指令**——**你不给逻辑，模型就替你选**（而它选的那个，就是 §八·一 里"训练数据里最常见的"那个＝**默认审美区**）。

## 来源与许可（2026-09-13 新建）

**本节为专项调研后的提炼 + 本库自建**，覆盖色彩三属性 / 加法减法色 / 六类配色 / 校色与调色的先后 / 示波器与肤色线 / LUT 两类。来源：

- **StudioBinder《What is a Vectorscope?》**——矢量示波器读法（角度＝色相、离圆心距离＝饱和度、**75% 广播安全线**【待核】此数值回一手源前不要当唯一答案；**肤色线位于红与黄之间**；两条纪律：**肤色调整放在校色最后一步**、**示波器是参考不是判决**（改完更难看就退回去）。<https://www.studiobinder.com/blog/what-is-a-vectorscope-definition>
- **ProVideo Coalition《A New Chart for Film-Style Production–The DSC OneShot》**——**I 线与 Q 线**；**饱和度与准确度是两件事**："没落进目标框但落在正确矢量线上，色相仍是准确的"；**只有最深的那块肤色芯片正好落在 I 线上**，其余分列两侧。<http://www.provideocoalition.com/cameras-a-new-chart-for-film-style-production-the-dsc-oneshot/>
- **openrv-web 官方文档《Vectorscope》**——**肤色线约 123 度**（红与黄之间）【待核】此数值回一手源前不要当唯一答案；**不论肤色深浅都聚在该线附近，变的只是离圆心的距离**；"**记忆色**"（天蓝 / 叶绿 / 肤色）；**日审片时点云整体朝一个方向偏＝全局色偏**，常见成因是输入色彩空间设错或现场白平衡没做。<https://lifeart.github.io/openrv-web/docs/scopes/vectorscope.html>
- **Pinnacle Studio《Color Grading: Selective Vectorscope》**——肤色线用于**跨镜**肤色一致性；**戏剧性冷暖光下不必强求落在线上**（判据要分场合）。<https://origin3-www.pinnaclesys.com/en/landing/color-grading/selective-vectorscope>
- **Simple LUTS《Technical vs Creative LUTs》** · **LogGate《LUTs Explained》** · **Creatoressentials《What Is a LUT?》**（三处独立来源口径一致）——**技术 LUT＝把 LOG 转成正确平衡的 Rec.709，是校准不是风格，厂商免费提供**；**创意 LUT＝风格，且为 Rec.709 输入而设计，直接喂 LOG 结果不可预测**；正确顺序：**曝光 → 白平衡 → 技术转换 → 创意 LUT**；另有 **monitoring LUT** 与 **output/display LUT** 两类。
- **本库自建部分**：第 八 节"**色 → 提示词的转化**"（模型怎么理解色彩 / hex 作为锚点 / 四层色彩词汇 / 固定写法顺序 / 光就是色彩陈述）**无外部来源，全为本库据 AIGC 实测归纳**——实拍调色的对象是**已拍到的像素**，提示词的对象是**还没生成的像素**，这一步没有现成文献可抄。

**许可红线**：以上**一律只提炼方法与机制，未复制任何来源文本**；影片名与配色搭配属**事实性指称**（"这部片用了这个色"），不构成对影片素材的复制。**LUT 厂商与器材商博客只取被多源印证的机制**（技术 / 创意 LUT 的划分与顺序在三个独立来源口径一致），**不取**其营销话术与具体产品推荐；**具体 LUT 产品名一律不进本库**。
