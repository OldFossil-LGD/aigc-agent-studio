## 一、★ 产出质量与规格（R40）

| 项 | 结论 |
|---|---|
| **资产图 quality/resolution** | **2K ＋ high quality 即够，不需为一致性追求 4K**——**一致性取决于"主体特征清晰 · 角度/光线标准 · 同一主锚点反复引用"，不是源图分辨率**；**4K 的价值在成片放大 / 二次裁切余量**；**"4K 更一致"无可量化依据（未映射）** |
| **`count`（1/2/4）** | **计费规则：未映射**（以客户端计费页为准）；**语义：`count=4` ＝ 同一 prompt 一次采样 4 张候选（同主体/同场景不同随机结果），用于挑最好一张**，**不是自动 4 个不同构图**；**推荐：写实人脸主锚点（高失败率、需挑脸）值得多出几张；场景/道具用 `count=1` 省额度** |
| **★ 写实人脸首帧用哪个模型** | **首选 `Lib Image 2.5 Pro`**（配 `reference_nodes` 一致性最稳）；**需更强写实可试 `Seedream 5.0 Pro`**；`General image Pro` 备选；**Midjourney 系偏风格化不作首选**；**务实做法：同一锚点同一 prompt 在两模型各出一张 A/B，选定后全片沿用同一模型避免脸部漂移** |
| **★ 首帧与故事板构图冲突以谁为准** | **以该首帧节点实际 prompt ＋ 引用为准**——**故事板图不会被自动读取**；**要严格照故事板，必须把对应格作为参考节点传入**并写明"构图/机位/景别严格参照此格"；**推荐：首帧 prompt 就是故事板该格的"等价视觉转写"，文字写死构图并引用主锚点** |
| **★★ 一镜几个动作节拍** | **5 秒＝1 个主动作节拍**（最多 1 主动作 ＋ 起幅/收幅微动作）；**"注视—拿起—放下"是 3 个状态变化节拍，塞进 5 秒会被加速/省略、界限糊、手部穿帮上升，不建议**；**经验值：物体交互节拍（拿起/放下/转身/推门）≈ 2–3 秒 · 纯表情/注视 ≈ 1–2 秒 · 还要留入画出画缓冲**；**落地：拆两镜（镜A 注视伸手拿起／镜B 持物放下）或延长到 8–10 秒并接受简化** |
| **★ "锁死项"怎么写** | **把"锁定对象"与"允许运动对象"分开写**：<br>「**摄影机完全固定：机位、焦距、构图全程不变，无推拉摇移、无变焦、无手持晃动。**」<br>「**画面内人物保持自然生命活动与表演：可呼吸、可有细微表情与视线变化、可执行（具体动作）；仅镜头本身不运动。**」<br>**→ ★ 锁的是 camera，不是 subject**；**避坑：不要只单独写"静止镜头/静态画面/static shot"** |
| **★ 微表情/生理活性** | **呼吸 · 眨眼 · 自然视线漂移：通常有正向作用**（写明"自然、轻微、不夸张"可减少假人感），**但不保证按指定节奏/次数精确执行**；**★ 瞳孔缩放基本白写**（像素占比极小）；**同样偏白写**：精确眨眼次数/间隔 · 精确呼吸频率 · 帧数级微动作时序 · 手指精确根数与复杂手势 · 极细微眼神聚焦距离变化 |
| **★ 转场** | **`composite_video` 不支持硬切以外转场**（无 `transition`/`fade`/`dissolve`/`wipe`）；**溶化/淡入淡出/淡到黑走 `edit_video_v4`**（能力含 `fade`/`dissolve`/`to-black`/`white`）——`source_node_keys` 给素材、`brief` 写明"X 秒处加 0.5s 溶化、片头淡入黑、片尾淡出黑"；**划像 wipe 未映射**；**默认：硬切为主，仅片头/片尾淡到黑，必要处短溶化** |
| **`mp4` vs `mov`** | **两者是封装容器不是编码器，画质不由容器决定**；**mp4 兼容性最好（默认，交付/预览/分发首选）**；**mov 仅 Apple 专业后期 / 明确要求 / 需透明通道**；**本任务用 mp4** |
| **★ 成片怎么下载** | **工具侧无下载/导出本地文件接口**；**成片＝画布节点（`node_key`），不是本地文件句柄**；**节点内部有可访问媒体 URL 但非承诺稳定长期外链**；**可靠做法：在客户端手动下载**；**自动化取片需平台开放 API → 未映射** |

## 二、★ 交付与外部运维（R41 · 大量"未映射"，但三条关键）

| 项 | 结论 |
|---|---|
| **产物 URL 永久性** | **未映射** → **应假定链接可能失效，不要把产物 URL 当永久存储**；**★ 落库时同时保存 `node_key`，用 `node_key` 重新获取可用地址** |
| **`resource_info`** | **它侧未映射**（我方有） |
| **★ `inspect_media` 能否当"一致性机检"** | **它侧未映射**；**它侧同类能力＝`analyze_video`**（返回**整体结构与分段级视觉分析**）；**★ 但"与锚点的一致性机检"不能直接当可靠手段**——**现有分析工具是对单个素材的内容描述，不提供"与指定锚点逐帧比对并给出一致/不一致判定"的契约化字段** → **最多作辅助人工核验，不能替代一致性校验** |
| **官方成片验收清单** | **未映射** → **自建建议**：产物可访问性/链接有效性 · 分辨率与画幅 · 时长 · 音轨是否符合预期 · 台词/字幕准确性 · **与锚点一致性** · **节点状态是否已生效** |
| **`task_status` 轮询** | **它侧未映射**；**它侧任务状态机制＝`task_list_v2`/`task_read_v2`（planned/in_progress/completed）＋ 节点是否已有产物**；**间隔/重试/限流：未映射** → **通用保守建议（非官方）：指数退避、起始 10–30 秒、避免高频轮询** |
| **单 run 节点上限** | **未映射**；**可确认的只有 Agent 侧并行约束（无依赖一次最多 5 个）**——**这是编排侧并发约束，不等于平台 run 的节点总数上限** |
| **★ run 超时** | **超时时长未映射**；**但一条有用事实**：**`create_*_node` 只写参数不扣费，节点以"已创建"状态存在于画布；"已创建但未运行"的节点通常保留、不因对话轮次结束而消失**（**但这是节点持久化行为，不等同"run 超时后平台如何处理"的官方承诺**） |
| **回调/webhook** | **未映射** → **现有契约下只能轮询** |
| **★ "先低档试跑再升档"** | **无"只收差额"机制（未映射）** → **保守假定：改参数后在原节点重跑＝按一次新生成计费（重复扣费）**；**推荐做法：先用低档（480p/720p、短时长）run 验证构图/动作/台词；确认后 `update` 到高档并重新 run，预算按两次独立生成算** |
| **★★ 外部编排者最易忽略的运维陷阱** | **把"节点已创建"当成"产物已生成/已生效"，并据此去轮询或下载产物。**<br>**`create_*_node` 只落参数、不扣费、不产生任何媒体；必须再经 `run_node` 提交、等待生成完成，节点才"已生效"并有产物 URL。**<br>**→ 必须以"节点已生效（有产物）"为唯一交付判据，并妥善保存 `node_key` 以便链接失效后重新取址。** |

## 三、★★★ 内容方法（R42 · 创作层最有价值的一份）

### 3.1 ★★ 无对白片怎么承载信息 ＝ 四条视觉通道
| 通道 | 承载 | 做法 |
|---|---|---|
| **动作** | **情节 / 因果** | **"目标—阻碍—反应"三段式设计每个动作**；**关键动作必须"可读"（一个动作只表达一个意图，幅度与景别匹配——远景看肢体、近景看手部/眼神）**；**用动作的"重复与变化"交代转折**（同一动作做两次、第二次结果不同） |
| **道具** | **身份 / 前史 / 关系** | **选 1 个核心道具做"信息锚点"**，**在开场/转折/结尾各出现一次，状态发生变化**（干净→碎裂→被放下）；**★ 道具的"拿取方式"比道具本身更传情**（攥紧 vs 轻轻放下） |
| **光影** | **情绪 / 时间** | **给全片定一个主光逻辑并让它随情节变化**（暖侧光＝安全 → 顶光/硬阴影＝暴露 → 冷低照度＝落空）；**用光源方向引导视线**（主光永远先打到"此刻最重要的信息"上） |
| **景别** | **心理距离** | **远景交代处境 · 中景交代动作 · 近景/特写交代情绪与关键道具**；**情绪转折点用"景别跳级"制造心理冲击** |
**★ 落地检查单（每镜过一遍）**：① **不看画面只看动作，能否复述发生了什么？** ② **遮住角色脸，只看道具/光影，能否读出情绪？** ③ **本镜若删掉，信息是否缺失？不缺失就删。**

### 3.2 ★ 结构：30 秒无对白推荐"铺垫—转折—落点"三拍
- **铺垫（0–10s）**：建立常态 ＋ 核心道具 ＋ 角色目标；
- **转折（10–20s）**：一个动作或一个新信息**打破常态**（发现 / 失败 / 误会 / 到达）；
- **落点（20–30s）**：**推荐"落空 / 余味"式收尾**（目标达成但意义改变，或差一点没达成）；**最后 2–3 秒留一个静止画面让情绪沉淀**；
- **★ 推荐 3 个大拍**（需要更强节奏可在转折内拆两个小拍，**全片 4 拍封顶**）；
- **★ 一句话故事模板**：**「【谁】在【什么处境】下想【目标】，却【转折】，最后【落点】。」**

### 3.3 ★★ 分镜密度
- **推荐 6–9 镜，写实无对白单场景舒适区 ≈ 7 镜**；
- **每镜 2.5–6 秒**；**铺垫/落点偏长（4–6s，让观众读信息与情绪）· 转折段偏短（2.5–4s，靠剪辑提速制造张力）**；
- **避免连续多个 1–2 秒短镜**（写实片会碎、削弱表演）；**避免单镜超 8 秒**；
- **★ 景别递进两种**：**情绪向**＝全/远→中→中近→近/特（转折）→特写（道具/眼神）→中/全（落点拉开，形成回响）即"收—放"；**悬疑/发现向**＝中近/特写开场（先给局部信息制造疑问）→拉开交代处境→再收紧到关键发现；
- **通用规则：相邻镜头景别至少差一级 · 转折点用一次景别跳级 · 全片至少给一个"场景全貌镜"**。

### 3.5 ★ 资产图官方模板
**`character_turnaround_3view`（全身/服装/体型）· `character_face_turnaround_3view`（脸部多角度）· `scene_turnaround_3view` · `product_turnaround_3view`（★ 平台没有独立的 `prop` 模板，道具复用产品三视图）**；
**用法：`tag` 分别选 `character`/`scene`/`prop`；prompt 中仍需文字描述本体，模板负责组织多视角版式**。

### 3.6 ★★ "一次出多个方案选一" vs "重抽"
- **平台没有"多方案/变体"独立字段或官方批量出图模板**（多格模板用途是**多机位/多节拍**，**不是"同一角色的多套设计方案"**）；
- **实践**：**建多个独立 image 节点（每个一套外观描述）→ 分别生成 → 横向比较 → 选定一个再出三视图**；
- **★ 判据**：**方案分歧大时**（主角长相、场景风格）→ **多节点并行比"一张反复重抽"更省**（**重抽是在同一描述上赌随机数，无法系统性比较设计方向**）；**方案已明确只差质感时** → **重抽或用 `portrait_texture_adjustment` 更省**。

### 3.7 ★ 多情绪版本
**无官方模板** → **替代**：**先出 `character_face_turnaround_3view` 锁五官与身份 → 再以它为参考节点分别建独立节点生成"笑/哭/疲惫"单表情特写**，prompt 明确"同一人物、保持五官一致，仅表情变为……"；**30 秒无对白片建议至少做 1 张"本片主情绪"表情图（通常是落点表情）**，不必凑齐全表情。

### 3.8 ★★ 资产图的负面项写法
**无独立 `negative`/`negative_prompt` 字段** → **写进 prompt 正文，用明确否定句式，且"正向描述优先、否定兜底"**：
- **先写想要的**（写实摄影质感、自然皮肤纹理、现场光），**再补排除项**："避免卡通化、避免塑料感皮肤、避免过度磨皮与美颜、避免夸张五官、避免多余手指与肢体畸形、不要文字水印、不要 logo"；
- **★ 写实人物建议固定写入**："**真实皮肤纹理与毛孔、不对称的自然细节、无磨皮、无美颜、无卡通渲染**"——**比单纯写"不要假脸"命中率高**。

### 3.9 ★★ 保证全片风格统一（无风格库时的替代）
- **先做一张 `style_display_board`（风格展示板）或定调关键帧**，写清：**胶片/数字质感 · 影调（冷暖、对比）· 光质（硬/软、光源方向）· 镜头焦段感 · 色彩清单 · 颗粒程度**；
- **此后所有资产图/分镜图/视频节点统一把该风格板加入 `reference_nodes` 并在 prompt 中以占位符引用**，写明"**视觉风格、影调与质感以该风格板为准**"；
- **文案上维护一段固定"风格串"，逐节点原样复制**（机型/焦段/光位/调色方向），**用词不变，减少漂移**。

### 3.10 ★★★ 写实人物片的成功学（7 条）
1. **光照：写具体光源而非抽象氛围**——"**窗边自然侧光，上午柔和日光，弱填充光，浅阴影，真实皮肤纹理**"；**避免"唯美光影/高级感"这类不可执行词**；**全片光位保持一致（如始终来自画面左侧）→ 跨镜连续性显著提升**；
2. **构图/镜头语言：用可执行的摄影术语**（焦段 35/50/85mm · 机位眼平/略俯/略仰 · 景深 · 画幅内人物位置）；**每镜只指定一个主机位意图，不要在一个 prompt 里堆叠运动**；
3. **★★ 参考图数量：每个生成节点引用 1–3 张最稳**（**1 张锁身份 · 1 张锁场景 · 1 张锁风格**）；**超过 3 张容易互相打架**；**被引用的每个节点都必须在 prompt 里以占位符出现并写明用途**（**只在 `reference_nodes` 挂名而 prompt 不说明，约束会变弱**）；
4. **写实模型**：图片用 **`Lib Image 2.5 Pro`（默认推荐）** 或 **`Seedream 5.0 Pro`**；**人像质感微调用 `portrait_texture_adjustment`**；**光效不统一时用 `cinematic_lighting_correction` 校正，而不是重抽**；
5. **人物一致性**：**先三视图/脸部图定稿，再让所有后续图与视频引用同一节点**；**服装/发型/年龄/体型在每个 prompt 里重复简述**（**不能假设模型记得上一镜**）；
6. **Prompt 组织**：**正向写实锚点 ＋ 具体动作 ＋ 具体光位 ＋ 禁止项兜底**；**一次只讲一个画面瞬间，不写跨时间的连续情节**（连续情节交给分镜拆分或视频节点）；
7. **★ 无对白表演**：**近景写眼神与微表情方向**（"视线落向桌面，嘴角轻微下压"），**避免只写"悲伤"这类情绪标签**——**给模型可画的肌肉动作，命中率高于抽象情绪词**。

## 五、★★★ 标准 11 段板块命名 + 账本文件层（2026-09-24 平台裁定 · 新增）

### 5.1 标准板块命名（**固定口径 · 按链路顺序**）
```
01_剧本定稿（Draft）
02_分镜总表（Board Index：画幅 · 模型 · 全局风格基调 · 时长 · 制作清单 · 规划核对）
03_分镜条目（Shots / Dn：每镜一条）
04_内容锚点（Anchors：角色/场景/道具，含状态变体）
05_派生锚点（Derived：三视图 · 近距版 · 机位视图 · 站位锚 · 续镜锚点）
06_故事板（Storyboard frames / Sn）
07_关键帧（Keyframes：首帧 Fn，必要时尾帧）
08_镜头生成（Shots video / Vn）
09_声音（Audio：BGM / 环境声 / 音效 / 旁白 TTS）
10_合成（Composite / video-clip：时间线 · 混音 · 转场 · 字幕）
11_交付验收（Delivery：导出参数 · 封面 · 验收清单）— 可与 10 合并落同一节点，但条目不能省
```

### 5.2 ★★ 三条切分纪律（最容易搞混的地方）
1. **`02_分镜总表` 与 `03_分镜条目` 不是一类**：总表＝**规划账本**（画幅/模型/全局风格基调/制作清单/规划核对）；分镜条目＝**每镜执行卡**。节点放同板块也要**在命名上区分**。
2. **`04_内容锚点` 与 `05_派生锚点` 要分层命名**：内容锚点＝角色/场景/道具本体；派生锚点＝三视图/近距版/机位视图/站位锚。
3. **`09_声音` 与 `11_交付验收` 是最常被漏掉的两段**——声音是**成片必交付物**，不能为 0；导出动作本身**不需要节点**（是 X1 上的操作），但**验收条件必须显式落账**。

### 5.3 ★★★ 账本文件层（**画布节点是镜像，账本才是正本**）
**问题**：把全部信息压在画布节点上 → **缺少可恢复、可逐版审计的文件层**。
**正解**：一个制作目标一个 **task**，账本按下列结构落文件：

```
制作账本_<片名>/
├── TASK.md                       制作目标 · 范围 · 成片规格 · 11 段板块落实表 · 交付验收标准 · 扩展公式
├── drafts/剧本定稿_vN.md           剧本定稿（原文唯一、逐字可核；改写必须出新版本号）
├── story_boards/分镜总表与分镜表.md  ★ 含"引用锚点"字段 —— 生成引用的正本
└── anchors/锚点集.md               锚点 node_key · 锁什么 · 不采用什么 · 派生关系 · 口径锁定
```
**★ 核心纪律**：
- **账本的"引用锚点"字段是生成引用的正本**；创建/点火节点时的 `reference_nodes` **必须与之一致**；
- 画布上的 `Dn` 文本卡是**人工可读镜像**，不是决定生成引用的地方；
- **每次生成只收到本次 prompt 与显式引用** → 不能假设模型记得 `Dn` → **`Fn`/`Vn` 的规格与动作/台词必须逐字写在 prompt 内**。

### 5.4 ★ 节点规模扩展公式（按镜数 N 推导）
```
节点总数 = 3（剧本 + 总表 + 合成）+ 4N（分镜条目 + 故事板 + 首帧 + 镜头）
           + (C + L + P)（内容锚点：角色/场景/道具种类数）+ D（派生锚点数）+ A（声音轨条数）
```
- **每条短视频 +4 节点**（分镜条目 · 故事板 · 首帧 · 镜头）；
- **不随镜数增长**：剧本 1 · 总表 1 · 合成 1（≤25 镜；超则 `ceil(N/25)+1`）· 内容锚点（随主体种类）· 交付 0–1；
- **随镜数线性**：分镜条目 / 故事板 / 首帧 / 镜头（各 N）；**尾帧＝承接边数**（硬切 0，全连戏 N−1）；
- **半固定**：声音轨条数（按层，不随 N）· 站位锚（按跨镜布局数）。
- **实测校核**：15s/3 镜写实片 ＝ `3+12+3+3+2 = 23` ✅ 与实际节点数一致。
  **★ 但它指出 23/57 里的 57 条边偏多**：主因是**母/派生锚点扇出到多层** → 见 §六·6.4。

## 六、★★★ 标准节点图 · 建造顺序 · 分化规则（2026-09-24 平台裁定 R47）

### 6.1 建造顺序表（**批 0–7** · 谁先建谁后建）
| 批 | 建什么 | 硬 / 逻辑依赖 | 写锁 |
|---|---|---|---|
| **批0** | `P1` 剧本 · `P2` 总表 · `D1…DN`（文件层） | `P1→P2` 硬 · `P2→Dn` 硬 | 文件写也建议串行 |
| **批1** | **母锚点 ×C**（角色/场景/道具） | **逻辑依赖**：可先建空锚点、后补 prompt | **逐条 create** |
| **批2** | 派生锚点（按需） | **硬**：必须先有母的 `node_key` | 逐条 |
| **批3** | `S1…SN` 故事板 | **硬**：被引锚点先有 `node_key` | 逐条（**`left` 一次排对**） |
| **批4** | `F1…FN` 首帧（+可选尾帧） | **硬**：`Sn` 先有 `node_key` | 逐条 |
| **批5** | `V1…VN` 镜头 | **硬**：`Fn` 先有 `node_key`；**点火前 `Fn` 必须已生效** | 逐条 |
| **批6** | `AU1…AUM` 声音 | **逻辑依赖：可任意早建**（与批3/4/5 时间独立） | 逐条 |
| **批7** | **`X1` 合成** | **公式级最硬**：全部 `Vn` + `AU` **已生效** | 工具一次调用 |

**★ 三条顺序铁律**
1. **内容上先 `P1`；画布实体第一个建"母锚点"**——它们是所有 image/video 的**引用根**，最先需要 `node_key`。**先建 S/F/V 再建锚点是最典型的错**（只能补引用 → `left` 顺序乱、易漏引）。
2. **最后建 `X1` 合成。**
3. **"先建空节点、后补边、最后一起点火"适用于**：母锚点 / 故事板 / 首帧 / 镜头 / AU；**必须等上游已生效的三处**：①派生锚点点火 ②`Vn` 点火（`Fn` 已生成）③`X1`。

### 6.2 分化规则（什么节点分化出几个）
| 节点 | 数量 | 公式 | 随镜数 N |
|---|---|---|---|
| `P1` 剧本 | 1 | 固定 | 否 |
| `P2` 总表 | 1 | **不分化** | 否 |
| `Dn` 分镜条目 | **N** | 1:N | **线性** |
| `A` 母锚点 | **C** | 主体种类/独立个体数 | 否 |
| `A` 派生锚点 | **Σdᵢ** | 每个母按需 dᵢ，可=0 | 弱增长 |
| `Sn` 故事板 | **N** | 一镜一板 1:1 | **线性** |
| `Fn` 关键帧 | **N·k** | **k 默认 1（首帧）**；尾帧/中间帧按需 | 线性 |
| `Vn` 镜头 | **N(+e)** | 一镜一节点；e＝超长镜拆段数，**通常 0** | 线性 |
| `AU` 声音 | **M** | 人声+音乐+音效条数，**与 N 解耦** | 否 |
| `X1` 合成 | **1** | ≤约 **25 镜**＝1；更多按场次拆 `X_sub` **树状**总合成 | 否（阶梯） |

**三档降级**：**最小版**＝砍派生锚点 / 尾帧 / 镜头拆段 / 子合成，声音仅 1 条或**用视频原声**；**标准版**＝母锚点＋少量派生＋Sn＋Fn(首帧)＋Vn＋AU(M)＋单一 X1；**完整版**＝全套派生＋一镜多关键帧＋长镜拆段续写＋声音细分＋子合成树＋色彩/字幕/章节卡。

### 6.3 ★ `left`（参考位）排列规范
**统一顺序原则：先"内容来源" → 后"一致性锚点（角色→场景→道具→派生）" → 最后"帧/上游段"**

| 节点 | `left` |
|---|---|
| `Sn` | `[本镜 Dn 依据(prompt 写明), A角色母, A场景母, A道具母, …本镜派生锚点]` |
| `Fn` | `[Sn, 必要的母锚点（仅当 S 不足以锁身份）]`；尾帧 `Fnb.left=[Sn]` |
| `Vn` | `[Fn首帧, Fn尾帧(若有), A角色母(仅身份漂移风险时), A场景母(少用)]` |
| `X1` | **`[V1…VN（延长段紧随母段）, AU1…AUM]`** —— **`left` 即时间线顺序，必须与放映顺序一致** |
| `A派生` | `[其母锚点]` |
| `AU*` | `[]`（**标准链不引 `Vn`**） |

### 6.4 ★★ 扇出收敛规则（**治"边数爆炸"**）
- **派生锚点只在需要它的那一层被引用：默认只服务 `S/F`，不回连 B 以外的所有层。**
- **`V` 层优先靠首帧继承**；只在**身份会漂移**时，把**母锚点（不是派生）**补进 `Vn`。
- **"不要让每个派生都扇出到 S/F/V 三层"** —— 否则**边数爆炸**，且**改一处母锚点要作废一大片下游**。
- **收敛后边数量级参考**（N=3）：约 **14–17 条**（不含文本层）。

### 6.5 命名模板
**`<层码><两位编号>[_子类或状态]`** —— 层码：`P` 文本 / `A` 锚点 / `S` 故事板 / `F` 关键帧 / `V` 镜头 / `AU` 声音 / `X` 合成。
例：`P1_剧本` · `P2_分镜总表` · `D01_分镜条目` · `A1_角色母` · `A1d1_角色表情怒` · `S01` · `F01_首帧` · `F01b_尾帧` · `V01` · `V01b_续` · `AU01_旁白` · `X1_合成`。**编号从 01，全程等宽。**

### 6.6 ★★ 建造顺序上最容易犯的 5 个错
| # | 错 | 后果 |
|---|---|---|
| 1 | **先建 S/F/V 再建锚点** | 锚点 `node_key` 后拿到 → **`left` 顺序乱、易漏引 → 跨镜不一致** |
| 2 | **派生锚点扇出到 S/F/V 全部层** | **边数爆炸**；改一处母锚点作废一大片下游 |
| 3 | **`left` 顺序随手排** | 事后不可重排 → **X1 放映顺序/角色主次错位，镜头或音频串位** |
| 4 | **锚点/首帧未生效就 run `Vn`** | 首帧无效 → **身份漂移，只能废弃重建（每产物最多 3 次）** |
| 5 | **超 25 镜塞单一 `X1`；把 AU 连到每个 `Vn`** | 时间线校验重、难定位；**声音被各镜头原声混音盖住**（composite 线性求和后限幅） |

### 6.7 ★ 它的两条"节点能力"说法与我方实测冲突（**以我方 MCP 为准**）
| 它说 | 我方实测 | 结论 |
|---|---|---|
| 可实体化节点类型**只有 image/video/audio**，文本层只能落文件 | `create_node` 的 `nodeType` **6 档**（含 `text`/`script`/`video-clip`），我方**已实建 text 与 video-clip** | **我方为准**（两侧工具面不同） |
| 合成 `X1` **不可空建**，须由 `composite_video` 产出 | `create_node(nodeType="video-clip")` **可建**，并让 `counts.timelines` +1 | **我方为准** |
| "没有独立建边工具，边只能建节点时定" | 我方有 `leftAdd`/`leftRemove`/`leftEnsure` **可事后改集合**（**顺序不可重排**） | 两者都对：**集合可改、顺序只能建时定** |

本轮它自称"已代建 `STD_` 参照链"，而**答案落画布时实测画布仅 1 节点 / 0 边**；随后才逐条真正建出（约 2–4 分钟/个）。

## 七、★★ CLI `download` 的实现契约（**REA 静态 · 2026-10-15/16**）

> 本册 §一/§二 记的是"工具侧无下载接口、可靠做法是客户端手动下载"；**本轮读到了 CLI `download` 命令的实现层**——**下载现在有契约可依**。

- **入口**：`executeLibtvDownload({ targetNodeKey, nodes, opts })`，`opts = { watermarkPref, isVip, outDir }`；
  **★ 下载一个分组＝递归展开组内全部叶子资源**（走 `childNodeIds`）；
- **三条逐字错误**：`画布中不存在节点: <key>` · `该节点（及组内子节点）没有可下载的资源（图片/视频/音频/脚本/文本）` · `可下载条目数为 0`（**两类空结果分开报**）；
- **资源按 `action` 分类**：图/视频**各三档**（RESOURCE/GENERATE/EDIT）；**音频只有两档（无 EDIT）**；脚本判定认 `nodeType` **或** `dataType` ∈ `{script, storyboard}`；
- **出什么文件**：图片 `label[_N].<原格式>` · **视频强制 `mp4`** · 音频 `label`/`音频`（**不走水印**） · 脚本 **CSV（带 UTF-8 BOM）** · 文本 `label`/`文字.txt`；**同批文件名用 Map 去重**；
- **★★ 水印是两个独立维度（最容易踩）**：**只有 `watermarkPref === 1` 且 `isVip` 同时成立才直取原 URL**；
  否则调水印接口并传 `watermark: pref !== 1` ＋ **`communityWatermark: !isVip`**；
  **接口返回空则回落原 URL** ⟹ **"下载成功" ≠ "水印如你所愿"，交付前必须看画面（不能只看文件名）**；
- **ZIP 策略**：**分组必打 ZIP** · 条目 >1 打 ZIP · **单节点多产物（一条视频多 URL）仍是单文件**；`zipSync` 用 **level 6**，父目录 `mkdir recursive`；
- **脚本 CSV 列序**：按 `SCRIPT_FIELD_META`，**动态角色列 `角色N`/`角色描述N`/`角色图N` 插在 `plotDescription` 之后**；**`videoReference` 列取 `videoReference.referenceFrameImage`**；表头名以服务端 `shotColumns` 为准。
