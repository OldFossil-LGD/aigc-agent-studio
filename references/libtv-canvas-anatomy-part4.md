## 十六、★★★ 坑位与异常（【实证】）

### 16.1 时长：三种关系都存在

| 关系 | 案例 |
|---|---|
| 声明 = 实际 | 绝大多数节点 |
| 声明 > 实际 | 33 秒声明 → 30.048s（30s 上限静默压缩） |
| **声明 < 实际** | `settings.duration:22` → **实际 30.048s** |
| 声明 ≠ params | `settings.duration:5` → **实际 29.056s**（且 prompt 为空） |

⭐ **想要准确时长不能只靠 `duration`**，必须在提示词末尾给收尾指令
（模型演完时间码后不会停，会继续填满到上限）。

### 16.2 `timeoutReported:true` 累计 7 例与 `status:2` 并存

`v-G6ep2P8sHV` / `v-MfsYcqv76w` / `v-RdsMdmNF0m` / `v-iZnO2O1DtH` /
`v-Tx9FUL2K1b` / `v-MXoxX5ZUzD` / `v-pj8TwYINJS`

→ **平台给实际成功的任务误报超时。遇"失联"必须多轮 `task_status` 确认，
不可据超时直接重跑。**

### 16.3 `audioList` 空但 `audioListOrder` 有 id

`v-gdTOFMOnHl`：`audioListOrder` 有两条，而 `mixedListOrder` 里**也确实没有音频**
→ 是**音频边被移除后 `audioListOrder` 没同步清理的残留**，不是序列化丢字段。
⚠ 只有这一例，不能断定所有空 `audioList` 都是这个机制。

### 16.4 `params` 与实际可能不符

- `mixedListOrder` 有但 prompt 是纯文字（插桩被删）
- `i-Z3Iv81BRzT` 声明 `text2image` 却挂了参考图
- `v-Tx9FUL2K1b` 全局块在复制中被截断（止于"这是一架高科技战术运输机"，无句号无后续）
- `v-iEpAbWmbww` 缺一个换行，标题粘在上一行

→ **复制后必须回读全文，不能假设源节点完整、副本也完整。**

### 16.5 `status:2` ≠ 提示词写得对

第七段 `v-DvjnyhsD53` status:2 成功，但实测三处引用质量问题：
银枪图在 `mixedList` 里而长枪是本段第一主角，提示词却完全没插桩它。

→ **平台不会因为漏插桩而拒绝生成。必须回读提示词逐条核对插桩。**

### 16.6 回读噪音字段（不要误当创作参数）

`expandedGeneratorHeight` / `expandedGeneratorWidth` / `videoHasAudioTrack`
—— UI 状态或单例字段

### 16.7 同节点重跑多次是常规动作

至少 7 对节点正文逐字相同但 `taskId` 不同，全部 status:2

### 16.8 同一段时间码可挂两条互斥且都成功的叙事分支

`v-LglMCZurbA`(11s) 与 `v-Tx9FUL2K1b`(14s)，镜号 S15–S17 与时间码完全相同，
一条是"本段不碰武器"，一条是"掷枪 + 跃出舱门"
→ ⚠ **导出前必须人工确认用哪条，画布数据无法判断。**

## 十七、★★ 候选池：变体 / 重试 / 复制 三分法

| 类型 | 判据 | 证据 |
|---|---|---|
| **变体** | 提示词有实质差异（换约束维度 / 加参考 / 改时长） | `v-8mZNyNjxF0` 对 `v-0DtTZq6PfG` |
| **重试** | 同一提示词在同一节点再次点火 | `v-0DtTZq6PfG` 与 `v-dN2w3gamFf` |
| **复制** | 派生新节点，提示词不变 | `prevTaskInfo.node_uuid` 可验证 |

⚠ **三者在画布上都表现为"多个同名副本节点"，光看节点名无法区分。**
⚠ 节点名后缀 `- 副本` = 候选版，不是只读副本。

## 十八、★★ 同一画布两套写作文化（owner 分工）

| | owner `5b4cb494`（一至六段） | owner `d57c1d05`（七至十一段） |
|---|---|---|
| 文体 | 临床克制的技术文体 | 网文体（极其/狂暴/天神下凡） |
| 时间码 | 全片绝对 01:14.0—01:43.5 | 局部 00:00.0—00:19.5 |
| 场次编号 | `镜头S1` / `镜头D1` / `场景5` | `第一场` / `镜头1` |
| 技法标注 | 中文 | **中英双写** |
| 执行锁定 | 有，12 条 | 没有 |

⭐⭐ **⚠⚠「某 owner 的风格"结论必须收窄，不能一刀切」**：
`d57c1d05` 既写过纯 `镜头1` 无功能句的，也写过
`裂缝与执念`/`背后的定海神针（极致子弹时间）`/`黑风衣降临` 全功能句的
→ **同一 owner 下两种写法都存在且都成功。**

⭐ 值得抄的一点：把电影技法术语与焦段写同一行
`28mm，倾斜贴地手持（Dutch Angle 20°）` = 给模型一整套镜头语言词汇表。

⭐ 网文体不等于空洞：夸张形容词挂在**具体物理量**上
（`三米内` / `数指宽` / `仰角75度`）。⛔ 空洞写法是"非常快""特别大"。

## 十九、★ 模型与声音

### 视频：全线单模型（【实证】）

当前 118 个 video 节点中 **115 个为 `star-video2.5`（Seedance 2.5）、3 个 missing**；旧 130 读数不作现行分母。
→ ⛔ 这批样本里"可灵 2.5 / mj-v8.2 可用于视频"**没有实证**
→ **这批制作者在视频模型选择上根本没做 A/B**

### 图像（【实证】）

`lib-image-2`（7 个）· `lib-image-2.5-s`（2 个，主角去脸图）· `mj-v8.2`（2 个）

### 声音：走音色克隆，不走独立 AU 节点（【实证】）

`enableSound:"on"` + 上传 mp3 音色样本作参考，对白直接写在提示词。
三个音频节点全是 3–5 秒音色样本：
`a-xZDjRDNsMg` 零的语音(3.576s) · `a-j11gAnv1GH` 五号声音(3.456s) ·
`a-LmepJpr3dz` 上司的语音2(5.352s)

### 资产形态（【实证】）

以上传真人实照为主：`action:"image_resource"` + `copyrightChain{author}` +
`portraitCertifiedInPlace` + `protectionType:"watermark"`
全局资产库每条引用带 `assetId` + `complianceCheckedAtMs` + `compliantExempt`

## 二十、⚠⚠⚠ 本库 11 步链路是【库规】，不是平台要求

### 本库 `SKILL.md` 写的链路

```
分镜卡(text) → 故事板(image) → 首帧(image) → 镜头(video) → 合成
```

### 画布实证

**《弥寿计划》当前 118 个 video 节点里，没有一个接首帧节点，也没有一个故事板节点。**
真实做法只有两层：`资产图 → video 节点`。

### 各环节强制性

| 环节 | 画布上真实存在吗 | 平台强制吗 |
|---|---|---|
| 资产 image 节点 | 大量存在 | **不强制**（八个悬空仍全部 status:2） |
| 分镜卡 text 节点 | 一个都没有 | 不强制 |
| 故事板灰度 image | 一个都没有 | 不强制 |
| 首帧 image 接 frames2video | 一个都没有 | 不强制 |
| video 到 video 衔接 | 连线被禁 | **物理必须靠文字** |
| 尾帧/截图 image 节点 | 4 个 | 不强制，但是唯一的血缘手段 |

### ⭐ 资产可以后补，但代价是造型失控

`i-Mu2dzClPz9`（上司的脸）与 `i-lbndv27pYl`（银枪）悬空，
被第七段与五个节点引用，结果**全部 status:2 成功**。

→ 画布**不强制**「资产必须先建」，可以先建 video 再补资产。
→ 但模型会按提示词里的语义名即兴生成，造型没有真实锚点约束。

⭐⭐ **「先建资产」不是平台门禁，是质量手段。**
（与「禁项要在参考图层同时检查」是同一件事的两面）

⚠ **这条是对本库 §0 定律的补充，不是推翻**：
平台不强制 ≠ 不该做。链条完整仍然是降低返工率的手段。
**但不要把它说成硬要求。**

## 二十一、节点顺序的三种含义（不要混）

| 含义 | 权威 | 来源 |
|---|---|---|
| **图序号** | `mixedListOrder` 的 1-indexed 位置 | 【实证】五组 |
| **叙事顺序** | **提示词标题行**的镜号 | 【实证】`v-ekvZ8VOk7W` 标题写「23—42镜」 |
| **画布位置** | 只表示分组归属，**与叙事顺序无关** | 【实证】x 三带布局 |

⭐ **读节点第一步是看标题行**，不是看它在画布上的位置。

## 二十二、开建前的检查清单（合并资产层 + 视频层）

```
资产层
☐ 主体与场景是分开的节点吗？（主体不许焊进场景图）
☐ image 节点需要 prompt 吗？（上传的不需要，生成的极简即可）
☐ 关键角色做了多角度图吗？（三宫格：正+背+特写）
☐ 禁项检查过「参考图层」吗？（参考图本身若就是错误造型，禁令会被压过）

连线层
☐ 每次 leftEnsure 后回读 mixedListOrder 了吗？
☐ 全部 {{Mixed N}} 按新的 1-indexed 位置重编了吗？
☐ 每个被引用的 key 同时出现在 left 和提示词里了吗？
☐ 有没有靠语义名反查图片？（必须查 mixedListOrder）

提示词层
☐ 越轴治法：在镜头表之前有独立的整体空间锁定块吗？
☐ 每个方位都配了"从哪个方向拍"吗？
☐ 交互移动路径锁了吗？
☐ 升格镜写了"进入升格后仍保留某种运动"吗？
☐ 每个"该帅"的时刻配了反摆姿势禁令吗？
☐ 禁项写的是"改成什么呈现方式"而不是"不要 X"吗？
☐ 执行锁定锁的是因果必然性吗？

顺序层
☐ 读了标题行确认这个节点负责哪段镜号吗？
☐ 段落之间的衔接指定了同一个画面元素连续吗？
☐ 时间码体系是全片绝对还是段内相对？
☐ 想要准确时长，提示词末尾给收尾指令了吗？

验收层
☐ 有没有把 agent 的客套话烧进提示词？
☐ status:2 之后逐条核对插桩了吗？（平台不管写得对不对）
```
