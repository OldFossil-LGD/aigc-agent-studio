# 剧本模块规格（M1–M12）：剧本板块的交付契约

> **何时读**：**每次接到"写剧本"时第一件事**；交付前用门禁跑一遍。
> **读完回哪**：M8 的版式 → `script-format.md`（**唯一权威源**）；各模块的内容方法 → `drama-*` 十七册（入口 `drama-library.md`）；下游 → `studio-workflow.md` 第二步（资产）与第三步（分镜）。
> **定位**：本文件管**"交付物由哪十二块组成、每块的接口是什么、缺哪块就返工"**。
> **★ 工作流，不是随手写**。按所选交付档位保留固定模块与顺序，缺少该档必需模块即 FAIL。档位见 §7。

---

## §0 三条纪律（先读，违反任何一条本文件就白写）

| # | 纪律 | 判据 |
|---|---|---|
| **1** | **模块齐备、顺序固定** | M1→M12，不重排、不合并、不新增第十三块。要加内容就加进**对应模块内部** |
| **2** | **缺一即返工，不"以后补"**（**按交付档位分判**：**L2 缺一即返工**；L0 / L1 本就只交部分模块〔L0＝7 块 · L1＝10 块，见 §7 阶梯表〕，**唯 L0 必须显式标注"本稿为 L0 可拍最小版"**——**静默降级与没做在门禁眼里是同一件事**） | 门禁 `script_lint.py --mode full --level <档位>` 按所选档位列出缺项，省略 `--level` 时沿用 L2 |
| **3** | **上游没定稿不动下游** | M2（前提）没定 → 不写 M5；M4（容量）没算 → 不排 M5 的秒；M11 没出 → 不进资产阶段 |

**为什么是 12 块**：与第三步的**分镜 12 板块**（`shot-craft.md`；块名与职责见 `block-spec.md` §一总图）**同一计数**——**剧本 12 模块 → 分镜 12 块**，**只对齐"数量"，不对齐"逐块内容"**（两侧各自定义，名与职责并不相同：M1 抬头 ≠ 第 1 块后期特效，M5 结构骨架在分镜侧亦无同名块）——**交接时按册逐块取，不要按序号硬套**；好记、好查、好交接。

## §1 十二模块总表

| # | 模块 | 一句话功能 | 必填 | 上游（谁喂它） | 下游（谁用它） | 最常见错 |
|---|---|---|---|---|---|---|
| **M1** | **抬头** | 片名 / 时长 / 画幅 / 版式档 / 交付范围 | ✅ | 用户提问 | 全流程的口径锚 | 时长写"大概一分钟" |
| **M2** | **前提** | 一句可反转的命题（Egri 前提 / McKee 主控思想） | ✅ | M1 | M5 的选型 · M8 的结尾 | 写成情绪词 |
| **M3** | **梗概** | Logline + 一句话梗概（类型 / 主角 / 目标 / 阻力 / 代价） | ✅ | M2 | 对外沟通 · M5 骨架 | 写成剧情流水账 |
| **M4** | **容量单** | 时长 → 拍数 / 反转 / 场数 / 台词字数上限 | ✅ | M1 | **M5 的上限闸门** | 先写后算（必超） |
| **M5** | **结构骨架** | 选定模型 + 各拍功能与秒数（秒数累加 = 总时长） | ✅ | M2 · M4 | M7 · M8 | 模型不具名 · 秒数不等 |
| **M6** | **人物** | ≤3 人：外在目标 / 内在需求 / 致命缺陷 / 一句话谎言 / 弧光型 | ✅ | M2 | M8 的表演 · 资产的身份锚 | 只有形容词 |
| **M7** | **场景表** | 逐场一行：场号 / 内外景 / 地点 / 时间 / **功能** / **进→出** | ✅ | M5 | 资产清单 · 分镜排镜 | 一场干两件事 |
| **M8** | **剧本正文** | 好莱坞格式的正文（六元素） | ✅ | M5 · M6 · M7 | 分镜正文与台词 | 用简版格式交付 |
| **M9** | **台词与旁白清单** | 逐字锁定：说话人 / 台词 / 所在场 / **字数 / 秒数**；旁白另列 | ✅ | M8 | 声音层 · 口型风险预算 | 字数超语速 |
| **M10** | **无对白版** | 纯画面若干行，验证"删掉台词仍能看懂" | ✅ | M8 | 检验叙事是否靠画面 | 直接抄正文 |
| **M11** | **交接契约** | 逐场四键（`scene` / `open_state` / `close_state` / `hard_facts`）+ 资产清单 | ✅ | M7 · M8 | **第二步出资产 · 第三步排镜** | 缺键 · 状态不可画 |
| **M12** | **诊断记录** | 十五病命中情况 + 最小改动 + **副作用** + 只改哪个变量 | ✅ | 全篇 | 返工依据 | 只写"没问题" |

**必填的含义**。表中勾选表示 L2 完整版必填，L0/L1 的必需模块以 §7 为准。已交付的可选模块仍须符合本模块接口。"这部片没有旁白"要**在 M9 里写"旁白：无"**——**"不适用"也必须显式写**，静默省略与没做在门禁眼里是同一件事。

## §2 逐模块接口

### M1 抬头
- **答什么**：这份稿子的物理参数。
- **必含五项**：片名 · **总时长（精确到秒）** · 画幅（竖屏 / 横屏 / 具体比）· **版式档**（B 中文工作版 / A 英文送审版）· 交付范围（只剧本 / 剧本+资产+分镜）。
- **判据**：时长能被解析成秒；版式档具名。
- **常见错**："大概一分钟""电影感"。**时长是唯一不可协商的输入**（`drama-scaling.md` §0）。

### M2 前提
- **答什么**：这部片在说什么，且**能推出反面**。
- **写法**：Egri 三段式（性格特质 + 冲突 + 结论）或本库的可反转测试。
- **判据**：把它反过来**不成立**；且它**不出现在任何台词里**。
- **下游**：M5 的模型选型、M8 的结尾动作都要为它服务。

### M3 梗概
- **答什么**：Logline（一句）+ 一句话梗概。
- **判据**：Logline 里能指出**类型 / 主角 / 目标 / 主要阻力 / 失败代价**五件（不齐就是没想清）。
- **常见错**：写"故事讲述了一个人如何……"——那是剧情摘要，不是 Logline。

### M4 容量单（**先算再写**）
- **答什么**：这部片**装得下什么**。
- **必含**：总时长 · 拍数 · 反转数 · 场数 · 台词总量上限 · **威胁递增写法**（空间收缩 / 代价升级 / 时间压缩 三选一）。
- **判据**：拍数 ≤ 档位上限；**秒数总和 = 总时长，无空档、无重叠**。
- **上游权威**：`drama-scaling.md`（档位表与折叠规则）。**超容量 → 换模型，不是删拍。**

### M5 结构骨架
- **答什么**：用哪个形状、每一拍干什么、各占多少秒。
- **必含**：**模型具名**（如"故事圈 8 步，折叠为 5 拍"）+ 逐拍功能 + 逐拍起止秒。
- **判据**：模型具名；秒数**累加等于 M4 的总时长**（门禁会算）。
- **上游权威**：`drama-structure-models.md`（十六模型 + 选型决策树）。
- **常见错**：拍数超容量；拍的功能写成"事情发生"而不是"局面变化"。

### M6 人物
- **答什么**：谁在挣扎、往哪变、靠什么撑。
- **必含（每人五项）**：外在目标 · 内在需求 · 致命缺陷 · **一句话谎言**（他自己真心相信的那句）· **弧光型**（A 正向 / B 负向 / C 平弧 / D 幻灭）。
- **判据**：五项齐；弧光型具名；**每人一处可执行的身体痕迹**（→ `character-sheet.md`）。
- **短片之外的题材**：人数上限随容量放宽，但**每次放宽都要在 M4 里给出场次与镜数预算**。

### M7 场景表
- **答什么**：全片由哪几场构成、每场干什么。
- **必含列**：场号 · 内外景 · 地点 · 时间 · **功能** · **进→出**（进场状态 → 出场状态）。
- **判据**：**每场都有功能**（删掉它后面就断）；**每场有进出差**（进出相同 = 废场）。
- **下游**：地点去重 → **场景资产清单**（同名不同写会造出多余资产）。

### M8 剧本正文
- **答什么**：可拍的文字。
- **版式**：**一律按 `script-format.md`**（中文适配档默认）——场景标题四要素、动作只写可见可听、人物名独占一行、括号 ≤4 词、对白不用引号、转场只在有意义时写。
- **★ 密度（不是"越省越好"）**：**每 1 分钟成片 ≈ 500–900 字正文**；**< 400 字/分钟 = 提纲，判不合格**。**动作行是页面主体**，对白只占版面约 1/3；**单段 3–4 行是常态也是上限**（→ `script-format.md` §2.1）。
- **判据**：过 `script_lint.py` 的格式组与**密度组**；**正文区不出现「人名：台词」的简版残留**；**正文能被没看过梗概的人复述出"这场发生了什么、周围什么样"**。

### M9 台词与旁白清单
- **答什么**：台词逐字锁定，且**能不能说完**有据可查。
- **必含列**：说话人 · 台词（逐字）· 所在场 · **字数** · **秒数**。
- **判据**：**字数 ÷ 秒数 ≤ 5**（门禁会算）；旁白单独一段并标**距离（当下 / 回望 / 冷叙）与主关系（补充 / 对位 / 矛盾）**。
- **注意**：**改写措辞本身就是漂移源**——清单一旦锁定，正文与分镜逐字复用。

### M10 无对白版
- **答什么**：删掉全部台词，画面还成不成立。
- **写法**：纯画面若干行（每行一个画面），不写台词、不写心理。
- **判据**：**只看它就能看懂故事**。看不懂 → 叙事过依赖台词，回 M8。

### M11 交接契约（**进第二步的放行门**）
- **答什么**：每场给下游的三行硬事实 + 需要出的资产。
- **必含（逐场四键）**：`scene`（场号）· `open_state` · `close_state` · `hard_facts`（恰好人数 / 唯一道具 / 逐字台词 / 禁止出现的东西）。
- **判据**：**逐场四键齐**（门禁按行查，整篇写会漏）；状态必须是**可画出来的**。
- **下游**：资产清单（场景 / 角色 / 道具）→ `studio-workflow.md` 第二步。

### M12 诊断记录
- **答什么**：这一稿哪里最可能坏、改了哪一处。
- **必含**：十五病命中情况 · **最小改动** · **副作用**（必填，不许空）· **只改哪一个变量**。
- **判据**：有"副作用"一栏；改动有账。
- **上游权威**：`drama-script-diagnosis.md`（十五病 + 五层顺序 + 五项误诊清单）。

## §4 与格式的关系（**别混**）

| | 管什么 | 权威源 |
|---|---|---|
| **本文件（模块规格）** | 交付物**由哪十二块组成**、每块的接口与判据 | 本文件 |
| **`script-format.md`（剧本格式）** | **M8 那一块纸面上长什么样**（六大元素 / 位置 / 特殊情形 / 中文档） | 该文件 |
| **`script-craft.md`（剧本机制）** | 钩子、留人三件套、分场到分镜的收口 | 该文件 |
| **`drama-*` 十七册** | 每一块**内容怎么想出来**（结构 / 人物 / 对白 / 类型 / 诊断 / 转换） | `drama-library.md` |

**一句话**：**模块给骨架，格式给皮，方法给肉**。三者缺一都能过门禁的一部分，但**只有三者齐才叫交付**。

## §5 门禁怎么跑

```text
python3 scripts/script_lint.py <剧本.md>              # L2 完整版，兼容既有默认调用
python3 scripts/script_lint.py <剧本.md> --level L1   # L1 标准版，十模块
python3 scripts/script_lint.py <剧本.md> --level L0   # L0 最小版，七模块且稿内显式标注
python3 scripts/script_lint.py <剧本.md> --mode body  # 只发剧本正文（M8 单发），跳过模块齐备
python3 scripts/script_lint.py --self-test            # 23 条自检
```

**退出码（与其余四个门禁同一套）**：`0` 全过 ｜ `1` 有 FAIL ｜ `2` 用法错 ｜ **`3` 没扫到（≠ 通过）** ｜ `4` 只有 WARN。

**它会判什么**：A 组（所选档位的必需模块与顺序）· B 组（场景标题四要素 / 中文档加粗 / 括号不含情绪形容词且 ≤4 词 / 简版格式残留 / 转场滥用）· C 组（语速 ≤5 字每秒 / 节拍秒数累加 = 总时长 / 交接契约**逐场**四键 / 诊断含副作用栏 / 块内元说明 / 空话词）· **D 组 俗套黑名单**（`drama-plotcraft.md` §4 的致命档：命中即 WARN，**M12 写明「加了什么条件」则放行**——黑名单不是禁止表，是「必须付代价才能用」的表）。

**⚠️ 读退出码，不要只看有没有输出**：看到 `3` 要当作**没验到**——先确认文件贴对了（`SKILL.md` 收尾自检第 4 条同口径）。

## §6 时长无关（**本 skill 覆盖任意时长**）

**同一套十二模块对任何时长都成立**；变的只有 **M4 容量单里的数值**与**M5 的拍数**：

| 档位 | M4 拍数 | M4 反转 | M5 常用模型 |
|---|---|---|---|
| 15–60 秒 | 2–6 | 1 | 起承转合 / 故事圈 / 序破急 |
| 90 秒–3 分钟 | 6–8 | 1–2 | 故事圈 / 七点 |
| 5–15 分钟 | 8–12 | 2 | 七点 / 15 拍（折叠） |
| 20–45 分钟（单集） | 按幕 | 2–3 | 幕结构 + 卡点 |
| 90–120 分钟（长片） | 完整骨架 | 2–3 | 15 拍 / 八序列 / 英雄之旅 |
| 多集 | 每集一套 M1–M12 + 一条总弧 | —— | 序列法 + 幕结构 |

> **纪律**：**门禁里不许写死任何时长上限**——"60 秒必须 ≤6 句"是某一档的容量，不是通用契约。**档位只在 M4 里生效**（权威源 `drama-scaling.md`）。

## §7 三档交付阶梯（**时间紧时按这三级砍，不许自由发挥**）

| 档 | 保留模块 | 什么时候用 |
|---|---|---|
| **L0 可拍最小版** | **M1 · M2 · M4 · M5 · M6 · M7 · M8** | 只想先看正文能不能拍 |
| **L1 标准版** | L0 + **M3 · M9 · M11** | **默认交付档**（能直接进第二步） |
| **L2 完整版** | 十二模块全（+ M10 · M12） | 正式交付 / 归档 / 要返工追溯 |

**L1 与 L2 的差别只有两块**：M10（无对白体检）与 M12（诊断账）。**跳过 L2 = 放弃"下次能改回来"的能力**——所以正式交付一律 L2。
**L0 必须显式标注**"本稿为 L0 可拍最小版"——**静默降级与没做在门禁眼里是同一件事**。

日常标准交付按 L1，正式交付按 L2。CLI 省略档位时检查 L2，检查 L0/L1 须显式传 `--level`。`--mode body` 用于单发正文，与 `--level` 互斥。

## §8 常见失败与处方

| 症状 | 根因 | 处方 |
|---|---|---|
| 每次生成的剧本结构都不一样 | 没有模块契约 | 改为按 M1–M12 出，跑 `script_lint` |
| 剧本很漂亮但拍不出来 | 没走 M4 → M5 的容量链 | 回 M4 量容量；过高风险项在 M7 里换戏 |
| 到了分镜才发现缺东西 | M11 没出或四键不全 | 逐场补四键；**M11 是进第二步的放行门** |
| 台词拍不完 | M9 没算字数秒数 | 按 5 字/秒回算，超了就砍字或改旁白 |
| 交付后不知道改哪 | M12 空着或只写"没问题" | 补"最小改动 + 副作用 + 只改一个变量" |
