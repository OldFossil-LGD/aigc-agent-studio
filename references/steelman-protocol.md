# 双向钢人论证（写提示词前的强制推演）

> **何时读**：动笔写任何提示词之前（强制）。**读完回哪**：推演完回到 `studio-workflow.md` 第三步写成品。

> **铁律：不许跳过反题。**
> 提示词写浅，不是不会写，而是**太快进入输出**——第一版思路没被质疑，就直接固化成句子了。
> 双向钢人论证 = 强制把「最强支持」和「最强反对」都写出来，再合成。
> 反对意见必须**针对本条的、具体的、能被反驳的**；写不到具体句子，就等于没想。

## 五步

### 第 1 步 · 正题：把自己的思路写成最强版本

不只是写"我要这么写"，还要写出**它为什么最可能成功**——依据哪条原理、哪次实测、哪个已知的模型行为。
没有依据的自信就是运气。

### 第 2 步 · 反题：站在模型那边，写出最强的失败论证

逐条自问，**每条都必须拿本提示词里的具体句子当证据**，不能泛泛而谈：

| # | 问什么 | 具体到 |
|---|---|---|
| 1 | **哪一句会被稀释或忽略？** | 被埋在长段落中间？是形容词而不是动作？被前后两句挤掉了权重？ |
| 2 | **这个动作在统计上是长尾吗？** | 模型见过类似动作吗？少见＝必崩（三点触碰、精密交互、少见工具） |
| 3 | **有没有互相打架的约束？** | 既要"静止锁定"又要"风吹动"；既要"极特写"又要"全身可见" |
| 4 | **顺序错了吗？** | 关键信息是否落在注意力弱位（末尾长段 / 被形容词包围 / 夹在两句之间） |
| 5 | **可执行性缺口** | 写的是**判断**（"她很累"）还是**可见的东西**（"肩线一边高一边低"）？ |
| 6 | **物理可算吗** | 力从哪来？接触点在哪？谁先停？被接触面有没有反应？ |
| 7 | **一致性会被谁破坏？** | 这一镜和相邻镜的资产 / 光位 / 状态有冲突吗？ |

每一条还要给**代价判断**：不修的后果是"画面直接废"还是"只是不够好"——只有前者才值得为它牺牲别的东西。

### 第 3 步 · 交锋：给每条反对意见配一个具体修法

修法必须落到 **改哪一句 / 加什么 / 删什么**。不许写"注意一下"。
若两条修法**互相冲突**（例如"加细节"与"减法提示"），**明确写出取舍和理由**——不要假装两边都满足了。

### 第 4 步 · 合成与留痕

输出最终版，并列出**三到五处关键改动**，每处标注它对应第 2 步的哪条反对意见。
最后补一句：**这版仍然可能失败在哪里，失败之后先改哪个变量。**

### 第 5 步 · 交付前自查（未全过 = 不交付）

合成之后、发给用户之前，对以下 10 项逐项打勾。**任何一项不过，修完重查，不许带病交付。**

- [ ] **具体名词覆盖空洞词**：没有"电影感 / 震撼 / 精致 / 4K / 高级"这类词，全部换成了具体器材、具体动作或具体材质
- [ ] **器材锚点在位**：写明了量级（摄影机 + 镜头型号，或风格化量级的渲染方式）
- [ ] **呼吸/机械浮动写全**：不是只写"手持有"，而是带全限定词（极轻微 + 如呼吸般 + **非恒定节律**——禁写"每 N 秒"式频率）
- [ ] **声音行在位**：写明了"无配乐、只保留现场音"，并**显式列出**关键环境音
- [ ] **瑕疵数量够**：角色 / 装备 / 服装各自至少有**两处**具体瑕疵
- [ ] **结尾克制**：没有在结尾堆特效、爆光、胜利姿势；用留白收
- [ ] **一镜一动作**：时间线里没有并列的多个主动作；关键动作只写 1–2 个
- [ ] **物理可算**：能指出力从哪来、接触点在哪、什么被压/被扬起、谁先停
- [ ] **无 IP 名**：没有把具体作品名、角色名、演员名写进要交给模型的提示词（正源 `quality-layer.md` §四·4：一律翻译成风格描述）
- [ ] **时长在限内**：单镜 ≤15 秒（默认档；长档模型按 `platform-matrix.md` §三另核）；多镜序列 ≤8 镜（快段另守 `sequence-craft.md` "约 7 镜已是上限"）

## 三条配套纪律

1. **反对意见不许写成清单式废话**——"注意物理""保持一致"这种话等于没写。
2. **改动要有账**——交付时给出"改了什么、为什么改"，不能悄悄换内容。
3. **不许为了显得周全而堆长度**——钢人论证的目的是**减少失败**，不是把提示词写得更长。
   最理想的结局是：推演很长，成品很干净。

## 什么时候必须走满五步

- 写**新的**一镜提示词
- **返工**（出片不合格、要求强化）
- 涉及**物理交互 / 负重 / 精密动作 / 多人同框**
- 用户明确指出"太浅""不对"

**可以简化的场合**：纯资产图（无动作）、纯格式转换。简化也要在回复里说明"这一步为什么可以省"。

## 第 6 步 · 外部盲评（交付前最后一道，2026-09-11 补）

**为什么需要**：钢人论证是**自己跟自己对打**——你反驳的是"你想到的失败"。真正的漏洞往往是**你没想到要反驳的那条**。自己写的推演会系统性地漏掉自己不知道的盲区。

**做法**：交付前，找一个**没参与过这个项目的人**（同事 / 朋友 / 用户之外的第三方），只给他**成品**（提示词块 + 板块一故事板），**不给任何背景解释**，问他三个问题：

| 问 | 想测出什么 |
|---|---|
| **① 你看完第一句，觉得这片子想拍什么？** | 意图是否自明（不明确 = 意图层漏了） |
| **② 有哪句话你没看懂，或者觉得前后打架？** | 内部矛盾（自审最容易漏的就是自相矛盾） |
| **③ 如果让你删掉一句，删哪句？** | 冗余（长度纪律的第三方验证） |

**三条纪律**：

1. **不许解释**——你一开始解释，测的就变成"你的口才"而不是"文档的自明性"。
2. **盲评成本极低**（三五分钟），但**回报率最高**——它专门抓"你潜意识里默认对方知道"的东西。
3. **没有第三方时怎么办**：把成品**隔一天**再读（时间是最便宜的外部视角）。隔夜重读时，**只当自己是接收者**，不许回忆"我当初为什么这么写"。

**记录**：盲评发现的问题写进交付说明（"外部盲评发现 X，已改为 Y"），这是**质量证据**，不是丢脸的事。
