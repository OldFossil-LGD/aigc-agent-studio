## §0 位置判据：它是**执行层**，不接管判据层

一句话：**WorkRally 提供「怎么把手里的提示词投出去并拿回产物」；「该写什么」一个字都不归它。**

| 层 | 谁定 | 判定凭据 |
|---|---|---|
| **判据层**（写什么 · 合不合格） | **本库** | 八个 `*_lint.py` + `blocks` + `lib_doctor`（`SKILL.md` 改动纪律 4–5） |
| **结构层**（排镜表 → 场次数据） | **本库 → 桥**（`workrally_bridge.py`） | 排镜表门禁（同一把尺子：`shotlist_lint.py`） |
| **执行层**（投喂 · 取件 · 记账） | **WorkRally** | 平台返回的 `task` / `get-result` / `asset_id` |

**为什么必须先把这条写死**：WorkRally 自带「提示词优化」（`generate optimize-prompt`）与平台内 Agent。
**它不读本库**——把定稿权交给它，等于把机检标准交给它猜。
**它只做加法，不做改写**：它补维度，我们定稿。

### §0·补 通道选择：**选的是「通道」，不是模型**

本册讲的是 WorkRally；本库另一条通道是 LibTV（平台枢纽）与 Updream。**什么时候走哪条**：

| 你当下缺什么 | 选 |
|---|---|
| **要"无人值守也能安全地跑"**——有免费预检、有幂等键与乐观锁、有导出契约 | **LibTV** |
| **要"项目→剧集→场次"三层批量生产 ＋ 资产库树形（人物/道具/场景）＋ 多模式视频 ＋ 三条生成线（图/视频/音频）** | **WorkRally** |
| 只要出图出视频、不依赖画布协同 | 两条都行；**先验通道**（`auth status` + 一次最轻只读命令），再按上面两条挑 |

**两条纪律**：
1. **通道选定后，命中率必须分通道记账**（`production-ledger.md` §6.1 的「平台」列）——
   同一个提示词在两条通道上命中率不同，**混算等于把两台机器的误差平均掉**。
2. **不许把一侧的纪律照搬到另一侧**：预检与幂等**只在 LibTV 侧有**，
   审核红线**只在 LibTV 侧有明文**——照搬会得到假安全感（预检 / 幂等的 WorkRally 侧替代见本册 §5；审核红线的处置见 §8「内容审核边界」行）。

> **模型选择（不是通道选择）仍归 `platform-matrix.md` §五**——本册不复述它。

## §1 六个能力 ↔ 库内工位（**这是本册的主表**）

| 平台能力 | 平台命令组 | 库内工位（谁在用它） |
|---|---|---|
| **项目 / 剧集 / 场次 CRUD** | `project` · `series` · `shotlist` | 三步交付的**承载结构**；排镜表（`shot-orchestration.md` §九）经桥落成场次 |
| **AI 生图**（Kontext 系，多参考图） | `generate image` · `shotlist generate-image` | 资产（站 5）· 故事板（板块一）· 关键帧（板块二的静块） |
| **AI 生视频**（6 模式） | `generate video` · `shotlist generate-video` · `update --extra-mode extendVideo` | 板块二投喂；**模式由 `motion-control.md` 决策树定**（见 §2） |
| **AI 生音频 / 音乐** | `generate audio` · `generate music` · `shotlist generate-audio` | **声音后置**（`sound-post-pipeline.md`）——**不许与视频同批**（见 §4 守卫一） |
| **提示词优化（产物是文本）** | `generate optimize-prompt` | **只作 `steelman-protocol.md` 的反题素材**——不进交付物（见 §4 守卫二） |
| **混元 3D** | `generate 3d --asset-id` | 本库**无对应工位**（全库无 3D 资产需求）——**启用前先问用户**，不要顺手带上 |
| **媒资库 / 资产库 / 画布** | `asset` · `material` · `role` · `canvas` | 站 5.5 的载体（见 §3）· 无限画布的排布（`shot-orchestration.md` 的几何用图） |

> **两个「库」不是一回事**（最容易混的一处）：**媒资库 (asset)＝扁平文件池，素材必须入库才能被系统用**；
> **资产库 (material)＝树形目录**（`role_person` 人物 / `role_prop` 道具 / `role_scene` 场景 / `root` 网盘），
> **只能从媒资库挂载**。**人物 / 道具 / 场景这三个词与本库第二步的三类资产同名**——这不是巧合，是可直接对齐的层级。

## §2 决策树 → 平台 mode（**本册最值钱的一条**）

本库早就把「动作怎么解」做成了决策树（`motion-control.md` · `actor-movement.md`），
但**树只说选哪条路，没说平台怎么填**。WorkRally 的 `--mode` 正好把这条路**做成了参数**：

| 决策树选的路 | 平台 mode | 为什么是它 |
|---|---|---|
| **参考主体**（默认） | `SubjectToVideo` | 资产图进参考主体线；本库「资产先行」的默认落点 |
| **首尾帧单步** | `FirstLastFrame` | 对应 `actor-movement.md` 的位移写法 ③；**周期动作的推荐路径** |
| **构图规避**（用画框藏住难点） | `Text`（`--single-image-url` 单图驱动） | 只给一张首帧、不承诺动作——**规避而非求解** |
| **参考视频驱动** | **场次线落 `SmartEdit`**（画布侧才是 `VideoEdit`）；要"延长"时是 `SubjectToVideo` 的**子模式** `extendVideo`，须另带 `--extra-mode extendVideo --extend-source-id <源片 asset_id> --duration <延长秒数>` | 对应位移写法里的「参考视频」与「延长」；**肢体崩坏率最高，预留重抽**（`platform-matrix.md` §二） |

**纪律**：
1. **mode 不许由脚本自选**——`workrally_bridge.py --video-mode` 是**必传参数**，桥只做提醒不做判定（语义判定归 `motion-control.md`）。
2. **模型字段互不通用**：切 mode 必须换对应类别的模型（`shotlist models --category video,videoSingle,videoFrame` 分别对应）。
3. **Auto 智能路由模型平台侧明确不支持 MCP/CLI 自动分流**——**必须选具体模型 id**，不要指望「让它自己挑」。

### ★ 决策树留痕（**桥的第 5 类机检：判没判，可以机检**）

路径是**语义判定**，桥不能替人判；但**"判没判"是可以机检的**——不留痕就无法证明这一镜走过决策树，
而"没走决策树"是本库最贵的一类返工来源（表现就是"试几个 mode 看哪个动得起来"）。

**写法**（每镜一行，写在**分隔线之后、第一个代码块之前**）：

```
──────── 镜2 · 停在枪套上的手 ────────
决策树路径：首尾帧单步
```（板块一·故事板）
```（板块二·视频提示词）
```

> **⚠️ 不许写进代码块**——本库铁律是**块内一切都会被当提示词执行**，「决策树路径」是元数据不是提示词。
> 写进块里桥直接判 **FAIL**（并给改法）。

**桥的三态判据**：

| 交付物里 | 桥怎么判 | 为什么 |
|---|---|---|
| 留了路径且四选一之一 | **按它落 mode**（`notes` 里留"路径 → mode"）；**多镜走了不同路径 → 按 mode 分组下发多条 `set-model`，各带 `--story-ids`** | 一条 `set-model` 只能给一个 `--video-mode`，分组是唯一正确做法 |
| **没留痕** | **WARN（汇总一条，不逐镜刷屏）**，沿用全局 `--video-mode` | 留痕是新规，老交付物不该被判死；但必须让人看见 |
| 留了**认不出**的值 | **FAIL**，回 `motion-control.md` 重判 | 凭感觉写的路径＝没走决策树 |

**四条路径的取值**：`参考主体` / `首尾帧单步` / `构图规避` / `参考视频驱动`（与 `motion-control.md` 决策树的四条路同名，不另起一套词）。

> **人不动 / 写不出位移** → 先回 `actor-movement.md` 走四个根因诊断与 A–D 分级，**再**回来填 mode。
> 不要反过来「试几个 mode 看哪个动得起来」——那是拿钱抽样，不是选型。

## §3 参考闭环的 WorkRally 化（站 5.5 的硬门禁照搬）

**本库的机制答案只有一句**：**一致性是「引用关系」，不是「相似度」**
（`asset-consistency.md`：资产只有 draft / locked 两态，**写在提示词里的身份锚点 ≠ 锁住了身份**）。
LibTV 侧靠「锚点节点 + `{{node_key}}` 插桩」落地；**WorkRally 侧有一套对等的、可机检的机制**：

```
资产图（经媒资库入库）→ material 挂到 role_person / role_prop / role_scene
                      → shotlist recognize 把资产写进场次的参考字段
                      → 每一镜生成时带着引用 → 一致性在系统意义上成立
```

| 平台动作 | 写进哪里 | 本库的对应判据 |
|---|---|---|
| `upload` → `asset create` | 素材入媒资库（**必须**） | 「资产已出」的前置（第二步判据） |
| `material add --json-list`（**必传 `material_id` + 完整 `material_detail`**） | 资产库树形目录 | 资产**可被引用**（缺这两个字段，素材在资产库里根本不显示） |
| `shotlist recognize` | 图片/视频路写 `video_role_data_json`；音频路写 `extra.audio_role_data_json` | **「每一镜都带引用」能否机检的唯一入口** |
| `shotlist bind --type image/video` | 同上（手动补） | `recognize` 认不出时的兜底（测试镜、非常规命名） |
| `shotlist get <story_id>` | 读 `extra.gen_config` 与参考字段 | **开生成前的放行检查** |

**★ 三条硬纪律（与 `asset-consistency.md` 一致，只是换了判据载体）**：

1. **空引用不许生成**：`shotlist get` 读到的参考字段为空 → **这一场不开工**（等价于「空白即不许生成」）。
2. **顺序即身份**：参考图顺序决定谁是谁——**prompt 里「第一张图片」必须对应 `--input-images` 的第一个 URL**。
   本库「最需精准的参考图放最前」（`platform-matrix.md` §二）在这一层就是**参数顺序**。
   **顺序错位＝引用错人，这是最常见的坑。**
3. **一张参考图只承担一个任务**：身份图只给脸、风格图只给风格——**这条在参考图数量上是硬约束**：
   张数必须 ≤ 该模型 `kontext_config.max_input_images`（**现场取，不许写死**）；
   超了不但浪费，还会让模型「平均」出一个谁都不像的主体。

> **⚠️ 参考图未就绪时不许写最终分镜**（本库既有铁律）在这一层的落地就是：
> `recognize` 后参考字段为空 → **停下，列出缺哪张、给谁用**；**不许静默降级为纯文生视频**。
> 「七环各跑通 ≠ 全流程跑通」的教训（每一环都成功、成片也出来了，人物与场景全不一致）
> **在 WorkRally 上同样成立**——因为它同样是「引用没进参考」。

## §4 三条守卫（**不设这三条，接进来就是负资产**）

### 守卫一 · 声音：平台默认开音效，本库默认 No BGM —— **必须显式关**

| | |
|---|---|
| **冲突事实** | WorkRally 生视频**音效默认开启**（不传＝开）；本库铁律是**分镜阶段 No BGM、声音后置**（`run-sheet.md` 站 6 第 11 块 · `sound-post-pipeline.md`） |
| **不设守卫的后果** | 每一镜都带一条模型自配音轨 → 后期必须整批剥掉，且它会**污染「有没有音轨」这条交付判据** |
| **落地写法** | **生视频一律显式 `--no-enable-sound`**（经 `set-model` 写入 `gen_config`）；**`VideoEdit` 模式例外——该模式不要传音效参数**。音频生成排到视频定稿之后，**不与视频同批**。 |
| **机检** | `workrally_bridge.py` 的输出里，配置行**必带** `--no-enable-sound`（自检有对应用例） |

### 守卫二 · 提示词优化：产物只能当**反题**，不许当成品

`generate optimize-prompt` 走平台侧 `gen_content`，**产物是文本（`output_text`），不是视频**。
它的正确用法**只有一个**：**喂 `steelman-protocol.md` 的反题段**——把它当成「模型那边会怎么读这段提示词」的第三方视角。

| ✅ 可以 | ❌ 不可以 |
|---|---|
| 把它的输出贴进反题，逐条判断「这条说到点子上没有」，**每条仍要拿本提示词的具体句子当证据** | 直接当交付提示词（它没读过本库 12 块规格 → 缺块即 FAIL） |
| 借它发现「我漏写了哪一层」 | 借它**替换**库内专有名词（器材型号 / 胶片印片 / 方案包 / 风格编号 / 运镜名——它不知道，一改就错） |

> 一句话判据：**它产出的是「第二双眼睛」，不是「定稿者」。**
> 机检口径更简单——**它的产物过不了本库门禁**（`audit_prompt.py blocks` 缺块即 FAIL），**所以根本不该拿它当交付物。**

### 守卫三 · 阶段门：不同阶段有不同的命令白名单

沿用本库既有的四档阶段（学习与准备 / 实片预演 / 实片测试 / 交付），**落到 WorkRally 的具体命令**：

| 阶段 | 允许 | **禁止** |
|---|---|---|
| **学习与准备** | `auth status` · `project/series/shotlist list·get` · `material list` · `asset search` · `*/models` · `tools list/describe` · `url build`（**全是免费只读**） | 一切 `generate-*` |
| **实片预演**（用户授权后） | 上面全部 ＋ **图片生成**（`generate image` / `shotlist generate-image`） | **视频生成 · 音频 · 3D · 合成导出** |
| **实片测试** | 按 SOP，逐镜跑（含视频） | 未批准的批量铺开（`--count` > 1 要先报数） |
| **交付** | `download` · `url build` · 归档 | —— |

> **判据**：**「这一步我能不能说清它会做什么、花什么？」** 说不清就不执行——先 `--help`，或先问平台内 Agent（**问它不计费**）。

## §5 预算与止损：WorkRally 上**没有**预检，所以止损要更前置

**先诚实说清平台侧的缺口**：

| 本库依赖的纪律 | 平台上有没有 |
|---|---|
| 付费前免费预检（validate / dry-run 类） | **无对应命令** → 只能靠「结构层全部免费 ＋ 先跑 1 条」替代 |
| 写操作幂等键 / 乐观锁 | **未暴露** → 防重复提交**只能靠我方提交前记账** |
| 成本可观测（余额 / 单价） | **无余额接口，无单价明文** → 只能按任务号请用户回查，**引用时必须带日期** |

**→ 所以 WorkRally 上的三条替代纪律**：

1. **能免费的全在结构层做完**：`shotlist create/update/set-model/sort/recognize/list/get`、`canvas build-draft`、
   `asset create`、`material add`、`*/models`、`url build`——**这些都不生成、不花钱**。
   **排镜表与提示词的返工一律在这一层做**（在这一层改是免费的，投出去再改要重抽）。
2. **先 1 条再铺量**：`--count` 默认 1，**不要用 `--count 4` 当「多抽几次」的解**——
   `--count>1` 是**并发发起 N 个独立任务并返回 task_ids 数组**，即**同时花 N 份钱**。
   正确顺序：**先 `--count 1` 跑 1 条验身份与构图 → 成立再批量**。
3. **止损线沿用本库原口径，不许现场松**：一镜 **超 8 次仍不过 → 改结构**（拆镜 / 换机位 / 换景别），
   **不是改词，更不是「再抽最后一次」**（`production-ledger.md` §四）。
   **成本不可读时**：**按任务号请用户回查，在回查前不再增加付费调用**。

**折算**（口径仍以 `platform-matrix.md` §四·补 为唯一权威源，本册不另定系数）：
`本批预算 = 镜数 × 单镜预估次数 × 单次单价`；**单镜预估次数查难度系数表**；
**单价与币种以平台侧账单为准（本册不写死数字——写死了就会过期）**。

## §6 证据链与台账（把「人记账」接成「agent 自动写」）

**四件证据在 WorkRally 上的取处**：

| # | 留什么 | WorkRally 取处 |
|---|---|---|
| 1 | **任务号** | `generate task <task_id>` 的 `task_id`；`--count>1` 时是 **task_ids 数组**（逐个留） |
| 2 | **参数快照** | 场次侧读 `shotlist get <story_id>` 的 `extra.gen_config`；画布侧读节点字段 |
| 3 | **结果路径** | `shotlist get-result --type image\|video\|audio` 的 `results[]` ＋ 落盘路径 ＋ `asset_id` |
| 4 | **判据结果** | 帧级 / 容器级 / 像素级判据的**原始输出**（`review-passes.md` 的七遍法笔记），**不是「通过」两个字** |

> **⚠️ 平台侧缺口要写在交付里**：WorkRally **未暴露幂等键** →
> **「同一 key 重试不会重复花钱」这条保障在 WorkRally 上不成立**。
> 交付时必须如实登记；**不许把「我记了账」说成「平台保证不重复扣费」。**

**台账（`production-ledger.md` §6.1）加两列**：`平台`（哪条通道）· `线索号`（task_id / asset_id / canvas 节点 id）。
**为什么必须加**：命中率要**分平台**算——同一个提示词在两条通道上的命中率不同，
混在一起算等于把两台机器的误差平均掉（与 `production-ledger.md` §6.2「按镜头类型分别算」同构）。

## §7 术语消歧（**接这条通道前必读，否则必踩**）

| 同一个词 | 本库的意思 | WorkRally 的意思 | 消歧写法 |
|---|---|---|---|
| **场次 / shotlist** | **排镜表 · 分镜表**（设计层：景别 / 时长 / 职能 / 唯一信息） | 平台数据对象 `story`（含 `image_prompt` / `animation_prompt` / `extra.gen_config`） | 说「排镜表（设计层）」vs「`shotlist`（平台层）」 |
| **镜号** | `镜1` / `段落B`（本库载体，见 `shotlist_lint.py` 的载体分流） | 平台侧是 `story_id`（`st_xxx`） | **桥负责映射**，人手不要两边对抄 |
| **参考图** | 资产图 / 首帧 / 风格图（按**用途**分） | `--input-images` 的 URL 列表（按**顺序**分） | 顺序＝身份（§3 第 2 条） |
| **画幅** | 六值 + `adaptive`（`platform-matrix.md` §7.4） | `--aspect-ratio`（取值须落在该模型 `aspect_ratios` 内） | 桥只做**格式归一**（`16比9` → `16:9`），**不改值** |

**⚠️ 与 `shotlist_lint.py` 同名的坑**：脚本名带 `_lint` ＝**本库的门禁**；平台子命令 `workrally shotlist` ＝**平台数据层**。
**桥的名字叫 `workrally_bridge.py`**（不叫 `shotlist_bridge.py`）——就是为了让「这是平台侧的桥」一眼可见。
