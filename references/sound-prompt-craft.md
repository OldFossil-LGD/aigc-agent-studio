# 声音提示词写法：**四档分层 · 句式模板 · 跨平台差异**

> **何时读**：写第 11 块【声音】、或给视频模型写音频行时。
> **读完回哪**：**写什么内容**回 `sound-lexicon.md`（词表 + §8 取词四步法）· **为什么这样设计**回 `sound-design-craft.md` ·
> **多大、怎么混**回 `mix-loudness.md` · **块的契约（必需元素/边界）**回 `block-spec.md`【声音】块。
> **★ 本册唯一负责**：**句式和结构**——**"这几行到底怎么落笔"**。

---

## §1 ★ 三档 + 一档：**分开写，不要揉成一句**

**这是官方口径**（Google Gemini API / Cloud prompting guide 明列三种 audio cue，并给出各自的写法前缀）。

| 档 | 什么时候用 | **前缀** | 例（照抄结构） |
|---|---|---|---|
| **① 对白** Dialogue | 角色在镜头里说话 | **台词加引号** | `A woman says: "We have to leave now."` |
| **② 音效** SFX | **离散的、定时的那一下** | **`SFX:`** | `SFX: thunder cracks in the distance` |
| **③ 环境** Ambient | **几乎每一镜都要**，填满声场 | **`Ambient noise:`** | `Ambient noise: the quiet hum of a starship bridge` |
| **④ 配乐** Score | **氛围才是重点时**（抽象情绪片、产品英雄镜、蒙太奇） | 描述**情绪 + 配器 + 速度** | `Soft melancholic piano with sparse strings, slow tempo, building gently` |

**★ 为什么必须分开**：**Google 自己就把 SFX 与 Ambience 分成两类**——
一个声音是"**事件**"（雷劈），一个是"**床**"（船桥的低嗡）。**揉成一句，模型只能猜哪个是哪个。**

**★ 一条最容易被忽略、代价最大**：
> **没有环境层，场景在声学上是"死的"——画面在动，声场是空的。**
> （`sound-design-craft.md` §6 第 1 条错误"忘了 room tone"的同一个病，只是在提示词层。）
> **一句话通常就够填满它。**

---

## §2 ★ 对白的三条写法纪律

1. **台词用引号**（官方常规）；
2. **★ 可给表演提示**——官方示例把动作与念法挂在说话人后面：
   ```text
   Man: (Hand on his hunting knife) "That's no ordinary bear."
   ```
   念法可指定：**耳语 / 喊 / 发抖 / 面无表情**（本库对应纪律见 `sound-craft.md` §一·补 声线母档：**音色先定，情绪后加**）；
3. **★ 台词要短**——**"8 秒不是很多跑道，一句长台词会被赶着说完"**。
   **判据**：**把台词念一遍，秒数超过这一镜的时长三分之一就要砍**（我们的口径是**对白占用 ≤ 总时长三分之一**，`script-craft.md`）。

---

## §3 ★ 写的顺序（**先环境，后事件，最后人声/音乐**）

```text
① 环境层  —— 这是哪？这个空间"什么都没发生"时有什么声？   （几乎每镜都写）
② 音效层  —— 这一镜真正的事件是什么？只写离散的那一下（点状）
③ 人声层  —— 谁在说话、说什么、怎么念
④ 音乐层  —— 只有在"氛围就是重点"时才写；对白密集的场**不要加**
```

**来源两条线互相印证**：
- 站点技能 `seedance-prompting-skills-for-cinematic-films` Block 6 原话：**"Specify ambient first, then any vocal line."**
- `higgsfield-veo-3-audio-director` 的音频结构：`[PRIMARY SOUND SOURCE] [SECONDARY SOUNDS] [MUSIC/SCORE] [AUDIO ATMOSPHERE] [AUDIO QUALITY]`

**★ 判据一句话**：**"把这一行读出来，第一个词是'在哪'还是'什么响'？"** 前者才对。

---

## §4 ★ 声音锚（audio bed anchor）：**声音层也有锚点句**

**规则**：**全片（或同一空间内的所有镜头）沿用同一句环境签名**，逐字复制。
```text
"Ambient: distant kitchen radio, refrigerator hum"   ← 所有室内镜都用这一句
```
**为什么**：**它的作用与"身份锚点句"完全相同**——模型没有记忆，**不逐字给，它每镜换一个厨房**。
→ **声音锚＝环境层的身份锚点句**（`asset-consistency-part2.md` §七 的纪律直接适用：**不许近义替换**，`冰箱低嗡` ≠ `冰箱嗡鸣`）。

---

## §5 ★ 音频桥（audio bridge）：**跨生成单元时必须写**

**什么时候**：一条内容被拆成**多个生成单元**（两次生成、两段拼）时。
**写什么**：**声明这两个单元在声音上怎么接**，使它们**剪成一个动作拍**而不是两段。
```text
上一个单元的收尾：保留 0.3 秒的环境延续（不掐干净）
下一个单元的开头：同一环境签名起头
桥：一个持续的低频底噪贯穿两段（不让它断）
```
**判据**：**"把两段直接拼上，声音会不会'咔'一下？"** 会 → 缺音频桥。
> **来源**：`lui-s-seedance-2-0-prompt-classic-v1-5`——**`[Audio]` 是它的第 14 个固定块**，
> 且**跨单元的边界检查明确包含 audio bridge**（其余检查项：主体 / 夹角 / 景别 / 屏幕方向 / 视线 / 连续性状态）。

---

## §6 ★ 空间与距离：**声音必须来自画面里的一个位置**

> **★ 一条必须写清的例外**：**若「听不见声源」是你刻意要的效果**（画外的吱呀、没有可见说话者的声音），
> **那不是违规，而是 `sound-narrative.md` §4 的「无源之声」——有意的例外**，要在设计里说明它为什么被听见。
> **本节管的是默认纪律：默认情况下，每一个声音都该指得出画面内的出处。**

**写法**：把声音**放到一个具体位置**，而不是笼统"有声音"。
```text
✅ rain close in foreground, thunder distant in background
✅ footsteps in left channel, crowd noise panning right
✅ music emanating from a source inside the scene      ← 音乐也要有画面内的来源
❌ "有雨声和雷声"（无远近，模型只能把两者堆在同一层）
```

**★ 与 `sound-lexicon.md` §7 的分工**：那边给**空间词**（多远、多大、什么壁面），本册给**句式**（怎么挂到位置上）。
**★ 一个可直接用的判据**：**"闭上眼，我能指得出这个声音从哪个方向来吗？"**

---

## §7 ★ 分工法：**只让模型出本体声，音乐与旁白留后期**

**这是默认架构**（站点技能实践出来的；§1 的 Score 档是它的例外分支——只在"要氛围、不要求音乐发展"时用）：

```text
生成时：每个片段**只要本体音效**（SFX-only），明确 NO music / NO soundtrack / NO melody / no voice / no dialogue
后期： 一条**连续的音乐床** + 逐段的旁白，混在上面
```
**★ 好处（原话提炼）**：**"音乐跨剪切连续流动，而不是每 10 秒重置一次。"**
**为什么值得学**：**生成模型给不出"跨镜连贯的音乐"**——它每个片段只顾自己。
**★ 所以"要不要让模型出音乐"是一个架构决策，不是风格偏好**：

| 你的目标 | 怎么选 |
|---|---|
| 音乐是重点、要连贯、要对剪辑点 | **生成只要本体声** → 后期铺曲（§7） |
| 只要氛围、不要求音乐的发展 | 可以让模型出（`Score` 档） |
| 对白是承重的 | **别让模型出对白**（质量/控制/法律三重风险，见 §9） |

**★ 配套的自动化口径（可落地）**：
- **人声一出现，音乐闪避到约 15%**（VAD 检测）——**"绝不让音乐层与人声竞争"**；
- **在每一个剪辑点上检查"是否有一拍落在该时间戳 100 ms 内"**，是则跳过额外的旋律标记；
- **音乐要跟着剪辑走时，从剪辑间隔反推节拍**（取最短间隔作基础脉冲）。

## §8 ★ 跨平台差异（**写错平台＝写不出来**）

| 平台 | 音频能力 | 怎么写 | 不能写 |
|---|---|---|---|
| **Veo 3.1** | **原生同步出音频**（对白/环境/音效/音乐四类） | **三档前缀**（`SFX:` / `Ambient noise:` / 引号台词 / Score 描述）；**支持时间戳分段** | **标准界面里不能指定具体台词文本**（内容是被推断的） |
| **Seedance 2.0** | **原生音频** | **`Ambient: …` 起头、先环境后人声**；用 `No dialogue, no music.` 收尾 | 同上 |
| **即梦 / 可灵 等** | 部分支持或需后期 | **按"只出本体声 + 后期铺"** 的架构写 | — |
| **其他无音频的模型** | 无 | **明确要求只留本体声、不要音乐**——避免与你的后期音轨打架 | — |

**★ 通用铁律（跨平台都成立）**：
**具体、熟悉的声源比复杂/罕见的声源组合更可靠**；
**自然场景（森林/海/雨/风）音频质量最好，城市多层声场的"位置精度"会飘，音乐最不稳定**（旋律与和声是随机的）。
→ **推论**：**要精确控制声音就自己后期做**；**让模型出的部分是"氛围"，不是"作曲"。**

## §9 ★ 六个常见错误 → 修法

| # | 症状 | 根因 | 修 |
|---|---|---|---|
| 1 | 出来是**泛化的背景噪音** | 提示词里**没有音频行** | 补四档（至少环境 + 音效） |
| 2 | **声场是空的**（画面动、声音没跟上） | **没有环境层** | 一句环境签名填满（§3 第①步） |
| 3 | **音频与画面情绪打架** | 音频的情绪基调和画面的光/节奏没对齐 | 让音频的**速度与情绪质量**去匹配画面的**光与节奏** |
| 4 | **音乐压过场景** | 音乐被写成"主导"，且没有本体声 | 把音乐写成"**在混音里低一档 / 垫在环境之下**"（§7 + `mix-loudness.md` §3） |
| 5 | **声音与场景脱节** | 描述抽象、**没有位置** | 补空间与距离（§6） |
| 6 | 看起来好、**听起来空** | 模型回退到了近静音 | **更具体**——用**有物理描述的具体声源**（§8 铁律） |

**★ 一条容易忽略的**：**让模型口播未获批的法律/产品/效果主张有风险**——
**台词要事实准确且克制**，避免无法验证的最高级表述、医疗声明、财务承诺、保证、虚构数字；
**精确的主张就做成后期字幕**，团队才能控制每一个字。

## §10 自检（写完后过一遍，六条）

- [ ] **四档分开了吗**：环境 / 音效 / 人声 / 音乐**各占其位**，没揉成一句；
- [ ] **环境层在不在**（缺它＝声场是死的）；
- [ ] **第一个词是"在哪"吗**（不是"什么响"）；
- [ ] **空间与距离写了没有**（能指出来自哪一侧/多远）；
- [ ] **跨镜/跨单元**：声音锚逐字复制了吗？音频桥声明了吗？
- [ ] **音乐**：有没有写它与对白的关系？（本库门禁：**有配乐却没写它与对白的关系 → WARN**）

## ★★ 官方「音乐控节奏、但不产生切镜」映射表（**LibTV 官方 `music-driven-product-ad/references/ad-form-and-rhythm.md` · 一手 · 2026-10-15**）

**① 音乐事件 → 视觉用途（官方 7 行，可直接迁移）**

| 音乐事件 | 视觉用途 |
|---|---|
| 开场留白 / 弱起 | 已经发生的环境事件 ＋ 主角追赶入画 |
| **第一次强落点** | **主体离开主角，镜头开始匀速横移** |
| 乐句边界 | 主体穿越硬边，下一空间接管主要画面 |
| 次级瞬态 | 主体浮沉 / 翻卷、人物伸手、灯光或环境动作 |
| 能量峰值 | 主体到达画框高点或最具规模感的空间 |
| 终止式前的落点 | 主体降低并接近结尾主角 |
| **终止式** | **主角接住，镜头停止，完成展示 / 穿戴 / 整理与离场** |

**② 三条硬约束（官方原话要点）**
- **"音乐决定动作时机，但不产生切镜"**；
- **镜头一旦开始横移就保持同一速度直到结尾停止**——**音乐密度只能靠「主体动态 / 环境动作 / 光线 / 人物反应」体现，不能用镜头变速、切镜或机位变化体现**；
- **删词清单**：提交前删掉**上升、下倾、俯冲、逆光、推近、环绕、航拍**等**会改变机位的词**。

**③ ★ 内部节奏 vs 提交文本（本库此前零记录）**：**"精确到毫秒的音乐事件保留在内部节奏分析中"**；交给模型的段落**只用连续的整数秒边界**，**只描述可见动作与空间变化**，**不提音乐、节拍、卡点或背景音乐**。

**④ 时间边界纪律（官方原话要点）**：开头静止通常 **1–2 秒**且**环境事件在首帧已经开始**；**所有边界取整后必须连续覆盖 `00:00–D`，不能产生空白、重叠或零时长段落**；D=20 时结尾约从 **16 秒**开始且**最后 2 秒空景静止**；**D 变化时按新配乐重排边界，不减少空间数量**。

## ★★ 音色（voice）接口族的字段与陷阱（**登录态编辑器 bundle 静态 · 一手 · 2026-10-15 读**）

### 一、逐条形状

| 操作 | 方法与请求体 | 失败处置 |
|---|---|---|
| 列音色 | `POST` 原样透传 | **抛错** |
| 收藏列表 | `POST` 原样透传 | **抛错** |
| **收藏 / 取消收藏** | `POST` **`{ voiceId }`** | **吞错并返回 `false`**（不抛） |
| **克隆** | `POST` 原样透传 | **抛错** |
| **音色积分** | **`GET`（无参数）** | **吞错并返回 `{ code: -1, msg }`** |
| 确认 | `POST` 原样透传 | **抛错** |
| 编辑 | `POST` 原样透传 | **抛错** |
| **删除** | `POST` **`{ id }`** | **吞错并返回 `false`** |

**★ 三条读法**
1. **只有"查音色积分"是 GET 且无参**；**其余全是 POST**；
2. **建/列/改/克隆/确认/编辑是"透传"** ⟹ **字段集由服务端定义**（客户端不校验），要拿准确字段只能实测或看服务端；
3. **失败策略分两档**：**读类与变更类抛错**，**收藏与删除吞错返回布尔**、**积分查询吞错包成 `code:-1`**。
 **→ 排查含义**：**"收藏没生效"或"删除没生效"在界面上可能连报错都没有**——**返回 `false` 就是失败信号**，别把"没弹错"当成功。

### 二、★ 一个真实的字段不一致陷阱（本库此前零记录）

| 接口 | 字段名 |
|---|---|
| 收藏 / 取消收藏 | **`voiceId`** |
| **删除** | **`id`** |

**同一个"音色"实体，在相邻两个接口里用了两个不同的字段名**——**照抄"voiceId"去删除会失效**。
**★ 纪律**：**音色族的参数名必须逐接口核，不要按语感统一命名**；同理，**凡"同一实体在不同接口里字段名不同"的地方，都要以接口为单位记，而不是以实体为单位记。**

### 三、另有：`visionClickSuggest` 支持可选 `signal`

同一模块里，视觉点选建议接口**可带 `AbortSignal`**（传了就用 signal、没传就不带）——**与本库记过的"长任务要能取消"同源**。
