### ★ 口径调和：悬空引用 ≠ 必然废片（【推断】）

本册「悬空引用照样出片」与 `asset-consistency.md`「资产没进参考 → 一致性崩」
说的是**两个不同环节**，不能互相推翻：

| 环节 | 行为 |
|---|---|
| **构建 / 建边时** | **不校验**引用能否解析 —— 悬空 id 照常入图 |
| **运行时** | 只看"能不能生成"，不看"写得对不对" —— 能生成即 status:2 |

→ 参考缺位 = **失去锚点控制**（模型按语义名自己编），但**不等于必然产出废片**：
本样本画布的资产节点已删，作品照样出片。
→ ⛔ 反向同样不成立：**不能因为"出片了"就断定参考生效。**
→ ⚠ **本条是两组实测的口径调和，未做对照实验，标【推断】。**

**在 `data` 顶层，不在 `params` 里。**

### 9.2 `prevTaskInfo`（复制血缘）

`data.prevTaskInfo.tracking.commonParams.node_uuid` = 来源节点的 id

⚠ **字段不是稳定存在的** —— `v-mYN3PRppeu` 自己就没有（它也是重跑过的）
→ 判读时先确认字段在不在，不能假定。

⭐⭐ **这两个字段是同一个用途的两半**：
`frameCaptureSourceNodeId` 回答「这帧从哪来」，`prevTaskInfo` 回答「这节点抄了谁」。

## 十、★★★ 三种 video 生成模式

| 模式 | modeType | 提示词 | 时长 | 用途 |
|---|---|---|---|---|
| **分段生成** | mixed2video | 300–3000 字多层结构 | 20–30s | 一次生成整段 |
| **局部返修** | videoEdit2video | **一句话** | duration:0 继承 | 改已有视频的局部 |
| **插入续接** | **mixed2video** | **一句话** | **5s** | 用上一段截帧接新事件 |

⚠ **判据不是 modeType，是意图**：改已有视频 vs 接一个新镜头。
我把"一句话提示词"当成 videoEdit2video 的专属特征，**错了**。

还有第四种（【实证】）：`v-kjngoByqCZ` 是全画布唯一 `text2video`，
`prompt:""`、`imageList:[]`、`settings.duration:5`，
**但 url 存在且 `resourceMeta.durationSec = 29.056`**，`taskInfo` 整段缺失
→ **产物一旦生成，就与节点当前的 `params` 解耦**。要用 `params` 反推成片。

### ★ 续接短镜的标准三件套（成本含义最大的一条）

1. `mixed2video` 节点（**不是** frames2video）
2. 一个 **image 节点**，装**上一段成片按时间码截的帧**（节点名就叫 `截图 00:19.666`）
3. 提示词插桩 `{{Mixed 1}} 从这里开始延续。`，**放在插桩行末尾**（人物/道具在前）

⭐ 截帧点选在"动作进行到一半"的位置（19.666 秒正落在上一段 18.6–20.2 秒那镜中间）
⭐⭐ **5 秒插入镜的成本远低于 20–30 秒整段重跑（16–25 分钟）**
→ **定点补镜优先用这种方式，不要重跑整段。**

### ★ 参考可以占位而不被引用（【实证】）

`Mixed 1` = 1.875 秒测试视频，被 10+ 节点共享，**提示词从不引用它**
→ 可以在插桩行留一个永久占位。

## 十一、★★★ 提示词结构：三段式，块名全自由

### 唯一共识的三段式

```
全局块（镜头表之前）→ 镜头表 → 尾部约束清单
```

⭐ **结构统一的是"位置与职能"，不是"名字"。**

### 已见全局块名 20+ 种

整体影像规格 / 整体规格 / 影像规格 / 高科技机舱设定 / 怪兽设定 /
怪兽形象锁定 / 空间与人物状态 / 语言设定 / 群众表演锁定 / 手持摄影锁定 /
节奏与信息检查 / 表演锁定 / 环境逻辑 / 氛围逻辑 / 光学环境 /
物理材质与特效 / 运镜风格 / 摄像机运镜轨迹 / 风场与流体逻辑 / 光影与材质逻辑

尾部块名：执行锁定 / 执行重点 / 群众表演原则 / 排除

### 组织单位（横切所有块名）

`镜头N` · `镜头A/B/C/D` · `镜组NN` · `场景N` · `插入段` · `阶段N` ·
`S6—S10`（镜号区间） · `00—04秒`（纯时间块）

### 段落内最大嵌套深度 = 四层（【实证】）

```
段落：场景7｜旧船坞·立体绞杀（02:53—03:19）
  └─ 阶段：【阶段三：TPS反重力跑酷 vs 六合大枪（双线高光）】
      └─ 镜头13｜03:03.5—03:04.5｜1.0秒｜拦、拿、扎！
          └─ 镜内子镜：【0.5秒】… / 【1.0秒】…
```

⭐ **【阶段N】是长段落的第二层**，实测用于 19 镜 / 26 秒。
阶段标题写功能不写画面：`深渊自愈与绝望通讯`（信息传递段）·
`极速变阵`（阵型改变）· `双线高光`（剪辑归属）
→ **>15 镜的段落建议用阶段分组**，审片效率远高于逐镜。

## 十二、★★★ 治越轴：`整体空间锁定` 块（最高价值的单条）

**越轴的根因不是"写错了左右"，是方位被交给每一镜重新发明。**
⛔ 逐镜写"塔在右边" = 每镜各自决定一次 → 必然漂。
✅ 在镜头表**之前**用独立块把方位一次性写死，镜头行只写变化。

原文（`v-eQHpWKVWnk`，【实证】）：

```
## 整体空间锁定
- 海岸与怪兽始终位于画面左侧，西侧避难所在画面右侧。
- 所有群众统一向画面右侧撤离，避免灾难场面失去方向。
- 巨爪从左侧海面上方越过防波堤，再压向岸边建筑与撤离街道。
- 零从右侧逆着撤离人群冲入，形成明确的迎敌方向。
- 零保持正常人类身高，绝不能巨大化。
- 全段采用近距离灾难纪录片式手持。摄影机与群众一起逃跑，会被撞偏、遮挡、失焦，
  但必须迅速重新捕捉主体。
```

### 三层结构

1. **锁死的**：主体**之间**的左右/前后关系 · 各自所属的空间段 · **不可穿越**的移动路径
2. **可变的**：主体在**画面**里的绝对左右 —— 由机位方向决定，必须与"从哪个方向拍"一起声明
3. **必写的四样**：坐标系绑定（世界方位 ↔ 画面方位）→ 机位→画面左右映射表 →
   互不穿插禁令 → 每镜 `构图` 里复述结论并注明拍摄方向

⭐ **同机位正反打导致画面左右互换是正确行为，不是越轴。**
⭐ **越轴更常见的成因是"走过去时穿过了对方"** → 必须锁移动路径。
⭐ 另一手段：让角色不入画来维持轴线（`零不进入画面，避免改变两人的空间轴线`）

### 动态版：交错换位时用「换位轴」

当两个主体高速交错移动时，静态锁不够用 —— 拿一个画面中央的移动物体当轴：

> **巨足始终处于画面中央，作为换位轴。零和五号分别从画面两侧通过，不直接跨轴切镜。**

三要素：指定中央物体作轴 / 两人分别从两侧通过 / ⛔ 明令不直接跨轴切镜

### ⚠ 同一镜可能有互斥的空间锁

第十一段 `镜头22` 存在两个版本，同一镜号、两个 `空间关系锁定` 块，**画面中央给了不同的人**。
→ **"写了空间锁"不等于"锁不自相矛盾"** —— 画布数据无法判断哪个是最终采用版。

| **首帧匹配转场** | `v-rHiu030NkZ` | `承接上一场海面下的红色控制光点，硬切到战术终端上一颗断续闪烁的红点` |

| **遮挡转场** | `v-FzZP4gouSs` | `深色战术装甲短暂遮住前景 → 镜头穿过空隙落回壹号侧脸` |

### ★ 动作匹配切的三步写法（全画布唯一显式声明剪辑手法处）

```
1. 先写上一镜的末动作：巨掌落下。
2. 单独一行写出剪辑术语：**动作匹配切——**
3. 写同一动作在新场景的落点：同一只巨掌，砸进指挥中心的立体全息战场。
```

⭐ "同一只巨掌"这四个字保住跨场景连续性，否则模型会重新生成一只。
⭐⭐ **这是"video 到 video 被禁"的正解**：既然必须靠文字，
就把文字写成剪辑术语，让模型按剪辑逻辑而非剧情逻辑理解。
同族术语：`亮度匹配剪辑`。

### ★ 关键链要写两遍

正文块 + 尾部执行锁定各写一次。`v-hZFvxC7qmz` 的执行锁定第 10 条
重复了正文里那句衔接约束。

### ★ 插入段结尾要主动交还主线
