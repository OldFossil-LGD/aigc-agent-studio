## 11. 跨节点衔接锁（video→video 连线被禁的必然解法）

不是只说"下一场接上一场"，而是**指定画面里同一个元素在两个节点间连续**：

```
**场景6最后一帧：**
零已经完全拔出唐刀。冷黑色刀锋横切夕阳与烟尘，画面上沿同时侵入怪兽巨掌的黑色阴影。
零尚未挥出第一刀。巨掌阴影压满画面的瞬间，硬切进入场景7。

执行锁定第10条：场景7开场的怪兽巨掌阴影，必须与本场最后一帧进入画面上沿的阴影连续。
```

可推广：`下一场开场的<某元素>，必须与本场最后一帧进入<某位置>的<同一元素>连续。`

## 12. 四种生成模式（同一画布并存）

| 模式 | modeType | 提示词 | 时长 | 用途 |
|---|---|---|---|---|
| **分段生成** | `mixed2video` | ~3000 字五层结构，12–15 参考 | 20–30s | 一次生成整段 |
| **续接插入** | `mixed2video` | 一句话 | 5s | 用上一段截帧接一个新事件 |
| 局部返修 | `videoEdit2video` | 一句话 | `duration:0` 继承 | 改已有视频的局部 |
| **单镜生成** | `mixed2video` | `每次只生成下面的一条镜头。单机位、连续画面` | 单镜 | 逐镜精修 |

- **判据不是 modeType，是意图**：改已有视频 vs 接一个新镜头 vs 一次生成一整段。
- **一句话提示词 ≠ 偷懒**。反例 `v-BrYrx6DoZf`（成功 30.08s）：全文无一个焦段、无 `相机／焦段` 字段、无全局规格块，只有「时间区间标题 + 纯散文对白」。
- **空提示词是合法对照组**：只留 `{{Mixed N}}` 引用声明行，仍产出完整时长成片 → **参考图是主载体，文字是叠加约束层**。

### 续接短镜三件套（成本远低于整段重跑）

1. `mixed2video` 节点（**不是** frames2video）
2. 一个 **image 节点**，装**上一段成片按时间码截的帧**（节点名就叫 `截图 00:19.666`）
3. 提示词插桩 `{{Mixed 1}} 从这里开始延续。`，**放在插桩行末尾**

- 截帧点选在"动作进行到一半"的位置，下一节点让动作继续。
- **定点补镜优先用这种方式，不要重跑整段**（5s vs 20–30s × 16–25 分钟）。

## 13. 时间码有 5 套体系，连同一 owner 都不统一

全片绝对（镜级）· 段级绝对+镜级相对 · 全片绝对（段落单行）· 段内相对 · 总秒数

最硬证据：第八段相邻两节点、同 owner、同段落 —— 一个镜级用**相对**，一个用**绝对**。
→ **时间码体系是逐节点自选的**。此前几次"时间码对不上"**不是错**。跨节点算时长前必须先确认那套体系。

### 时长三种关系都存在

| 关系 | 案例 |
|---|---|
| 声明 = 实际 | 绝大多数节点 |
| 声明 > 实际 | 33s 声明 → 30.048s（30s 上限静默压缩） |
| **声明 < 实际** | `settings.duration:22` → **实际 30.048s**（模型演完时间码后继续填满到上限） |

**想要准确时长不能只靠 `duration` 参数**，必须在提示词末尾给收尾指令。

## 14. 升格镜必须防「变成静帧照片」

```
**相机／帧率：** 前段24fps手持；大哥闭眼时瞬间切换至96fps升格。
**进入升格后仍保留轻微摄影机漂移，不变成完全静止的展示镜头。**
```

- **把"帧率"从"焦段"里拆出来单列**，让升格指令获得独立位置。
- **每个升格镜都要显式写 `进入升格后仍保留<某种运动>`**。
- 升格要给帧数不只给帧率：`接触瞬间短暂提高至48fps约六帧，随后立即恢复24fps`。
- 主观时间感要配客观帧率，不能互相替代。

### 帧率之上还能控"哪一帧用哪种风格"（全片唯一一例）

```
**帧1/2（0.06s）：**画面黑白负片反转，幽蓝血变为刺眼的纯白。
**帧3（0.03s）：**画面硬切为一帧线条粗糙、黑白对比极强的铅笔素描风格冲击力画面。
```

→ **把"帧"当可控单位**，且每种风格占几帧都写死。配套：全局块先声明手法，镜头里精确执行。

## 15. 声音

- **全局写底层，各镜只写变化**：`退远／顶上来／被掩住`
- **可用分贝量化**：`零握住刀柄的一瞬，环境声短暂降低约3分贝`（全样本唯一一次）
- **事件并行锁**：`市民撤离与怪兽攻击必须同时发生，避免变成角色站着等待通讯完成`
- **台词三层**：原文 → 中文译文 → 罗马音
- **台词可以承担战术指令**：`零："断浪！"` / `五号："探海！"`
- **无台词的镜要显式写 `台词：无。`** —— 不省略
- **台词时机锁定**：锁物理时刻，不只锁词
- 哑片镜也要逐镜列 2–3 个具体环境音，不能写"合成阶段统一混入"

## 16. 物理与规模

- **写阶段链，不写结果**：`先弯曲 → 内部白化裂纹 → 密封失效 → 边框崩溃`，每阶段写清先后与方向。
- **尺度靠对比物**，不靠台词：`通过"鲸鱼在它面前小得异常"建立百倍体量，避免依靠台词解释`。
- **阻挡写成两段式**：`银枪没有立即把巨尾停住。它持续承压，直至枪杆接近弯曲极限。下一瞬…同时反弹`。
- **表现不可见的力**：让作用力**依次掀翻从远到近的一组物体**（井盖→碎石→积水）。
- **人群写流向差异**：有人逃／有人僵住／有人逆向找家人／有人摔倒，形成真实阻力。
- **先给假象，再逆转**：`先制造明确的获救假象，再于一秒内彻底逆转`。
- **"最后一刻给一点信息"允许略微放宽禁项。**

## 17. 参考图三条

1. **必须声明管什么不管什么**：`参考图锁定造型，不锁定展示比例`
2. **不可重新设计成 X、Y、Z** —— 点名排除模型最可能替换成的错误造型
3. **形态清单里写明"什么条件下才看得到什么"**

## 18. `status:2` ≠ 提示词写得对

实测存在 `status:2 成功` 但有三处引用质量问题的节点：银枪图在 `mixedList` 里而长枪是本段第一主角，提示词却完全没插桩它。

- 平台**不会**因为漏插桩而拒绝生成。**平台只管能不能生成，不管你写得对不对。**
- 必须回读提示词逐条核对插桩。
- **画布制作者会把 Agent 回复整段粘进提示词框**（含"收到！""终极完整版""定稿"等客套）→ 对生成零帮助，还可能污染语义。**若用 agent 生成提示词，必须自己清掉这层元对话。**

## 19. 开写前检查清单

```
☐ 读的是【实产】还是【例子】？—— 例子不可当规格
☐ 越轴治法：在镜头表之前有独立的「整体空间锁定」块吗？
☐ 每个方位都配了"从哪个方向拍"吗？
☐ 交互移动路径锁了吗（不穿过对方）？
☐ 每个引用 key 同时出现在 left 和提示词里吗？
☐ 每个 {{Mixed N}} 的 N == 它在 mixedListOrder 的 1-indexed 位置吗？（回读确认，非推算）
☐ 升格镜写了"进入升格后仍保留某种运动"吗？
☐ 每个"该帅"的时刻配了反摆姿势禁令吗？
☐ 禁项写的是"改成什么呈现方式"而不是"不要 X"吗？
☐ 执行锁定锁的是因果必然性吗？
☐ 声音全局写了底层、各镜只写变化吗？
☐ 跨节点衔接指定了同一个画面元素连续吗？
☐ 时间码体系是全片绝对还是段内相对？（跨节点算时长前必须确认）
☐ 想要准确时长，提示词末尾给收尾指令了吗？
☐ 有没有把 agent 的客套话烧进提示词？
```

## 20. 与技能库 12 块模板的差异

| 技能库 12 块 | 实产做法 |
|---|---|
| 全片通用 3 块 + 本镜专属 9 块 | **全局规格 + 镜头表 + 尾部执行锁定**，块数不固定 |
| 光位与影调独立成块 | 并入"整体影像规格"的**色调／摄影风格**两行 |
| 运镜独立成块 | 并入每镜的 `相机／焦段` + `构图／运镜` |
| 禁止项写元素清单 | **执行锁定写因果必然性 + 呈现方式禁令 + 反摆姿势** |
| 声音块逐镜写 | **全局写声底层，各镜只写变化** |
| 无对应 | **主体规格锁定 / 语言设定 / 参考图管什么不管什么 / 节奏与信息检查 / 表演锁定** |

## 21. 诚实结论：`提示词该写多细` 没有统一答案

同一画布里**同时**存在：

- 3000 字五层结构（12–15 参考）· status:2 成功
- 全文无焦段、纯散文对白 · status:2 成功
- 只剩引用声明行的空正文 · status:2 成功

| 情况 | 怎么写 |
|---|---|
| 灾难奇观 / 动作段 | 焦段 + 构图 + 运镜 三件套，**密度越高越稳** |
| 对白 / 喜剧 / 人物互动段 | 焦段写了也用不上，**直接写对白与动作** |

此前把「每镜必写焦段/构图/运镜」当成硬标准 —— 它是这批制作者**在动作段的习惯**。

status:2 成功，并在 9 个 video 节点里被插桩为 `{{Mixed 4}} 玩偶。`

### 两层对照（完整答案）

| | image 资产层 | video 镜头层 |
|---|---|---|
| 长度 | **6–34 字** | 300–3000 字 |
| 形态 | 名词短语 / 祈使指令 | 分层结构 + 约束清单 |
| 承载者 | **参考图本身** | 文字 |

⛔ **「简短」是资产层的正常做法，不是缺陷。**

### image2image 的提示词是「指令式」

`生成类似的，但是不要脸` —— 不描述要什么，只说不要什么。
→ **资产层最省的写法：参考图已承载全部外观信息，提示词只写「相对参考图改什么」。**

### 三条可直接抄的资产层手法

1. **三宫格 = 一次生成多角度**：`上面是脸部特写，下面是全身正图跟背图`
   → 替代「为每个角度单独出图」
2. **把角色此刻的物理状态写进资产提示词**：`脸上有灰`
   → video 提示词就不必再解释
3. **统一称呼 + 剥离分类**：`统一称为"怪兽"，不使用鳄鱼或爬行动物描述`
   → ⭐⭐ **怪兽组第一张参考图本来就是 crocodilian（鳄鱼形）**
   → **禁项必须同时查提示词层和参考图层**，只在提示词里写禁令会被参考图压过

### ⚠ 三个新发现的读节点字段

| 字段 | 位置 | 用途 |
|---|---|---|
| `frameCaptureSourceNodeId` | **data 顶层**（不在 params） | 截帧血缘的真实来源视频节点 |
| `frameCaptureStackIndex` | data 顶层 | 取的是源节点第几个产物 |
| `alt` | data 顶层 | "视频尾帧" / "视频截图" |

⭐ **判断 image 是不是从 video 截的帧，读 `data.frameCaptureSourceNodeId`，不要靠节点名猜。**
⚠ **读节点时不能只看 `params`。**
