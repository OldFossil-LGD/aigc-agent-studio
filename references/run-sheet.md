### 站 5.5 · ★ 参考闭环（**自主版新增 · 2026-09-20**）

- **读**：**`references/asset-pipeline.md` §2（ReferencePlan：这一镜凭什么挂这几张）** · `references/asset-consistency.md` §四·补（**前序素材传递律：跨镜一致性的唯一机制**）与 §一·补（资产图三条硬规格）· `references/libtv-canvas-nodes.md` §一（节点即资产、边即引用）
- **★ 本站在讲一件事**：**资产的职能就是做一致性。** 它不是"流程的第 5 站的一个交付物"，它是**一致性链条上的中转站**——没有它，下游每一镜只能吃最弱的那一档输入。

**★★ 传递优先级（库内原文 · 硬性，不许降档）**：

```
实际生成的视频（尾帧）  >  静态图  >  文字描述
```

**→ 全片默认（不是特例）**：**资产图定身份 → 首镜生出视频 → 此后每一镜用「上一镜的尾帧」续接**。
**用文字描述前情＝必定漂移——每传一代就漂一次，三代之后就是另一个人。**
**⚠️ 只做前半（资产图）不做后半（尾帧续接）＝只拿到第二档，仍会漂。**

- **做什么**：
  1. **资产图登记为参考**（LibTV：`create_node(nodeType="image", run=false)` 建资产节点 + 生成时 `reference_nodes` 放 `node_key`）；
     **★★ 平台口径（2026-09-20 修正）**：**"一致性靠『锚点节点 + prompt 里 `{{node_key}}` 插桩』实现，不是靠画布连线。边只是可视化，真正起作用的是字段引用；画布连线不影响生成，可连可不连。"**　**★★★★ 2026-10-01 实测更正（这条与平台校验原文冲突）**：上面引的「边只是可视化、画布连线不影响生成、可连可不连」——**至少在 MCP 侧成立不了**：平台校验原文为「params.imageList 不可通过 --set 直接设置：媒体列表/排序/混合列表**由画布连线重算**与 CLI 内部现算得出，**请用连线**（如 --left/--left-add）调整」——**不建边，连列表都填不出来**。**疑因**：那句口径可能记的是**平台 Agent 那层**（它走 `reference_nodes` 字段），与**我们这层的画布边**被记混了（可对照 `agent-autonomy.md` 纪律七 7.1「已被实测推翻的自述」）。**另项实测**：位序权威是 **`left` 边序**，**改 prompt 插桩顺序不会重排 `imageListOrder`**（回读不变、`incomingRecalcNodeKeys` 为空）——**事后惯错位只能拆边重建**。
     **插桩铁律**：`{{}}` 必须与 `reference_nodes` **一一对应且顺序一致**（两角色同框时按 prompt 中首次出现的先后排）；**"顺序错位会导致引用错人，这是最常见的坑"**；
     **★★ MCP 侧落地动作（2026-09-21 实测）**：**用 `left: [资产节点 key, …]` 建引用边**（增量用 `leftAdd` / `leftEnsure` / `leftRemove`）→ **系统自动重算出 `imageList` 与 `imageListOrder`**（`params.imageList` **不可手填**，直接设会报 `NODE_VALIDATION_FAILED`）；**顺序即 `imageListOrder`**；**引用节点必须先"生效"（有产物、`url` 非空）**；`modeType` 按需选 `image2image` / `mixed2video` / `frames2video` / `videoExtend2video`；
  2. **每一镜的生成请求都必须带引用**（`singleImage2video` / `mixed2video` / `frames2video`）——**空白即不许生成**；
  3. **有连贯要求时，用上一镜尾帧作为本镜首帧**（`frames2video`），**优先于静态资产图**。
- **过什么才许走（硬门禁）**：
  1. **每个角色 / 场景 / 道具都要有独立资产图**（**不是"只做主角"**——实测踩过：只做了男角，女角无资产）；
  2. **预检返回的 `resolvedReferences.image` 必须非空**；
  3. **资产图先自检**：色板对不对（用像素均值核）· 写脏是否逐条落地 · 材质受光响应 · **三条硬规格**（纯中性灰底 / 柔光近乎无影 / 场景 3-4 角度见两面墙）。
- **★ 资产图三条硬规格的"为什么"（全部指向一致性）**：**背景零杂物** → 杂物会被当作场景一起继承，且会跟角色抢注意力；**柔光近乎无影** → 设定图的光**会被继承进每一条下游生成**，硬光图"再像也没用，它会污染下游"；**3/4 角度见两面墙** → 正对墙＝一张压平的背景板，**后续无法运镜**。
- **为什么单列一站（血泪）**：**"七环各跑通 ≠ 全流程跑通"**。实测在同一次任务里跑了分镜表→资产→图→视频→时间线→预检→导出，**每一环都成功、成片也出来了**，但**人物与场景全不一致**——因为**每一镜都是 `text2video` 从零生成，`resolvedReferences.image` 全程为空**，资产图**一次都没进参考**。
  实测数字：同一块墙面区域平均色 **T2 视频 `RGB(165,146,146)` · 场景图 `RGB(102,110,94)` · 多角度板 `RGB(184,168,149)`**——**三处互不相同，"同一间办公室"其实是三个房间**。
- **★ 一句话纪律**：**"提示词里写了身份锚点" ≠ 锁住了身份。** 文字只是最弱的一档，**实物才是机制**。

## 二·补 · 反问边界（**该问就问，该定就定**）

**为什么单列这一条**：它同时防两种失职——**替用户拍板（曲解）** 与 **把难题抛回用户（甩锅）**。
**曲解与偷懒是一对**：只堵一边，一定倒向另一边。**判断力越强，擅自拍板的风险越大**，所以必须有规则要求你在关键分岔口停下来。

**必须反问 —— 答案只能由用户提供**：

| 场合 | 在哪一站 |
|---|---|
| **意图分岔**：同一命题有两种都成立的走向（他最后是释然还是垮掉、反转是善意还是恶意） | 站 1 |
| **题材边界**：用户的题材触及他不一定想拍的尺度（暴力 / 死亡 / 真实人物 / 地域敏感） | 站 2 |
| **审美取向**：风格编号在两条明显不同的路上（写实 vs 描边），且用户没说 | 站 3 |
| **验收标准**：用户说的"好看"没有可判形式，且从题材也推不出来 | 站 1 / 6 |
| **判断与偏好冲突**：你的判断和用户偏好相左 → **先说出冲突与理由，再执行** | 全站 |

> **冲突时那条最硬**：既不许**默默照做**，也不许**默默不照做**。
> 依据：`evals/scenarios.md` 场景 19 评分——**"用户偏好与判断冲突时照做不误"判 Fail**。

**禁止反问 —— 能自己查证 / 能自己推出来**：

- 平台参数与限额（查 `platform-matrix.md`；不确定就说"**需核**"，不要猜，也不要问用户）
- 物理与光学（六杠杆 / 半影公式算得出来）· 器材选型（六轴 + 33 包推得出来）
- 构图 / 景别 / 运镜（六问推导推得出来）
- 任何"**我其实查得到，只是懒得查**"的事

**问的形态**（这一条比"问不问"更容易做错）：
- ✅ **给选项 + 给推荐 + 说取舍**：*"我倾向 B10 王家卫式——它能把'等'拍成节奏；另一条路是 E03 敦煌壁画，会把年代感拉到古代。你更接近哪一个？"*
- ❌ 开放式空问：*"你想要什么风格？"*（把复杂度抛回用户，等于没做功课）
- **一次最多问两个**；超过就先按最可能的那一版做出来给他改——**做一版给他改，比问三个问题更快**。

## 三、每镜写之前的「强制四问」（**不答完不许动笔**）

1. **这一镜的唯一信息是什么？** 写不出 → 这镜不该存在（`shot-orchestration.md` 静音自检）
2. **物理能不能算？** 力从哪来 · 接触点在哪 · 什么被压/扬起 · **谁先停**（六杠杆至少覆盖 ①质量 ③摩擦 ⑤接触点）
3. **人物三层写了吗？** 外观（每处痕迹指向一段经历）· 体态（怎么占空间）· 行为（每段有停顿）；再加**矛盾**（表面 vs 身体背叛）与**呼吸/静默**
4. **题材的核心动作在这一镜里能被看见吗？** 看不见 → 我是不是为了安全把题材删了？
