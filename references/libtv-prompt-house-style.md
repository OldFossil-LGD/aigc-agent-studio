**★ 2026-09-28 落库注（内部字段非契约）**：本节 `taskParams` / `taskResult` 各字段是**读回侧的内部字段**（平台任务系统自用），**不是调用契约入参**——`create_*` / `generate_*` 不收这些名字，勿当作可传参数照抄。

**它的 `taskResult`（产物结构 · 全录）**：
```
{"images":[{"previewPath":"https://…png", "originalPath":"", "storagePath":"sd-gen-save-img/…",
            "imageInfoJson":"{\"width\":2048,\"height\":1152,\"seed\":-1,…}", "resourceId":"res_1e374432a893412bba0a018b9dc136b8"}],
 "videos":[], "audios":[]}
```
**★ 要点**：**`previewPath` 就是可直接用的产物 URL**；**`resourceId`（`res_` 前缀）是资源 id**；**`storagePath` 是存储路径**。
**★ 另有**：`taskInfo.taskId: "20260922135703774142788"`（时间戳型任务号）· **`status: 2`（数字状态码；此值为"已生成/有产物"）** · **`outputMaterializedFromTaskResult: true`** · **节点的 `data.url: ["https://…png"]`（产物 URL 也在 data 层）**。

```
无对白。环境声仅有办公室清晨的安静底噪、钥匙轻碰桌面的金属声、椅子滑动声与脚步声。
无背景音乐。 No BGM
```

### 6.3 ★★★ 七条可抄（**它这一版最值得学的**）

| # | 写法 | 为什么强 |
|---|---|---|
| **1** | **★★ 每个引用都写"用于什么 ＋ 不采用什么"**——"`{{Image 1}}` 用于…基线，**不采用图片的浅灰纯色背景**"｜"`{{Image 2}}` 用于…光线基线，**不采用图片的固定空镜构图**" | **既说明用途，又排除"资产图自带的背景/构图污染"**——**这是解决"引用资产图会带进灰底或固定构图"的现成答案** |
| **2** | **引用分区声明**：【人物】/【场景】/【道具】**三段各声明一个引用** | 位次与用途一目了然，**天然对应 `imageListOrder` 的顺序** |
| **3** | **★ 镜内"多段"时间结构**：【阶段一/二/三】，每段含 **开始时 / 主要事件 / 结束时**，且**每段以"承接上一阶段"开头** | **把"镜内多个动作"写成可执行的时间链**；**这正是"一镜承载多个节拍"的写法**（我们叫【时间线】，但它的分段更清楚） |
| **4** | **末尾一句"稳性约束"**："**保持人物身份、数量、服装、道具归属、空间方向和声音关系稳定。**" | **一句话覆盖六项跨段稳定性**——比分散约束更省字 |
| **5** | **风格句独立一段**（"写实电影感…低饱和、偏青灰…35mm 纪实摄影质感"） | **与我们的"全局风格"同构** ✓ |
| **6** | **声音写成"无对白。环境声仅有…。无背景音乐。 No BGM"** | **★ 末尾直接上英文 `No BGM`**（平台能认）；且**分镜只写声音"需求"，BGM 明确不由分镜生成** |
| **7** | **【教学】段与【提示词】段同在一个 `prompt` 里，元信息在前、正文在后** | **节点自带台账**（阶段/参数理由/引用用途/下一步都能追溯）——**且它标了"教学本轮不运行"** |

### 6.4 ★ 与我们写法的对照（差异 → 采纳）

| 维度 | **它（实物）** | 我们 | 采纳建议 |
|---|---|---|---|
| **引用声明** | **【人物】/【场景】/【道具】三段 + "用于X，不采用Y"** | 【关键参数】列表 + 画面段沿用声明 | **★ 采纳"用于X / 不采用Y"这个句式**（治"资产背景污染"） |
| **时间结构** | 【阶段N】开始/主要事件/结束 + "承接上一阶段" | 【时间线】五相（起始/触发/主动作/反应/定格） | **两者可融合**：**多节拍镜用"阶段分段"，单节拍镜用"五相"** |
| **稳性约束** | 末尾一句六项覆盖 | 分散在各块 | **★ 采纳末尾一句** |
| **模式** | **`image2video`** | `mixed2video` / `frames2video` | **补记：多参考图生视频它用 `image2video`** |
| **声音** | 末尾"无对白…无背景音乐。 No BGM" | 【声音】块 | **★ 采纳末尾一句 + `No BGM`** |
| **元信息** | **与正文同在一个 `prompt`，标"本轮不运行"** | 分开（我们写入册/台账） | **可采纳**（节点自带台账，便于交接） |

### 6.5 ⚠️ 一处要标注的：`sound=on` 与"声音本地做"的冲突

它这次写了 **`enableSound:"on"`** 且**给了环境声清单**；而我方《钥匙》的决定是 **"平台侧关声、声音回本地做"**。
**→ 两者不矛盾，是两种路线**：
- **要平台出环境声** → `enableSound:"on"` ＋ 写清环境声；
- **声音本地做** → **仍要写清"无对白/无 BGM"**（约束），但 **`enableSound:"off"`**（**注意：`sound=off` 永久丢该 clip 音轨，不可逆**）。
**★ 纪律：同一条片只能选一条路线，不要混。**

**★ 官方预演三步法（抄这个结构）**：
1. **搭场景与人物**：先说清空间、主体、道具与关系（“古代庭院 + 青衣女子 + 黑衣侍卫”）。
2. **按秒分段写镜头**：每段写时间范围 + 景别/机位 + 人物动作 + 镜头运动（第三例就是 0–4 / 4–8 / 8–12 三段）。
3. **收尾三件**：**用简化模型表现 · 保持人物/场景/动作连续 · 重点看走位、节奏与镜头衔接**。

**★ 使用边界**：
- **预演秒表只属于预演**：官方预演示例用 `0—4秒` 分段；本库常规单镜仍按“镜头顺序、不写秒数”，不要把预演写法静默带回正式生成。
- **场景种子只属于选题**：6 条种子句用于 brief/选题热身；进入站 6 仍须按 `libtv-prompt-structure.md` 的输出层重排。
- **官方示例不替代实时 schema**：时长、画幅、模型能力仍以现场 `search_models` / live schema 为准。
