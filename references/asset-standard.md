# 资产系统（四层 · 版本化 · 可追溯）

> **何时读**：出任何资产之前；判断"这张图算不算资产、能不能进参考、改了要不要重做下游"之前。
> **读完回哪**：逐块写法 → `block-playbook-asset.md` · 流水线与门禁 → `asset-pipeline.md` · 落地动作 → `run-sheet.md` 站 5/5.5。
> **★ 地位**：与 `asset-consistency.md` · `asset-prompt-spec.md` · 其续册 · `asset-and-stage-checklist.md` 及其续册冲突时，**以本册为准**；那几册保留"为什么"与实测。
> **★ 本次重设（2026-10-31）**：按 `CHARACTER_PIPELINE_PLAN` 的四层身份模型重排——**资产不再是"图"，是带版本、出处、状态的对象**；人物 / 道具 / 场景**共用同一套层与状态机**。

---

## §0 为什么要重设

| 旧问题 | 症状 | 解法 |
|---|---|---|
| 资产＝一堆图 | 改了服装，不知道哪张脸还算数；旧图还在被引用 | **分层**：身份与造型分开，各有版本 |
| 只有"好 / 不好" | 答不出"这一镜凭什么用这张图" | **版本 + 出处 + 引用计划**三件留痕 |
| 单次成功当规则 | 例子被当成通用保证 | **证据档位**（§8），未验的写"拟订 / 未核" |

**一句话**：**L1 不可变，L2 可版本化，L3 每镜变，L4 随剧情演变**；**只有 approved 能进镜头**。

---

## §1 四层模型（三类通用）

| 层 | 名称 | 同一主体内变不变 | 怎么变 | 产出文件 | 存在哪 |
|---|---|---|---|---|---|
| **L1** | 身份核心 | **不变** | 只能新建 `identity_version` | 脸部特写 / 身份锚点文本 / 体型比例 | `identity/v###/` |
| **L2** | 外观版本 | 可变，**必须显式版本化** | 新 `look_version`；旧版保留可读 | 五视角 / 无头身体 / 服装 / 状态版本 | `looks/L###/` |
| **L3** | 镜头态 | **每镜变** | 由 `ShotSpec` 给，**不入资产库** | 不产出资产文件 | `shots/` |
| **L4** | 连续性 | 随剧情事件演变 | 事件补丁 → 状态快照（带内容哈希） | 不产出资产文件 | `continuity/` |

**继承链**：`身份版本 → 造型版本 → 连续性快照 → 镜头态 → 平台参数`。

**★ 三条硬规矩**：

1. **主锚点只在 L1**；L2 的所有视图都是派生件，**不得反过来当身份源**。
2. **L3 / L4 永不产出"资产图"**——它们只是参考计划的输入。把每镜的姿态做成资产，等于每镜重新设计一个人。
3. **不可变是"逻辑不变"**：同一身份版本内，脸在侧光、湿发、表情下可以不同；**换脸 / 换年龄 / 换人设＝新身份版本**。

## §2 三类资产的分层映射（**本册核心表**）

| 类 | L1 身份核心（不可变） | L2 外观 / 状态版本 | L3 镜头态 | L4 连续性 |
|---|---|---|---|---|
| **人物** | **脸部特写** · 40–70 字冻结块 · 体型比例（数值） | **前 / 后 / 左 / 右 / 俯 / 无头身体**（每个造型一版） | 姿态 · 表情 · 视线 · 机位 · 光 | 伤 · 湿 · 脏 · 发型散乱 · 妆容花 |
| **道具** | **主图** · 材质 + 年代 + 磨损指纹 · 尺度 · 多面结构 | **开合 / 亮灭 / 满空 / 新旧 / 损坏**（每态一版） | 握持面 · 摆放位置 · 接触点 | 转手 · 损毁 · 修复 · 遗失 |
| **场景** | **俯视平面图** · 空间指纹 · 面积/层高/进深/门窗四数 | **时段 / 灯态 / 天气** · **机位视图库** | 这一镜选哪个机位 · 构图 · 空镜 | 破坏 · 积水 · 断电 · 陈设搬动 |

**★ 道具与场景为什么能沿用**：把"会变的东西"一律推到 L2 用版本管，把"剧情造成的变化"推到 L4 用事件管——**人物只是"变化最多"的那一类，不是特例**。
**★ 子地标**：出现 ≥2 镜且观众会认出的局部（窗 / 招牌 / 机器 / 杯），按 L1 单出一件（形态、比例、表面写死）。

## §3 人物（七件套 · 1 件 L1 + 6 件 L2）

### 3.1 七件清单

| # | 文件 | 层 | 视角 / 取景 | 必须看见 | 必须没有 |
|---|---|---|---|---|---|
| ① | **脸部特写** | **L1** | 胸以上 · 正对镜头 · 85mm 感 · 中性表情 | 双耳、发际线、眉/眼/鼻/唇全可判 | 手、道具、环境 |
| ② | **前视** | L2 | 正面全身 · 双臂自然下垂 · 双脚并拢 | 全套服装、正面剪裁、体型 | 夸张姿态、遮挡 |
| ③ | **后视** | L2 | 背面全身 · 不回头 | 后脑发缝、后领、衣摆、后腰 | **任何面部** |
| ④ | **左视** | L2 | 正左 90° · 视线正前 | 耳廓、鼻梁、下巴轮廓、侧缝 | 四分之三、回头 |
| ⑤ | **右视** | L2 | 正右 90°（镜像） | 同上 | 同上 |
| ⑥ | **俯视** | L2 | 正上方 90° · 两臂微张 | 发旋、肩线、脚背 | **任何面部**、透视畸变 |
| ⑦ | **无头身体** | L2 | 去头 · 保留头顶留白 | 领口结构、服装轮廓、体型 | 头、颈、发（B 型留一小段颈） |

**生成路径**：先出①并审批为 L1，**其余六件都以它为身份参考生成**（`reference_nodes` 挂①，prompt 只写"同一人物 + 本张视角"）。七次独立文生＝七个人。

**★ 可合并成更少节点，但只按"脸数"合**：`前+后`（1 张脸）· `左+俯`（1 张脸）· `右`（1 张脸）· `无头身体`（0 张脸）→ 加①共 **5 个节点**。**"前/后/左/右四合一"＝3 张脸，不做**（官方明确多视图会被当多个主体，每格脸只剩约 1/4 像素）；只有封装主体通道例外。合并图：同一画布、同背景同平光、**无分格线**、格与格只变视角。

**为什么是七件**：要的是"任何机位都有实物可挂"，不是"最小够用"。**代价**：7 文件 × 造型数；多视图在平铺通道有漂移风险，对冲见 §3.2。

### 3.2 投喂：每镜只挂一张"带脸"的图

| 镜头朝向 | 主挂（结构件） | 补脸（身份锁） | 本镜带脸数 |
|---|---|---|---|
| 正面 / 中近景 | **脸部特写** | — | 1 |
| 侧面 | **左视或右视**（按实际朝向） | — | 1 |
| 背面 / 转身 | **后视** | 本镜要露脸才加特写 | 0–1 |
| 俯拍 | **俯视** | 本镜要露脸才加特写 | 0–1 |
| 全景 / 远景 | **前视**（或 无头身体＋特写） | 视需要 | 0–1 |

**硬规则**：**同一身份在一批参考里，带脸的图 ≤1 张**（合并节点按它含的带脸视角个数算；`前+后` 算 1 张）。
**★ 本表只决定"挂哪些"，不决定顺序**：顺序按 `asset-pipeline.md` §2——**空间 / 首帧在前，人物在后，道具与卡片最后**（两张成片画布的共同口径；脸不是默认第一位）。
**★ 只有上限，没有下限**：背面 / 俯拍 / 剪影镜**允许 0 张脸**——硬塞一张正脸反而可能让模型把她转过来。但**每个入画角色至少要有一张参考**（结构件即可），否则报 `FEED_THIN`。
**为什么不是七张一起挂**：平铺通道下多张脸＝模型随机挑一张锁；实测 2–3 视图最好，5 张已进下降段。**七件是"库"，不是"批"。**
**封装通道例外**：平台若把整组打包成一个"主体"（可灵主体库 / updream 锁定资产），七件可同批；**LibTV 未核 → 默认按平铺从严**（§8）。

### 3.3 设计板与无头身体（两件容易混的东西）

- **设计板**（十格 / 三格 / 正背胸上特写）：**只给人看**，不进参考、不连线。它没有版本意义，也不参与 L1/L2。
- **无头身体**（L2 正式资产）两型：**A 幽灵人台**（有真实领口：T 恤 / 圆领 / 高领 / 帽衫 / 衬衫）→ 无头、无颈、无发，领口保持立体、开口是看向衣物内部的空黑洞；**B 干净颈切**（抹胸 / 吊带 / 深 V / 大露背）→ 颈从肩膀升起一小段，在喉部终止于干净锐利的水平边。
- **共同抑制栈**：不模糊、不淡出、不溶解、无发丝、无烟、无重影、身体不透明、无残端、切口无解剖细节、无血。**头发跟头一起走。**
- **用途**：全身 / 远景镜的身体基准（无脸，不占"一张脸"名额）；**不进任何特写镜的投喂集**。

### 3.4 必填块不变，按视角换句

九块整套照写；下表只列**每类图必须改的那几块**，没列到的块（2 冻结块、4 调性）**逐字不变**。

| 块 | 脸部特写（L1） | 前 / 后 / 左 / 右（L2） | 俯视（L2） | 无头身体（L2） |
|---|---|---|---|---|
| **1 板式行** | 单张 · 2:3 · 胸以上 | 单张 · 2:3 · 全身入画 | 单张 · 1:1 · 正上方 | 单张 · 2:3 · 头顶留白 |
| **3 视角句** | 正对镜头，视线平视 | 正面 / 背面 / 正左 90° / 正右 90°，视线正前 | 正上方 90° 垂直俯拍 | 无头，领口朝上 |
| **5 材质与脏** | 皮肤哑光、毛孔、胡茬 | 服装分层＋磨白；背面写发缝与后领；侧面写侧缝与肩线 | 发旋、肩线、鞋面 | 领口结构、内衬、衣摆 |
| **6 尺度** | 不写 | 身高＋肩宽 | 头肩比 | 肩宽＋身高到画框 |
| **7 色板** | **唯一写色板的一张**（全片基准） | 不复述 | 不复述 | 不复述 |
| **8 布光** | 正面平光，眼里有眼神光 | 同左；背后/侧面也平光 | **光从相机方向（正上方）均匀来** | 同左 |
| **9 提质层** | 全量 | 全量 | 全量（可见皮肤处） | 全量；无皮肤只留材质句 |
| **参考声明** | 仅参考面部，不继承背景光线 | 仅参考比例与服装结构，不继承构图 | 仅参考顶视结构，不继承透视 | 仅参考服装轮廓，不继承任何面部 |

**★ 三条最容易写错的**：① 俯视图写"顶部光"＝造型光，会被下游继承 ② 后视图露半张脸＝废图 ③ 七件共用一个冻结块，一个字都不许改。

### 3.5 造型版本（L2 内再分版）

```text
状态 A（基准）＝身份锚点冻结块逐字（不改一个词）
状态 B：[同一冻结块逐字]；差异：左袖自肘部起撕开约 15 厘米，右手背新增一道约 3 厘米的浅红划痕。
```

**每个造型 × 六件 L2 文件**，各带版本号；`look_id` 变更不影响 L1。**冻结块改一个词＝换人**（那是新身份版本）。

**★ L2 造型 vs L4 事件的判据**：**跨场持续、需要独立出图**的（换装、长期伤、发型改变）＝ **L2 造型版本**；**只在某一场或某一镜成立**的（本场擦伤、淋雨、沾血）＝ **L4 连续性快照**，**不新出 L2 图**，只写进该镜提示词与连续性表。上例按"本片后续都存在"处理，故属 L2。

## §4 道具（L1 主图 + L2 状态版本）

| 层 | 产出 | 规格 |
|---|---|---|
| **L1** | **主图 ×1**（可含 3 视角拼版） | 材质 + 年代 + **≥3 处逐处写脏**（位置＋形态＋尺寸）＋受光响应＋接触阴影；**尺度写死**（部位对照或数字）；4–5 视角是上限不是默认 |
| **L2** | 状态版本（开/合、亮/灭、满/空、新旧、损坏） | 每态一版、单独 id；**不许在同一张图里画状态变化** |
| **L3** | 握持面 / 摆放位置 / 接触点 | 手持类写"哪面朝手、手指落点"；陈设类写相对位置（**定下就进冻结块**）；环境类给"组"不给"个" |
| **L4** | 转手 / 损毁 / 修复 / 遗失 | 由剧情事件给，**不预先出图**；受影响镜按事件重算 |

**道具拼版允许**（无身份脸）；**物证另出近距版**（L2，条件：有特写且是剧情物证）。
**★ 含文字/数字的物证（屏幕、纸条、工单、倒计时牌）**：**生成只出底图，文字与数字后期合成**——文字是生成的必崩项（`ai-artifact-control.md`），多加参考救不回来。
**★ 手物接触**：手是高风险项；**没有手部资产时，宁可让手离开画面**（"手插在口袋里""画面中不出现手"），或按 `ai-artifact-control.md` 的接触面写法（①固定接触面 → ②藏手指 → ③只拍结果）。
**尺度与位置一旦定下＝L1 冻结**，`大约两倍` 改成 `两倍` 就是漂移源。

## §5 场景（平面图 L1 + 机位库 L2 + 剧情变化 L4）

```text
① 平面图（L1 · 俯视正投影 · 无透视 · 无人 · 不写机位）
      ↓ 每个机位派生一张（L2 机位库）
② 机位视图（该机位下的透视 · 空间 + 光位 + 遮挡关系）
      ↓ 该机位的主镜若为空镜/建立镜
③ 空镜（即②中 empty_plate 的那一张，不另立类目）
```

| 层 | 产出 | 规格 |
|---|---|---|
| **L1** | **平面图 ×1 / 空间** | 家具位置与朝向按比例；核心情节位（抽屉拉开一指宽、门半掩）标坐标；**空间指纹**一处；面积/层高/进深/门窗四数；**图中不许有人** |
| **L2** | **机位视图库** + 时段/灯态/天气版本 | 每个不同机位一张、由平面图派生；反打只在真有反切镜时出；日夜/灯态各一版，命名清楚（`S1-夜-灯亮半`） |
| **L3** | 这一镜选哪个机位、空镜与否 | 与分镜"机位"列一一对应；**三镜同机位只用一张** |
| **L4** | 破坏 / 积水 / 断电 / 陈设搬动 | 由剧情事件给；**跑过一次动态后再删一次**（远景车辆会被克隆） |

**★ 3/4 与"正对中轴"的官司**：两者都是**机位选择**，不是资产硬规则。3/4 只作参考图（不当首帧、不当主锚点）；"正对中轴"只在"主力机位恰好正对"时成立（《钥匙》是特例）。
**★ 180° 自检**：摄影机转 180° 时，哪一张已批准的参考能描述这个画面？答不出＝地理没锁，不许开生成。

## §6 投喂纪律（L3 的引用规则）

1. **一图一任务**：脸 / 身体 / 结构 / 空间 / 光 / 构图，一张只给一样。
2. **张数**：**2–3 张起步**；复杂镜可到 9–25（成片画布实测），但**超过 4 张必须逐张声明用途**——张数由复杂度定，不是固定上限。
3. **同一身份≤1 张脸**（§3.2）。
4. **设计板 / 网格 / 带字 / 带标注的图，一律不进参考**。
5. **按景别加权**：全景以场景为主、道具弱挂或不挂；特写以道具/局部为主、**不挂场景全景**；中近景按"是否入画"。
6. **顺序即权重**：最需精准的放最前；prompt 点名"图 N 只供 X，不继承 Y"。**落成 `reference_plan.assets` 的数组顺序与 `prompt_refs`，契约见 `asset-pipeline.md` §2**。
7. **身份永远走锚点，尾帧只接末态**。
8. **只露手 / 肩 / 背影也算该角色入画**：必须登记进 `characters`——否则投喂与检查都会把它当"本镜无人"漏掉。

## §7 旧口径处置（历史全表见 E160–E165）

| 旧写法 | 现值 |
|---|---|
| 人物"十格横版" / "三格正背胸上特写" | **设计板选项**；投喂用七件（§3.1） |
| 三视图【必出】、可当身份锚点 | **脸部特写才是 L1**；五视角是 L2 派生件 |
| 道具"4–5 视角·可直接当参考图" | 主图 1 张 · 多面 3 视角 · **4–5 是上限** |
| 场景"必须 3/4" / "必须正对中轴" | 都是**机位选择**；主锚点是平面图 |
| "空镜主锚点"与"平面图主锚点"并存 | **分层**：平面图 L1；空镜是某机位的 `empty_plate` |
| "去头正面格"仅设计板变体 | **无头身体是 L2 正式资产** |

## §9 资产清单与流水线契约

**最小字段**（每件资产）：`asset_id · subject · role · layer(1/2) · version · status(draft/review/approved/deprecated/stale) · origin(user/approved_asset/project_preset/llm_inferred) · sha256(64 hex) · source(剧本行) · parent(派生自哪件) · qc_report_id · artifact_ready`。
**★ 状态口径**：`approved` ＝ 已过资产 QC 且有 `qc_report_id`（缺报告＝没验过，脚本报 `QC_MISSING`）；**`locked` 不是第六态**，它是 `approved ∧ artifact_ready`，映射见 `production-ledger.md` §二。

**三条硬判据**：① 每件能回指剧本某一行 ② 剧本里有 / 清单里没有的是漏 ③ 只有 `approved` 能进镜头。

```bash
python scripts/asset_manifest.py <breakdown.json> --out asset_manifest.json
python scripts/asset_manifest.py --self-test
```
