# 交付工程：**命名 · 版本 · 目录 · 清单 · 元数据**

> **何时读**：出片之后——**生成了一批候选要怎么命名、怎么归档、怎么交出去**。
> **读完回哪**：回 `post-production.md`（处理与剪辑）· `production-ledger.md`（台账）· `platform-matrix.md`（平台参数）。
> **★ 本册补的是全库真空**：2026-09-19 全库扫描——`命名规范` / `版本命名` / `文件命名` / `目录结构` **各 0 命中**，`交付清单` 仅 1 册、`元数据` 仅 2 册。
> **AIGC 为什么必须有这一册**：**一次生成动辄 10–50 条候选 × 十几镜**——**没有命名规范＝三天后自己也认不出哪条是哪条**。

---

## §1 ★ 命名：一条片子从生到死只有一套名字

**★ 命名三原则**（顺序不能反）：
1. **可排序**（时间/序号在前，名字在后——排序就是找片）；
2. **可追溯**（看名字就知道**是哪一镜、第几次抽、什么状态**）；
3. **无中文路径**（工具链会乱码；**中文只留在"片名"那一段，且用拼音或短代号**）。

**★ 生成件命名（照抄结构）**：
```text
sNN_序号_状态_日期_版本.扩展名（s = shot；分隔符统一用下划线 _）
s03_04_take_20260919_v1.mp4
s03_04_sel_20260919_v2.mp4      ← sel = 选定
s03_04_fix_20260919_v3.mp4      ← fix = 修复过
```

**★ 状态词只用这五个**（**不许自造**）：
| 词 | 意思 |
|---|---|
| `raw` | 刚生成、没看 |
| `take` | 看过、留档备用 |
| `sel` | 选定（进入剪辑） |
| `fix` | 处理过（修复/补帧/变速/调色） |
| `final` | 定稿（可交付） |

**★ 版本号纪律**：**只增不覆**（`v1` 永不被 `v2` 覆盖）；**改了任何东西就 +1**；**不许出现 `v2final` `v2final2`** 这类名字——**"final" 是一个状态词，不是版本名**。同日多机/多人抽卡防撞号：序号段用**全局递增**或含机位代号。

## §2 目录：八个抽屉，一条片一个文件夹

```text
<片名拼音缩写>/
  00_brief/       一页 brief · 命题 · 容量单
  01_script/      剧本（M1–M12 完整档）
  02_assets/      资产图（角色 / 道具 / 场景 / 参考帧）
  03_shots/       逐镜生成件（按镜号子目录）
  04_audio/       配音 / 音效 / 音乐 / 混音
  05_edit/        剪辑工程与导出
  06_deliver/     交付包（§4）
  99_ledger/      生成台账 · 训练/抽卡记录
```
**★ 一条纪律**：**`06_deliver` 里的东西只许从别处拷进来，不许在里面直接改**——**它是"出厂状态"，不是工作区**。

## §3 ★ 元数据：给每条生成件留一行（**这是三个月后唯一能救你的东西**）

**最小集七字段**（一次一行，写进 `99_ledger/generations.csv`）：

| 字段 | 例 |
|---|---|
| 生成时间 | 2026-09-19 13:20 |
| 镜号 | 03 |
| 文件名 | s03_04_take_20260919_v1.mp4 |
| **提示词版本** | `p03_v2`（指向提示词文件的版本，**不是把全文抄进来**） |
| 平台 / 模型 / 参数 | Seedance 2.0 · 1080p · 5s |
| **成败** | 通过 / 过一半 / 废（**失败要写"废在哪一层"** → `qa-failure-codes.md` 的责任层） |
| 备注 | 手部糊；下次把动作幅度收一半 |

**★ 交付状态闭环**：表另加一列「交付状态」（是否已入 `06_deliver` + 交付批次/日期）——否则无法从台账反查"哪条最终交了"。
**★ 为什么只留"提示词版本号"而不是全文**：**全文会让这张表在 50 行之后没人打开**；**版本号 + 提示词文件本身 = 可还原**。
**★ 与 `production-ledger.md` 的分工**：那边管**资产与方案的锁定状态**，本册管**生成件与交付包**。

## §4 交付包：**六件必交**（少一件对方就要回来问）

| # | 件 | 为什么必交 |
|---|---|---|
| 1 | **成片**（母版） | 交付主体 |
| 2 | **分轨音频**（对白 / 音乐 / 音效拟音 / 环境） | **给别人重混的余地**（`mix-loudness.md` §1：Netflix/Prime/电视台都要求）。**⚠️ 分轨必须在合成母版前从工程单独导出——混音母版导出后无法反拆分轨**（→ `mix-loudness.md` §1『AI 成片流程怎么落地』） |
| 3 | **无字幕净版**（underscore / clean） | 平台要自己叠字幕或多语言时用 |
| 4 | **字幕文件**（`.srt` / `.ass`） | 别烧进画面 |
| 5 | **交付清单**（`delivery-manifest`：文件名 · 时码 · 规格 · 响度实测值） | **没有它，对方不知道收到的是什么** |
| 6 | **素材与工程**（提示词全文 · 资产图 · 剪辑工程） | 对方要改时不必从零重做 |

**★ 交付清单模板（照抄）**：
```text
片名 / 版本 / 交付日期
成片：<文件名> · 分辨率 · 帧率 · 时长 · 画幅 · 响度（整合 LUFS / 真峰值 dBTP）
音频分轨：<四个文件名>
字幕：<文件名> · 语言
素材：提示词 <文件名>（版本 pXX）· 资产 <目录> · 工程 <文件名>
校验：<sha256> · <字节>
已知问题：<一至三条，不藏>
```

**★ 一条硬纪律**：**"已知问题"栏不许空着**——**空栏＝没看片**；确无遗留问题写「无遗留（附机检全过 + 抽看记录）」，不许只写一个"无"字；**把问题写在清单里，比让对方发现要好一百倍**。

## §5 交付前的七条机检（**能脚本化的已经脚本化**）

| 检查 | 怎么做 |
|---|---|
| **文件名合规** | 正则：`^s\d{2}_\d{2}_(raw|take|sel|fix|final)_\d{8}_v\d+\.(mp4|mov|wav|mp3|srt|ass|png|jpg|jpeg|csv)$`（扩展名集合按实际交付件扩充） |
| **无中文/空格路径** | 文件名与目录名只许 `[A-Za-z0-9_.-]` |
| **版本不覆写** | 同名不同版本必须并存（比对目录快照） |
| **六件齐** | 交付包内逐项点；**分轨为独立文件而非从母版提取** |
| **响度实测值已填** | 清单里的 LUFS / dBTP 不是占位符 |
| **净版真无字幕** | 抽帧检查无字幕净版未烧字幕 |
| **字幕时码对齐** | 首末条时码与成片头尾对齐，抽 1–2 条中间 cue 核对 |

> **★ 本册状态**：**「拟订」**——**命名与目录结构是本库自建约定**（业界无统一标准），
> **判据：只要同一部片内一致、且三个月后自己能认出来，就算成立**。**若与你既有的交付习惯冲突，以你的习惯为准，把本册当"没有习惯时用的一套"。**

## §6 从平台批量取件（2026-09-20 补 · 以 LibTV 为例）

- **平台给什么**：批量下载脚本按 `{prefix}_{NN}.{ext}` 命名（`NN` ＝ **URL 的提取顺序**）→ **它只覆盖本册 §1 名字里的"前缀＋序号"两段**；**`状态 / 日期 / 版本` 三段必须自己补**（别把平台默认名直接当交付名）。
- **★ 落盘后必做一次"后缀分诊"**：MCP 取件**落盘层**上，URL **没有扩展名会被存成 `.png`**，**视频会被错标成图片** → 逐条核 MIME 再改名，**别把一张 `.png` 当首帧喂回去**。（画布**节点层**无此问题：image/video/audio 节点创建即分型，取件以 node_key 为准——两层口径不同，各管各的。）
- **一片一项目**：平台的项目/画布是**物理隔离单位**（文件沙箱按项目作用域隔离），与本册 §2「一条片一个文件夹」同构——**用平台的隔离单位当我们的抽屉边界**；同一片的多轮任务（task）复用同一项目。
- **元数据（§3 那一行）补两个字段**：`projectUuid` 与 `projectUrl`（**画布链接是交付件的一部分**，算"可回溯的唯一入口"）；**纪律：过程别给、完成再给**。
- **取件句柄两层**：会话内创建产物以工具返回的 **node_key** 为首选句柄；从 run 消息流 / 历史会话提取产物时，结果可能同时出现在 `tool` 消息（JSON 里的 `previewPath`）与 `assistant` 正文（URL 正则）——**只扫一种会漏**。
- **★ CLI 取件入口（本轮补）**：`libtv download -n <node> -o <dir>` 可把单节点媒体直接落盘；普通分组或多文件场景会输出 ZIP。`--without-ai-watermark` 只是偏好请求，水印是否去除仍以实际文件和会员权益为准；**本轮只读过 help，未执行下载**。
- **取件后仍走 §5 七检**：ZIP / 单文件都要核 MIME、文件名、大小与哈希；“平台成功提示”不等于“本地文件已正确落盘”。
