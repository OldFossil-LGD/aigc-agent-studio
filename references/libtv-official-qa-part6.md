## R18 · 非 VIP 三模型差异：`wanx3.0-prime` / `wanx3.0` / `seedance-1.5-pro`

> **适用场景（它给的前提）**：40 秒写实无对白短片，单场景单角色，10 镜，全程正对中轴，每 3 镜用资产图拉回。
> **口径**：以下为工程经验性对比结论（**非官方逐字规格**）；倍率随分辨率/时长/平台活动浮动，**以下单页为准**。

### 18.1 六维度对比（排序口径：强 > 中 > 偏弱）

| 维度 | `wanx3.0-prime` | `seedance-1.5-pro` | `wanx3.0`（标准版） |
|---|---|---|---|
| **① 人脸还原**（对角色资产图的身份保持） | **最强**。五官比例、骨相、年龄感稳定，侧脸/微仰俯后回到正脸不易"换脸"；单角色长片最省心 | **中上**。正脸还原好，表情自然、皮肤质感写实；但多次重跑或镜头间脸型/眼神**偶尔轻微漂移**，需资产图拉回 | **中等**。认得出是同一人，但骨相与眼神光稳定性弱于 prime，连续多镜后"像但不完全是"概率更高 |
| **② 中轴透视保持**（正对/对称不歪） | **中上**（与标准版接近，略稳）。强在身份**而非几何**；复杂运镜下仍需 prompt 显式写死"光轴正对、居中对称、无透视偏转" | **最强**。对"正对镜头、居中、光轴不偏"这类几何约束理解最准，推/拉/轻微升降不易斜轴、透视跑偏 | **中上**。正面静态稳；**一旦带位移运镜，偶发轻微偏轴或双肩不等高** |
| **③ 参考遵从度**（资产图权重与还原） | **最强**。服装、发型、道具、场景陈设的还原度与"听图程度"最高，**适合每 3 镜拉回** | **中上**。能较好遵从，但**有时会"按自己理解美化/改动"**，非常具体的陈设细节需在文字里重复强调 | **中等**。主特征跟随，细节（配饰、材质、背景物件）容易自由发挥 |
| **④ 手部与微动**（手指/小动作/呼吸/眨眼） | **中上**。大幅动作没问题，**极特写手部仍可能出小瑕疵**，避免把手放到画面焦点 | **最强**。手指数量/结构最稳，拿物、触摸类微动自然，**畸形率最低** | **中等偏弱**。复杂手势风险较高，建议用遮挡/景别/道具规避 |
| **⑤ 指令遵循**（复杂文字约束/否定词/构图规则） | **中上**。单条强约束执行好；**约束过多时优先级会自己取舍** | **最强**。多约束（正对+居中+无对白+特定动作+光线方向）同时下达时遵守度最高，对"不要/禁止"类也更买账 | **中等**。长 prompt 尾部约束容易被弱化，**关键约束要前置、重复** |
| **⑥ 生成速度** | **最慢**（三者中最慢；高画质/高一致性换来的代价） | **中等**（略慢于标准版，排队时长随高峰波动） | **最快** |

**一句话总结**：
- `prime` = **"脸和资产最稳"**，慢、贵；
- `seedance-1.5-pro` = **"几何/手/指令最稳、性价比高"**；
- `wanx3.0` 标准版 = **"快、便宜，适合试错和预览"**。

### 18.2 积分相对倍数（**非绝对值**）

以 `wanx3.0` 标准版 ≈ **1.0** 为基准（同分辨率、同时长、同设置下的大致量级）：

| 模型 | 相对倍数 |
|---|---|
| `wanx3.0`（标准版） | **约 1.0x**（基准，最省） |
| `seedance-1.5-pro` | **约 1.3–1.8x** |
| `wanx3.0-prime` | **约 2.0–3.0x** |

**三条注意（它原话要点）**：① 这是相对量级，**不是平台官方固定价**——实际随分辨率（720p/1080p）、时长、是否用首尾帧、高峰期定价而变，**以下单页为准**；② **prime 最慢且最贵，应只花在"必须锁脸/锁资产"的关键镜**，不要全片无脑 prime；③ **标准版大量用于试构图，是把总积分压下来的关键**。

### 18.3 选型与分工（它给的三套方案）

- **A）全片只用一个 → 选 `seedance-1.5-pro`**。理由：本片是"全程正对中轴 + 写实微动 + 无对白"，最大风险是**几何跑偏与手部/微动穿帮**，而这是 seedance 最强项；其人脸在"每 3 镜资产图拉回"的节奏下足够稳，速度与积分又明显比 prime 省，**综合最均衡**。（若把"绝对不换脸"排在一切之前且预算充足，才退而选 prime 全片。） **（★ 2026-09-28 落库注：`seedance-1.5-pro` 的 `duration` 为**枚举 `[5,10]`**——全片选它，则每镜时长只能在 **5 秒 / 10 秒** 二档里挑，做不了 3／4 秒短镜。）**
- **B）锚点镜用 A、运镜镜用 B 的分工**：
  - **锚点镜**（每 3 镜的资产拉回镜、正脸定妆/身份锁定镜）= **`wanx3.0-prime`** —— 产出/确认身份与资产最稳的关键帧，作为全片"脸和陈设的真值"。
  - **运镜镜**（推拉升降、带位移、手部微动）= **`seedance-1.5-pro`** —— 保中轴、保手部、保复杂指令执行。
  - **可选补充**：纯试构图/试调度阶段先用 `wanx3.0` 标准版快速出预览，定稿后再让 B（必要时 A）出正式镜。
- **C）跨模型切换时，人脸与光线怎么拉齐**：
  - **人脸**：① 以 prime 锚点镜产出/确认的**同一张角色定妆图作为唯一身份源**，所有 seedance 镜头都用 reference 引用这同一张图（**不要每次换参考图**）；② prompt 里固定同一段"角色描述模板"（年龄、脸型、发型、肤色、服装逐字一致），**每镜复制不改写**；③ 每 3 镜回到锚点镜做一次显式拉回；发现漂移，**用最近一张合格锚点帧做首帧/参考重新对齐，而不是硬跑**。
  - **光线**：① 所有镜头 prompt 写死同一套光线参数（光位如主光 45° 前侧、光比、色温、氛围、阴影方向），**逐字统一**；② 尽量固定场景与时间设定（同一室内、同一时段），避免模型自行换光；③ 用同一环境/场景参考图贯穿；必要时把上一合格镜的尾帧作为下一镜首帧，做曝光与色温的连续承接；④ 跨模型仍可能有细微色调差，**留到后期统一调色（一级校色 + 同一 LUT）收口**，不要指望生成端 100% 一致。

### 18.4 首尾帧 `frames2video` / 续写 `videoExtend2video` 支持情况

**总体**：三类都属于"图生视频/视频延展"能力范畴，三模型大体都支持图生视频与视频续写；但**"首+尾双帧同时约束（frames2video）"的可用性在模型/版本间并不完全一致，且会随平台更新开关**。

> **★ 抬头注（2026-09-28 落库复核）**：① 本表能力名与取值**以 `get_model` 当前 schema 为准**（modeType 枚举与开关随版本变）。② **「modeType 支持」≠「首尾帧槽位支持」，是两件事，须分两列分判、勿用一条判语同时覆盖**：前者是模型 schema 层有没有 `frames2video` / `videoExtend2video` 这个 modeType（决定能否提交）；后者是工具字段层有没有 `start_frame_image_node` / `end_frame_image_node` 首尾帧槽位（决定怎么传）。schema 有字段也不保证模型真吃尾帧约束——效果层须逐型号实测。

| 模型 | `frames2video`（首尾帧） | `videoExtend2video`（续写） |
|---|---|---|
| `wanx3.0-prime` | **通常支持双帧**，且对首尾身份/资产一致性最好（最适合用尾帧锁下一镜的脸） | 支持，续写后**身份稳定度较高** |
| `wanx3.0`（标准版） | 多数版本支持，但**部分入口只开放"首帧"或"首+尾"其一**，以当前下单页是否出现尾帧入口为准 | 支持 |
| `seedance-1.5-pro` | **支持首帧**；"首+尾双帧"在不同版本/入口开放程度不一，**部分版本对尾帧约束权重较弱**（尾帧还原不如 prime 硬） | 支持，续写时**几何/动作承接自然** |

**不支持时通常怎么报（典型表现，文案随前端变化）**：
- **参数级报错**：类似 `model does not support end_frame / frames2video`、`unsupported parameter: end_frame`、"该模型暂不支持尾帧（首尾帧）"——**提交即被拒、不生成**。
- **入口缺失**：下单页根本没有"尾帧/结束帧"上传位，或置灰提示"当前模型仅支持首帧"。
- **续写不可用**：提示 `videoExtend not supported for this model`、"该模型/该素材不支持续写"，或续写按钮不可点。
- **版本/时长不符**：尾帧与首帧分辨率不一致、续写源时长超限等，**会报参数校验错误而非模型不支持**。

**实操建议（它原话）**：把 `frames2video` 当作"**以 prime 为准**"的能力来设计流程；标准版/seedance 若尾帧入口不可用，就退化为"**首帧 + 强 prompt 描述结尾**"，**不要在流程里假设三者双帧都硬支持**。

### 18.5 省积分的六种做法（"同镜重跑多次取最好"之外）

按省积分程度排序：

1. **低档试构图 → 同 key 升档（最推荐）**：先用最便宜的 `wanx3.0` 标准版低分辨率快速跑构图/调度/景别，定稿后在同一计划/同一镜头上换成 `seedance-1.5-pro`（关键锚点再上 prime）出正式高清镜。**★ 它自己加的限定**：是否"同一 key 直接升档复用"取决于平台是否提供"升档/重绘高清/换模型复用参数"入口；**若不支持跨模型同 key 复用**，则保留同一 prompt 与同一参考图在新节点出正式版，**效果等价**（省的是"用高档反复试错"的积分，而不是把低档结果一键变高清）。
2. **首帧锁构图，减少视频侧自由度**：先用图片模型把关键构图/身份/光线定成一张合格首帧，再图生视频。视频只负责动，不负责"重新发明构图和脸"，一次过率显著提高。
3. **短时长分段 + 续写，而非长镜一次赌**：把难镜拆成更短的段，先保每段成立，再用 `videoExtend` 承接。
4. **批量"小样"筛选**：同一镜先用标准版/低分辨率出 2–3 个方向小样，只对选中的那一个升档出高清。
5. **固化可复用资产**：角色定妆图、场景参考图、光线模板一次做好全程复用；锚点镜成片当"真值帧"反复引用，降低漂移率从而减少重跑次数——**长片里最隐蔽也最大的节省**。
6. **针对性规避高风险元素**：手部极特写、复杂手势、快速大动作是重跑高发点；用景别/道具/遮挡规避，比靠重跑救场更省。

## R19 · 无对白写实短片的音频：建立序列 / 引用挂法 / 音画同步 / 本地做声代价 / 审核边界

### 19.0 一句话结论（它给的五条）

1. **环境床用音频节点 `type=sound_effect` 建立，不要用 `music`**；`tts` 只在有旁白/对白时用，本无对白片基本用不到。
2. 音频的"**依赖引用**"走 `reference_nodes`（即 `left` 建边同一类机制）；但"**挂到成片时间线**"不靠 `left`，而是合成时放进 `composite_video` 的 `audio_list`，用 `start_time/end_time` 定位。
3. **音画同步时间码在"合成层"控制**，即 `audio_list` 的 `start_time/end_time`（成片时间轴秒），**不在音频节点本身**。
4. 平台侧关声代价：丢失现场拟音/房间声天然连贯、多轨要自防相位与电平、批量逐镜做床声易不连续——靠"**一条统一环境床 + 分层**"解决。
5. **审核高发区集中在写实人物的身体/年龄/弱势状态/儿童/医疗等组合**。

### 19.1 三种音频节点类型（建节点只建不跑）

工具 `create_audio_node`，`type` 三选一：

| `type` | 用途 | 写法要点 | 对应模型 |
|---|---|---|---|
| **`sound_effect`** | 单一音效/环境声/拟音/氛围 | **描述用英文，只写声音本身**（来源、动作、材质、空间、强度、时长），**不写台词、不写音乐风格** | Seed Audio |
| **`music`** | 音乐/BGM/歌曲 | 给歌词会唱，不给歌词是纯器乐。**环境床不要用，避免带出旋律节奏** | Mureka V8 |
| **`tts`** | 人声朗读 | **必须同时给逐字台词与音色/语气/人设/情绪**。无对白片不需要 | Seed Audio |

**环境床 `sound_effect` 的英文 prompt 示例（它原样给的）**：
> `"A quiet old office room tone: soft distant birdsong through a window, faint gentle rattling of venetian blinds in a light breeze, subtle hum of an old building, very low sparse, natural realistic ambience, no music, no speech, seamless loopable bed, gentle intensity, long continuous duration."`

**三层写清**：房间底噪 `roomtone` ＋ 远处鸟叫（稀疏）＋ 百叶窗轻响（偶发），并**显式 `no music` / `no speech` / `loopable`**。

**其余参数**：`title` 例＝`环境床_旧办公室_鸟叫_百叶窗`；`ai_model` 留空走默认；`settings_spec` 无要求留空，本地有规格可写 `output format wav, sample rate 48kHz`；`reference_nodes` **纯床一般不引用**，要匹配某画面空间时引用该视频节点并在 prompt 用其 node_key 占位说明用途。

### 19.2 ★ 建议分层，而非一镜一床（均 `type=sound_effect`）

| 层 | 内容 | 特性 |
|---|---|---|
| 1 | 房间底噪 / 旧楼恒在声 | 最底层、可循环、几乎不变 |
| 2 | 远处鸟叫 | 稀疏偶发，可单独淡入淡出 |
| 3 | 百叶窗轻响 | 偶发点，可打点对齐画面 |
| 4 | 按需：脚步、椅子、纸张、门等拟音点 | 单独节点，便于卡动作 |

**好处（它原话）**：本地分别调电平/EQ/摆位；**批量换镜时底噪保持同一条，连续性最好**。

### 19.3 音频引用分两步（`left` 与 `audio_list` 职责不同）

- **依赖**：若音频依据某画面/锚点生成，用 `reference_nodes` 引用，prompt 内以对应 node_key 占位插桩。
- **上时间线**：成片合成调 `composite_video`，音频放进 `audio_list`。**决定哪里响、响多久的是 `audio_list` 时间参数，不是 `left`**。
- **混排顺序**：① 按依赖方向排——被依赖的（锚点/画面/源素材）在前，派生在后；**引用只为生成提供依据，不决定播放先后**。② **`left` 排列顺序不承担时间线意义**；播放顺序由 `video_list` 先后与 `audio_list.start_time` 决定，**别靠 `left` 排序做同步**。③ 实操：`reference_nodes` 中空间/画面依据放前、条件性参考放后，prompt 用对应 node_key 占位逐个写明用途。④ **硬规则：每个被引用 key 必须在 prompt 以其双花括号占位出现；只在文字里提到不算引用。**

### 19.4 音画同步：时间码在合成层

- **控制层**：合成层 `composite_video`，**不是音频节点层，也不是 `left`**。
- **做法**：
  1. `video_list` 按序拼接，每段可用 `start_position/end_position` 裁剪源素材，形成成片时间轴。
  2. `audio_list` 每条给 `node_key` + `start_time`（成片输出时间轴入点，秒）+ 可选 `end_time`：
     - **全片床**：`start_time=0`，`end_time` 留空或显式给成片时长。
     - **拟音点对齐动作**：算出该动作在成片时间轴秒数（**前段时长累加 + 段内偏移**），填入该条 `start_time`。
  3. **电平**：关声后源视频无声；若有素材残留原声，**显式 `video_volume=0` 压掉**，避免叠加被限幅器拉低。`audio_volume` 为 `audio_list` 整体线性电平 0~1，精修留本地。
  4. **composite 是线性求和后峰值限幅整体下拉，叠太多会让声音变小发闷**；平台只做粗对齐/预览，多轨平衡、淡变、相位回本地。
- **口径**：`audio_list.start_time` **相对最终成片起点**，不是相对源视频或音频文件自身。

### 19.5 平台侧关声、本地做声的代价（A–E）

**好处**：干净可控、无平台配乐/拟音污染，写实片值得。**代价与对策**：

| # | 代价 | 对策 |
|---|---|---|
| **A** | **平台环境声 vs 本地声**：`sound=off` **永久丢弃该 clip 音轨**（非只关 BGM），正常不残留冲突；**任一镜头误开 on，其现场声会与本地床声叠加产生梳状滤波/撞顶** | 逐镜核对 off；合成时对不确定素材 `video_volume=0` 兜底 |

## R20 · 它挑我方工作流的错（对我方五步/七站流程的评审）

> **它的总判断**：我方流程骨架（门控、独立锚点、引用插桩、波次、隔离重建、证据交付）**方向是对的**，问题集中在三处——
> **① 把"平台引用机制"和"一致性保障机制"混为一谈；② 缺少真正的剧本/分镜结构化资产与变更影响传播；③ 用固定数字（每 3 镜）代替可观测信号。**

### 20.1 最大的三个错误或遗漏

**【错误一】"参考闭环"被当成一致性的充分条件——它只是必要条件。**
- **错点**：我方认为"用 `left` 把锚点连进每一镜 + prompt 双花括号插桩"就闭环了。但它侧口径：**引用关系只有通过工具的引用字段（`reference_nodes` / 首尾帧节点）才真正成立**；**prompt 里出现占位符而该 key 没有同时进引用字段，等于没引用**。
- **它要求的强制校验（双向）**：**prompt 中出现的每一个占位 key 都能在该节点引用字段里找到，反向亦然**（引用字段里的每个 key 都要在 prompt 中说明用途），否则不允许进入投喂生成。
- **遗漏**：**锚点"生成生效" ≠ "可用"**。它建议在锚点站与参考闭环站之间加一个**极轻的锚点验收**（合格/返工）——**角色锚点至少要有可复用的正面信息（面部、服装、标志物），场景锚点要有可延续的空间关系**；否则错误会被全片复用放大。

**【错误二】剧本与分镜之间缺"结构化中间资产"，且全流程没有变更影响传播机制。**
- **错点**：剧本直接跳分镜，**中间没有可被机器读取的场次/出场表**（哪个角色、场景、道具出现在哪几镜）。后果是"每镜该连哪些锚点"靠人记，**漏连、错连无法被系统性发现**。
- **遗漏（它标为"更严重"）**：我方有"失败隔离/重建 3 次"，**却没有"被引用节点变化后的下游作废与重跑"规则**。**它侧的硬规则**：**一个锚点被 update 或在同一 node_key 上重新生成，它就回到"已创建"态，所有引用它的分镜现有结果一律作废**，必须沿引用链找出全部受影响节点重新生成。**否则"改了主角脸却只重跑失败镜"，会造成"同一角色跨镜两张脸"。**

**【错误三】用固定节数（每 3 镜拉回）管理一致性；且剪辑合成被放在"投喂生成之后串行收尾"，缺少声画在时间线上的前置设计。**
- **错点**：见 §20.3，"3"没有信号依据。
- **遗漏**：`enableSound=off`、声音回本地做本身可行，但我方把声音完全踢出平台侧后，**分镜阶段没有为声音预留节奏/时长**——分镜时长若只按画面估，本地配音/配乐时会发现**镜头时长与台词不匹配**。**它侧口径**：估镜时长本就要求"**台词自然朗读时长 + 无台词动作时长**"，即使声音离线做，**时长也要在分镜阶段就按台词算好**，否则合成后被迫改镜。

### 20.2 做过头的一步 / 以为不必要但必须做的一步

- **做过头（实际不需要）**：**"create(run=false) 之后 read_node 核 left/imageList/imageListOrder"** 在本侧**大部分是冗余的**——create 写入的参数就是我方自己传入的参数，工具不会在创建时偷偷改 `left/imageList`。**真正需要回读的时机**是"用户可能在编辑器里手动改过节点"或"节点刚运行完确认产物生效"。**应保留的是**：运行前（若存在人工编辑可能）以节点当前状态为准 + 运行后确认生效。
- **以为不必要但必须做**：**锚点之间的"关系/连续性资产"与分镜的"首尾帧衔接设计"**。我方明确"不建派生子链"——这对普通镜是对的（避免误差逐镜累积），但**把它绝对化了**：本侧明确存在合法的**"续写链/continue"（用上一镜尾帧作下一镜首帧）**，用于强连续动作（同一动作跨镜、转身、进出画）。**必须补的是**：在分镜时给每一镜打标——**普通复用镜（只引锚点）还是续写镜（引上一镜+锚点）**；这个标记**决定投喂拓扑，不能临场决定**。

### 20.3 ★★ "每 3 镜拉回"有没有更科学的判据（它给四类信号）

**有。不要按镜数，要按"漂移信号"和"连续性类型"决定。满足任一即应拉回锚点：**

1. **内容信号（最强）**：本镜是否需要**角色面部/身份被清晰辨识**——特写、正脸、对话、定妆式镜头**之前，强制拉回**；**远景/背影/虚化/运动模糊镜不需要**。
2. **漂移累积信号**：连续 N 个镜都只靠"上一镜产物"或弱引用延续、**没有重新直引锚点时**拉回（**N 不是固定 3**，而是看引用拓扑里"**距锚点的跳数**"——跳数越大误差累积越大；**普通复用镜跳数应恒为 1，即每镜直引锚点，根本不存在"每 3 镜"问题**）。
3. **变化信号**：**场景切换、时间/光线变化（日/夜、室内外）、服装或道具有变化、跨 montage/转场之后**——必须拉回，因为这些是身份最容易被模型重解释的**断点**。
4. **观测信号（事后）**：把交付纪律里已有的"**像素级色板比对 + 人工审片**"**前移成逐镜的自动一致性检查**——面部/主色板/关键道具与锚点的**相似度一旦低于阈值，下一镜强制拉回**。**让审片结果反哺投喂**，而不是只在成片后做一次。

**它的一句话**：**普通镜本就应每镜直引锚点（node_key 全片复用），"拉回"是续写链才需要的概念**；续写链里按"**特写需求 + 跳数 + 场景/光线断点 + 相似度阈值**"决定，而不是固定 3 镜。

### 20.4 ★★ 比"波次＋引用已生效"更好的并行度控制：**DAG 驱动的就绪队列**

**它的评价**："波次 + 引用已生效"在**正确性上是对的**（它精确对应本侧的可创建/可运行判据），但**它是手工调度，优化目标只有"别出错"，没有"最大化吞吐"**。

**替代做法**：
- 以**锚点和分镜为节点、引用关系为边**建 DAG；节点状态 = 已创建/已生效/已废弃。
- 调度器每轮自动取出"**所有入边来源均已生效、且彼此之间无依赖**"的节点放入就绪队列，受**并发上限（如一次 ≤5）**约束分批提交，跑完回写状态再触发下一轮。这本质上是把"波次"从"**人按批次切**"变成"**按拓扑层自动滚动就绪**"——波次边界不再需要人判断，且**天然最大化同层并行**。
- **续写链在图里是串行长边**（只能逐镜等生效），**普通镜是共享锚点的宽扇出**（锚点一生效，一大批镜同时就绪）——**DAG 能自动区分这两种拓扑，人工波次做不到**。
- 再叠加两条已有但应纳入调度器的规则：**失败节点隔离**、**出度影响传播**（某节点重跑，自动把其全部下游标记作废重排）。

**它的结论**：**不是推翻"引用已生效"，而是把它从"波次准入条件"升级为"DAG 就绪判定 + 自动滚动调度 + 失败/变更重排"。**

### 20.5 只保留五步，保留哪五步（它给的合并方案）

1. **命题 + 可行性门**（合并原①②）：先确认做得了、边界与硬约束，避免后面整链返工。
2. **剧本结构化 + 锚点资产**（合并原④⑤，并**强制产出"场次/出场表"与"经审核可用的独立锚点"**）：这是一致性的根。
3. **分镜 + 引用/续写拓扑标注**（合并原⑥与参考闭环站）：每镜明确引哪些锚点、是否续写、**时长按台词估算**；**占位 key 与引用字段双向强校验**。
4. **DAG 就绪调度投喂生成**（原投喂生成站的升级，含**失败隔离 ≤3 次、变更影响传播、按信号拉回**）。
5. **合成 + 证据交付**（合并原剪辑合成/交付两站，含**逐镜一致性检查反哺、成片色板比对、人工审片、参数快照与全链状态可回读**）。

**被砍掉的**：独立的"风格/方案包"站（并入命题门与锚点）、独立的"参考闭环"站（并入分镜拓扑）、独立的"返工复盘"站（其有效部分 = 变更传播与失败隔离，已并入第 4 步）。

### 20.6 它针对我方具体措辞的三处提醒

- **"read_node 核 left/imageList/imageListOrder"**：本侧对应能力是 `get_node_details` / 节点参数与引用字段；**创建后回读自己刚写的字段无意义**，**运行后或人工编辑后回读才有意义**。
- **"validate_generation_plan"**：本侧**没有这个同名工具**，等价保障 = **引用字段与 prompt 占位插桩的双向一致性 + 可创建/可运行状态判定**，需我方在编排侧自行实现该校验。
- **"enableSound=off 声音回本地"**：可行，但 **off 会永久丢弃该镜音轨**；务必确认这些镜确实不依赖现场声，且**分镜时长已按离线台词预估**，否则后期只能改镜。
