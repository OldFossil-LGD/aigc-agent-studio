# Agent 自主版纪律：三条核心 ＋ 四条增补（核心三条：预算 · 证据链 · 可计算一致性）

> **何时读**：站 6.5（投喂与生成）与站 6.7（交付与证据）必读；**任何要花钱的动作之前**必读。
> **为什么单列**：本 skill 从"人操控"改成"agent 自主跑"之后，**原来由人承担的三件事没人接了**——**控成本、看片、记账**。
> 这三条纪律就是把那三件事**变成 agent 自己的义务**。
> **编号说明（2026-09-27 补）**：纪律一–三为核心三条；**纪律四–七为后续增补**，物理顺序按增补日期倒序排列（六 09-22 → 五 09-21 → 四 09-20，七在其后）——**编号≠物理顺序，按物理序顺读即可**。

## §0 · 心智模型：AIGC 的流程为什么长成这样（**先懂这个，三条纪律才不是条文**）

**它不是"渲染"，是"按提示词在巨大的可能空间里采样"。** 由此推出四条，**它们才是流程形状的真正原因**：

| # | 事实 | 推论（直接决定流程） |
|---|---|---|
| 1 | **采样有随机性**（同一提示词两次不一样） | 流程的核心不是"把参数调对"，而是**收窄搜索空间**——**参考图/资产是收窄空间的主手段**（只写文本锚点＝没在收窄） |
| 2 | **模型无跨批记忆** | 跨镜/跨批的连续性**必须由外部机制强制**（参考图 / 主体库 / 首尾帧）。"锚点句逐字复述"是**人投喂时代的替代品**，不是解法 |
| 3 | **分层生成**（文本→图→视频→音频→合成），**每层产物是下层输入** | **错误向下游传播**（色板在图那层丢了，视频不可能捡回来）；**下游发现问题必须回上游改**——在下游加形容词＝无效 |
| 4 | **越靠下游越贵**（图 ≈ 1/40 视频） | **上游多花、下游少返工**——这才是"资产先行"的真正理由（不是好看，是省钱） |
| **5** | **★ 一致性是「引用关系」，不是「相似度」** | 文字＝一个集合（无数张脸都符合）；**资产图＝把集合塌缩成一个点**。下游于是从"重新描述"变成"引用同一份文件"：**重新描述＝重新采样＝必漂；引用＝把漂移从"必然"降为"可抽检的残差"（仍须抽帧并排看一眼）** → **▶ 这就是"为什么必须先生产资产"的机制答案**（详见纪律三 · 修正块） |

**再叠五条硬约束**（不是方法论，是工程的墙）：单次生成有边界（时长/prompt 长度/分辨率/张数）· 时间是分片的（4/8/15 秒）· **成本只加在"生成"上** · 一致性不在模型里 · **平台没有余额接口（成本不可观测）**。

**→ 于是正确的流程形状必然是这样**：
**① 结构层免费随便跑**（分镜表 / 连续性 / 时间线 / 预检）→ **② 在上游把一致性锁死**（资产 → 参考 → 每一镜）→ **③ 生成层极度节制**（先报数、先 dry-run、幂等键）→ **④ 全链留证据**（因为**没有人替你记账，也没有人替你看片**）。

**★ 一句话（本 skill 的地基）**：
**"每环成功" ≠ "链路正确"。** 资产没进参考时，下游每一环都会成功，只是全都错了。
**流程不是一条链，是一个"状态机 + 一条证据链"。**

## 纪律一 · 预算与止损（**原来由人克制，现在由 agent 计算**）

**旧前提**：`platform-matrix.md` 写"单镜 2–4 次"——那是**给人看的建议**，人自己会心疼。
**新要求**：**agent 没有"心疼"，只有"算"**。

**三条硬规矩**：
1. **每一笔付费调用之前先报数**：说清"这一步要花什么（模型 / 时长 / 清晰度 / 条数）· 为什么值"；
2. **能免费的一律先免费**（每一条都实测过是 0 成本的）：
   - **预检**：`validate_generation_plan` · `generate_video(run:false)` · `export_readiness`
   - **结构层**：`create_script_v2` / `read_script_v2` / `edit_script_v2` / `check_continuity`（明写"不生成内容或媒体"）
   - **时间线**：`read_timeline` / `apply_timeline_edit`（含 apply——"editing never starts a render"）
   - **发现层**：`search_models` / `get_model` / `recommend_video_models` / `read_project` / `get_project_snapshot` / `browse_project_media` / `inspect_media`
   - **Agent 规划与对话**：`run_agent(autoGenerate: **false**)` ← 本次实测为零媒体任务；**对话本身是否计费仍【不可判定】，不得外推为“一定免费”** → 遇到不明确的事可先问，但按接口计费边界留证
   - **计费与退还按动作分列**：生成、合成、剪辑、音频编辑、导出计费；R24 口径下生成失败、审核拒绝、超时可退，手动取消看阶段；量级：**8 秒 480P ≈ 几十积分 · 1K 图 ≈ 个位数到十几积分**（拟订，以计费页为准）
3. **压缩到平台的硬上限内再投**：投喂前**先数 `prompt.maxLength`**（实测 Wan 3.0 = 3000 字）。**压缩顺序：先删形容词与重复复述，绝不删计数约束与不变项。**

**止损线（写死，不许现场松）**：
- **同一镜超过 8 次还不过 → 改结构，不是改词**（`qa-failure-codes.md` 原口径保留）；
- **任何一步的实际消耗无法读取时**（平台没有余额接口，实测确认）→ **按任务号请用户回查**，并**在回查前不再增加付费调用**；
- **"再抽最后一次"是禁止项**（原口径保留）。

**★ 最有用的成本事实（按动作分列）**：**结构、读取与预检免费；媒体生成、合成、剪辑、音频编辑和导出计费**。
**因此抽卡要克制，结构与预检优先；剪辑/导出仍需按 R24 报预算。**

## 纪律二 · 证据链（**原来由人记账，现在由 agent 留痕**）

**为什么**：人会忘、会记错；agent 会**断线、会跨会话失忆**。**没有证据链，任何人（包括我自己）都无法复核。**

**每一笔都要留四件**：

| # | 留什么 | 从哪来 |
|---|---|---|
| 1 | **任务号** | `task_id` / `runId` / `export` 的 `task_id` |
| 2 | **参数快照** | 节点的 `taskParams`（**逐字留存**，它是"我到底投了什么"的唯一凭据） |
| 3 | **结果路径** | 本地落盘路径 + 平台 URL |
| 4 | **判据结果** | 帧级 / 容器级 / 像素级判据的**原始输出**（不是"通过"两个字） |

**三条连带纪律**：
- **写操作一律带 `idempotencyKey`**：断了重试**不会重复生成**（"Reusing the same key recovers the original run without resending"）；**绝不新建替代任务**；
- **写操作按接口读取并携带该接口要求的 revision**：`update_project` 用上一次 `update_project` 返回的 `projectRevision`，不是 `read_project.revision.token`；其他接口按 schema 是否必填处理，冲突时拒绝盲重试；
- **台账自己写**（`production-ledger.md`）：**从"人记账"改成"agent 交付时自动写"**。

**★ 一句判据**：**"我这句话，能指回哪次调用 / 哪个任务号 / 哪个文件？"** —— 指不回去的结论，不许写进交付。

**★★ 实测错误码表（2026-09-20/21 · 全部是亲手踩到的原文）**

| 错误码 | 触发场景 | 正确做法 |
|---|---|---|
| `PROJECT_REQUIRED` | `run_agent` 没带 `projectId` | 带上 `projectId` 或已选定的 `projectContext` |
| `LEGACY_RUN_ID_REQUIRED` | `get_agent_status` 空手问（不带 runId/agentSession） | **runId 只能由 `run_agent` 返回**；先起 run 再读 |
| `AGENT_RUN_ACTIVE` | 已有活跃 run 时起新 run / 写画布 | **一个活跃 run 独占画布**；先等它终止或 `stop_agent_run` |
| `AGENT_QUESTION_PENDING` | 它反问了，此时 `steer` 被拒 | 必须先用 `answer_agent_questions(feedback, toolCallId)`；**而 `toolCallId` 只在网页端进度卡里** → 需人处理 |
| **`AGENT_ACCEPTANCE_UNKNOWN`** | `steer` 时它回"**Wait for the initiating input/control to be observed**" | **run 的初始输入尚未被观测**（run 没真正跑起来）→ **等；重试仍失败则视为该 run 未起**（本轮实测：连试两次均失败，画布无变化） |
| `AGENT_RUN_SUPERSEDED` | 旧 run 被更新的会话轮次取代 | 该 run 已作废；**用新 key 起新一轮** |
| `AGENT_REMOTE_TERMINAL` | 对已结束的 run 发 steer | run 已结束（**这也是探活手段**：能看出它是"活着"还是"结束了"） |
| `IDEMPOTENCY_CONFLICT` | **同 key 换了内容**再发 | **重试必须"同键同文"**；要改内容就**换新 key** |
| `NODE_VALIDATION_FAILED` | 参数越界（实测：`params.settings.quality` 只接受 `low/medium/high/xhigh/max`，写 `"1K"` 被拒） | 按字段取值域改；**画布层参数 ≠ 模型层参数** |
| `NODE_NOT_FOUND` | `read_node` 按名字找不到（节点还没被建出来） | 确认节点已建、名字逐字一致；**节点未生成 ≠ 节点不存在** |
| `MCP error -32602: Invalid request parameters` | 用 `ReadMcpResource` 去读对方工作区的文件 | **MCP 资源 ≠ 对方沙箱文件**；该路不通（见 `libtv-canvas-nodes.md` §十·补） |

**★ 一条探活技巧**：**对 run 发一次 `steer`，从它的错误码就能读状态**——`AGENT_REMOTE_TERMINAL`＝已结束 · `streaming`＝活着 · `AGENT_QUESTION_PENDING`＝在等你答 · `AGENT_ACCEPTANCE_UNKNOWN`＝根本没起。

**★★ 死锁形态（2026-09-21 实测 · 会卡死整条外部流水线）**
**一个"未真正启动"的 run 会同时满足三件事**：
1. **它占着画布锁**（起新 run 回 `AGENT_RUN_ACTIVE`）；
2. **不能 `steer_agent_run`**（回 `AGENT_ACCEPTANCE_UNKNOWN: Wait for the initiating input/control to be observed`）；
3. **连 `stop_agent_run` 也回同一个错误** → **无法用 API 解除**。
**→ 三条逃生路（按推荐序）**：
1. **★ 自己 `create_project` 开一张新画布**（`name` + `idempotencyKey` 必填；**零成本**）→ 立刻在新画布上继续（**不必等人**）；
2. 人在网页端点停止；
3. 等它自然超时。
**→ 纪律**：**一个画布同一时间只能跑一件事**；**发现 run 起不来（`AGENT_ACCEPTANCE_UNKNOWN`）时，不要在同一画布反复重试**——**直接换画布**。

## 纪律三 · 可计算一致性（**原来由人看片，现在必须变成数**）

**旧前提**：`acceptance-check.md` 是**给人念的清单**；门禁里到处"WARN 需人工定性"。
**新要求**：**没有人替我们看片了 —— 所以"看完的结论"必须由可复现的判据支撑。**

**已实测可用的判据（免费、可复现）**：

| 判据 | 怎么做 | 判什么 |
|---|---|---|
| **容器级** | `ffmpeg -i <片>` | 时长 / 分辨率 / fps / **有无音轨**（注意导出会强加静音轨） |
| **切片级** | `ffmpeg -filter:v "select='gt(scene,0.30)',showinfo"` | **硬切数** → 核"段落版恰好 N−1 个切换点"；拼接后内部切换点应**整体平移** |
| **像素级（色板）** | `ffmpeg -vf "crop=…,scale=1:1"` 取区域均值 RGB | **同一空间跨图的色板一致性**（实测用它证明了"三处墙面互不相同"） |
| **结构级** | `check_continuity` | 逐对相邻镜 9 类事实 + 9 条看片项 + **3 条"没证据不能判"** |
| **可读性级** | 缩到 **120px** 宽再看 | 主体还立得住吗（构图问题，不是细节问题） |

**★ 尚未解决的一格（诚实列出）**：**人脸 / 服装的跨图一致性**——但**注意：这一格不是"缺算法"，是我原来的问法错了**。

**★★ 正确的问题不是"怎么量相似度"，而是"这一镜引用了哪张资产图"**（2026-09-20 修正）：

| | |
|---|---|
| **一致性是「引用关系」，不是「相似度」** | 文字描述在采样空间里是**一个集合**（无数张脸符合"穿灰开衫的女人"）；**一张资产图把这个集合塌缩成一个点**。于是下游从"重新描述同一个对象"变成"**引用同一份文件**"——**重新描述＝每次重新采样＝必然漂；引用＝不可能漂** |
| **可计算的是引用关系** | `referenceImageNodes` 非空？预检的 `resolvedReferences.image` 非空？——**这个能机检**（站 5.5 的硬门禁就是它） |
| **相似度不需要算法** | 引用成立 → 一致性在**系统意义上**已经成立；剩下"像不像"只需**抽帧并排看一眼**，并把打勾结果写进证据链 |
| **引用不成立时，量测毫无意义** | 你无法"修正"一个没被引用的东西——只能重生成，而重生成又再漂 |

**★ 为什么"资产必须先做"（机制上的必然，不是"省钱"）：**
1. **它是最便宜的一层**（图 ≈ 1/40 视频）→ **在最便宜处解决最贵的问题**；
2. **它是唯一能被引用的东西**——文字不能被引用，只能被重新采样；
3. **它是并发前提**：资产 locked 之后多镜可并行而互不漂；没 locked，串行也漂；
4. **它是单点**：母版只有一个、必须先定；**母版一改，所有印件全部作废** → 所以必须 `draft → locked` 才开工。
**顺序反了就废**：先出视频再补资产，那个资产与已出的视频之间**没有引用关系**，照样漂——**锚的位置错了，补也白补**。

**★ 三条不许说的话**（没有判据支撑时）：
- 不许说"看着像" / "感觉对了"；
- 不许说"门禁过了所以能交付"（**门禁只判结构，不判画面**）；
- 不许把**预检通过**说成**渲染正确**（平台原文：**"Sources are readable; rendering and playback are not verified."**）。

## 纪律六 · ★★ 远程依赖的自检与降级（2026-09-22 实测故障立规）

**事实**：**自动化会话挂载的 MCP ≠ 交互会话的 MCP。**
- **自动化只挂载"连接器注册表里 `enabled` 的连接器"**；
- **顶层 `~/.workbuddy/mcp.json` 里的"自定义 MCP"，若没在客户端走一次「添加 + Trust」，注册表里不会出现** → **自动化全程 `not found`**（实测：LibTV 连断 12 轮）。
- **权威名单在哪**：`~/.workbuddy/connectors/<accountId>/connector-states.json` 的 `connectors{}`，与 `connector-states.v3.json` 的 `enabled[]` / `everConnected[]`。**顶层 `mcp.json` 只代表"写它的那个会话"。**
- **旁证**：`headerOverrides` 里出现 `custom-mcp:ardot` → **"自定义 MCP"这条路本来能被注册**，只是缺那一次 Trust。

**→ 三条纪律**：
1. **首轮必做"能力自检"**：跑任务前先用该依赖的**最轻接口**试一次（如 `read_project`）。**`not found` ＝ 依赖未挂载**，**立刻停手**，**不要反复重试**（空转烧轮次）；
2. **降级三件套**：**① 如实登记**（"发出 0 轮"、**绝不编造 runId/结果**）**② 备好恢复路径**（把待发的活写成"待发队列"文件，通道一恢复即可一键补发）**③ 保留运行不暂停**（修好即在下一轮自动恢复）；
3. **★ 禁止手改加密的连接器注册表**（`connector-states*.json` 的 `headerOverrides` 是 aes-256-gcm 加密的）——**改坏会连带毁掉整个连接器体系**；**该动作只能由用户在客户端点 Trust**。

**→ 判据**：**"这个依赖现在到底挂没挂？"** —— 用一次最轻调用问出来，**而不是假设它在**。

## 纪律五 · ★★ 阶段门与"未验证先问"（2026-09-21 用户立规）

**① 阶段门：不同阶段有不同的"允许动作"，越阶就是事故。**
| 阶段 | 允许 | **禁止** |
|---|---|---|
| **学习与准备** | 问接口 · 读回 · 落库 · 适配 skill · 建/改**不点火**的节点 | **点火 · 生成 · 合成 · 导出**（一切花积分或产生资产的动作） |
| **实片预演**（**当前 · 2026-09-22 用户授权**） | **图片生成**（关键帧 / 角色 / 场景 / 道具）· 建节点 · 写剧本 · 读回 · 探测接口 | **视频生成 · 合成 · 导出**（用户原话：「**视频先不生成 允许生成图片以及其他操作**」） |
| 实片测试 | 按 SOP 执行（需用户逐阶段批准） | 未批准的批量铺开 |
| 交付 | 验收与归档 | —— |

**→ 落实**：**两个自动化任务都已写死"阶段闸"**（禁止 `run=true` / `generation_submit` / `export_video` / `apply_timeline_edit` / `composite_video`）；**SOP 顶部必须挂阶段门**，并注明"此刻是核对与提问，不是照着跑"。
**★ 2026-09-22 松绑（范围限定，别外推）**：用户授权「**视频先不生成，允许生成图片以及其他操作**」→ 进入**实片预演**。**松绑只适用于「用户在旁的交互会话」**；**两个自动化任务仍维持全禁**（无人值守，不点火）。**"视频闸"未解除**——`generate_video` / `video` 节点 / `composite_video` / `export_video` 在交互会话里**也仍禁**。

**★ 2026-09-22 补 · 平台 Agent 的提问"不可自答"（已穷举证明，别再花轮次试）**：`get_agent_status` **句柄有效时恒不回状态**（只有句柄无效才回真错误：`PROJECT_REQUIRED` / `AGENT_RUN_NOT_FOUND` / `AGENT_SESSION_INVALID`）→ **拿不到 `toolCallId`**；`steer_agent_run` 被 `AGENT_QUESTION_PENDING` 拦；`run_agent(runId=<活动run>)` 被 `AGENT_RUN_ACTIVE` 拦；**换自带全流程模板（`skills=[短剧·导演级全流程编排]`）同样卡**。→ **用户既可用「遇到提问自己回答」，在本宿主只能兑现为两条**：① **我方接手点火**（接它的产出自己 `run=true`——已证 6/6 + 4/4）② **用户在 LibTV 界面答**。**"免审批声明"与"铁律禁提问"都不算**（前者无效，后者跳过提问但**它也不点火**）。

**② 未验证的事 → 先问，不要盲试。**
- **接口/字段不知道** → **先"探 schema"**（用空参数调用，**在校验阶段就被拒、绝不扣费**）或 **直接问平台 Agent**；
- **★ 写操作（会改东西的接口）绝不在真画布上盲试**——那可能改坏资产、误点火、白花钱；
- **判据**：**"这一步我能不能说清它会做什么？"** 说不清就不执行，先问。

## 纪律四 · 人机分工：**自动化到 90%，剩下 10% 留给"人"（2026-09-20 定案）**

**★ 结论**：**Agent 不能完全自动化做片——但这不是缺陷，是正确的设计。**
依据（平台自己的口径 + 本库实测）：

| | 内容 |
|---|---|
| **可全自动（API）** | 建任务 · 写读文件 · **建图片节点（含 `mode:"create"` 零成本铺）** · 生成视频/音频 · 合成 · 后处理 · 查询节点/搜索资产 · 分析素材 · **导演台编排 `director_apply`** |
| **必须人做** | 画布点选/连线/拖拽 · 运行审批弹窗 · 仅网页端的模板/宫格预览 UI · **★ 人工审片（看人物是否漂）** · 成片确认与导出 · 资产库整理/命名/归档 · **★ 取回平台内 Agent 的回复（实测：我读不到，只能人搬）** |

**★ 两处真正的"不可自动化"**
1. **判定（审片）**——**这是唯一本质不可自动化的**：它判的是"对不对"（感知/审美），不是"有没有违反规则"。**恰恰是 AIGC 最容易翻车的一关**（本库实测：七环全绿、成片出来了、**人物与场景全不一致**）。
2. **界面交互**（点选/拖拽/审批/预览）——**这是产品形态决定的，不是本质障碍**，且大多可用 API 绕开。

**→ 所以正确的形态不是"全无人"，而是「自动执行 + 人在关键闸门」（human-in-the-loop）。三道闸门**：
| 闸门 | 交给谁 | 为什么 |
|---|---|---|
| **① 花钱之前** | **人批准** | 成本按动作计费且余额不可自证；退还按 R24 分情形，不把“生成失败才退”写成全集 |
| **② 审片（判定）** | **人判定** | 机器只能判结构，判不了画面 |
| **③ 交付确认** | **人确认** | 门禁过了 ≠ 能交付 |

**★ 一句话**：**机器负责"不出错"，人负责"对不对"。**
**→ 这也正是本库"门禁过了 ≠ 能交付"的机制性原因**：**平台自己就把画面判定交给了人**（`check_continuity` 把"视觉身份"列为不可判）——**两边是一致的。**

**附 · 一个具体反例（本轮亲历）**：我连续三轮试图**自动化"取回平台内 Agent 的回答"**，全都失败（它无建文本节点能力；我无 `read_file_v2`）→ **平台把它设计成必须人搬**。这就是"不能完全自动化"的一手证据。

## 纪律七 · ★★★ 对"平台 Agent"的提问协议：**要思考审计，不要断言**

> **立规原因（用户 2026-09-24 定）**：**"你要明白他说的不一定准"** → 以后问答**必须让它进行思考审计**。

### 7.1 已被实测推翻的两条自述（先记住）
| 它的说法 | 我方实测 | 结果 |
|---|---|---|
| 可实体化节点**只有 image/video/audio**，文本层只能落文件 | `nodeType` **6 档**（含 `text`/`script`/`video-clip`），**已实建** | **推翻** |
| 合成 `X1` **不可空建**，须由 `composite_video` 产出 | `create_node(nodeType="video-clip")` **可建**，`timelines` +1 | **推翻** |

### 7.2 每次问询**必须**写进的三条要求
1. **给依据**：每条结论必须标来源（**工具 schema / 报错原文 / 官方文档 / 我实测**）；无法给来源的**必须标"这是我的推断"**。
2. **给反例**：请它主动说明**"什么情况下这个结论不成立"**（边界条件）。
3. **★ 自我审计一节**：请它列出**"本轮回答中你最不确定的 3 条 + 为什么不确定 + 我方该如何验证"**。

### 7.3 两条判据纪律
- **区分"他那层的限制"与"平台的限制"**：它说"做不到"时，**必须追问**是 **工具面限制**（它没那个工具）还是 **能力层限制**（平台真做不到）。
- **对表优先**：它的结论先与 **`pipeline-cross-source-consensus.md`** 的**跨来源共识**对表；**无外部佐证且与外部冲突的，不采信**。

### 7.4 ★ 独立核验（**自述 ≠ 事实**）
- 一切以 **`get_project_snapshot` / `read_node`** 的实测为准。
- **实测案例**：它自称"已代建 `STD_` 参照链（9 节点 + 4 边）"，而**答案落画布时实测仅 1 节点 / 0 边**；其后才逐条真建（约 2–4 分钟/个）。
- **凡"已完成/已建好/已生效"，必须回读核对**，不得转述其自述。

### 7.5 四段式问询模板（照抄）
```
【事实】把现状客观交底（节点数/边数/实测到的硬约束，附报错原文）
【我的问题】逐条编号，不许合并
【交付要求】逐条答 · 每条标依据（schema/报错/文档/你的推断）· 给边界反例
【自我审计】请列出你最不确定的 3 条 + 为什么 + 我方如何独立验证
```
